# AI 工作流 v2.1

按阶段顺序执行任务。**两条不可豁免的红线**贯穿全程：① **用户确认前不执行**（不得产出文件/跑脚本）② **计划先行**（未落盘 plan.yaml 不得开始处理）。其余阶段可按下方「任务分层」裁剪。

## 任务分层（开工第一件事：判定走哪条路）

| 层级 | 判定标准 | 执行方式 |
| --- | --- | --- |
| **L0 轻操作豁免** | 纯问答/查询/翻译、单文件读取、改一行字或一个变量、临时状态检查 | **直接做**，不建任务目录、不走阶段 0-6。回复保持简洁 |
| **L1 快速通道** | 阶段 0 命中 `assets/templates/` 同类模板，且配置无实质差异 | 提议"按上次配置开跑"→ 用户确认后跳过追问循环，直接引用模板缓存的查重结论 |
| **L2 全流程** | 产出文件/代码/报告、多步操作、数据分析、跨文件改造、方案评审 | 完整走阶段 0-6 |

判定存疑时**默认 L2**。用户明确说"直接做/别走流程"则从其指令，但两条红线中对用户的**明示授权**可替代"确认前不执行"，**计划先行**仍需满足（可在同一消息内给出计划并直接执行）。

## 阶段 0：开工前查可用 Skill

**必须**在进入阶段 1 前完成检索，并在回复中说明结果（有则列出，无则明确说明未找到）：

1. 检查本地已安装 skill：用户级 `~/.workbuddy/skills/` 与项目级 `.workbuddy/skills/` 清单。
2. 本地无匹配时，用 find-skills / 推荐市场搜索现成可装的 skill。
3. 判定：匹配 → 优先加载复用；部分匹配 → 复用可复用部分，差异点按本工作流执行；无匹配 → 全新执行。
4. **快速通道**：查 `assets/templates/`（字段定义见 `assets/templates/README.md`）是否已有同类任务确认表；命中 → 按「任务分层」走 L1。

## 阶段 1：任务理解（交互式追问循环）

**红线①：未获得用户确认前，禁止执行任何脚本或产出文件。**（L0/L1 除外）

1. 用澄清问题多轮追问，每轮 1-4 个问题，选择题优先并附推荐项；下一轮基于上一轮回答深挖。
2. 追问直至五要素齐备：① 目标 ② 输入 ③ 交付物（格式/路径/命名）④ 验收标准 ⑤ 边界约束。
3. 五要素齐备后输出「任务确认表」，并在**同一轮消息**里请求放行——用户回复"确认/开干"即视为放行，**禁止再单独发起一轮确认提问**；用户提出纠正则修改后再次请求放行。
4. **模板沉淀**：确认通过后把确认表存为 `assets/templates/<任务类型>.yaml`，**必须遵守 `assets/templates/README.md` 的统一 schema**（task_type / confirmed_at / goal / inputs / deliverable / acceptance / constraints / research / flow）；同类型已存在则更新而非新建。

## 阶段 2：调研（开源查重优先 + 证据分级）

**未完成查重并给出复用决策前，禁止进入实现环节。**

1. **查重按任务类型分流**：
   - 开发/建项目类 → 查重对象是开源项目与数据集；产出「开源查重对比表」（项目/数据集、功能覆盖度、Star/活跃度、许可证、可复用部分、差距），决策三选一：直接复用 / 克隆改造 / 参考思路自研（附理由，倾向克隆到本地精读）。
   - 调研/报告类 → 查重对象是既有报告与横评文章（避免重复劳动、站上现成横评做增量）；GitHub API 仅作 star/活跃度**数据源**，不作查重对象；产出「既有资料盘点表」+ 数据实测记录。
2. **数据一律实测**：GitHub 指标用 `scripts/http_fetch.py --github-repo <owner>/<repo>`（内置限流重试）。**禁止引用二手转述的 star 数**——实测与转述差距常达数倍。
3. **证据分级标注**：每条结论标注证据强度——【RCT】/【基准实测】/【大样本自评】/【官方推荐】/【实践观点】/【反例】。**厂商案例、营销倍数、"N× 效率"一律不得作为证据**。详见 `references/quality-gates.md`。
4. **并行检索硬规则**：检索方向 ≥3 个时必须并行派发子代理（见下"子智能体编排"），禁止串行等待。
5. **引入前安全与许可检查**：克隆/复用外部项目或安装依赖前，核对许可证兼容性（`license.spdx_id` 须为 MIT/Apache-2.0 等宽松型；**CC-BY-4.0 不适合软件代码**），并做基础安全检查（混淆脚本、硬编码密钥、异常外联、维护者可信度、`pushed_at` 是否停更）；有疑点先说明再引入。

## 阶段 3：AI 处理（计划 → 验证闭环 → 精检索 → 编排 → 质检）

**红线②：未产出 plan.yaml 前，禁止调用任何处理脚本；每步未明确目标前，禁止发起检索。**

1. **任务目录制**：建 `tasks/<任务类型>-<YYYY-MM-DD>/`，`plan.yaml`、交付物、中间数据统一落盘其中。plan.yaml 严格用 `assets/plan-template.yaml` 的**中文键格式**（`步骤 id / 做什么 / 输入 / 预期产出 / 验证方式 / 状态 / 交付物`）。**`交付物` 字段必填**——阶段 5 的 Anti-drop 对账完全依赖它。禁止把 plan.yaml 或交付物散落在工作区根目录。执行中实时更新状态（待办/进行中/完成/受阻）；中断后可凭此断点续做。
2. **验证闭环前置检查（v2 新增硬门禁）**：动手前先回答"**这个任务完成时，用什么可判定的信号证明它成了？**"
   - 有信号（测试/构建退出码/lint/断言脚本/schema 校验/截图对比）→ 把它写进 plan.yaml 的「验证方式」。
   - 无信号 → **先补一个最小验证物**（哪怕是一个校验脚本或一份人工检查清单），再开始处理；补不了就在 plan.yaml 里显式登记「人审点」。
   - 交付前要求**出示证据而非声称成功**：测试输出、命令返回值、文件清单；并在报告中填「验证闭环证据」一节（模板见 `assets/report-template.md`）。
3. **逐步执行**：每步开始前重述目标与判定标准；完成后核对预期产出并更新 plan.yaml（用 `checks.py plan <plan.yaml>` 复核，见阶段 5）；未达成先修正再推进。
4. **进度汇报节奏**：L2 任务每完成 2-3 个步骤或每切换一次阶段，向用户回报**一行**进度（`步骤 x/y 完成 → 下一步：…`）；只在受阻、需决策或全部完成时展开说明。长任务（预计 >5 分钟）开始前先给一句预期耗时与中间产出节点。
5. **精确检索**：定向检索——精确关键词、按需读片段、先索引/摘要后原文，禁止整库加载或无目的浏览；网页类优先 `http_fetch.py --grep "<关键词>" --max-chars 3000` 只取命中行；引用标明来源文件/URL。
6. **Token 纪律**（依据《调研-token优化与对话精简-2026-09-10》）：
   - **缓存优先**：稳定前缀在前、动态内容在后；DeepSeek 保持前缀一致吃磁盘 KV 缓存（命中 98% 折扣）；Anthropic 对稳定块加 `cache_control`；多轮任务复用同一系统提示词，禁止每次改写前缀。
   - **上下文分层**：热（近 10 轮原文）/温（滚动摘要）/冷（目标级摘要）；每层压缩 40-60%，**禁止压到 90%+**（会重新取数，总成本反升）。
   - **按需加载**：记忆/资料只取索引与摘要，命中后再读片段；历史任务先读 plan.yaml 断点。
   - **上下文文件极简**（v2 新增，依据 ETH Zurich arXiv:2602.11988 基准实测）：项目级上下文文件保持 30-60 行，**只写模型推断不出来的东西**（非常规命令、禁区、隐性约束）；**删除并禁止提交 `/init` 自动生成产物**（实测平均 -3% 成功率、+20% 成本）；仓库架构概览类内容无用。
   - **选型黑名单**：RouteLLM、GPTCache、Memobase 已停更，只参考思路不引入为依赖；LiteLLM 必须 ≥1.83.7。
7. 需要外部模型做批量总结/生成时用 `scripts/ai_call.py`（`--model` 可临时覆盖、`--stats` 回显用量与成本估算）；调用侧同步遵守第 6 条。
8. 项目差异化流程（量化 / 选品 / 小说 / 学习资料）见 `references/playbook.md`；对应任务确认表模板已就绪，可直接走 L1 快速通道。

### 子智能体编排

细则见 `references/orchestration.md`。硬规则：

- **Handoff 结构化交接**（不得用自由文本）：`task`（做什么）、`background`（背景与约束）、`input_paths`（绝对路径）、`acceptance`（验收标准）、`deliverable_path`（落盘路径）、`evidence_rule`（要求标注证据等级与来源）。
- **独立才并行**：无依赖的子任务并行派发（建议 ≤4 个）；**有依赖关系的任务必须串行**（B 依赖 A 产出）；探索用 Explore、方案设计用 Plan、写码执行用通用代理；只读调研类用轻量模型。
- 主代理负责拆分与汇总；子代理产出**只回传浓缩结论**（1-2k token），避免污染主上下文。
- 可委派的重复性工作不亲自做。

### 质量把关（信任但验证）

细则见 `references/quality-gates.md`。硬规则：

- **子代理产出未经主代理核实（查真实文件/输出）不得进入下一环节**；核实时优先抽查可复现的硬数据（如 API 实测值）。
- 关键产出对照任务确认表逐项核对；不合格带具体问题退回重做（**最多 2 轮**）。
- **对抗式互审**：2 轮仍不合格 → 派两个子代理独立审查并互相质证，主代理汇总裁决；仍不合格才升级用户。
- **评审防偏差**（当评审由模型完成时）：位置交换双跑取一致、裁判与产出异家族、rubric 明确"长度/格式不加分"、pin 裁判版本、用容差带而非精确阈值。

## 阶段 4：Office 产出

1. 用 `scripts/office_io.py` 生成 Excel/Word/PDF；报告结构参照 `assets/report-template.md`。
2. 写文件统一 `utf-8-sig`；Word 中文内容必须设置两层字体（`run.font.name` + `w:eastAsia`）。
3. 产出前先列出将写入的文件路径清单；库的坑见 `references/office-guide.md`。

## 阶段 5：自检交付

1. **Anti-drop guard（计划-交付对账）**：运行 `checks.py plan <plan.yaml 路径>` 自动核对——每个步骤的 **`交付物` 字段**对应文件是否真实存在（不接受"应该生成了"）、必填字段是否齐全、状态是否合法；非文件型交付物会标 SKIP 需人工确认。**禁止静默跳过**；FAIL 未清零不得交付。
2. 逐项核对自检清单并输出状态表：文件存在、可正常打开、编码正确、数据完整、符合验收标准、**验证闭环证据已出示**。
3. 全部通过后用 present_files 交付；任何一项不通过，回到对应阶段修复后重新自检。
4. 交付说明保持简洁：结论 + 关键文件 + 下一步建议。

## 阶段 6：复盘与沉淀（v2 新增）

任务交付后（L2 任务默认执行，L1 可跳过）：

1. **复盘四问**：哪个阶段返工最多？哪条假设被推翻？踩了什么坑（工具/接口/编码/权限）？下次能少走哪一步？
2. **沉淀去向**（按性质分流，不写流水账）：
   - 可复用的**流程** → 更新本 skill（SKILL.md 或 `references/`）或新建 skill。
   - 可复用的**配置** → 更新 `assets/templates/<任务类型>.yaml`。
   - 新的**反模式/坑** → 追加到 `references/quality-gates.md` 的反模式清单。
   - 仅本次有效的事实 → 工作区 `memory/YYYY-MM-DD.md` 一行带过。
3. 复盘结论压缩到 3-5 行，随交付说明一并给出。
4. **任务目录治理**：工作区 `tasks/` 超过 10 个任务目录，或存在 30 天以上的旧任务时，将旧任务移入 `tasks/_archive/<YYYY-MM>/`（保留 plan.yaml 与最终交付物，中间产物可删）；**归档只做移动，不做删除**，且须在回复中列出移动清单。交付物已归档的任务，交付说明中注明新路径。

## 故障排查

- 控制台乱码 → 脚本已强制 UTF-8 输出；仍乱码用 `chcp 65001`。
- AI 调用 401/超时 → 检查 AI_API_KEY / AI_API_BASE / AI_MODEL；脚本自带 3 次退避重试。
- **GitHub API 403** → 多为匿名限流（非权限问题），`http_fetch.py --github-repo` 已内置识别与退避重试；仍失败则改用已取证数据并注明"未实时校验"。
- PowerShell 报"无法识别" → 检查是否用 `&` 运算符加引号完整路径调用。
- Excel 打开乱码 → 确认用的是脚本默认 `utf-8-sig`。
- 交付前对账报 FAIL → 运行 `checks.py plan <plan.yaml>` 查看具体缺失项（字段为空 / 交付物文件不存在 / 状态非法）。
- `checks.py plan` 报缺 pyyaml → 运行 `scripts/setup_env.ps1` 装上（依赖清单已含 pyyaml）。
