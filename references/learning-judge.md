# 学习信号 · 快判（learning-judge，v4.8.0 新增）

> **定位**：ai-workflow 跑的第 5 个 **System 1 结构化判别** —— 判「**这次交互里有没有值得留下来的东西、属于哪一类**」，据此决定进 K2 抽取、还是直接判「无」。
> **它是红绿灯，不是车**：只输出「这属于哪种学习类型」与可学度，**不写库、不授权、不改技能本体**。
> **配套（机器侧随 v4.8.0 一同新增）**：判定结果落 `assets/plan-template.yaml` 的 `meta.学习判定`；机器校验见 `scripts/checks.py plan` 检查项 20/21；类型枚举的口径守卫见 `scripts/checks.py skill`（**三源**：本文件 §1 表 ↔ `scripts/judges.json` ↔ `references/data-model.md` §2.2 镜像）。
> **管线与本判定的关系**：本判定是 [K1 采集 → **K2 抽取**] 之间的那道闸 —— 判「无」就别往池里塞（效率项：不让噪声进池）。管线全文见 `references/learning-model.md`。
> **哲学来源**：与 `self-judge` / `method-judge` / `retrieval-judge` / `homework-judge` **严格同构** —— Jev（TypeSafe AI 的 System One 模型）三原语 Choice / Score / Noul + 校准概率 + fail-closed。

## 1. 定位与形态

| 项 | 值 |
| --- | --- |
| **模块名** | `learning-judge`（中文：**学习信号 · 快判**） |
| **形态** | ai-workflow 的**内部子模块**（非独立顶层 skill）；本文件即其完整契约，由阶段 6 收尾的**学习循环**加载 |
| **本质** | 纯判别（System 1）：**单次前向、无 chain-of-thought、无自回归展开** |
| **主语** | "这次交互里有什么值得留下来的" —— 判的是**可复用性**，不是"这次做得好不好" |
| **与另四块的分工** | `self-judge` 判**产出什么**（入口级）／`method-judge` 判**这步用什么手段**（步骤级）／`retrieval-judge` 判**该不该查、查哪类源**（检索级）／`homework-judge` 判**要不要按作业模式组织**（结构级）／**本模块判"这次有什么值得学"（经验级）** —— 五者各盯一根轴，**任何两者不可互推** |

**类型取值（Choice，五选一 + 组合）** —— 本表即**机器可读的守卫锚点**（表头 `| 学习类型 | 含义 |` 唯一，`checks_parity._p_learning_kinds` 按它取值；本表在**源规格内恰一处**，`references/data-model.md` 的镜像是另一源，二者与 `judges.json` 取并集比对）：

| 学习类型 | 含义 |
| --- | --- |
| **偏好** | 使用者**稳定**的习惯 / 口味 / 明确纠正（"以后都这样"「别这样」「太啰嗦」）→ 门槛最高（≥2 次独立证据） |
| **领域知识** | 从交互中提炼的**可复用领域结论**（口径、判据、方法取舍） |
| **流程坑** | 踩过的**坑与规避法**（反模式） |
| **事实** | 可复用的**稳定事实**（外部服务行为、环境常量、版本兼容性） |
| **无** | 本次交互**没有**值得沉淀的东西 → 不进池、不产候选 |

> ⚠️ **本表与主类三态／模式三态／能力四态都是不同的物理量** —— 主类问"这次产出什么"、模式问"要不要按作业结构答"、能力问"缺哪类能力"，本表问"有什么值得学"。**字形相近、语义无关**，不得合并、不得互相推导。
> ⚠️ **组合态**：`kind` 允许 `A+B` 形式（top2 概率差 < `combine_kind_delta` = 0.15 时产出，如 `偏好+流程坑`）。**`无` 不得参与组合** —— "没有"与"有"并列无意义，故它是**确定性非法**（不是判断分歧）。**刻意不设 `secondary` 字段**：本表本就允许并用（同 `homework-judge`）。

### 1.1 与「学习模型手册」的关系（判据 vs 快判，不是两套判据）

| 层 | 载体 | 承担什么 |
| --- | --- | --- |
| **判据语义源** | `references/learning-model.md` §3（四类知识的定义与门槛） | "什么算值得学的"**定义** |
| **执行形态（本契约）** | 本文件（`kind` 五态 + `V1–V5` 维度 + 阈值路由 + 落盘字段） | 把判据落成**单次前向的结构化快判**，可留痕、可机器校验结构 |

> 同 `capability-routing.md` ↔ `method-judge.md` 的分工：判据给"该不该"，快判给"这次实际判成了什么、置信多少"。**两条口径必须一致**：若本契约与手册 §3 冲突，以**手册 §3 的语义**为准，并把冲突登记为契约缺陷。

## 2. 触发条件

| 场景 | 是否触发 | 说明 |
| --- | --- | --- |
| L2 任务阶段 6 收尾（复盘沉淀同轮） | **必触发** | 判定与沉淀**同轮**跑 |
| L1 快速通道收尾 | 不触发 | 无足够留痕（L1 升 L2 则随之触发） |
| L0 轻操作 | 不触发 | 不建任务目录、无留痕 |
| 用户显式要求（"复盘你的学习"） | **触发** | 可跨任务批量判定池内积压候选 |
| 任务中途（阶段 3 某步） | **不触发** | 学习是**收尾回路**，只作用于任务末梢 |

**主动克制（判定阶段禁止做的事）**：**不触发重检索、不整读历史任务正文、不派子代理、不展开思维链、不预写知识条目** —— 一旦开始撰写条目就退化成 System 2，且会让判定被"写得好不好"污染。判定只看**指针与摘要**。

## 3. 执行步骤（单次前向、四步、无自回归）

```
① 解析 ：本任务的留痕指针 → 结构化信号态（来源 / 类型候选 / 缺口）  —— 不触发重检索、不预写条目
② 评估 ：并行打分 5 个正交维度 V1–V5 → 各维 Score(0–1) 或 Noul(P(true))
③ 选择 ：Choice 类型 + 校准分布 {偏好, 领域知识, 流程坑, 事实, 无}（五者之和 = 1）
④ 二值 ：Noul 判定「是否模糊 / 混合」→ 输出结构化判定
```

四步**全为单次前向**；第③④步共用同一次判别，不得为"提高准确率"多次采样（Realization A 下多次采样即多付一次前向）。

### 3.1 判定维度 Schema（Schema-First：**先定义维度，再判定**）

| 维度 | 含义 | 原语 | 高分指向 |
| --- | --- | --- | --- |
| **V1 复现性** | 这条经验**下次还会遇到**吗（一次性 vs 反复出现） | Score | 值得学 |
| **V2 特征性** | 它是**使用者/本项目的特征**，还是放之四海皆准的通用常识 | Score | 值得学（通用常识不值得占库） |
| **V3 纠正强度** | 用户是否**明示纠正或强调**（"别这样"「以后都照这个来」） | Score | 偏好（**并提高其证据权重**） |
| **V4 缺口度** | 当前 KB **未覆盖**的程度（`coverage=false` 时高） | Score | 值得学（已覆盖的不必再记） |
| **V5 稳定性** | **一个月后还成立**吗（低分 = 时效性事实，宜进 memory 而非 KB） | Score | 长期知识 |

> **V5 是本模块的效率与质量双闸门**：它的作用是**阻止"什么都往库里塞"** —— 一条只对本次有效的临时事实 V5 极低，判定应落在 `无`，否则库会被时效性内容稀释，直接损害 KB-First 的检索质量（**这正是"蒸馏"要做的第一件事**）。
> **V3 不是"要不要记"的判据**：它只**提高偏好的证据权重**（用户明示纠正时，一次即可视作强证据的**候选**，但**仍需过 §5.1 的门槛**才自动入库 —— 门槛不在本判定里松动）。
> **V2 是"通用常识"的挡板**：像"Python 列表从 0 开始索引"这类 V2 极低，即便正确也不该占库位。

### 3.2 三原语在模式选用中的对应

| Jev 原语 | 语义 | 本模块中的角色 |
| --- | --- | --- |
| **Choice** | 从 N 个里选（含分布） | 类型判定：`偏好/领域知识/流程坑/事实/无` + 校准分布（允许 `A+B` 组合） |
| **Score** | 连续位置 + 置信 | V1–V5 五个正交维度的连续分（0–1） |
| **Noul** | P(true) 是非判断（**无独立置信字段**） | `ambiguity`（是否模糊 / 混合） |

## 4. 输入输出契约（Contract）

**输入（最小化；判定阶段不取额外上下文）**：

```yaml
task_dir:       str|null     # 本任务目录（读 meta 与 trace，不整读交付物）
ledger_rows:    list|null    # 本次追加的 Ledger 行
user_quotes:    list|null    # 用户放行 / 纠正的**原话**（已脱敏）
kb_coverage:    bool|null    # 本次 KB-First 检索是否覆盖
in_workflow:    bool         # 是否任务中途（决定本次是否真触发）
```

**输出（机器可读，落 `plan.yaml` 的 `meta.学习判定`，与另四块 judge 同构）**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `kind` | `偏好` \| `领域知识` \| `流程坑` \| `事实` \| `无` | ✔ | Choice 主类型。**允许 `A+B` 组合**（`无` 除外）。**枚举唯一取值源见 §1 表** |
| `distribution` | `{偏好, 领域知识, 流程坑, 事实, 无}` | ✔ | 校准概率分布，**五键齐全且和 = 1** |
| `confidence` | float 0–1 | ✔ | = `max(distribution)` |
| `dimensions` | `{V1..V5}` | ✔ | 各维 Score 值（0–1） |
| `ambiguity` | bool | ✔ | Noul 判模糊 / 混合 |
| `route_hint` | str | ✔ | 处理指引（见 §5），非空 |
| `needs_learning` | bool | ✔ | **派生字段**：=（主类型 ≠ `无`）。**不是独立问句** —— 从设计上消除"kind 与 flag 自相矛盾" |
| `入库` | int ≥0 | 否 | 本次实际写入 KB 的条数（由 `kb_learn.py commit` 回填，供对账） |
| `候选` | int ≥0 | 否 | 本次留在累积池的条数（同上） |

> **字段化而非散文**：判定结果可进账本、可回溯、可机器校验结构（结构合法 ≠ 判得对，见 §10）。

## 5. 阈值路由（Threshold Routing）

| 区间 | 行为 |
| --- | --- |
| 主类型 `confidence ≥ 0.95` | **自动采信**，按对应 `route_hint` 进 K2 抽取 |
| `0.70 ≤ confidence < 0.95` | **中置信**：进 K2 但**标 `观察`**，即便过门槛也**不自动入库** |
| `confidence < 0.70` **或** `ambiguity = true` | **fail-closed：不进池**（见下方口径差异说明） |

**`route_hint` 按类型给出处理指引**：

| 类型 | route_hint |
| --- | --- |
| **偏好** | 进 K2 抽取 → 累积池（`MIN_EVIDENCE` 最高）→ 达门槛方可自动入 KB；**不改技能本体**（改本体须用户确认） |
| **领域知识** | 进 K2 → 池 → 达门槛自动入 KB（`category = 学习-领域知识`） |
| **流程坑** | 同上；另建议同步 `references/quality-gates.md` 反模式清单（走既有第 6 路，须用户确认） |
| **事实** | 同上，但**先查 V5**：时效性事实改记工作区 memory，不入 KB |
| **无** | 不进池、不产候选；在结论里写明「本任务无可学信号」 |
| 模糊 / 混合 | fail-closed：留池标 `观察`，**不自动入库** |

> ⚠️ **上表只按「学习类型」（`kind`）给指引**；`冲突` / `待废止` / `已废止` **不是 `kind` 的取值**，而是**池条目状态**（`state`），由 `kb_learn.py` 的池侧机制处理（`--contradicts` 冻结 / `--supersedes` + `retire` 提案）。**两者不得混写进同一张表** —— 那会把"判成哪一类知识"与"这条知识现在能不能动"压成一根轴。冲突分支的处理口径见 `learning-model.md` §4.3 第 4 条。

> ⚠️ **校准优先于准确率**：一个 70% 准确但**完美校准**的判定器，比 95% 准确却**错标**的更有路由价值 —— 这正是阈值取保守值（0.95 自动采信）的理由。
> ⚠️ **低置信不升级前沿模型**：低置信只意味着"说不准值不值得记"，**留池观察比升级模型更轻也更对症**（同另四块 judge 的口径）。

### 5.1 聚合规则（V1–V5 → 五态分布，**唯一口径源**）

§5 的阈值作用在 `confidence` 上，但**没有定义它从哪来** —— 本节补上这一段。它是本契约**唯一**的聚合规则，机器实现见 `scripts/kb_learn.py`（`judge` 子命令）。

**四步，全部确定性、无随机、无第二次采样：**

1. **原型锚点** —— 五个类型各有一个在 V1–V5 上的「理想位置」向量；
2. **距离** —— `d(k) = ‖v − anchor_k‖₂ / √5`，归一化到 [0,1]（`v` = 本次的 V1–V5）；
3. **分布** —— `distribution = softmax(−d / τ)`，`τ` = 温度；
4. **取值** —— `kind = _combine(distribution, combine_kind_delta)`（top2 差 < 0.15 → `A+B`）；
   `confidence = max(distribution)`；`needs_learning = (argmax != 无)`（**派生**，见 §4）。

**锚点与温度**的数值**只写在** `scripts/kb_learn.py` 的 `ANCHORS` / `TAU` **一处** ——
本手册与 `scripts/judges.json` 均**不复制**（同一物理量不写两处）。要数值请看代码或跑 `selftest`。

⚠️ **参数未拟合（与另四块同一条纪律）**：`ANCHORS` 与 `TAU` 都是**先验**，未经任何数据拟合。
故输出里 `_model.anchors_fitted` 恒为 `false`；由此得到的 `distribution` / `confidence`
**只可用于对照、回归与抽样指路**，不得据此声称准确率，也不得作为阈值依据。

**档位映射**（沿用 §5 表；代码不得另立一套）：

| 条件 | `_model.band` | 行为 |
| --- | --- | --- |
| `ambiguity = true` | `hold` | fail-closed：留池标 `观察`，不自动入库 |
| `confidence ≥ 0.95` | `auto` | 自动采信，进 K2 抽取 |
| `0.70 ≤ confidence < 0.95` | `mid` | 进 K2 但标 `观察`，即便过门槛也不自动入库 |
| `confidence < 0.70` | `hold` | fail-closed：不进池 |

> ⚠️ **`hold` 与另四块的 `clarify` 刻意不同（一处必须说准的差异）**：入口级 judge 的 fail-closed 是**问用户一句**（因为要动手了）；本模块的 fail-closed 是**不写、留池观察**（因为写库有长期副作用，而"没记住"是可恢复的）。**理由**：把一个不确定的结论写进长期知识库，会持续影响此后每一次检索 —— 代价不对称（漏记可补，错记难清）。故本模块的默认动作是**保守地不动**，而不是追问。
> ⚠️ **本模块不向用户发起澄清提问** —— 收尾阶段追问"这条要不要记"会把收尾变成一次交互，违反效率项。低置信一律留池，下次同 key 再来一次即自动升级（§4.2 门槛）。

**示例**（当前参数下的**真实输出**，2026-09-25 实跑；参数一变即失效）：

| V1–V5 | kind | confidence | band |
| --- | --- | --- | --- |
| 0.90 / 0.90 / 0.85 / 0.50 / 0.90（典型偏好） | 偏好 | 0.9803 | auto |
| 0.85 / 0.75 / 0.10 / 0.90 / 0.85（典型领域知识） | 领域知识 | 0.9925 | auto |
| 0.90 / 0.60 / 0.40 / 0.30 / 0.90（典型流程坑） | 流程坑 | 0.9846 | auto |
| 0.50 / 0.30 / 0.05 / 0.40 / 0.35（典型事实） | 事实 | 0.9934 | auto |
| 0.15 / 0.08 / 0.03 / 0.06 / 0.10（无可学） | 无 | 0.9865 | auto（判"无"判得**很确定**，正确） |
| 0.50 ×5（无信息） | 事实 | 0.5872 | **hold**（不动，正确） |

> ⭐ **两轮参数返修史（由 `selftest` 的结构性断言暴露，如实登记）**：
> ① **τ 初值 0.35** —— 实测使五类 softmax 的 `max` **结构上不可达 0.70** ⇒ `band` 恒为 `hold`
> ⇒ **整条学习管线永不吸收任何条目**。症状是"没有报错、没有 FAIL、只是什么都不吸收"——
> 这正是最危险的一类缺陷（伪装成运行正常）。
> ② **τ 改 0.08（只调温度）** —— `偏好` 达标，但 `领域知识` / `流程坑` 仍停在中置信档（0.846）
> ⇒ 暴露**第二因不是温度而是锚点间距**：这两类在 V1–V5 上几乎重合（归一化距离仅 **0.153**），
> softmax 无论 τ 多小都分不开。修法是把它们在 **V3 纠正强度**（0.10 vs 0.45）与 **V4 缺口度**
> （0.95 vs 0.30）上强分开 —— 语义上也成立：踩坑多伴随用户当场指出，而"领域知识"多是自己
> 实测归纳、不在既有文档覆盖内。重设后最近的锚点对距离 = **0.289**，τ 取 **0.055**（判据：需 `d₂ − d₁ ≥ 3.5τ`）。
>
> ⚠️ **由此确立一条纪律**：**软化的阈值函数必须配一条"极端输入要打满"的结构性断言** ——
> 否则"永远走兜底分支"会伪装成"运行正常"。该断言已落在 `kb_learn.py selftest` 的 ③′ 组：
> 「落在任一锚点上的输入必须达 `auto` 带」+ 阴性对照「无信息输入（全 0.5）不得落入 `auto` 带」。
> 任何人调 `ANCHORS` / `TAU` 后跑一次 `selftest` 即可拦住这类失效。
>
> ⚠️ **`confidence` 是「分布集中度」，不是「值得学的程度」** —— 两个物理量不可混读：
> 上表第 5 行「无可学」的 `confidence = 0.9865`（**很高**）并不意味着"很值得学"，
> 而是"判『无』判得非常确定"。**低置信 ≠ 不值得学**（可能是判不准），**高置信 ≠ 值得学**
> （可能是判"无"判得准）。该混读在本模块首次自检中就出现过一次（断言写错），故显式登记。

## 6. 集成位置与机制

落点 = **阶段 6 第 4 条（沉淀分流）之后、第 5 条（复盘结论）之前**：

```
任务收尾
```

### 6.1 与各组件的协作方式

| 协作对象 | 关系 | 协作方式 |

## 7. 判定模型：双 Realization（由谁 / 什么执行判断）

### 7.1 结论

与另四块 judge 相同：**基础设计不需要独立训练的神经网络** —— 脑内协议（Realization A）即可运行；独立决策模型（Realization B）是**可选升级路径**。

### 7.2 Realization A —— 脑内协议（默认，零新增依赖）

按 §3 四步单次前向完成判定；`route_hint` 直接取自 §5 表。**这是当前唯一的主判据**。聚合的算术半边由 `scripts/kb_learn.py judge` 提供（可复现），**语义打分仍归模型/人**。

### 7.3 Realization B —— 独立 System 1 决策模型（影子期只作对照）

| 项 | 事实 |
| --- | --- |
| **落地形态** | 若将来 Laya 服务（`127.0.0.1:8731`）常驻，可加 `judges.json` 的 `learning_judge` 模板与客户端映射 |
| **模板** | `scripts/judges.json` 的 `learning_judge`（`kind` / `ambiguity` / `V1–V5`；**无候选注入** —— 学习类型没有候选池） |
| **本轮状态** | `judges.json` **已备模板**（供口径守卫第三源与未来接入）；`laya_client.py` **未加该校验映射** —— 接入是**独立的一次改动**，本轮不做 |
| **降级** | 服务不可达 → 沿用 `laya_client.py` 既有的 exit 3 + `{"degraded":true}`，调用侧回退 Realization A，**流程不中断** |
| **风险边界（C1 影子形态）** | 只作对照、**不接管路由**、不进执行期闭环；判定主判据仍是 Realization A |

> ⚠️ **口径陷阱（与另四块同款）**：若将来接 Laya，其自带的 `confidence` 是**熵置信**，与契约的 `confidence = max(distribution)` 是**两个量**，不得混用。

## 8. 不可委派与护栏

1. **判定不可外包给产出方**：执行"这次任务"的那一步**不得**同时充当学习判定者（自证同一件事）；
2. **判定不产生写库授权**：`kind = 偏好` **不等于**已经可以写 KB —— 写库仍须过 §4.2 五条门槛；
3. **判定不产生改本体的授权**：`kind = 偏好` **绝不**授权改写 `SKILL.md` / `references/`；改本体属不可逆动作，须用户确认（红线① + 手册 §7.6）；
4. **不得用低置信绕过保守**：`confidence < 0.70` 或 `ambiguity = true` 时必须留池观察，不得"先记一条看看"；
5. **不得把 `无` 写成有内容**：若判定为 `无`，**不得**为凑数而编造候选（手册 §2.1 末条）。

## 10. 诚实边界（如实登记，不假装有保护）

1. **它不是门禁**：`confidence` 由模型自填、**校准无法被机器证明**；`checks.py plan` 只校验**结构合法与派生自洽**（类型合法 ≠ 判得对）。整段缺省只 WARN、不追认历史计划。
2. **识别仍是启发式的**：与手册 §3 同为启发式 —— 误判两条路都不致命（漏判少记一条；误判多一条待观察）；**故本模块刻意不新增"判定质量"类门禁脚本**，"这条算不算偏好"无法稳定机器判定。
3. **`kind` ≠ "这条知识对不对"**：本模块判**值不值得留**，不判**正确性**；`kind = 领域知识` 与"这结论是对的"毫无关系（§7 手册同条）。
4. **V3 不松动门槛**：用户明示纠正只**提高候选的证据权重**，自动入库仍须过 `learning-model.md` §4.2 **六条**（且**状态未冻结** —— 见第 8 条）—— 门槛不在本判定里改。
5. **影子期一切数值不可采信**：温度未拟合前，`thresholds` 与 `confidence` **只作留痕**；不得据此声称"学习判定准确率 X%"。§5.1 的示例表是**真实输出**（2026-09-25 实跑），但它证明的是「**实现与公式自洽**」，**不构成准确率证据** —— 锚点与温度仍是未拟合先验，与该表出自同一次设计，存在「锚点 ⟵ 样例 ⟵ 锚点」的循环嫌疑（同 `homework-judge.md` §5.1 已登记的那条）。
6. **参数失配会伪装成"运行正常"**：§5.1 记录的两轮返修（τ 过大 ⇒ `band` 恒 `hold` ⇒ 管线永不吸收）**没有任何报错**，是靠 `selftest` 的结构性断言才捕获的。**故调参后必须跑 `selftest`** —— 这条纪律已机器化，但"是否跑了"本身无法机器强证。
7. **组合态的下游行为未定义到细节**：`偏好+流程坑` 时按"以主类型落库 + 另一类型加标签"处理，**该处置是纪律而非机检**。
8. **本判定不负责"这条知识现在能不能动"** —— `kind` 只回答"属于哪类知识"；**冲突/废止属池条目状态**（由 `kb_learn.py` 的 `--contradicts` / `--supersedes` + `retire` 处理，见附录 A 末条与 §5 表末注）。⚠️ 更重要的是**照实登记一条历史缺陷**：K4 的冲突分支曾**不可达**（进入条件 `state == "冲突"` 由它自己的输出提供，全程序零赋值入口 ⇒ 循环依赖型死代码），致使**两条互相矛盾的结论被同时判「入库」**；2026-09-25 已修（`note --contradicts` + `selftest` CLI 端到端断言）。**该缺陷不报错、不 FAIL**，与第 6 条同型 —— 手册"已登记"不等于"已可达"。
