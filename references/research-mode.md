# 科研模式（research-mode，v4.24.0）

> **定位**：ai-workflow 在**产出结构层**上的第五个模式 —— 与 self-judge（认知轴：这次产出什么）、入口分型（来源轴：请求怎么来的）**正交叠加**，可叠加在任意主类与任意来源之上。它与**作业模式**、**文献阅读模式**、**逆向拆解模式**、**图示设计模式**同轴不同域：作业模式管「题目该怎么答」，文献阅读模式管「一篇文献该怎么读」，逆向拆解模式管「一个外部产物该怎么拆」，图示设计模式管「一份内容该不该画」，本模式管「**一次研究活动从选题到投稿该怎么组织**」。
> **一句话**：**做研究的难点不在“会不会做”，而在“哪些话是别人说的、哪些是我说的、我的结论撑得起多重的口气”** —— 本模块把这条分界从「读一篇文献」扩展为**贯通全链的证据纪律**，并把一次完整科研活动的阶段结构固化下来。
> **本模块不新增任何东西**：不加主类取值、不加来源分型取值、不改任务分层判据、**不加 plan 字段、不加 judge 判定层、不加机器判据**（理由见 §9）。它只规定**科研产出的组织方式**与**贯穿全链的证据纪律**。
> **加载口径**：命中「科研识别」（§2）后加载；未命中不加载（勿预读）。**R2 文献精读**的完整契约在 `references/literature-reading-mode.md`（本模式只引用其结构名，不重述）。
> **阶段结构的设计依据**（引用外部资产按本仓约定**用纯文本提及、不加反引号**）：对照外部 `deep-research` 的 8 阶段（SCOPE → PLAN → RETRIEVE → TRIANGULATE → OUTLINE → SYNTHESIZE → CRITIQUE → REFINE → PACKAGE）、`ARIS`（`wanshuiyin/Auto-claude-code-research-in-sleep`）的 88 skill 分工（idea-discovery / experiment-plan / experiment-queue / auto-review-loop / claims-drafting / figure-spec / citation-audit）与 `scientific-agent-skills` 的「数据检索 → 分析 → 报告」链路，**按本仓既有结构裁剪为 7 阶段**。差异处逐条写明于 §2.1，可被反驳。

## 1. 定位与形态

| 项 | 值 |
| --- | --- |
| **模块名** | `research-mode`（中文：**科研模式**） |
| **形态** | ai-workflow 的**内部子模块**（非独立顶层 skill）；本文件即其完整契约 |
| **所在轴** | **产出结构轴**（科研产出怎么组织）—— 与认知轴、来源轴**三轴正交** |
| **触发落点** | 阶段 0 第 2 步（入口分型）**之后**的「科研识别」；见 `SKILL.md` 阶段 0 |
| **主语** | “这次是不是一次科研活动、各阶段的产出该按什么结构给” —— **判形态，不判能力、不判越界** |
| **适用对象** | 从选题到投稿的一次完整研究活动，或其中的**任一阶段**（含用户只问其中一环，如只问「这个创新点站不站得住」） |
| **角色** | **研究者本人**（researcher）—— 对自己的结论负责，先问「我的证据撑到哪」，再决定话说到多重 |

**为什么不做成「来源分型的第四类」**（与前四模式同一条设计收敛，不是遗漏）：

来源轴枚举（消息 / 正式需求 / Bug）现有 **4 处载体** —— `SKILL.md` 阶段 0 第 2 步、`references/self-judge.md` §1.1、`assets/ledger-template.md` 命名规则表、`assets/熔断报告模板.md`。把「做一项研究」塞进去要同步改 4 处，**且该枚举目前没有机器守卫**（`checks.py` 的 `PARITY_ITEMS` 不含它）→ 改 4 处、零守卫、语义上还站不住：**「帮我看看这个思路能不能做」既可能是「消息」（顺口一句），也可能是「正式需求」（带开题报告与时间节点）**。真正需要挂的不是「从哪来」，而是「科研产出按什么结构给」。故做成**正交叠加**，与前四模式同一形态。

**与前四个模式的分界**（五者都在产出结构轴上，别混用）：

| 情形 | 归属 |
| --- | --- |
| 「这道题怎么做」 | **作业模式**（S0–S2 解题结构） |
| 「这篇文献讲了什么、站不站得住」 | **文献阅读模式**（Q1–Q4 四问结构）；在科研活动里即 **R2** |
| 「这个库怎么实现的、哪几处值得抄」 | **逆向拆解模式**（D0–D5 拆解结构） |
| 「把结论画成一张图 / 出个示意图」 | **图示设计模式**（P0–P4 图示结构）；在科研活动里即 **R5 的图部分** |
| 「从选题到投稿做一项研究」 | **本模式**（R0–R6 七阶段） |
| 「帮我查这个结论对不对」 | **检索/校核类**；可复用本模式的证据档，但不走 R0–R6 |
| 「把这篇论文翻译成中文」 | **L0 翻译**（不叠加任何模式） |

⭐ **本模式与文献阅读模式是「包含」关系，不是「并列」关系**：`literature-reading` 的 Q1–Q4 是本模式 **R2 的完整内部结构**；本模式额外向上（R0 选题、R1 调研）与向下（R3 实验、R4 分析、R5 撰写、R6 自审）展开。**只问「读一篇文献」时仍走 `literature-reading-mode.md` 独立入口**（见 §3.4）。

## 2. 阶段结构 R0–R6（七阶段，次序固定，不可跳步）

| 阶段 | 一句话判据 | **内容维度** | 继承 / 新增 |
| --- | --- | --- | --- |
| **R0 选题与创新点** | 研究问题是什么（一句话）＋ **它为什么还没被解决**（gap 的出处）＋ 我的贡献声明（**标为我方主张**） | **主张层** | 新增 |
| **R1 调研与查重** | 已有工作盘点 ＋ **本仓「调研先查重」纪律**（防重复造）＋ **检索范围与未覆盖范围声明** | **主张层 + 证据层** | 新增（复用 `references/playbook.md` 调研报告类） |
| **R2 文献精读** ⭐ | **原 `literature-reading-mode` 的全部内容**：审稿人 P1–P4 ＋ 四问 Q1–Q4 ＋ 位置锚 | **主张层 / 证据层 / 结构层** | **并入**（契约仍在 `references/literature-reading-mode.md`） |
| **R3 实验与数据** | 实验设计可复现（变量 / 样本 / 控制）＋ **数据来源与取得方式**＋ **未取到的范围** | **可核层** | 新增（义务借自 `references/teardown-mode.md` T1/T3） |
| **R4 分析与结论** | 结论强度**必须与证据强度匹配**（承 R2 的 P1）＋ 阴性结果如实登记 | **证据层** | 新增 |
| **R5 撰写与绘图** | 论文结构 ＋ **图**（交本仓 `diagram-mode` 或外部数据图技能）＋ **claim–evidence 对齐** | **构造层**（图部分含**可数层**） | 新增（**引用不重述**） |
| **R6 自审与投稿** | **投稿前自查**（立场 = 查验自己，非质疑他人）＋ 信源可信度核查 | **构造层** | 新增 |

⭐ **本模式的核心分界是「两层 + 三域」双轴**：

| 轴 | 内容 | 答错的后果 |
| --- | --- | --- |
| **三域**（承 R2，扩全链） | **主张层**（R0/R1/R2 的 Q1/Q2，是**别人的话或我的声称**，可在原文/检索记录核对）· **证据层**（R1/R2 的 Q3/R4，是**我构造的质疑与判断**）· **结构层**（R2 的 Q4，阅读策略） | 主张层答错 = **编造**（把别人没说的话安在别人头上）；证据层/结构层不标注 = **误导** |
| **两层**（承逆向拆解与图示设计） | **可核层**（R3 的数据来源与取得方式 —— 机器/原文有对应）· **构造层**（R4 结论、R5 撰写、R6 自审 —— 机器没有对应） | 可核层答错 = **编造数据来源**；构造层不标注 = **把自己的推断说成既成事实** |

**两者防法不同，不得混用**：三域的分界靠**「必须给位置锚 / 必须给推断标记」**；两层分界在 R3 靠**「必须给取数与未取范围」**、在 R4/R5/R6 靠**「必须给推断标记 + 结论强度不超证据」**。给构造层硬配机器判据会制造**假绿**（机器算不出「这个结论站不站得住」）。

### 2.1 与外部 `deep-research` 8 阶段的关系（为什么是 7 不是 8）

| 外部阶段 | 本模式的处置 | 理由 |
| --- | --- | --- |
| SCOPE | → R0 / R1 的一部分 | 本仓阶段 1「六要素确认」已覆盖范围界定，不重复 |
| PLAN | → **不设独立阶段** | 本仓**全流程已有 `plan.yaml` 计划先行**（红线②），再设一层会形成两套口径 |
| RETRIEVE / TRIANGULATE | → R1 + R2 | 「检索」与「多源交叉验证」在本仓拆成「泛调研」与「精读」两段 |
| OUTLINE / SYNTHESIZE | → R4 | 本仓把「出提纲」并入「分析结论」 |
| CRITIQUE / REFINE | → R6 | **提升为独立阶段**（外部是 deep 档才有的第 6/7 阶段，本仓认为投稿前自查不可选） |
| PACKAGE | → **不设** | 本仓阶段 4/5 的 Office 产出与交付已覆盖 |

**净结果**：8 → 7，**不是机械搬运，而是按本仓既有结构裁剪**。差异处都在上表写明，可被反驳。

## 3. 触发条件（科研识别，三判据）

阶段 0 在入口分型之后跑一次识别，**命中任一即叠加本模式**：

| # | 判据 | 特征 | 例 |
| --- | --- | --- | --- |
| **S1** | **显式科研特征** | 用户给出研究主题 / 开题要求 / 基金或课题 / 投稿目标期刊，或用「做研究 / 科研 / 课题 / 论文」指代整件事 | 「帮我做个研究」「这个课题怎么开题」 |
| **S2** | **期望形态** | 要的是**跨阶段的科研产出**（选题理由 / 调研结论 / 实验设计 / 分析与结论 / 论文稿件 / 投稿前自查），且**跨越两个以上阶段** | 「先读一批文献，再定创新点，再设计实验」 |
| **S3** | **语境线索** | 开题、写论文、投稿、复现、答辩、结题语境 | 「投出去前帮我把一遍关」 |

**不触发的相邻情形**（别把同类都算进来）：

| 情形 | 归属 |
| --- | --- |
| 「读一下这篇，回答审稿人式四问」 | **文献阅读模式**独立入口（= 本模式的 R2 单用） |
| 「把结论画成一张图」 | **图示设计模式**（= 本模式的 R5 单用） |
| 「这个库怎么实现的」 | **逆向拆解模式** |
| 「总结一下这几篇的摘要」 | **L0 直接答**；摘要级总结不需要 Q3/Q4 |
| 「帮我查这个结论对不对」 | **检索/校核类**；可复用 §5 证据档，但不走 R0–R6 |
| 「写一篇关于 X 的综述」 | **报告类**（`references/playbook.md`）；R2 可作为其中「单篇精读」的子步骤被复用 |

> ⚠️ **识别是启发式，不是门禁**：无法机器判定，也没有对应判据（本模块刻意不加 —— 见 §9）。误判**两条路都不致命**：漏判 = 按通用六阶段走，少一层阶段结构；误判 = 输出结构偏重，多几行小标题。

### 3.4 与「保留入口」的双轨口径（本模式与文献阅读模式并存）

用户 2026-10-08 决议：**`literature-reading` 保留入口 + 降为 R2 子阶段（双轨）**。三重入口同时有效：

| # | 入口 | 何时走 |
| --- | --- | --- |
| ① | **独立触发词直呼** | 用户只说「读这篇文献 / 文献阅读 / 审稿意见」⇒ 走 `literature-reading-mode.md`，**不展开 R0–R6** |
| ② | **科研模式的 R2 子阶段** | 用户在做一项研究 ⇒ R2 按该手册执行，**不重复读第二遍契约** |
| ③ | **手册索引表仍列该模式** | `SKILL.md` 手册索引表保留 `literature-reading-mode.md` 行（描述改为「科研模式 R2 子阶段手册」） |

⚠️ **两条轨不得同时叠加**：`literature-reading-mode` 与 `research-mode` 是**同一产出结构的不同粒度**，同时命中时**以 `research-mode` 为准**（粒度大者胜），其中文献部分按 R2 执行 —— 否则会出现「Q1–Q4 与 R0–R6 并列」的两套口径。

## 4. 研究者角色契约（四条）

它是一组**可执行的立场约束**，四条缺一不可（**与 R2 的审稿人 P1–P4 是不同立场，不得混用** —— 见 §6 N5）：

| # | 条款 | 具体做法 | 反面（不合格形态） |
| --- | --- | --- | --- |
| **R-a** | **结论强度 ≤ 证据强度** | 每一处「证明 / 必然 / 显著 / 首次」都要能指到对应强度的证据；弱证据只说弱话 | 用小样本的相关性说「证明了因果关系」 |
| **R-b** | **主张与证据分离** | 每条结论标明「我方主张（claim）／引来的事实（evidence）／我的推断（inference）」 | 把自己的推断与引来的事实混写，读者分不清哪句是我说的 |
| **R-c** | **阴性结果如实登记** | 不显著、失败、未复现的，照样写出来并注明；不做选择性报告 | 只报显著的三个指标，隐去失败的七个 |
| **R-d** | **gap 有出处** | 声明「还没被解决」时必须指向具体文献或检索记录；断不了存在的，改写为「在 X 范围内未检索到」（承本仓 `references/retrieval-judge.md` 的「不得断言不存在」） | 「该问题至今无人研究」却说不出检索了什么 |

> **R-d 的易踩点**：① 不得用记忆里的「另一篇文献」支撑 gap —— 除非该文献确实在检索记录中被核到（走 `references/retrieval-judge.md`）；② 不得把「我没查到」写成「不存在」（有界否定：只写「在 `<检索范围>` 内未检索到 X」）。

## 5. 证据档 A/B/C/D（全局纪律，只引用不重述）

**证据档 A/B/C/D 在本模式中升为贯穿 R0–R6 的全局纪律。**

> ⚠️ **四档的完整定义与唯一口径源在 `references/literature-reading-mode.md` §5** —— 本仓硬约定第 4 条：同一物理量不写两处。本页**只引用、不重述定义**。若发现两处并存，**以后者为准并报告冲突**。位置锚要求（页码优先 → 章节号 → 图表公式编号，拿不到标 `[位置不可得]` ＋ 原因）同样以该文件 §5.2 为准。

**升格后各阶段的档位落点**（这是本模式新增的部分 —— 只说「哪一阶段主要吃哪几档」，不重述档位定义）：

| 阶段 | 主要档位 | 说明 |
| --- | --- | --- |
| **R0 选题与创新点** | 我方主张 ⇒ 不套 A/B/C/D 的「引文档」；**gap 声明** ⇒ A/B（有检索记录）或 D（查不到就是查不到） |
| **R1 调研与查重** | A / B（已有工作盘点）＋ **D（检索范围声明）** |
| **R2 文献精读** | A / B / C / D 全档（原口径，见该手册 §5.1） |
| **R3 实验与数据** | 数据来源与取得方式 ⇒ A（可直接核对）／D（拿不到就写 D）；**未取到的范围必须写 D** |
| **R4 分析与结论** | 数字与检验结果 ⇒ A / B；**推断与解释 ⇒ C** |
| **R5 撰写与绘图** | 引文与数据点 ⇒ A / B；图上结论 ⇒ C；**claim–evidence 对齐表**标出每条 claim 的支撑档位 |
| **R6 自审与投稿** | 信源可信度核查 ⇒ A / D；**自查发现的问题 ⇒ C**（不写成「作者的问题」，那是 R2 的立场） |

### 5.1 三条硬纪律（承 R2 §5.3，扩全链）

1. **不得跨档冒充**：C 档的内容不许写成 A/B 档的口气。凡「未直接说明」的判断，一律带 `[C]` 且显式声明。
2. **不得用 D 档的沉默代替 D 档的明说**：读不到、数据未取到、检索未覆盖、原文没给、存在歧义 —— 都要**写出来**，不许静默略过（静默略过会让读者以为「已核过且没问题」）。
3. **不得外部补强**：不许用记忆里的其他文献补足或驳倒自己的论证 —— 除该文献确实在检索记录中被核到，否则先走检索并核实，且须声明「以下来自外部检索」。

## 6. 产出义务 N1–N6（落实「不得编造、结论不超证据」）

| # | 义务 | 判据 | 机器可查？ |
| --- | --- | --- | --- |
| **N1** | **主张与证据分离** | 每条结论标明「我方主张（claim）／引来的事实（evidence）／我的推断（inference）」—— 承 R2 的三域分界，扩为全链 | ❌ 纪律项 |
| **N2** | **结论强度 ≤ 证据强度** | 不得用「证明」「必然」等强断言描述弱证据；阴性结果如实登记 | ❌ 纪律项 |
| **N3** | **gap 有出处** | R0 声明的「还没被解决」必须指向具体文献或检索结果（**承本仓「不得断言不存在」纪律**，走 `references/retrieval-judge.md`） | ❌ 纪律项 |
| **N4** | **可复现三件套** | 数据来源 / 取数方式 / **未取到的范围** 三者齐（借自 `references/teardown-mode.md` T1/T3，**注明出处**） | ❌ 纪律项 |
| **N5** | **自审 ≠ 审他人** | R6 自审立场必须是「查验自己」；**不得**把 R2 的审稿人 P1–P4 直接套用（那是质疑他人的立场） | ❌ 纪律项 |
| **N6** | **图走既有通道** | R5 的图**不新造流程**：数据图（折线 / 柱 / 散点 / 箱线…）→ 外部数据图技能；示意 / 架构 / 时序 / 流程 / 看板 / 象限图 → 本仓 `references/diagram-mode.md` | ✅ **部分**（`diagram-mode` 的 F5 机器判据可复用，本模式**不新起一套**） |

> ⚠️ **N1–N5 是纪律项，机器不校验**。**不得**宣称「已自动拦截」（与四模式同一句诚实边界）。唯一有机器输入的是 N6，而它是**复用**而非新增。

## 7. 产出骨架（R0–R6 七段式）

```
① 研究问题与贡献      —— R0；主张层；gap 必须有出处（N3）
② 相关工作与查重结论  —— R1；已有工作盘点 + 检索范围与未覆盖范围声明
③ 文献精读            —— R2；按 references/literature-reading-mode.md 的 Q1–Q4 与证据档（引用不重述）
④ 实验与数据          —— R3；可复现三件套（来源 / 取数方式 / 未取到的范围，N4）
⑤ 分析与结论          —— R4；结论强度 ≤ 证据强度（N2）；阴性结果如实登记（R-c）
⑥ 撰写与绘图          —— R5；论文结构 + 图（走既有通道，N6）+ claim–evidence 对齐表
⑦ 自审与投稿          —— R6；自查立场 = 查验自己（N5）+ 信源可信度核查
```

**两条使用规则**：

1. **只覆盖部分阶段时，被跳过的阶段必须显式声明跳过理由**（不是省略 —— 省略会让读者以为是漏了）。
2. **① 一句话结论（optional）**：与 R2 同理，可在最前面给「这项研究值不值得做下去 / 现有证据支撑到哪」，但它**必须是可回退的** —— 若 R4 的阴性结果足以动摇结论，① 要如实写「其核心主张在现有证据下未获充分支撑」。

## 7.0 运行级要素（v4.24.0 新增：从「产出结构」扩到「怎么跑」）

> **本节的定位**：§2–§7 规定的是**产出结构**（R0–R6 该按什么骨架给）；本节规定的是**运行要素**（每阶段谁在什么输入下做什么、交出什么、怎么判合格、出问题怎么办）。
> **加载口径**：命中科研识别后按需加载；只问单阶段时可只读对应那一张表。
> **与既有节的关系**：本节**只填运行要素**，不重述 §2 的阶段判据、不重述 §5 的证据档定义、不重述 §6 的产出义务 —— 遇交叉一律**引用节号**。

### 7.1 各阶段运行要素表（R0–R6 × 七要素）

> 字段口径：**输入**＝开工前必须已有（缺则不得开工）｜**关键任务**＝必做的 3–6 件｜**输出**＝必须交出的产物｜**分工**＝谁做（⚠️ 标出**不可由 AI 代劳**项）｜**质量门**＝过门条件｜**风险**＝最可能出的问题 + 缓解｜**工具**＝指路，不安装。

#### R0 选题与创新点

| 要素 | 内容 |
| --- | --- |
| **输入** | 研究兴趣或问题线索；领域背景（可来自 R1 的初步检索）；**导师 / 团队的方向约束**（若有） |
| **关键任务** | ① 把研究问题写成**一句话** ② 查证「它为什么还没被解决」（gap）③ 写贡献声明并**标为我方主张** ④ 判断**是否值得做下去**（可行性 + 价值） |

| **关键任务** | ① 按预注册 / 预声明的口径做分析 ② **结论强度与证据强度对齐**（N2）③ 阴性结果如实登记（R-c）④ 敏感性 / 稳健性检查 ⑤ 区分「数字」（A/B）与「解释」（C） |

| **分工** | AI 可做：计算、统计、绘图代码、格式核对；⚠️ **不可由 AI 代劳**：**结论的强度定级**、**因果解释**、**「这是否推翻了我的假设」的判断** |

### 7.2 协作分工与角色矩阵

**角色位**（本仓默认单人 + AI 语境；多人场景按下表扩展）：

| 角色 | 职责 | 不可代劳的硬门 |
| --- | --- | --- |
| **研究者本人**（researcher）| 全流程主体；对结论与署名负责 | **全部「不可由 AI 代劳」项**（§7.1 各表已逐阶段标出） |
| **协作者 / 合作者** | 分担实验、数据、写作的具体环节 | 其**所负责环节的创造性判断** |
| **导师 / PI** | 方向把关、资源、投稿决策 | **选题决议**、**投稿决定**、**署名与贡献确认** |
| **AI（本助手）** | 检索、整理、草拟、计算、核查、格式化 | 不得代替上述任何**判断与取舍**（U2） |
| **外部工具 / 技能** | 计算、绘图、文献管理 | 其输出**须被人工核验**后才可进入产出 |

⭐ **AI 参与的边界（U1–U4，用户 2026-10-08 口径）**：

| # | 条款 |
| --- | --- |
| **U1** | **创造性投入是硬门**：§7.1 表中标「⚠️ 不可由 AI 代劳」的项**未由人类完成时，该阶段不得判为完成** |
| **U2** | **AI 辅助 ≠ AI 代劳**：AI 可做检索 / 整理 / 格式 / 核查 / 草拟骨架 / 代码；人类必做**研究问题与创新点的选择**、**实验设计的判断**、**结论强度与解释**、**叙事与论证的组织**、**署名与责任承担** |
| **U3** | **不得隐藏 AI 参与**：成果登记表须登记 AI 参与范围；投稿须遵守目标刊物 / 机构的 **AI 使用披露**要求 |
| **U4** | **「没有灵魂」的可操作化判据**：自问「这一段的判断与取舍，是我做的还是模型默认的」—— 若整段可被「换个模型也差不多的通用表述」替换，视为**创造力投入不足，须重做该段** |

### 7.4 风险控制

**风险登记表模板**（每项风险一行；随任务推进更新）：

| 字段 | 说明 |
| --- | --- |
| 编号 | R-01, R-02… |
| 阶段 | R0–R6 |
| 风险描述 | 具体到「什么会出问题」 |
| 类型 | 数据 / 方法 / 结论 / 合规 / 进度 |
| 可能性 × 影响 | 高/中/低 × 高/中/低 |

| **止损** | 一旦发生怎么办（退路） |
| 责任人 | 谁盯 |
| 状态 | 未发生 / 已发生 / 已关闭 |

**五类典型风险与默认缓解**：

| 类型 | 典型形态 | 默认缓解 | 止损 |
| --- | --- | --- | --- |
| **数据** | 数据泄漏 / 不可复现 / 取不到 | 切分规则先写；种子与版本固定；未取范围写 D | 换数据集或缩小结论范围 |
| **方法** | p-hacking / 口径事后改 / 相关当因果 | 口径先写下再跑，改动留痕 | 结论降级为「初步证据」 |
| **结论** | 过度断言 / 选择性报告 | N2 + R-c 强制 | 回 R4 重做分析 |
| **合规** | 引用未核 / 伦理与署名遗漏 / AI 未披露 | 投稿前清单逐条卡 | 补声明后重投 |
| **进度** | 选题过大做不完 | R0 一句话判据自检 | 缩小题目或分批交付 |

> ⚠️ **本表是纪律项**（不新增判据，P1）：机器不校验，**不得**宣称已自动拦截。

### 7.9 可追溯性机制（贯穿 R0–R6）

**目标**：任何一条最终结论都能沿「结论 → 分析 → 数据 → 来源」**倒着走回来**，且每一步有留痕。

## 9. 诚实边界（如实登记，勿夸大）

| # | 边界 | 说明 |
| --- | --- | --- |
| 1 | **科研识别是启发式，无机器判据** | §2 的 S1–S3 无法稳定机器判定（可为一句话、可带材料、可只问其中一环）。误判两条路都不致命（§3 末注）。 |
| 2 | **R0–R6 是产出结构，不是流程开销** | ① L0 单次咨询也照此组织，但**不建任务目录、不落 plan**（不必为此升级为 L2）；② **不得**因「只是问问思路」跳过证据档标注与结论强度约束。 |
| 3 | **本模式不替代研究能力** | 结构齐全 ≠ 研究做对了。它是**组织方式**，不是能力的替代品。 |
| 4 | **证据档 A/B/C/D 无法机器校验** | 它是**产出文本约定**，不在 `plan.yaml` 字段里 ⇒ 不纳入 `PARITY_ITEMS`（与 `literature-reading-mode.md` §9 第 2 条同口径）。判定靠人审。 |
| 5 | **§8 自检 10 项全是纪律项** | 机器不校验，**不得**宣称「已自动拦截」。唯一有机器输入的是 N6，且它是**复用** `diagram-mode` 的判据。 |
| 6 | **「不做独立 PLAN 阶段」是刻意的** | 因本仓已有 `plan.yaml`。若有人认为科研的 plan 粒度不同，需先论证「两套计划如何不冲突」。 |
| 7 | **图片段分界依赖外部技能的自我声明** | 外部数据图技能声明「不做示意图 / 流程图 / 架构图」是其**自述**，本模式采信但**未实测**其边界（若实测发现它也能画流程图，分界需重划）。 |
| 8 | **外部技能本模式一个都不安装** | 本模式只**指路**（数据图交外部技能、示意图交 `diagram-mode`），**不克隆、不安装、不代管**任何外部技能。外部技能的接入须单独走整合流程（许可、门禁、依赖序、lock）。 |
| 9 | **本页落地不等于生效** | 本页是**纪律项契约**，`SKILL.md` 侧的判定口径与索引行须同时在位，否则会出现「手册在、入口不在」的悬空承诺 —— 本次落地已在同批改动中写入 `SKILL.md` 与手册索引表。 |
