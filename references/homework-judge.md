# 模式选用 · 快判（homework-judge，v4.7.0 新增）

> **定位**：ai-workflow 在**任务最前端**跑的第 4 个 **System 1 结构化判别** —— 判「**这次该不该叠加「作业模式」**」，据此决定产出按 H1–H5 组织、按讲解组织、还是不叠加。
> **它是红绿灯，不是车**：只输出「这属于哪种模式」，**不产出具、不授权、不判越界**。
> **配套（机器侧随 v4.7.0 一同新增）**：判定结果落 `assets/plan-template.yaml` 的 `meta.作业判定`；机器校验见 `scripts/checks.py plan` 检查项 18；模式枚举的口径守卫见 `scripts/checks.py skill`（手册 ↔ 模板 json ↔ 代码常量三源同源）。
> **哲学来源**：与 `self-judge` / `method-judge` / `retrieval-judge` **严格同构** —— Jev（TypeSafe AI 的 System One 模型）三原语 Choice / Score / Noul + 校准概率 + fail-closed。

---

## 1. 定位与形态

| 项 | 值 |
| --- | --- |
| **模块名** | `homework-judge`（中文：**模式选用 · 快判**） |
| **形态** | ai-workflow 的**内部子模块**（非独立顶层 skill）；本文件即其完整契约，由阶段 0 的**作业识别**步骤加载 |
| **本质** | 纯判别（System 1）：**单次前向、无 chain-of-thought、无自回归展开** |
| **主语** | "这次请求要不要按作业模式作答" —— 判的是**产出形态**，不是"我能不能解" |
| **与另三块的分工** | `self-judge` 判**产出什么**（入口级）／`method-judge` 判**这步用什么手段**（步骤级）／`retrieval-judge` 判**该不该查、查哪类源**（检索级）／**本模块判"要不要按作业模式组织答案"（结构级）** —— 四者各盯一根轴，任何两者不可互推 |

**模式取值（Choice，三选一 + 组合）** —— 本表即**机器可读的守卫锚点**（表头 `| 模式 | 含义 |` 唯一，`checks_parity._p_homework_modes` 按它取值；本表在**源规格内恰一处**，`references/data-model.md` 的镜像是另一源，二者取并集比对）：

| 模式 | 含义 |
| --- | --- |
| **作业题** | 含题干结构（已知/求/证明/计算/设计/论述，或题号与小问编号）**且**要答案与过程 → **叠加作业模式**，按 H1–H5 组织 |
| **讲解题** | 要求讲解概念、原理或答疑，**不针对具体题目求解** → 不叠加；可借用 H2（知识点关联）与 H4（关键步骤解释） |
| **非作业** | 生成练习题/题库、普通工程或文档任务、闲聊 → 不叠加，按宿主模式处理 |

> ⚠️ **本表与主类枚举是两个物理量**：主类问"这次产出什么"（会话内回答／可运行产物／给人阅读的文件），本表问"要不要叠加作业模式"。**字形相近、语义无关**，不得合并、不得互相推导 —— 合并即造成同形异义的两套口径（这正是「技能库卫生」第 4 条要防的漂移）。
> ⚠️ **组合态**：`mode` 允许 `A+B` 形式（top2 概率差 < `combine_mode_delta` = 0.15 时由客户端产出，如 `作业题+讲解题`）。**刻意不设 `secondary` 字段** —— 一件事只在一处表达（与 `self-judge` 的 `secondary` 不同：那边主类是**互斥**的产出形态，这边模式本就允许并用）。

### 1.1 与「作业模式手册」的关系（判据 vs 快判，不是两套判据）

| 层 | 载体 | 承担什么 |
| --- | --- | --- |
| **判据语义源** | `references/homework-mode.md` §2（C1–C3 三判据、相邻情形处理） | "什么算作业题"的**定义** |
| **执行形态（本契约）** | 本文件（mode 三态 + W1–W5 维度 + 阈值路由 + 落盘字段） | 把判据落成**单次前向的结构化快判**，可留痕、可机器校验结构 |

> 同 `capability-routing.md` ↔ `method-judge.md` 的分工：判据给"该不该"，快判给"这一步实际判成了什么、置信多少"。**两条口径必须一致**：若本契约的判定与手册 §2 的三判据冲突，以**手册 §2 的判据语义**为准，并把冲突登记为契约缺陷。

## 2. 触发条件

| 场景 | 是否触发 | 说明 |
| --- | --- | --- |
| 用户请求进入 ai-workflow 处理（阶段 0 第 2 步之后） | **必触发** | 与 self-judge **同轮**跑，判完主类再判模式 |
| 请求明显属 L0（「1+1 等于几」） | **触发但可秒达** | 判 `非作业` 或 `作业题` + 低结构收益（W5 低）→ 直接答；不必落 plan |
| 用户明示「别走流程 / 直接说答案」 | **触发后遵从授权** | 判定仍留痕供回溯；**输出结构此时可压缩**（H2–H4 从简），但 H1 与 H5 不省（手册 §7） |
| 已在某工作流中途的子步骤 | **不触发** | 同另三份 judge：只作用于**任务入口**，不作用于执行期子步 |

**主动克制（判定阶段禁止做的事）**：**不触发重检索、不读全库、不派子代理、不展开思维链、不预先解题** —— 一旦开始算题就退化成 System 2，且会让判定被"答案好不好"污染。

## 3. 执行步骤（单次前向、四步、无自回归）

```
① 解析 ：用户原始请求 → 结构化意图态（题干 / 期望 / 语境）  —— 不触发重检索、不预先解题
② 评估 ：并行打分 5 个正交维度 W1–W5 → 各维 Score(0–1) 或 Noul(P(true))
③ 选择 ：Choice 模式 + 校准分布 {作业题, 讲解题, 非作业}（三者之和 = 1）
④ 二值 ：Noul 判定「是否模糊 / 混合请求」→ 输出结构化判定
```

四步**全为单次前向**；第③④步共用同一次判别，不得为"提高准确率"多次采样（Realization A 下多次采样即多付一次前向）。

### 3.1 判定维度 Schema（Schema-First：**先定义维度，再判定**）

| 维度 | 含义 | 原语 | 高分指向 |
| --- | --- | --- | --- |
| **W1 题干结构度** | 请求里含明确题意结构（已知条件 / 所求 / 条件限制 / 小问编号）的程度 | Score | 作业题 |
| **W2 期望形态** | 期望「答案与过程」，还是「交付物 / 系统」 | Score | 作业题 |
| **W3 语境线索** | 教材、章节、作业、复习、考试这类学习语境的强度 | Score | 作业题 / 讲解题 |
| **W4 受评压力** | 是否处于考试、测验或限时评价场景 | Score | 作业题（**并触发手册 I4 的诚信提示**） |
| **W5 结构收益** | 按 H1–H5 完整结构作答相比直接回答的增益 | Score | 作业题（低分 = 直接答即可，**效率项**） |

> **W5 是本模块的效率闸门**：它的作用是**阻止"所有题都套五阶段"** —— 像「1+1 等于几」这类请求 W5 极低，判定应落在 `非作业` 或结构压缩档，否则恰好违反三项核心原则的效率项。
> **W4 不是"要不要答"的判据**：它只驱动**附加提示**（受评场景提示学业诚信，手册 I4）。**本模块不裁定是否该帮**（见 §10）。

### 3.2 三原语在模式选用中的对应

| Jev 原语 | 语义 | 本模块中的角色 |
| --- | --- | --- |
| **Choice** | 从 N 个里选（含分布） | 模式判定：`作业题 / 讲解题 / 非作业` + 校准分布（允许 `A+B` 组合） |
| **Score** | 连续位置 + 置信 | W1–W5 五个正交维度的连续分（0–1） |
| **Noul** | P(true) 是非判断（**无独立置信字段**） | `ambiguity`（是否模糊 / 混合） |

## 4. 输入输出契约（Contract）

**输入（最小化；判定阶段不取额外上下文）**：

```yaml
request_text:   str          # 用户原始请求（题干原文）
context_clues:  str|null     # 可选：极少量语境线索（教材/章节/老师要求）
in_workflow:    bool         # 是否任务中途（决定本次是否真触发）
```

**输出（机器可读，落 `plan.yaml` 的 `meta.作业判定`，与 `meta.入口判定` 同构）**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `mode` | `作业题` \| `讲解题` \| `非作业` | ✔ | Choice 主模式。**允许 `A+B` 组合**（top2 差 < 0.15）。**枚举唯一取值源见 §1 表** |
| `distribution` | `{作业题, 讲解题, 非作业}` | ✔ | 校准概率分布，**三键齐全且和 = 1** |
| `confidence` | float 0–1 | ✔ | = `max(distribution)`（**不是** Laya 的熵置信，见 §7.3） |
| `dimensions` | `{W1..W5}` | ✔ | 各维 Score 值 |
| `ambiguity` | bool | ✔ | Noul 判模糊 / 混合 |
| `route_hint` | str | ✔ | 处理指引（见 §5），非空 |
| `needs_homework` | bool | ✔ | **派生字段**：=（主模式恰为「作业题」）。**不是独立问句** —— 从设计上消除"mode 与 flag 自相矛盾"（该坑在 `method-judge` 的 `needs_tool` × `gap_class` 上出现过） |

> **字段化而非散文**：判定结果可进账本、可回溯、可机器校验结构（结构合法 ≠ 判得对，见 §10）。

## 5. 阈值路由（Threshold Routing）

| 区间 | 行为 |
| --- | --- |
| 主模式 `confidence ≥ 0.95` | **自动采信**，按对应 `route_hint` 执行 |
| `0.70 ≤ confidence < 0.95` | **中置信**：按主模式**轻量起步**（结构从简）并标记待复核 |
| `confidence < 0.70` **或** `ambiguity = true` | **fail-closed**：返回一句澄清问题（如"这是要我按作业题的方式解出过程，还是只讲方法？"），**不猜测、不默认** |

**`route_hint` 按模式给出处理指引**：

| 模式 | route_hint |
| --- | --- |
| **作业题** | 叠加作业模式：按 H1→H5 组织（审题与已知条件 → 思路与知识点 → 分步推导/求解 → 关键步骤解释 → 答案与验证）；题型骨架见 `references/homework-mode.md` §4 |
| **讲解题** | 不叠加；按讲解组织，可借 H2／H4 结构，不必走全五阶段 |
| **非作业** | 不叠加；按宿主模式（`self-judge` 的 category 与来源分型）正常处理 |
| 模糊 / 混合 | fail-closed：一句澄清，不猜测 |

> ⚠️ **校准优先于准确率**：一个 70% 准确但**完美校准**的判定器，比 95% 准确却**错标**的更有路由价值 —— 这正是阈值取保守值（0.95 自动采信）的理由。
> ⚠️ **低置信不升级前沿模型**：低置信只意味着"没说清要的是过程还是讲解"，**澄清一句比升级更轻也更对症**（同另三份 judge 的口径）。

### 5.1 聚合规则（W1–W5 → 三态分布，**唯一口径源**）

§5 的阈值作用在 `confidence` 上，但**没有定义它从哪来** —— 本节补上这一段。它是本契约**唯一**的聚合规则，机器实现见 `scripts/homework_model.py`（`aggregate()`）。

**四步，全部确定性、无随机、无第二次采样：**

1. **原型锚点** —— 三个模式各有一个在 W1–W5 上的「理想位置」向量；
2. **距离** —— `d(m) = ‖w − anchor_m‖₂ / √5`，归一化到 [0,1]（`w` = 本次的 W1–W5）；
3. **分布** —— `distribution = softmax(−d / τ)`，`τ` = 温度；
4. **取值** —— `mode = _combine(distribution, combine_mode_delta)`（top2 差 < 0.15 → `A+B`）；
   `confidence = max(distribution)`；`needs_homework = (argmax == 作业题)`（**派生**，见 §4）。

**锚点与温度**的数值**只写在** `scripts/homework_model.py` 的 `ANCHORS` / `TAU` **一处** ——
本手册与 `scripts/judges.json` 均**不复制**（同一物理量不写两处）。要数值请看代码或跑 `selftest`。

⚠️ **参数未拟合（与 Laya 侧同一条纪律）**：`ANCHORS` 与 `TAU` 都是**先验**，未经任何数据拟合。
故输出里 `_model.anchors_fitted` 恒为 `false`；由此得到的 `distribution` / `confidence`
**只可用于对照、回归与抽样指路**，不得据此声称准确率，也不得作为阈值依据。

**档位映射**（沿用 §5 表；代码不得另立一套）：

| 条件 | `_model.band` | 行为 |
| --- | --- | --- |
| `ambiguity = true` | `clarify` | fail-closed：一句澄清（**优先于置信判断**） |
| `confidence ≥ 0.95` | `auto` | 自动采信，按 `route_hint` 执行 |
| `0.70 ≤ confidence < 0.95` | `mid` | 轻量起步 + 标记待复核 |
| `confidence < 0.70` | `clarify` | fail-closed：一句澄清 |

**示例**（当前参数下的**真实输出**，仅供体感；参数一变即失效）：

| W1–W5 | mode | confidence | band |
| --- | --- | --- | --- |
| 0.90 / 0.85 / 0.60 / 0.20 / 0.85 | 作业题 | 0.9636 | auto |
| 0.15 / 0.30 / 0.75 / 0.05 / 0.60 | 讲解题 | 0.9131 | mid |
| 0.85 / 0.95 / 0.85 / 0.95 / 0.90（受评场景） | 作业题 | 0.9250 | mid |
| 0.50 ×5（无信息） | 讲解题 | 0.5373 | **clarify** |

> ⚠️ **本节不改任何判据**：§2 触发、§3 四步、§5 阈值、§8 护栏、§10 边界**全部不变**；
> 它只是把「维度分 → 分布」从**黑箱**变成**可执行**。语义半边（打分）仍由模型/人完成 ——
> **模型不做识别、不从文本猜维度**（否则等于把 §10.2 刻意排除的启发式从后门放回来）。

> ⭐ **锚例 8/8 已过留一法复核（2026-09-23 实证，不是循环自证）**：锚点值与锚例的维度分出自
> 同一次设计，天然有「锚点 ⟵ 样例 ⟵ 锚点」的循环嫌疑。实测三条 ——
> **留一法 8/8**（剔除该条、用其余同类样例均值重算锚点，仍判对）、
> **全量均值锚点 8/8**（完全不手调）、**随机锚点均值 3.0/8**（对照显著低）
> ⇒ 8/8 反映的是样例在维度空间中**可分**，而非"拟合到自身的复述"。
> ⇒ **但锚例的维度分仍是推定值、不是独立标注**，故 8/8 **不构成准确率证据**，
>    只是「实现与公式自洽」的回归锚（与 §7.3「一致率 ≠ 准确率」同一条纪律）。

> ⚠️ **`needs_homework` 的派生口径有 4 个载体**（2026-09-23 审查发现，原写"三处"与实现不符，已更正）：
> `aggregate()` ／ `checks_judges._check_homework_verdict` ／ `homework_model._nh_of_mode` ／
> **`laya_client.map_homework_judge`（B 侧）**。四处口径等价，但**第 4 处独立实现、不走公共函数、
> 无机器判据保证同步**。未收敛为 import 的理由：`laya_client.py` 存在第二份物理拷贝，
> 收敛会把"一个文件双写"膨胀成两个 —— 故维持独立实现 + 显式登记为**已知边界**。

### 5.2 A/B 一致率：出口条件与测量方式（2026-09-23 补）

§7.3 原写：「切换 B 为主判据需**温度拟合 + ≥50 条 A/B 一致率达标**，阈值未定值」。
该条件此前**结构上无法满足** —— 不是样本不够，而是 **A 侧没有可复现实现**：脑内协议每次现场给分布，
同一组题两次可能不同，测出来的"一致率"是噪声。§5.1 补上了 A 侧的可复现半边，故测量链路现在是：

```
同一份题集 ─┬─► A 侧：W1–W5（模型/人打分）──► homework_model.py aggregate ──► mode_A / dist_A
            └─► B 侧：laya_client.py --judge homework-judge（真机）───────► mode_B / dist_B
                              └─► homework_model.py agree --pairs pairs.json ──► 一致率报告
```

`agree` 报四项：`mode_exact_rate`（串相等）、`mode_set_rate`（拆 `+` 后集合相等）、
`needs_homework_rate`、`dist_l1_mean`（分布 L1 距离均值，0 = 完全一致），并列出分歧清单。

**仍未闭环的部分（如实登记）**：

| 缺什么 | 由谁补 |
| --- | --- |
| ≥50 条**真机** B 侧输出（服务须先常驻） | 服务可用后跑；本轮服务未运行，**真机样本 0 条** |
| A 侧 W1–W5 的**独立标注**（不能用模型推定的值当金标准） | 人工或前沿模型逐条标注 |
| `ANCHORS` / `TAU` 的拟合 | 有标注样本后替换（`--anchors-file` / `--tau` 为预留入口，本轮不做） |
| 一致率阈值（`--min-agree` 取多少） | **用户拍板** —— 脚本刻意不给默认值，未传参时**只报告不判定** |
| B 侧第 4 个派生载体（`laya_client.map_homework_judge`）与 A 侧**同步性无机器判据** | 见 §5.1 末条；当前靠人工双写 + 显式登记，漂移不会被门禁抓到 |

> ⚠️ **不许把「一致率」说成「准确率」**：两者都要金标准。一致率只说明 A/B 两个判定器是否**同步**；
> 同步也可能是**同步地错**（同 §10）。

## 6. 集成位置与机制

落点 = **阶段 0 第 2 步（入口分型）之后、第 3 步（查可用 Skill）之前**：

```
用户请求
  └─► [self-judge]      → category（产出什么）
  └─► [入口分型]         → 来源分型（怎么来的）
  └─► [homework-judge]  → {mode, distribution, confidence, dimensions, ambiguity, route_hint, needs_homework}
        └─► 写入 plan.yaml 的 meta.作业判定   （字段清单以 §4 为准：7 项必填）
              └─► 驱动：(a) 是否按 H1–H5 组织产出  (b) 题型骨架选择  (c) 是否提示学业诚信（W4 高分时）
```

### 6.1 与各组件的协作方式

| 协作对象 | 关系 | 协作方式 |

## 7. 判定模型：双 Realization（由谁 / 什么执行判断）

### 7.1 结论

与另三份 judge 相同：**基础设计不需要独立训练的神经网络** —— 脑内协议（Realization A）即可运行；独立决策模型（Realization B）是**可选升级路径**，本机已落地为 Laya 影子后端。

### 7.2 Realization A —— 脑内协议（默认，零新增依赖）

按 §3 四步单次前向完成判定；`route_hint` 直接取自 §5 表。**这是当前唯一的主判据**。

### 7.3 Realization B —— 独立 System 1 决策模型（Laya，影子期只作对照）

## 8. 不可委派与护栏

1. **判定不可外包给产出方**：执行"解这道题"的那一步**不得**同时充当模式判定者（自证同一件事）；
2. **判定不产生授权**：`mode = 作业题` **不等于**可以做更难的事（越界仍需当次授权，红线③）；
3. **W4 只驱动提示，不驱动拒答**：受评场景的处置口径（不代做、改讲方法）属**纪律项**，由手册 I4 定义，本模块只负责把它**标出来**；
4. **不得用低置信绕过澄清**：`confidence < 0.70` 或 `ambiguity = true` 时必须澄清一句，不得"先按作业题做一版看看"。

## 9. 判定样例锚（边界判例，供 Realization A 的 few-shot 锚定）

| 请求 | 期望判定 | 为什么（关键维度） |
| --- | --- | --- |
| 「已知 a=1,b=2，求 a+b，要完整过程」 | **作业题** | W1 高、W2 高、W5 中高 —— 典型计算题 |
| 「第 3 章课后第 5 题：证明……」（附题面） | **作业题** | W1 高（题号 + 命题）、W3 高；**注意仍需 H5 验证** |
| 「帮我讲讲拉格朗日乘数法」 | **讲解题** | W1 低（无题干）、W3 中、W2 指向"听懂"而非"答案" |
| 「给我生成 20 道高数练习题」 | **非作业** | W1 有"题"字但**要的是题不是解** —— 属学习资料生成类 |
| 「这段代码为什么报错」（附报错） | **非作业**（走 Bug 闭环） | W1 中但形态是"排障"；**Bug 优先级更高**（来源轴） |
| 「1+1 等于几」 | **作业题**（低结构档）或 **非作业** | W1 低、**W5 极低** —— 直接答即可，这正是 W5 的作用 |
| 「这道题答案是不是 42？」 | **作业题** | 校核型：仍须 H1→H5 复算并给**独立结论**，不因"用户已给答案"放弃验证 |
| 「明天考试，帮我做完这 10 道大题」 | **作业题** + **W4 高** | 受评线索 → **触发 I4 提示**（不代做，改讲方法） |

## 10. 诚实边界（如实登记，不假装有保护）

1. **它不是门禁**：`confidence` 由模型自填、**校准无法被机器证明**；`checks.py plan` 只校验**结构合法**（类型合法 ≠ 判得对）。整段缺省只 WARN、不追认历史计划。
2. **识别仍是启发式的**：与手册 §2 同为启发式 —— 误判两条路都不致命（漏判少一层结构；误判结构偏重）；**故本模块刻意不新增门禁脚本**，"这是不是一道题"无法稳定机器判定。
3. **模式三态不是"答案对不对"的判据**：本模块判**形态**，不判**正确性**；`mode = 作业题` 与"答案正确"毫无关系。
4. **W4 的处置不由本模块裁定**："该不该帮做"涉及学业诚信，**非本流程权限**；W4 只保证**提示被触发并可留痕**。
5. **影子期一切数值不可采信**：温度未拟合前，`thresholds` 与 `confidence` **只作留痕**；不得据此声称"模式判别准确率 X%"。
6. **组合态的下游行为未定义到细节**：`作业题+讲解题` 时按"以作业题骨架为主 + 附加讲解段"处理，**该处置是纪律而非机检**。
