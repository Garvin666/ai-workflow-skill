# 记忆管理与交接（memory-handoff，v4.37.0 新增；v4.38.0 起为**双向**：写入轨 `place` ＋ 读取轨 `pull`；v4.39.0 起按**记忆库两库**落位；v4.40.0 起落位自带条目契约 frontmatter）

> **定位**：ai-workflow 的**记忆归档回路** —— 把任务收尾时的留痕（plan / trace / Ledger / 日结），整理成两篇对人类与后继会话都友好的文档（**交接文档** 与 **会话记忆**），落进知识库 `40-记忆`（**记忆库**）区，并在同轮做**两段式自升级**（低风险自动、结构类提案）。
> **它解决什么**：任务做完后，「做了什么、结果如何、后续事项」散落在任务目录与 Ledger 里 —— 下一会话若要接手，得先考古。本机制把这类信息**归档到统一记忆区**，让加神模式（dsh 侧）与未来会话能直接读到。
> **它不解决什么**：① 不做**知识沉淀**（那是学习模型的事 —— 可复用领域知识写个人知识库 KB，与本机制的「工作记忆」是两个物理量，见 §8）；② 不做**对话级临时交接**（那是外部技能 `handoff` 的职责）；③ **不自动改写技能本体**。
> **加载口径**：L1／L2 任务阶段 6 收尾时读；日常任务不需要。

## 1. 存储位置与分项目组织（权威结构）

```
知识库根（E:\ChatGPT\知识库）\
└── 40-记忆\                          ← 「记忆库」的物理根（语义名=记忆库，目录名沿用，见 §1.1）
    ├── 00-记忆索引.md                ← 自动生成（本机制 index 重建，勿手改）
    ├── 用户记忆库\                   ← 记「人」：与用户的交互内容
    │   ├── 会话记忆\<项目>\YYYY-MM-DD-HHmm-<主题>.md   ← place --kind memory
    │   ├── 会话记忆\*.md             ← 存量平铺（2026-10-16 前的历史文件，原位保留）
    │   ├── 问答记忆\<项目>\          ← 按需启用（手写，无引擎校验）
    │   └── 画像\做事方式.md          ← 自升级自动档维护（语义判断）
    └── 工作记忆库\                   ← 记「活儿」：可复用的工作经验
        ├── 交接\<项目>\YYYY-MM-DD-HHmm-<任务短名>.md    ← place --kind handoff
        ├── 经验沉淀\<项目>\          ← 按需启用（手写，无引擎校验）
        └── 纠错账本.md               ← 自升级自动档维护（统计 + 语义）
```

**1.1 两库口径（2026-10-19，用户指定）**：记忆库下分**用户记忆库**（会话记忆 / 问答记忆 / 画像）与**工作记忆库**（交接 / 经验沉淀 / 纠错账本）。判据：记**人**的进用户库，记**活儿**的进工作库；一篇只归一处，跨库内容拆两篇互链。**物理根目录仍叫 `40-记忆`** —— 它是 kbpipe 分区登记、宿主配置与全库双链的锚点；「记忆库」是语义名。

**分项目组织规则**：

| 项 | 口径 |
| --- | --- |
| 项目名 | **任务所在工作区的目录名**（如 工作流 / 数模 / 量化分析与数据分析）；口径与恶补报告一致 |
| 分层 | `<库>/<层>/<项目>/<文件>`；引擎可写的层 ∈ {用户记忆库/会话记忆, 工作记忆库/交接} |
| 命名 | `YYYY-MM-DD-HHmm-<短名>.md`（短名 = 任务短名或会话主题；继承 40-记忆 既有命名惯例） |

| 模板权威源 | **知识库 40-记忆 的 README.md**（三段式 / 五段式的定义在彼，本手册不复述；只写校验口径） |

## 2. 写入时机与流程

**触发**：**L1 与 L2 任务阶段 6 收尾，每次必写**（SKILL.md 阶段 6 第 9 条），与复盘沉淀同轮。**L0 轻操作豁免**（纯问答／单文件读取／改一行字，不建任务目录，也不落记忆）。
> v4.38.0 扩面（用户 2026-10-16 拍板：「每次工作完成之后都同步将记忆写入记忆板块」）。**代价如实登记**：L1 也落位后，`用户记忆库\会话记忆\`／`工作记忆库\交接\` 的篇数增速约翻倍，§3 T2 阈值（交接单项目 ≥10 篇）会更早触发；体量口径的权威源仍是 40-记忆 README。

**分工（语义归模型，算术归脚本）**：

| 环节 | 谁做 |
| --- | --- |
| 从 plan / trace / Ledger / 日结抽取素材、撰写两篇文档的**内容** | 模型 |
| 结构校验（关键节齐备与顺序）、落位路径计算、幂等备份、写入、索引重建、统计 | `scripts/memory_handoff.py` |

**一步命令（示意）**：

```
python scripts/memory_handoff.py place --kind handoff --project <工作区名> --task <任务短名> --src <草稿.md>
python scripts/memory_handoff.py place --kind memory  --project <工作区名> --task <主题>   --src <草稿.md>
python scripts/memory_handoff.py index        # 重建索引（幂等）
python scripts/memory_handoff.py stats        # 输出统计（自升级输入）
python scripts/memory_handoff.py pull --root <知识库>\40-记忆 --out <宿主记忆目录>\<快照>.md   # 刷新只读共享快照（见 §2.1）
```

**幂等与更新口径**：**同名重放（同 `--project` / `--task` / `--date` / `--time`）= 更新**（旧版自动备份为 `<文件名>.bak-<时间戳>`）；不同任务短名不互撞。⚠️ **更新既有篇目须显式传 `--date` / `--time` 与首版一致** —— 缺省取当前时刻 ⇒ 会**新增**一篇；同日同任务异时间会打印**防重复 WARN**（不阻断，防「想更新却静默新增」）。索引重建幂等（内容相同不重写）。**写入逐字节保真**：读写均 `newline=""`，不注入 CRLF（2026-10-16 实测：默认参数会把 LF 静默转 CRLF，与 会话记忆 存量行尾不一致 ⇒ 已修 ＋ 加「行尾保真」夹具）。

**校验口径（脚本判）**：交接须含三个按序节 ——「内容 / 结果 / 后续」；会话记忆须含五个按序节 ——「任务与结果 / 关键决策 / 偏好信号 / 未决 / 重要事实」（正则容忍「一、」等编号与措辞变体）。**占位符告警**：`<xxx>` / TODO / 待填 等命中时打印 WARN（不阻断，但应在交付前清掉）。

### 2.1 读取轨：`pull` 只读导出共享快照（v4.38.0）

写入轨解决「记得下」，读取轨解决「别的宿主读得到」 —— 加神会话直接扫 `40-记忆`，但 Qoder／codex 侧的会话开工时读不到该区。`pull` 把该区导出为**宿主可读的单文件快照**（落宿主自己的记忆目录），收尾 `place` 之后刷一次即可。

```
python scripts/memory_handoff.py pull --root <知识库>\40-记忆 --out <宿主记忆目录>\kb-shared-40记忆.md
# 可选：--kinds 画像,索引,交接,会话记忆（缺省 画像,索引,交接）--project <项目名> --recent N（缺省 2）--max-bytes（缺省 200000）--dry-run
```

**五条口径**（与写入轨同源，不造第二套判据）：

| # | 口径 | 为什么 |
| --- | --- | --- |
| ① | **只读**：`--out` 落在 `--root` 之内一律拒绝（rc=2），写回 40-记忆 永远只有 `place` 一条通路 | 导出轨若同时能写，写入面就变成两处，红线③与常态授权的边界会失效 |
| ② | **内容指纹幂等**：快照头记 sha256 前 16 位，指纹**不含时间戳与 mtime** ⇒ 同输入复跑不重写、不留 `.bak` | 与 `index` 同一口径（v4.37.0 实测：头部写「最后重建时分」会让幂等分支结构性不可达，一日堆 9 个 `.bak`） |
| ③ | **分层取舍**：缺省导 `画像`＋`索引`＋`交接`（完成态与稳定偏好），流水层 `会话记忆` 只取按文件名字典序**最近 `--recent` 篇**；存量平铺不导 | 全量倒灌会让快照与画像大量重复、体量翻倍；快照要给"接手用"的，不是给"归档用"的 |
| ④ | **截断显式**：超 `--max-bytes` 时按序省略并在头部列出**被省略清单**，不静默丢内容；一个源都没取到 ⇒ 拒绝写空快照 | 「少了几篇」必须可见；空快照会让下一宿主误读成「记忆区已清空」 |
| ⑤ | **原子写、恒 LF**：临时文件 + `os.replace`，读写 `newline=""`；快照头部标注 `⛔ 含本机绝对路径与用户做事方式，不得推入任何 git 仓` | 与写入轨行尾保真同源；快照属本地私有物，外推即隐私外发面 |

**阴性对照**（selftest 夹具 10–13）：改 1 字节必须重写／`--out` 落区内必须 rc=2／空源与非法 `--kinds` 必须 rc=2／幂等复跑 `st_mtime_ns` 不变且无 `.bak`。

### 2.2 写入轨自动写条目契约 frontmatter（v4.40.0）

`place` 落位时**自动**在正文前写一块条目契约（`id / kind / layer / scope / status / confidence / provenance / review`，契约见知识库《记忆库第二大脑架构设计》§3.3）。此前靠「收尾时别忘了手工跑一次 `mem fm`」—— 236 篇里只有 2 篇带块，就是这个「别忘了」失效的实证（2026-10-19 实测）。

| 项 | 取值 / 行为 |
| --- | --- |
| `kind` | `--kind handoff` → `handoff`；`--kind memory` → `record`（与知识库条目层工具 mem.py 的路径推导同源） |
| `layer` | 两者均 `M1` |
| `scope` | `project:<--project>` |
| `id` | `mem-<kind>-<YYYY-MM-DD>-<HHmm>-<task>` |
| `confidence` | 恒 `1`（观察：出现 1 次、未经复核） |
| `provenance` | `source: task`（本机实测产出）／`ref: <--src>`／`at: <日期>T<时分>` |
| `review` | `half_life_d: 90`、`pinned: false`、`next_check: <+90 天>` |
| `--no-fm` | 关掉自动写块（仅用于逐字节比对等场合；正常落位不要用） |
| `--link REL:ID` | 追加一条条目关系，可重复（如 `--link derived_from:mem-handoff-2026-10-19-1245-x`）。`REL` 只能是契约五种的 `supersedes` / `refines` / `contradicts` / `derived_from` / `applies_to`；给别的值**硬拒且不落位**（selftest fixture 18），因为自造关系名会让 `mem doctor` 的 F3 直接断链。`links:` 块落在 `provenance:` 之前，与知识库侧 `build_frontmatter` 同序（fixture 17）。 |

**三条幂等语义**（selftest fixture 14–16）：

1. 草稿没有 frontmatter → 直接加块，且**去掉首块后正文逐字节不变**（行尾保真不因加块失效）
2. 草稿已带含 `id` 的契约块 → 原样沿用，不再叠第二块（拿旧产物当草稿重放也安全）
3. 草稿带无 `id` 的外来块（`tags` / `created` / `项目` 这类自用注释）→ 外来行**逐字保留**、排在契约段之后

**跨模块互锁**：技能侧自实现这段序列化（要能脱离知识库独立运行），知识库侧（mem.py，在 `30-产出\记忆库工具\`）有自己的解析与校验 —— 同一格式两处实现，靠文档同步必然漂移。故 mem.py 的自检会读取 `30-产出\记忆库工具\fixtures\` 下的两份 place-产物.md / place-产物-带链接.md（本脚本 place 的**真实**输出）并跑契约校验：格式一漂移，`mem.py selftest` 先红。带链接那份专测 `--link`：两条关系必须读得回、且 `links:` 在 `provenance:` 之前（两处实现同序）。夹具重生成：`tasks\实施-记忆条目层P1-2026-10-19\make_fm_fixture.py`（无链接版）／`tasks\实施-记忆条目层P2-2026-10-19\make_link_fixture.py`（带链接版）。

**落位时就把关系写清楚，别指望事后推断**：`place` 是唯一知道「这次任务基于什么」的时刻（上游设计稿、前序交接、被修正的旧结论）。事后再补只能靠正文双链（知识库侧 `mem autolink` 只敢从 `[[...]]` 推 `derived_from`，因为那是可验证的引用事实），实测 238 篇里可建 0 条 —— 记忆条目之间本就少互相引用。故**能在 place 时用 `--link` 说明的关系，不要留给事后猜**。

> 引用写法约定：**技能内**文件用反引号（会被 `checks.py` 的「文档引用完整性」当链接核对）；**库外／用户级**工具用纯名 ＋ 路径定位，不加反引号 —— 否则校验器会按技能内相对路径找不到而报 FAIL（与 kb.py 走白名单是两种处置；选不改校验器，因为那不在本任务的授权面内）。

## 3. 两段式自升级

**触发条件（三个）**：

| # | 触发 | 说明 |
| --- | --- | --- |
| T1 | 任务收尾同轮 | place 完成后跑 `stats`：产出统计与建议清单 |
| T2 | 阈值 | 会话记忆（含存量）合计 ≥20 且无索引 / 交接单项目 ≥10 篇 / 纠错账本同类计数 ≥2（统计供模型判定） |
| T3 | 用户显式要求 | 「整理记忆」「升级记忆机制」——可跨任务批量 |

**更新范围（两档 + 一红线）**：

| 档 | 动作 | 处理 |
| --- | --- | --- |
| **自动档**（低风险，执行后留痕即可） | 画像行的**追加/合并**（仅满足「重复 ≥2 次或用户明示」的特征）、纠错账本**统计行**、记忆索引**重建**、README **修订记录行**、过期标记 | 直接执行；改文件前先 `.bak` 备份；在 README 修订记录加一行 |
| **确认档**（结构类，只出提案） | 三段/五段**模板变更**、记忆区**结构调整**（增删层）、**口径修订**、一切**删除** | 出「升级提案」（落任务目录或 `40-记忆\升级提案\`），含 触发/拟改/影响面/回滚方式；**用户确认后才执行** |
| **红线**（永不做） | 碰加神守则、碰知识库其它分区、碰 ai-workflow 核心判据、碰 40-记忆 内的 `.bak` 存量与灵枢插件另一条轨的文件 | — |

**留痕**：每次自动档动作在 40-记忆 README 的「修订记录」区加一行（日期 / 变更 / 触发）；确认档在提案执行后同样补记。

**诚实边界**：自升级的**质量无机器 oracle** —— 机器只保证「有依据（stats 数字）、可回滚（备份）、留痕（修订记录）」；画像合得对不对、纠错归类准不准，只能人审。`stats` 的 `suggestions` 是**指路不是决定**。

## 4. 授权与边界

- **常态授权**（用户 2026-10-16 拍板，v4.38.0 起扩至 L1）：**所有 ai-workflow L1／L2 任务收尾均可写入 40-记忆 区**；写入面**严格限于 40-记忆 的 `用户记忆库\` 与 `工作记忆库\` 两棵子树**，不碰知识库其它分区，也不许两库互写。
- 每次任务在 plan 的 `meta.越界授权` 登记当次实际写入路径（常态授权下免逐次申请，但**留痕不豁免**）。
- **读取轨 `pull` 的落点在工作区外**（宿主自己的记忆目录，如 `~/.qoder/memory/`）：属**只读导出物的落盘**，须按红线③当次登记 `meta.越界授权`；快照**不得推入任何 git 仓**（含本机绝对路径与用户做事方式）。
- **绝不碰**：`.obsidian\`、`kb-workbench\`、知识库 `Ledger.md`（知识库 CLAUDE.md 的禁改区）；`40-记忆` 内 `.bak-*` 文件；灵枢插件（@furongjun1999/dsh-memory）的记忆体系（另一条轨，不读不写不整合）。
- **凭据纪律**：两篇文档不写凭据、密钥、隐私；写入口径与 40-记忆 README 边界一致。

## 5. 机器检查

| 命令 | 作用 |
| --- | --- |
| `scripts/memory_handoff.py selftest` | 自测（18 组 fixture：合法×3／阴性对照×2／幂等×3／JSON×1／行尾保真×1(`--no-fm`)／防重复 WARN×1／条目契约×3／写面守卫×1／空源与越界拒绝×1／links 写入与拒收×2）——改动脚本后必跑 |
| `place --dry-run` | 只校验不落位（先看后写） |
| `place --no-fm` | 落位但不写条目契约块（v4.40.0；仅用于逐字节比对，正常收尾别用） |
| `index --dry-run` | 预览索引条目计数 |
| `pull --dry-run` | 预览快照（打印正文与指纹，不写 `--out`） |
| `stats` | 自升级统计（JSON）；含 `旧路径残渣` 字段（v4.39.1 起） |

**旧路径残渣探测（v4.39.1）**：两库化后 `index` / `stats` 只扫 `用户记忆库\`、`工作记忆库\` 两棵子树。若某个宿主仍持旧版引擎（或旧文档教它这么写），会把篇目写进根级 `40-记忆\会话记忆\`、`40-记忆\交接\`、`40-记忆\画像\` —— **不报错，但索引里看不见**（2026-10-19 实测发生过一次）。故两命令均会检出这类文件并 `[WARN]` 列出，`stats` 另加一条 suggestion。**只报警不搬动**：归位属结构性操作，须人工确认后按 `用户记忆库/会话记忆/`（会话记忆、画像）或 `工作记忆库/交接/`（交接）移动，再跑 `index`。

判据边界（诚实声明）：结构校验只证「节齐、序对、非空」，**不证内容质量**；幂等只证「同路径重放有备份」，**不证不该更新的没被更新**（那是模型纪律）；`pull` 只证「导出的字节与源一致且复跑不重写」，**不证快照里的内容仍然正确** —— 它是源的副本，不是第二份事实。

## 6. 与既有件的关系（防两套口径）

| 既有件 | 关系 |
| --- | --- |
| 学习模型（`references/learning-model.md` / kb_learn.py） | **不同物理量**：学习管「可复用的知识」（写 KB 本体），本机制管「工作记忆与交接」（写 40-记忆）。收尾同轮分别跑，互不代管 |
| 外部技能 `handoff` | **不同层**：handoff 是对话级临时交接（存系统临时目录）；本机制是任务级归档交接（存知识库、长期可查） |
| 工作区 `.workbuddy/memory/` 日结 | **过程流水 vs 完成态**：日结记「这一天做了什么」；本机制记「这个任务完成态 + 交接」 |
| 恶补报告（knowledge-cram-report） | **并列归档**：恶补落各工作区 `恶补\`；记忆落知识库 40-记忆 —— 项目名口径一致 |
| 加神模式（dsh 侧）与其他宿主 | **三宿主共用同一记忆区**（口径权威源＝40-记忆 README）：dsh／Qoder／codex 都写同一批分层文件。写入互不代管，**读取分两条物理路径** —— 加神会话直接扫该区，Qoder／codex 侧经 `pull` 快照读（区外进程无法整目录扫）。格式对齐五段式 |
| 宿主侧 `~/.qoder/memory/` 等持久记忆 | **素材 vs 共享**：宿主记忆是本次会话提炼出的**素材与本地口径**，40-记忆 是**跨宿主的事实源**；两者冲突以 40-记忆 为准，宿主记忆档须写清快照来源与生成时间 |
