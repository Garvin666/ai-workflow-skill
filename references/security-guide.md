# 信息安全与数据保护（按需加载）

> **归属**：`SKILL.md` §信息安全与数据保护的细则手册。
> **何时加载**：任务涉及**凭据**、**个人隐私**、**商业秘密**、**内部基建信息**，或含**对外动作**（发送／推送／发布／写入共享位置）时加载。**其余情况勿预读**（Token 纪律）。
> **口径**：本文件是信息安全类要求的**单一事实源**。其他手册与正文若与其冲突，以本文件为准；正文只做索引，不重复展开。

---

## 一、凭据纪律（S1，唯一口径，无例外）

| 场景 | 正确做法 | 禁止 |
| --- | --- | --- |
| 传入脚本 | 环境变量（`GITHUB_TOKEN` 等）或 `--token` 参数 | 写进代码常量、配置文件、命令行明文回显 |
| 展示/确认 | **前缀掩码 + 长度**，如 `ghp_****…（40 位）` | 打印完整值、贴进回复、贴进截图 |
| 落盘 | **一律不落盘** | 写进 `plan.yaml`／`Ledger.md`／trace／日志／临时文件／交付物 |
| 记忆 | **不写记忆**（用户级与工作区级都不写） | "记一下方便下次用" |
| 多环境复用 | 用凭据管理器（Windows 凭据管理器 / `gh auth`） | 复制到第二个文件方便切换 |
| 失效处理 | 走 `secret-leak-response` 流程 | 直接删文件了事（未确认吊销是否生效） |

**判定优先级**（与既有脚本一致）：`--token` → 环境变量 → 已登录 CLI 的凭据存储。**只读不落盘。**

> ⚠️ **本节是全流程唯一口径**。任何脚本、任何环节**不得另立例外**——散落的口径必然分叉（本技能 v3.2.1 之前，凭据要求只写在「仓库与推送工具」一节，其他环节无从遵循）。

## 二、敏感信息四级分级（S2）

**先分级，再决定处理方式**。分级在**阶段 1** 完成（识别输入）、**阶段 4/5** 复查（确认输出与外发）。

| 级别 | 典型内容 | 可否出工作区 | 可否入交付物 | 可否经外部服务 | 处置要点 |
| --- | --- | --- | --- | --- | --- |
| **L1 凭据** | API Key、Token、密码、私钥、会话 Cookie、连接串 | ✗ | ✗（**任何形式**，含截图与示例） | ✗ | 按 §一 处置 |
| **L2 个人隐私** | 邮箱、手机号、身份证/护照号、住址、真实姓名+单位、生物特征 | 仅必要且经用户同意 | 仅必要；否则**脱敏** | 仅必要且经用户同意 | 掩码（`138****1234`）、聚合（只留统计量） |
| **L3 商业秘密** | 未公开的财务数据、客户名单、定价与策略、竞品情报、未发布产品信息 | 仅必要且经用户同意 | 按用户指定范围 | 优先本地处理 | 最小化字段；外发前确认可见性 |
| **L4 内部基建** | 内网主机名/IP、内部目录结构、账号名、内部系统 URL、端口拓扑 | 可（限工作区内） | **避免**；确需则以占位符代替 | 避免 | 用 `<内部主机>` 之类占位符 |

**未识别的数据默认按最严一级处理**，直到确认其级别为止——**"不知道算不算敏感"不等于"不敏感"**。

**分级结果落点**：阶段 1 确认表（本任务输入含哪几级、处理范围与去向）；阶段 5 出站清单（外发内容含哪几级、可见性如何约束）。

## 三、数据保护（手段）

| 手段 | 具体做法 | 常见违背 |
| --- | --- | --- |
| **本地优先** | 敏感数据优先本地处理（本地模型 / 本地脚本）；不可行时回到 S3 由用户决定是否接受外发 | 默认丢给云端 API "先试试" |
| **最小化** | 只取完成本步**所必需**的字段与行；能聚合就不取明细 | 为省事整表读入，再在代码里过滤 |
| **去标识** | 分析与建模用 ID 替代身份字段；需要对齐时用映射表并单独保管 | 把姓名/手机号直接喂进模型 |
| **留存有界** | 中间产物放 `tasks/<任务>/tmp/`；交付后按需清理（**只清理自己生成的中间产物，不动用户数据**） | 临时文件散落在工作区根、长期留痕 |
| **传输** | 只走 HTTPS；不通过明文 HTTP、查询串或第三方 paste 服务传数据 | 用短链/图床/粘贴板"顺便"传文件 |
| **不外传给子代理** | 派子代理时**只给它完成该步所需的那部分数据**，并告知其级别 | 为了让子代理"了解背景"而附上全量数据 |

## 四、访问控制与授权登记（S4）

**判定口令（发起前自问）：不越界，这一步还能不能完成？** 能完成 → 别越界；不能完成 → 按下列格式申请。

### 授权请求格式（请求时必须写全五项）

```
要访问：<具体路径，不用通配与目录级泛写>
操作：  读 / 写 / 删改
频次：  一次性 / 本次任务内持续
用途：  <一句话，这一步为什么要它>
不做会：<不授予时的替代方案或后果>
```

**收窄原则**：用户给的宽泛许可（"D 盘随便看"）由**执行方主动收窄**到实际所需的最小子集，并在确认表中**复述收窄结果**供其纠正。**上一任务的授权不延续到本任务**（红线③）。

### 登记格式

| 位置 | 内容 | 机器校验 |
| --- | --- | --- |
| `plan.yaml` 的 `meta.越界授权` | `{路径, 操作, 依据, 时间}` | **有**（`checks.py plan` 检查项 9：交付物落到工作区根外且未登记即 FAIL；登记项作白名单。**不校验「依据」是否属实**，见 §九 第 3 条） |
| `Ledger.md` 的「越界授权记录」列 | 路径 + 用户授权原话摘要 + 时间 | 人审 |
| 交付说明 | 本次是否发生越界、越界了哪些路径、依据 | 人审 |

> **登记不等于放行**：登记是**事后可追溯**，不是**事前许可**。顺序永远是「先请求 → 拿到当次同意 → 再执行 → 后登记」。
> **技能生成例外**：正在生成的技能其功能实现本身必须跨出工作区时（技能安装目录、自身运行环境／依赖、附带资源），**无需申请即可执行**；但须在回复中说明越界了哪些路径。**"顺手省事"与"取用工作区外的数据/素材/他人文件"不在豁免内。**

## 五、出站前扫描清单（S3/S4）

**触发时机**：交付物或其他文件**将对外可见**之前（发送给他人、推送远端、发布上线、写入共享目录、附进邮件）。

**扫描范围**：**将外发的全部文件**（不是抽样）。逐项比对：

| # | 检查项 | 命中即处置 |
| --- | --- | --- |
| 1 | 凭据特征：`ghp_`／`sk-`／`AKIA`／`-----BEGIN * PRIVATE KEY-----`／`password=`／`token=`／连接串中的账号密码 | **停止全部对外动作**，走 §八 应急 |
| 2 | 个人隐私：邮箱、手机号、身份证号、住址 | 脱敏或移除外发范围 |
| 3 | 内部基建：内网主机名/IP、内部绝对路径、内部账号名、内部系统 URL | 换占位符 |
| 4 | 本地绝对路径：含用户名的主目录路径（如 `C:\Users\<名>\…`） | 换成相对路径或占位符 |
| 5 | 未公开数据：商业密级内容是否超出用户指定范围 | 缩减到授权范围 |
| 6 | 元数据：Office 文档属性中的作者/公司名、图片 EXIF 中的 GPS 与设备信息 | 清除元数据后外发 |
| 7 | 可见性：目标是否为 public / 全员可见 / 未被授权的对象 | **重新确认可见性**（S3 内容清单必备项） |
| 8 | 隐藏内容：批注、修订记录、隐藏工作表/行列、被删除但未清除的单元格 | 清理后再外发 |

**清单化（S3）**：外发确认时**必须列出**：文件与字段清单、目标位置、**可见性**、留存期、回滚方式。**未列清单不得执行**；实际外发与清单不符即**中止并重新确认**。

> **诚实标注（v3.5.0 更新）**：本清单**第 3 / 4 项已机器化** —— `scripts/outbound_scan.py` 扫描「将外发的全部文件」，命中即判 FAIL，并在 `push_router.py` 的改动面扫描中**阻塞推送**（fail-closed：扫描器导入失败同样阻塞，不静默放行）。**第 1 / 2 / 5 / 6 / 7 / 8 项仍是纪律项**，无机器门禁。执行者逐项比对后，**须在交付说明中声明「已扫描 / 命中项与处置」**，**不得声称六项都已自动拦截**。机器化部分的射程边界见 §九 第 1 条。

## 六、留痕脱敏

**留痕的目的是可追溯，不是留证据链把敏感数据一并留下。** 以下位置一律**不得**出现 L1 凭据与 L2 隐私原文：

| 位置 | 允许写 | 禁止写 |
| --- | --- | --- |
| `plan.yaml` | 路径、判定、结论、时间 | 凭据、隐私原文、内部主机名 |
| `Ledger.md` | 「用户授权原话**摘要**」（不抄敏感细节） | 授权请求的完整原文（若含敏感信息） |
| trace / metrics | 动作、命令**骨架**、结果摘要、耗时 | 命令中内联的凭据、返回体中的隐私字段 |
| 熔断报告 | 失败命令**原始输出**（阶段 5 要求） | 原始输出中若含凭据 → **先脱敏再贴**，并注明"已脱敏" |
| 错误信息 | 错误类型与定位 | 把凭据回显在异常消息里 |

## 七、供应链检查清单（阶段 2 引入外部依赖时）

| # | 检查项 | 不通过的处理 |
| --- | --- | --- |
| 1 | 许可证宽松型（MIT / Apache-2.0 / BSD 等；CC-BY-4.0 不适合代码） | 换方案或自研 |
| 2 | **锁定版本**（不用浮动版本、`latest`、无版本约束） | 显式 pin 版本后再引入 |
| 3 | 来源可校验（官方源、发行方署名或校验和） | 从官方源重取并校验 |
| 4 | 无混淆脚本、无可读性为零的构建产物 | 不引入（无法审计＝不能信任） |
| 5 | 无硬编码密钥、无异常外联（安装/导入即回连未知域） | 不引入 |
| 6 | 活跃度：`pushed_at` 未长期停更 | 评估替代方案 |
| 7 | **权限最小**：安装与运行不申请超出所需的权限 | 拒绝提权安装 |
| 8 | 依赖树未见高危及已知漏洞版本 | 升级或替换 |

**判定**：命中任一不通过项即**不得引入**——改用替代方案或自研（自研产物按「自研工具与技能」规则标注与留痕）。

## 八、泄露应急（发现凭据/隐私已外泄时）

1. **停止**：立即中止全部对外动作（不再推送、不再发送、不再发布）。
2. **确认范围**：哪些凭据/数据、出现在哪些位置（工作区文件、git 历史、远端、缓存、日志）。
3. **吊销验证**：对服务端接口实测确认吊销是否**真生效**——"我已经删掉了"不等于"这个 Key 已失效"。
4. **清理**：删除或脱敏，并做**脱敏备份**（保留证据但不保留明文）。
5. **留痕**：记录时间线、影响面、处置动作与验证结果。
6. **升级**：涉及第三方或监管影响时，由用户决定是否告知受影响方。

> 完整流程见技能库中的 `secret-leak-response`（本手册只列要点，避免两处口径分叉）。

## 九、诚实边界（如实登记，不假装有保护）

| # | 边界 | 说明 |
| --- | --- | --- |
| 1 | **出站前扫描只有第 3/4 项机器化** | `scripts/outbound_scan.py` 仅覆盖「本机绝对路径」（§五 第 3/4 项）；**第 1/2/5/6/7/8 项仍是纪律项 + 人工清单**，执行者可以漏项，流程不会自动拦。**不得声称六项都是自动拦截。** 且机器化部分只认**字面路径**——靠变量拼接、Base64、URL 编码等间接形态出现的路径不在其射程内。 |
| 2 | **「凭据永不落盘」无法被本流程机器证明** | 只有独立审核抽查能提高检出率，属纪律项。 |
| 3 | **越界授权登记「有校验」但「内容不可信」** | v3.5.0 起 `checks.py plan` 会核对交付物是否落在白名单内（旧模板无 `meta.越界授权` 键时只 WARN，**不追认历史计划**）。但登记内容由模型自填、**「依据」无法被机器核实**——它仍是留痕，不是许可。顺序永远是「先请求 → 拿到当次同意 → 再执行」。门禁只能抓「没登记」，抓不到「登记了但没真授权」。 |
| 4 | **分级靠人工判定** | §二 的分级是判断，不是扫描结果；误判会传导到后续所有处置。 |
| 5 | **本地优先不是绝对隔离** | 是否可行取决于本机能力（本地模型是否够用）；不可行时回到 S3 由用户决定。 |
| 6 | **元数据清理需人工确认** | Office/图片元数据清理依赖具体工具是否支持，需逐一验证，不能默认已清。 |

**若要让其中任一项变成门禁**：须新增扫描脚本、纳入 `checks.py`、并**配阳性 + 阴性对照测试**（故意植入一个密钥确认会红；放一个合法样例确认不会误红）——否则给流程加的是随机 FAIL 源，而非保护（本工作区实测教训：门禁出问题绝大多数是**误判**而非漏判）。
