# 能力路由 · 使用说明（阶段 0 / 3 按需加载）

> 配套 `SKILL.md`「自主决策层」。本文件回答一个问题：**这一步该不该引入外部辅助？该引入哪一种？**
> 本文件属「方法定义」类文档，按阶段感知模型路由走 **mid** 档。

## 〇、与相邻文档的分工（先划清，否则会混）

| 文档 | 回答的问题 |
| --- | --- |
| 本文件 `capability-routing.md` | **要不要外部辅助？用哪一类？**（能力选型） |
| `routing-guide.md` | 选定能力后，**用哪一档模型**（strong / mid / cheap） |
| `orchestration.md` | 决定起子代理后，**怎么派**（Handoff 字段、并行上限、回收纪律） |

三者**正交且按序**：先定能力类 → 再定模型档 → 最后定派发细节。跳步的典型症状是"用便宜模型干规划（档位错）"或"派了子代理却没写 Handoff（协议错）"。

## 一、四类能力与判据

把"外部辅助"拆成四类。每类都给出**该用**与**不该用**的判据——只给"该用"会造成滥用，滥用是比不用更贵的错误。

| # | 能力类 | 手段 | ✅ 该用的判据 | ❌ 不该用的判据 |
| --- | --- | --- | --- | --- |
| ① | **知识** | 加载其它 skill | 任务需要**专门方法论或领域流程**，且本地或市场确实存在匹配技能 | 技能只是"看起来沾边"；或它教的正是你已在本技能内定义过的东西 |
| ② | **算力（隔离）** | 派子代理 | 子任务**独立**（相互无数据依赖）、可并行、或高噪音只读、或**需要未参与者的独立视角** | 子任务间有依赖；任务琐碎（格式化 JSON、单条命令）；开销大于收益 |
| ③ | **事实（外部）** | 联网检索 | 需要**本机推不出**的当世事实：版本号、价格、star 数、许可证、在职者、时效性结论 | 工作区内已有的既有产物、台账、日志（用 `Grep`／`Read` 就够，联网是绕远路） |
| ④ | **手脚（执行）** | 本技能 `scripts/`、本地工具、MCP 连接器 | 需要**确定性**的计算、结构解析、批量产出、探活（`checks.py`／`data_query.py`／`office_io.py`／`http_fetch.py`） | 需要**语义判断**的场合——把判断塞进脚本只会制造假确定性 |

## 二、决策三步（引入任何能力前走一遍）

```
① 识别缺口：这一步缺的是 知识 / 算力 / 事实 / 手脚 中的哪一类？
        ↓ 说不清缺什么 → 说明不需要外部辅助，或说明你还没想清这一步要做什么
② 估算收益：引入它能带来什么**可验证**的改善？（更准 / 更全 / 更快 / 更省）
        ↓ 说不出可验证的改善 → 不引入（"感觉会用得上"不是收益）
③ 估算开销：上下文占用 / 额外轮次 / 成本 / 新增失败面
        ↓ 收益 ≤ 开销 → 不引入
④ 通过 → 写一行声明 + 一条决策记录（见第四、五节）
```

**三步的共同底线**：本判断是**判据**，不是**检查清单**。走到 ③ 判定"不引入"是完全正常的结论，且**不需要留痕**——留痕只针对**实际引入了能力**的动作。这与"每次都必须调用点什么"的强制式机制刻意相反。

> ⚠️ **与 superpowers 的口径差异（有意为之）**：`obra/superpowers` 的 `using-superpowers` 采用**无条件强制**——"只要有 1% 可能某技能适用，你就必须调用它"，并附 12 条反合理化红线表来封死"跳过"的念头。本技能**只取其机制、不取其强制**：要不要走本流程、要不要引入某能力，一律由模型按「**能否让结果更快更好**」自判（用户 2026-09-11 定稿的「最高准则」）。**照搬强制口径会直接推翻该准则**，故此处明确排除。

## 三、优先级（两类排序，都不可倒置）

1. **方法先于执行**：先确定"怎么做"（知识类／规划），再决定"用什么做"（执行器类／子代理）。先调执行器再想方法，通常意味着返工。
2. **只读先于写入，本地先于联网**：能只读验证的不写入；能在工作区内读到的，不联网检索。这条同时是 Token 纪律的落地。

## 四、声明制（引入能力时的一句话）

决定引入某能力时，在进入该步前输出一行：

```
[能力] <知识|算力|事实|手脚> → <具体手段> ← 依据：<一句话判据>
```

示例：

```
[能力] 事实 → gh api repos/obra/superpowers ← 依据：star 数/许可证属当世事实，本机推不出
[能力] 算力 → 子代理(只读) ← 依据：三个方向的检索相互独立，可并行，且主上下文需留给汇总
[能力] 手脚 → scripts/checks.py plan ← 依据：交付物存在性是确定性判定，不该靠肉眼
```

这行不是仪式：它是**决策留痕的原始素材**，直接喂给第五节与 `adaptive-planning.md` 的「决策记录」。

## 五、反合理化红线表（借其形，改其义）

superpowers 的红线表用于**封死"跳过技能"的借口**（强制语境）。本技能把它改造成**"封死'跳过量化判断'的借口"**（判据语境）——拦的不是"没调用"，而是"没想清楚就调用/不调用"：

| 常见念头 | 现实（为什么必须停下来量化） |
| --- | --- |
| "这问题简单，不用查" | **简单问题的答案变更最频繁**（价格、版本、在职者），恰恰最难凭记忆答对 |
| "我大概记得这个 API/接口" | 记忆 ≠ 当前版本。API 签名、字段名是典型高变更事实 |
| "先动手，依据事后补" | **决策依据无法事后补造**——留痕的价值就在它是决策当时写的 |
| "不用起子代理，我自己也行" | 但"我自己"缺**独立视角**：本技能已确认「作者自查对『改一处忘一处』失效」 |
| "顺手写个脚本跑一下" | 语义判断塞进脚本 = **假确定性**；脚本只用在确定性任务上 |
| "工作区我都熟，不用翻" | 既有产物与台账常已含答案，凭印象重复劳动是纯浪费 |
| "这技能看着沾边，调了再说" | 相关 ≠ 适用。误调技能既吃上下文又误导方向 |
| "能力都备齐了才显得专业" | **引入能力的成本是真实的**：上下文、轮次、失败面。能不用而不用才是本事 |

## 六、硬规则

1. **说不出可验证收益的能力，不引入**。
2. **语义判断不外包给脚本；确定性判断不外包给肉眼**——两者错配都会制造假信号。
3. **每次实际引入能力，写一行声明 + 一条决策记录**（格式见 `adaptive-planning.md`）。
4. **本文件是判据手册，不是强制清单**：不要求"每步必须调用某能力"，"不引入"是合法且常见的结论。
5. 引用的外部资源须**实测**取指标（禁二手数据），并做许可证与基础安全检查——沿用 `SKILL.md` 阶段 2 第 2、5 条。
