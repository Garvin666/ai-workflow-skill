# 文风判别 · 快判（style-judge / humanize-judge，v4.15.0 新增）

> **定位**：ai-workflow 跑的第 6 个 **System 1 结构化判别** —— 判「**本次产出要不要走去 AI 味改写、命中哪几组模式**」，据此决定阶段 3 是否展开「去味改写 → 事实保真核对」。
> **它是红绿灯，不是车**：只输出「要不要改写、命中哪几组、置信多少」，**不改写、不授权、不改技能本体**（改本体须用户确认）。
> **它是家族里唯一带机器验收的判别块** —— 其余五块是**识别**（模型自报 confidence，机器只校结构）；本块**另有一层机器门禁**：登记了产物就把 `scripts/humanize_scan.py` **实跑一遍**，跑出 FAIL 即 FAIL。**登记里的数字一概不采信。**
> **配套（机器侧随 v4.15.0 一同新增）**：判定结果落 `assets/plan-template.yaml` 的 `meta.文风判定`；机器校验见 `scripts/checks.py plan` 检查项 26；判据集与实现的口径守卫见 `scripts/checks.py skill`（`humanize-rubric.yaml` 的 machine 档规则 id ↔ `humanize_scan.py` 实现集合，双向比对）。
> **判据源**：`references/humanize-rubric.yaml`（31 条模式 A–F，来自 `op7418/Humanizer-zh`，基于 `blader/humanizer` v3.0.0 + PR 39）。
> **哲学来源**：与 `self-judge` / `method-judge` / `retrieval-judge` / `homework-judge` / `learning-judge` **严格同构** —— Jev（TypeSafe AI 的 System One 模型）三原语 Choice / Score / Noul + 校准概率 + fail-closed。

## 1. 定位与形态

| 项 | 值 |
| --- | --- |
| **模块名** | `style-judge`（中文：**文风判别 · 快判**；判据源文件别名 `humanize-judge`） |
| **形态** | ai-workflow 的**内部子模块**（非独立顶层 skill）；本文件即其完整契约，由阶段 0 第 1.5 步加载 |
| **本质** | 纯判别（System 1）：**单次前向、无 chain-of-thought、无自回归展开**；判别之后才由阶段 3 做 System 2 的改写 |
| **主语** | "本次产出读起来像不像人写的、要不要去味" —— 判的是**文风形态**，不是"内容对不对" |
| **与另五块的分工** | `thinking` 判**该不该按原样做**／`self` 判**产出什么**／`method` 判**这步用什么手段**／`retrieval` 判**该不该查**／`homework` 判**要不要按作业结构答**／`learning` 判**有什么值得学**／**本模块判"要不要去 AI 味"** —— 七者各盯一根轴，**任何两者不可互推** |

**判定取值（Choice，四选一）**：

| 判定 | 含义 |
| --- | --- |
| **走去味** | 是面向人阅读的散文正文，且命中可机器判的表层特征 → 阶段 3 展开改写＋保真核对 |
| **只登记** | 有信号，但改动风险（误伤正当用法）高于收益 → **不改写**，把命中项登记为人审点 |
| **已达标** | 是散文正文但 `humanize_scan.py` FAIL = 0 → 无需改写；SKIP 档仍登记为人审点 |
| **不适用** | 不是散文正文（代码／JSON／YAML／数据表／公式／纯结构文本）→ **判 SKIP，不喊一遍** |

> ⚠️ **本表与主类三态（chat/code/content）、模式三态、能力四态、源类五态、学习类型五态、裁决四态都是不同的物理量** —— 字形相近、语义无关，不得合并、不得互相推导。
> ⚠️ **`不适用` 是本模块的效率闸门**：去味只对「给人读的散文」有意义。对代码、JSON、YAML、数据表、公式跑一遍是纯浪费 —— 那正是宿主「效率」原则要罚的冗余步骤。故用 `self-judge.category == content` 做前置闸门，而非无条件必跑。

### 1.1 与「审美判据」的关系（同族但不同输入）

| 层 | 载体 | 吃什么输入 | 判什么 |
| --- | --- | --- | --- |
| **审美判据（检查项 22）** | `references/aesthetic-rubric.yaml` ＋ `scripts/check_aesthetics.py` | `.css` 与渲染色 | 视觉产物好不好看 |
| **文风判据（检查项 26）** | `references/humanize-rubric.yaml` ＋ `scripts/humanize_scan.py` | `.md` / `.txt` / `.docx` 的**散文正文** | 文字读起来像不像人写的 |

> **两者共用同一套纪律，互不替代**：`PASS / FAIL / SKIP` 严格分开（**SKIP 不得并入通过率**）、每条判据带 `source`、`豁免` 是唯一出口且**不得为消 FAIL 改阈值**、每条修复配**阴性对照**。
> **两者可同时命中**：一份 PPT 的文案既吃审美判据（配色/层级），也可能吃文风判据（讲稿正文）—— 此时两条门禁各跑各的，不合并。

## 2. 触发条件

| 场景 | 是否触发 | 说明 |
| --- | --- | --- |
| `self-judge.category == content` **且**交付物面向人阅读 | **必触发** | 阶段 0 第 1.5 步跑一次；阶段 3 质检按判定展开 |
| `self-judge.category == code` | **不适用** | 代码不是散文正文（注释/文档字符串另论，见下方边界） |
| `self-judge.category == chat` | **不适用** | 会话内回答无落盘产物 |
| `content` 但产物是纯结构文本（JSON/YAML/CSV/公式） | **不适用** | 无散文正文可改 |
| 用户显式要求（"去 AI 味"「别这么写」） | **必触发** | 即使用户没提 category，也按 content 处理 |
| 用户给出**作者文风样本** | 触发并升级 | 可跑 `spec` 档的 voice calibration；**无样本则判 SKIP，不得假装校准过** |

**主动克制（判定阶段禁止做的事）**：**不整读交付物全文、不预写改写稿、不派子代理、不展开思维链** —— 一旦开始写改写稿就退化成 System 2，且会让判定被"改写得好不好"污染。判定只看**产物指针 + 抽样片段**。

## 3. 执行步骤（单次前向、四步、无自回归）

```
① 解析 ：产物类型与体裁 → 结构化信号态（是否散文正文 / 语言 / 有无作者样本）
② 评估 ：并行打分 5 个正交维度 S1–S5 → 各维 Score(0–1) 或 Noul(P(true))
③ 选择 ：Choice 判定 + 校准分布 {走去味, 只登记, 已达标, 不适用}（四者之和 = 1）
④ 二值 ：Noul 判定「是否模糊 / 混合」→ 输出结构化判定
```

四步**全为单次前向**；第③④步共用同一次判别，不得为"提高准确率"多次采样。

### 3.1 判定维度 Schema（Schema-First：**先定义维度，再判定**）

| 维度 | 含义 | 原语 | 高分指向 |
| --- | --- | --- | --- |
| **S1 散文度** | 产物是不是**面向人阅读的连续散文正文**（而非代码/数据/结构文本） | Score | 走去味（**这是闸门维度**） |
| **S2 表层信号强度** | `humanize_scan.py` 可判的**表层特征**命中密度（客服腔/套话收尾/拔高/emoji 标题…） | Score | 走去味 |
| **S3 外发可见性** | 产物是否**对外交付**（发给他人/推送远端/发布上线） | Score | 走去味（并提高审核权重） |
| **S4 事实密度** | 数字/否定/限定/归因 token 的密度 —— **保真风险** | Score | 走去味**且必须跑 `--diff-fidelity`** |
| **S5 作者样本可得性** | 是否有该作者的文风样本可校准 | Score | 可升级到 `spec` 档；低分则**判 SKIP 不假装校准** |

> **S1 是闸门维度**：S1 低（不是散文正文）⇒ 直接落 `不适用`，**不进入后续判定**（效率项）。
> **S4 是安全维度**：S4 高意味着"改坏事实"的代价大 —— 这正是本工作区核心痛点「描述与实现不符」的高发面，故它**不是可选项**：S4 高时 `--diff-fidelity` **强制跑**。
> **S3 是审核维度**：S3 高（对外交付）⇒ 命中「高危产出」送审条件，见 §6.1。

### 3.2 三原语在文风判别中的对应

| Jev 原语 | 语义 | 本模块中的角色 |
| --- | --- | --- |
| **Choice** | 从 N 个里选（含分布） | 判定：`走去味/只登记/已达标/不适用` + 校准分布（**不允许组合** —— 四态互斥） |
| **Score** | 连续位置 + 置信 | S1–S5 五个正交维度的连续分（0–1） |
| **Noul** | P(true) 是非判断（**无独立置信字段**） | `ambiguity`（是否模糊 / 混合） |

## 4. 输入输出契约（Contract）

**输入（最小化；判定阶段不取额外上下文）**：

```yaml
product_path:   str|null     # 待判产物路径（只取指针，不整读全文）
category:       str          # self-judge 的 category（content 才展开）
genre:          str|null     # 体裁线索（报告/方案/讲稿/邮件/…）
audience:       str|null     # 面向谁（对内/对外/客户/公众）
author_sample:  str|null     # 作者文风样本路径（决定能否跑 spec 档）
in_workflow:    bool         # 是否任务中途（决定本次是否真触发）
```

**输出（机器可读，落 `plan.yaml` 的 `meta.文风判定`，与另六块 judge 同构）**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `verdict` | `走去味` \| `只登记` \| `已达标` \| `不适用` | ✔ | Choice 主判定。**枚举唯一取值源见 §1 表** |
| `distribution` | `{走去味, 只登记, 已达标, 不适用}` | ✔ | 校准概率分布，**四键齐全且和 = 1** |
| `confidence` | float 0–1 | ✔ | = `max(distribution)` |
| `dimensions` | `{S1..S5}` | ✔ | 各维 Score 值（0–1） |
| `ambiguity` | bool | ✔ | Noul 判模糊 / 混合 |
| `route_hint` | str | ✔ | 处理指引（见 §5），非空 |
| `needs_humanize` | bool | ✔ | **派生字段**：=（`verdict` == `走去味`）。**不是独立问句** —— 从设计上消除"判定与 flag 自相矛盾" |
| `适用范围` | str | ✔ | **人审信号**：写明本次判定的产物范围与体裁（供核对「未对代码/JSON/YAML 跑去味」） |
| `产物` | list | 否 | 实跑的文本产物路径（供检查项 26 **实跑校验器**；相对路径以 `--base` 为基准） |
| `判据集` | str | 否 | 缺省取技能自带 `references/humanize-rubric.yaml` |
| `改写前` / `改写后` | str | 否 | 事实保真比对的两份文本；**填了就必须解析到位**（解析不到即 FAIL，不静默退回"未检测"） |
| `豁免` | list | 否 | 每项 `{id, 理由}` —— **理由必填且禁占位符**，逐条留痕打印 |

> **字段化而非散文**：判定结果可进账本、可回溯、可机器校验结构（结构合法 ≠ 判得对，见 §10）。
> ⚠️ **`产物` 与 `改写前/改写后` 是"实跑入口"**：登记了就**必须**跑校验器／保真比对，**登记里的数字一概不采信**（自报计数是"静默失真"高发面）。

## 5. 阈值路由（Threshold Routing）

| 区间 | 行为 |
| --- | --- |
| 主判定 `confidence ≥ 0.95` | **自动采信**，按对应 `route_hint` 执行 |
| `0.70 ≤ confidence < 0.95` | **中置信**：按主态执行，但**标 `观察`**，并在交付说明里注明"判定置信中等" |
| `confidence < 0.70` **或** `ambiguity = true` | **fail-closed：不改写**（见下方口径） |

**`route_hint` 按判定给出处理指引**：

| 判定 | route_hint |
| --- | --- |
| **走去味** | 阶段 3 展开：以 rubric 为线索改写 → 跑 `humanize_scan.py --gate` → 跑 `--diff-fidelity 改写前 改写后` → **双条件均满足**（FAIL 下降 **且** 保真零丢失）才进阶段 4/5；FAIL 未清零按 **T1 反思重试**，耗尽升「返修复查」 |
| **只登记** | **不改写**；把命中项（含 SKIP 档）登记为人审点，在交付说明里逐条列出并写明"未改写、理由是误伤风险" |
| **已达标** | 直接过；SKIP 档（17 条语义项）仍须登记为人审点，**不得声称"已全面检查"** |
| **不适用** | 判 SKIP；在结论里写明"本产物不是散文正文，未跑去味"（**不喊一遍 ≠ 通过**） |
| 模糊 / 混合 | fail-closed：**不改写**，在结论里写明"文风判定未定"并登记为人审点 |

> ⚠️ **fail-closed 的动作是「不改写」，不是「向用户追问」** —— 与 learning-judge 同源理由：**不改写的代价（少了点润色）远低于改坏的代价（静默失真）**，代价不对称，故保守侧是"不动"。
> ⚠️ **校准优先于准确率**：一个 70% 准确但**完美校准**的判定器，比 95% 准确却**错标**的更有路由价值 —— 这正是阈值取保守值（0.95 自动采信）的理由。
> ⚠️ **低置信不升级前沿模型**：低置信只意味着"说不准要不要改"，**不动比升级模型更轻也更对症**（同另六块 judge 的口径）。

### 5.1 聚合规则（S1–S5 → 四态分布，**唯一口径源**）

§5 的阈值作用在 `confidence` 上，但**没有定义它从哪来** —— 本节补上这一段。它是本契约**唯一**的聚合规则：

```
若 S1 < 0.5            → 判定 = 不适用（闸门先短路，其余维度不参与）
否则按加权分：
   走去味 = w2·S2 + w3·S3 + w4·S4
   只登记 = (1 − S2)·S3          # 有外发风险但表层信号弱 → 只登记不改
   已达标 = (1 − S2)             # 无表层信号命中
   不适用 = 1 − S1               # 散文度不足的残余概率
再归一化到四者之和 = 1
默认权重：w2 = 0.5，w3 = 0.2，w4 = 0.3
```

> ⚠️ **权重与公式是"可复核的默认值"，不是拟合结果** —— 与另六块 judge 一样，**参数未拟合前只作留痕，不接管路由**（温度标定需要人工标注样本，见 §10）。
> ⚠️ **S1 的短路是确定性的**：`不适用` 不是"判出来的一态"，而是**闸门**——散文度不足时其余维度不参与聚合（否则会对着一份 JSON 算出"走去味 0.3"，那是判据在造信号）。

## 6. 集成位置与机制

| # | 位置 | 动作 | 触发条件 |
| --- | --- | --- | --- |
| **1** | **阶段 0 第 1.5 步** | 跑 `style-judge` 快判，落 `meta.文风判定` | 仅 `self-judge.category == content` 且交付物面向人阅读 |
| **2** | **阶段 3 质检** | 「**去味改写 → 事实保真核对**」：以 rubric 为线索改写 → `humanize_scan.py --gate` → `--diff-fidelity` → FAIL 未清零不得进阶段 4/5 | 判定 = `走去味` |
| **3** | **阶段 5 自检状态表** | 新增一行「**文风判据**（仅面向人阅读的文本类产物）」 | 同落点 2 |
| **4** | **阶段 6 沉淀分流第 6 路** | **文风偏好纠正 → 回写 `references/humanize-judge.md`** | 用户说「太啰嗦」「别这么写」「以后都照这个来」 |

### 6.1 与各组件的协作方式

| 组件 | 关系 | 具体口径 |
| --- | --- | --- |
| **self-judge** | **子步骤，非并列** | 复用其 `category` 做闸门，**不新增一次前向**；`content` 才展开，其余判 `不适用` |
| **审美判据（检查项 22）** | **同族但不同输入** | 共用 `PASS/FAIL/SKIP` 三档纪律、`source` 字段、`豁免` 出口、阴性对照要求；两者互不替代，可同时命中 |
| **证据纪律（估算值标注 / 数值口径一致）** | **合并为硬约束** | 「保留信息和确定程度」与「估算值强制标注」是同一件事的两半。整合后写成一条：**去味改写不得改动任何数字、否定、限定、归因、时间、范围**；且由 `--diff-fidelity` **机器判**，不只靠纪律 |
| **反思重试（T1–T3）** | **复用，不新造** | scan 出 FAIL 属 **T1（验证信号未通过）** → 自动重试改写 → 耗尽升「返修复查」。**不得**为它新增触发编号 |
| **独立审核（抽查制）** | **命中三类才送审** | 文风改写产出面向人阅读、常属对外交付：命中「高危产出／用户点名／返修触顶」即送审。**事实保真必须由未参与者复核** —— 作者自查对「改一处忘一处」失效（这是本工作区已登记的自我弱点，见 Agent 身份文件的「已知的自我弱点」一节） |
| **出站前扫描（S3/S4）** | **前后都跑** | 改写可能把内部路径「口语化」进正文，故**改写前后各跑一次** `outbound_scan.py`；去味不得引入新外发面 |
| **熔断机制** | **明确排除** | 文风 FAIL **不构成熔断触发**（属可自我纠正的 T1/T2，且非 F1–F5）。理由：反模式 46 —— 阈值太紧会让熔断器本身变成故障源 |
| **计划修订（R1–R6）** | **不混入** | 去味不改目标与事实，不属重规划场景 |
| **learning-judge** | **独立** | 文风偏好纠正走「第 6 路沉淀」，**不改技能本体**（改本体须用户确认）；learning 只进个人知识库 |

## 7. 判定模型：双 Realization（由谁 / 什么执行判断）

### 7.1 结论

与另六块 judge 相同：**基础设计不需要独立训练的神经网络**。默认 Realization A（脑内协议），升级路径 Realization B（Laya 影子后端）。

### 7.2 Realization A —— 脑内协议（默认，零新增依赖）

主代理按 §3 四步、§3.1 五维、§5.1 聚合规则**单次前向**产出判定，直接落 `meta.文风判定`。零新增依赖，判定质量取决于主代理对 §3.1 维度定义的理解 —— 故 §9 给出边界判例锚。

### 7.3 Realization B —— 独立 System 1 决策模型（影子期只作对照）

经 Laya 后端跑同一组维度（`laya_client.py --judge style-judge`），**只作对照、不参与放行**；不可达 → exit 3 降级（`laya.status ∈ {ok, degraded, absent}`），**不阻断流程**。A/B 一致率的出口条件与测量方式同另六块（分母只含人工标，须 `review` 逐条回填）。

> ⚠️ **机器判据不参与 A/B**：`humanize_scan.py` 的 FAIL 数是**确定性**的，它不进一致率分母（那不是"判断分歧"，是"跑了没跑"）。

## 9. 判定样例锚（边界判例，供 Realization A 的 few-shot 锚定）

| 情形 | 判定 | 理由 |
| --- | --- | --- |
| 一份对外发布的方案正文，命中 H01/H06/H07 | `走去味` | 散文正文 + 强表层信号 + 对外 |
| 一份 `.py` 脚本，注释里有"好问题！" | `不适用` | S1 低（不是散文正文）—— **不对代码跑去味** |
| 一份正式公文，正当使用破折号与四字格，FAIL = 0 | `已达标` | 无 FAIL 命中；WARN 可有（不误伤） |
| 一份含大量数字与"尚未/计划/部分"的调研报告，表层信号弱 | `只登记` | 保真风险（S4）高于润色收益 —— 不改比改坏好 |
| 用户说「别这么写，以后都照这个来」 | 触发**第 6 路沉淀** | 偏好纠正 → 回写本契约（须用户确认） |
| 产物是 JSON 配置 | `不适用` | 无散文正文 |
| 产物是 PPT 讲稿正文 | `走去味` | 散文正文；**同时**可能吃审美判据（两门禁各跑各的） |

## 10. 诚实边界（如实登记，不假装有保护）

**以下五条必须原样保留在契约中**（来自 humanizer 上游声明与 `aesthetic-rubric` 既有纪律）：

1. **不判作者身份、不保证通过任何 AI 检测器** —— humanizer 原文即如此声明；宿主**不得**把它写成"过检测"。
2. **模式命中 ≠ AI 生成** —— 「不是 X 而是 Y」「破折号」「四字格」在人类写作里正当存在；判据只给线索。
3. **machine 档只覆盖可枚举的表层特征** —— 深层空泛、意义拔高、借权威只能人审；**不得宣称已全覆盖**（17 条 SKIP 档即此边界）。
4. **不得为消 FAIL 改阈值** —— 与 `aesthetic-rubric` 同一条禁令；改阈值即改判据，须留痕并配阴性对照。
5. **「去味效果」无机器 oracle** —— `--diff-fidelity` 只证「没改坏事实」，**不证**「读起来更像人」。后者只有人审（盲评 A/B、位置交换双跑、异家族裁判）。

**另有两条本模块特有的诚实边界**：

6. **结构合法 ≠ 判得对** —— `checks.py plan` 检查项 26 判的是"有没有落盘 + 结构是否合法 + 产物实跑结果"，**不判判定准不准**（校准无机器 oracle）。
7. **`已达标` 不等于"没问题"** —— SKIP 档 17 条是**未检测**，不是通过。**把「未检测」报成「正常」比漏判更危险。**

### 10.1 验收信号表（机器 / 人审分开标注）

| 信号 | 判定方式 |
| --- | --- |
| `plan.yaml` 含 `meta.文风判定` 且结构合法 | **机器**（`checks.py plan` 检查项 26；L2 缺省 FAIL、L1 出口 SKIP） |
| rubric 规则 id 集合 ↔ 校验器实现集合同源 | **机器**（`checks.py skill` 口径守卫，含阴性对照） |
| `humanize_scan.py` 实跑 FAIL 已清零，或逐条 `豁免` 且理由非占位符 | **机器**（`checks.py plan` 实跑，**登记数字不采信**） |
| `--diff-fidelity` 零丢失 | **机器** |
| 四条夹具对照全部符合期望（`--selftest` 退出码 0） | **机器** |
| 盲评 A/B 位置交换双跑一致率 | **人审** |
| SKIP 档逐条已登记为人审点且已过目 | **人审** |
| 未对代码/JSON/YAML 跑去味（触发面收敛） | **人审**（查 `meta.文风判定.适用范围`） |
