# 学习模型（learning-model，v4.8.0 新增）

> **定位**：ai-workflow 的**持续优化回路** —— 把散落在各次任务留痕里的一次性经验，经「**采集 → 抽取 → 蒸馏 → 校验 → 入库**」五阶段，收敛成**结构化知识**写入个人知识库；此后每次任务的 KB-First 检索会直接吃到这些历史经验，从而形成「越用越顺」的闭环。
> **它解决什么**：本技能此前已有六路「沉淀分流」（阶段 6），但沉淀是**分散、逐次、靠人记**的 —— `Ledger.md` 里躺着几十条结论，没有任何机制把它们**归纳**成"使用者的稳定偏好"或"可复用的领域知识"。学习模型就是那条缺失的归纳管线。
> **它不解决什么**：它**不做识别**（不从自由文本猜"这条算不算偏好"），也**不自动改写技能本体**。两条边界见 §7。
> **配套**：
> - 判定层 —— `references/learning-judge.md`（第 5 块 System 1 快判，判「这次有没有值得学的、属于哪类」），落 `meta.学习判定`，机器校验 = `checks.py plan` 检查项 20/21；
> - 引擎层 —— `scripts/kb_learn.py`（证据计数 / 去重 / 门槛 / 入库 / 留痕），语义归模型、算术归代码；
> - 存储层 —— 累积池 `~/.workbuddy/kb/learning/`；长期知识写入 `~/.workbuddy/kb/`（KB 本体）。

## 1. 定位与形态

| 项 | 值 |
| --- | --- |
| **模块名** | `learning-model`（中文：**学习模型**）；判定层叫 `learning-judge`（**学习信号 · 快判**） |
| **形态** | ai-workflow 的**内部子模块**（非独立顶层 skill）；本文件是管线手册，判定契约在同名 judge 手册 |
| **本质** | 一条**跨会话**的知识收敛管线（不是单次任务内的步骤） |
| **主语** | "从过往这些交互里，有什么值得留下来的？" —— 判的是**可复用性**，不是"这次做得好不好" |
| **关键分工** | **语义归类归模型/人，算术与判据归代码** —— 与 `homework_model.py` 同一条纪律（§7.2） |
| **零新增依赖** | `kb_learn.py` 纯标准库；KB 交互通过 `kb.py` 的 CLI 子进程完成 |

**为什么是"五阶段管线 + 一块快判"而不是"一个大模型"**：本技能已确立「判据语义源 ↔ 执行形态」两分的体例（`capability-routing.md` ↔ `method-judge.md`、`homework-mode.md` ↔ `homework-judge.md`）。学习模块沿用同一形状 —— 手册给**规则**，快判给**单次前向的结构化结论**，脚本给**确定性的算术**。三者不得互相替代。

## 2. 五阶段管线（K1–K5，次序固定）

> 与作业模式的 H1–H5 同体例，但**性质不同**：H1–H5 是**单次产出**的结构，K1–K5 是**跨会话累积**的回路。K 阶段**不引入新的流程开销** —— K1–K4 由脚本一次调用完成（单次进程，秒级），K5 的入库走两段式（§5）。

| 阶段 | 一句话判据 | 输入 | 产出 |
| --- | --- | --- | --- |
| **K1 采集** | 从**既有留痕**收割原始信号 —— 不新造数据 | `Ledger.md` 条目 / `plan.yaml` 的 meta / `trace.jsonl` / 用户放行原话 / 用户纠正原话 / KB 检索的 `coverage=false` 缺口 | `signals`（原始信号，带来源指针） |
| **K2 抽取** | 把信号抽成**候选知识条目**（四类之一，§3） | signals | `candidates`（含 `text` / `kind` / `confidence` / `provenance`） |
| **K3 蒸馏** | **压缩 + 去重 + 精炼**：同一物理量合并、去掉一次性细节、保留可复现口径 | candidates + KB 现有文档 | `distilled`（合并后的条目 + 证据计数） |
| **K4 校验** | **证据门槛 + 冲突检测 + 敏感扫描** —— 不过门槛的不升级 | distilled | `verified`（可入库候选 / 留观察 / 驳回，三者各带理由） |
| **K5 入库** | **两段式**：达门槛自动入 KB，其余留候选池待确认 | verified | KB 文档（`category=学习-*`）+ 候选池 + `meta.学习判定.入库` 计数 |

**K5 的留痕**：入库条数与候选条数回写 `meta.学习判定`（可选字段 `入库` / `候选`），使"这次学习到底发生了什么"可对账 —— 而不是靠回忆。

### 2.1 触发时机（每次 L2 任务收尾 + 跨会话累积）

| 时机 | 是否触发 | 说明 |
| --- | --- | --- |
| **L2 任务阶段 6 收尾** | **触发** | 与「复盘沉淀」同轮；**沉淀 → 学习**是上下游（沉淀记下来，学习归纳它） |
| L1 快速通道收尾 | 不触发 | 无足够留痕；若 L1 运行期升级为 L2 则随之触发 |
| L0 轻操作 | 不触发 | 不建任务目录、无留痕 |
| 用户显式要求（"复盘一下你的学习"） | **触发** | 可跨任务批量蒸馏（`kb_learn.py commit` 扫全池） |
| 任务中途 | 不触发 | 学习是**收尾回路**，不占执行期的步数（效率项） |

> ⚠️ **它不能是"每次都跑的固定开销"**：K1 只读**索引与指针**（不整读历史任务正文），且同一份留痕在池内只计一次证据（§4.1）。若某次任务留痕为零，K1 应**快速返回空**并在结论里写「本任务无可学信号」，而不是硬凑条目（**零沉淀不是中性结果，零学习也不是** —— 但"凑数"比"承认没有"更糟）。

## 3. 四类知识（学习类型，Choice 枚举）

> ⚠️ 这是**「学习类型」枚举**，与「入口主类」三态、「模式选用」三态、「能力类」四态**都是不同的物理量** —— 字形相近但语义无关，**不得合并、不得互推**。取值唯一源见 `references/learning-judge.md` §1。

| 类型 | 含义 | 典型来源 | 默认门槛（§4.2） |
| --- | --- | --- | --- |
| **偏好** | 使用者**稳定**的习惯 / 口味 / 明确纠正（"以后都这样"「别这样」「太啰嗦」） | 用户放行原话、偏好纠正、返修理由 | **≥2 次独立证据** |
| **领域知识** | 从交互中提炼的**可复用领域结论**（口径、判据、方法取舍） | 方案评审结论、实测数据、踩坑后的正确做法 | ≥1 次 + `confidence ≥ 阈值` |
| **流程坑** | 踩过的**坑与规避法**（反模式） | 返修记录、熔断报告根因、`quality-gates.md` 反模式清单增量 | ≥1 次 + `confidence ≥ 阈值` |
| **事实** | 可复用的**稳定事实**（外部服务行为、环境常量、版本兼容性） | 实测输出、官方页复核结论 | ≥1 次 + `confidence ≥ 阈值` |
| **无** | 本次交互**没有**值得沉淀的东西 | —— | 不产生候选 |

> ⚠️ **`偏好` 的门槛刻意更高（≥2 次）**：单次出现的"用户说了句偏好"极可能是一次性情境（今天赶时间所以要简短）。把噪声写成长期偏好，比漏掉一次偏好**危害大得多** —— 它会持续污染后续每一次任务。这与 `homework-judge` 把 `confidence` 自动采信阈值定在 0.95 是同一条保守纪律。
> ⚠️ **`偏好` 与 `领域知识` 的分界**：偏好是**关于人**的（他要什么），领域知识是**关于事**的（这世界怎样）。拿不准时选 `领域知识` —— 它门槛低、写进 KB 的副作用小，误判成本更低。
> ⚠️ 组合态：`kind` 允许 `A+B`（top2 差 < `combine_kind_delta` 时由聚合产出，如 `偏好+流程坑`）。**`无` 不得参与组合**（"没有"与"有"并列无意义）。

## 4. 累积池与门槛（跨会话承载）

### 4.1 累积池的位置与结构

**累积池 = `~/.workbuddy/kb/learning/`** —— 属 `~/.workbuddy/kb/` 基础设施（**不算越界**，见 SKILL.md 工作区边界「基础设施例外」），且 **KB 与累积池内容禁止推入任何 git 仓**。

| 文件 | 内容 | 写入方式 |
| --- | --- | --- |
| `pool.jsonl` | 候选条目池：`{key, kind, text, confidence, evid_count, first_seen, last_seen, sources[], state}`，另带**生命周期字段** —— `evidence[]`（证据快照，P0-3）／`conflict_with[]`（冲突对手，P0-1）／`supersedes[]`、`retire_proposed_by[]`、`superseded_by[]`、`retired_at`（P0-2） | 追加 + 计数更新（**同一 key 合并，不新增行**） |
| `decisions.jsonl` | 每次动作的决策留痕：`{time, key, action, reason, kb_id}`；`action ∈ 入库/观察/冲突/待废止/已废止/驳回/冲突登记/废止提案/废止/驳回废止` | 追加不覆盖（可定位与回滚） |
| `state.json` | 上次运行快照：计数、阈值版本（含 `evidence_max`） | 覆盖写 |
| `retire_proposals.jsonl` | **废止提案**（P0-2）：`{id, old_key, new_key, old_kb_id, new_kb_id, status, proposed_at}` / `{id, status=已放行\|已驳回, resolved_at}` | **append-only 事件流**，同 `id` 取最后一条为当前状态（**状态可折叠、审计链不丢**） |
| `archive/<YYYY-MM>.jsonl` | **证据固化归档**（P0-3）：`{time, key, kind, action, snapshot_kind, evidence[], sources[]}` | **append-only**；池内只留最新 `EVIDENCE_KEEP` 条，**全量在此** |

> ⚠️ **新增的三个文件/字段都属 P0（2026-09-25 开源对标后补）**，共同原则是「**按危险度分级，而非只按置信度**」：新增/更新可自动（按置信度），**冻结与废止只提案**（不可逆动作，按危险度）。逐条口径见 §4.3 第 4、5、6 条。

**`key` 的稳定性是去重的地基**：`key = sha1(normalize(text))[:12]`，`normalize` = 去掉空白/标点/全半角差异后折叠大小写。同一句话换标点不换含义 → 同 key → 合并计数，而**不是**产生第二条。KB 侧文档 id 用 `learn-<key>`（幂等），故重复提交**不会**在库里长出第二篇。

### 4.2 门槛（全部机器可判定）

一条候选要**自动**入库，须同时满足：

| # | 条件 | 默认值 | 判据位置 |
| --- | --- | --- | --- |
| 1 | 证据计数达标 | `偏好` ≥2；其余 ≥1 | `MIN_EVIDENCE`（代码一处） |
| 2 | 置信达标 | `confidence ≥ 0.85` | `AUTO_COMMIT`（代码一处） |
| 3 | 非敏感 | 不含凭据/隐私/内部基建模式 | 复用出站扫描口径（§6.3） |
| 4 | 库内未重复 | 与 KB 现有文档相似度 < `0.86` | `DUP_THRESHOLD`（代码一处） |
| 5 | 不与非本任务证据冲突 | 同 key 无相反结论 | **`note --contradicts` 登记 → `evaluate` 双向冻结**（§4.3 第 4 条） |
| 6 | **精炼完成** | 已填「适用边界」（§4.3 骨架的必填项） | `render_content` / `evaluate`（代码一处） |

> ⚠️ **门槛之外还有一层「状态冻结」（P0）** —— 二者**不是同一件事**，别混为一谈：
> 门槛是"够不够格"，冻结是"**无论够不够格都不许动**"。`state ∈ {冲突, 待废止, 已废止}` 时，
> `evaluate()` **先返回冻结结论、门槛结果不生效**（`evaluate` 的次序即优先级：敏感 > 冻结 > 门槛）。
> 冻结由 `note --contradicts`（P0-1，双向）/ `supersedes`+`retire`（P0-2）置入，**只能由用户解除**。


**门槛的数值只写在 `scripts/kb_learn.py` 一处** —— 本手册与 `judges.json` 均**不复制**（同一物理量不写两处，与 `homework_model.py` 的 `ANCHORS`/`TAU` 同一条纪律）。要改阈值改代码，并跑 `selftest` 的阴性对照。

**不达门槛的去向**（不是丢弃）：留池并标 `state = 观察`，附「缺哪一条」。下次同一 key 再来一次，`evid_count` +1 —— 累积到门槛后**自动转正**。这正是"多次调用后自动归纳"的落点：**归纳的动作由计数完成，不是靠模型某次忽然领悟**。

### 4.3 蒸馏规则（K3：压缩 / 去重 / 精炼）

1. **同物理量合并**：同 key 的多次出现合并为一条，`sources` 列出全部来源指针，`evid_count` 即独立证据数。
2. **库内去重（可选增强）**：`--kb-check` 开启时用 `kb.py retrieve` 取 top-k，最高分 ≥ `DUP_THRESHOLD` → 判「库中已有」，走**合并到已有文档**路径（`kb.py update` 追加证据行），**不新增文档**。默认关闭并在输出中**如实标注"未做库内去重"**（不假装做了）。
3. **精炼（去一次性细节）**：正文按固定骨架重写 ——
   ```
   【结论】<一句话，可独立读懂的陈述>
   【依据】<来源指针：任务目录 / 实测输出 / 用户原话（已脱敏）>
   【证据】<次数 + 首见/末见时间>
   【适用边界】<什么情况下不成立>
   ```
   「适用边界」**必填** —— 没有边界的"经验"是整条管线最大的噪声源。
4. **冲突检测（P0-1，**已可达**）**：同 key 若出现相反结论（如"A 可行"vs"A 不可行"），**不静默采用新的** —— 把两条**都**标 `state = 冲突`、`conflict_with` **互指**，**双向冻结**（双方都不得入库，即使门槛全过），进候选池待用户裁决，并在结论里**显式列出**。自动消解冲突需要语义理解，不在本模块射程内。

   **实现口径（务必按此理解）**：`--contradicts <text|key>` 由**调用方（模型/人）声明**"这两条矛盾"—— **判定语义归模型，登记与冻结归脚本**。脚本用 `cand_key` 定位目标条目；**引用不到池内条目即报错退出（fail-closed）**，绝不静默给一个不存在的目标打标签。

   > ⚠️ **这条曾经是「声称有、实际不可达」的空头承诺**（2026-09-25 取证并修复）：`evaluate()` 的冲突分支条件是 `state == "冲突"`，而全程序**零处**能把它置为"冲突"（唯一途径就是走进那个分支本身 —— **循环依赖 = 死代码**），且 CLI 无任何入口。后果是**两条互相矛盾的结论被同时判「入库」**。修复即上面的 `--contradicts` 通道；`selftest` 现含 **CLI 端到端 + 阴性对照**断言，机器上不可再退回死代码。
5. **废止（P0-2，**永远走提案**）**：`--supersedes <text|key>` 声明"本条替代该条"。**新增/更新可按置信度自动，废止/删除一律只提案**：
   - `note --supersedes` 只登记关系（记在**新条目**的 `supersedes[]` 上）；
   - `commit` 时生成**废止提案**（`retire_proposals.jsonl`），并把旧条目冻结为 `state = 待废止`（**不写 KB、不改旧文档**）；
   - 放行是**用户闸门**：`kb_learn.py retire --approve <id> --apply`。未放行前，旧条目**一动不动**；
   - 放行后 KB 侧**只加废止标记与标签、绝不删除**（保审计链）—— 对齐 `tigerless-labs/agent-memory` 的 "updating never destroys"；
   - ⚠️ **已决提案不自动重开**：同 `(旧,新)` 对只提一次；放行/驳回后再次 `commit` **不会**重新提议，也不会把条目拉回 `待废止`。要重开须人工清掉该 `id` 的记录。
6. **证据固化（P0-3）**：`note --evidence <原文片段>` 把证据**随候选落池**（`evidence[]`，单条截断到 `EVIDENCE_MAX`）**并追加进 `archive/<YYYY-MM>.jsonl`** ⇒ 原任务目录被归档/清理后，证据仍可复核（"**漏了 ≠ 丢了**"）。
   - 不给 `--evidence` 时退化为 `--source` 的**指针**，并**如实标 `kind = 指针`** —— 不把指针冒充成原文；
   - ⚠️ **快照同样过敏感扫描**：`--evidence` 命中凭据模式即**整条驳回、不入池、也不落档**（归档是把原文落盘，故这一关必须在落档**之前**）。

## 5. K5 入库：两段式（用户 2026-09-25 拍板）

| 路径 | 条件 | 动作 | 留痕 |
| --- | --- | --- | --- |
| **自动入 KB** | §4.2 **六条全过** 且**状态未冻结** | `kb.py add/update`，`category = 学习-<类型>`，`tags` 含 `ai-workflow` / `学习沉淀` / 来源任务 | `decisions.jsonl` 记 `action=入库` + `kb_id` |
| **留候选池** | 任一条不过 | 留在 `pool.jsonl`，标 `state = 观察`，附缺口 | `decisions.jsonl` 记 `action=观察` + 原因 |
| **已入库** | §4.2 **六条全过** 且**加了 `--apply`**（未加则只是判定通过，池不动） | `kb.py add/update` 成功 ⇒ 池置 `state = 已入库`、记 `kb_id` | `decisions.jsonl` 记 `action=入库`（含 `kb_id`） |
| **冲突冻结**（P0-1） | `state = 冲突` | **双方都不入库**，须用户裁决（解除冻结后回到门槛判定） | 记 `action=冲突登记`（登记时）与 `action=冲突`（每次 commit） |
| **待废止**（P0-2） | `state = 待废止` | **不写 KB、不改旧文档**；等 `retire --approve <id> --apply` 放行 | 记 `action=废止提案`（登记）与 `action=待废止`（每次 commit） |
| **已废止**（P0-2） | `state = 已废止` | **终态，永不再写回 KB**（否则"废止"会被下一次 commit 自动撤销）；KB 侧保留原文 + 废止标记 | 记 `action=废止`（放行时） |
| **驳回** | 命中敏感模式（正文**或证据快照**） | **不入池、不入库、不落档**，只在结论里报条数（**不打印内容**，防二次泄露） | 记 `action=驳回` + 规则名（不含原文） |

**写入动作默认 dry-run**：`kb_learn.py commit` 不加 `--apply` **只报告将入库什么**，加了才真写。这是本技能一贯口径（`push_router.py` / `publish_tools.py` / `archive_tasks.py` 同款）。

> ⚠️ **dry-run 同样地不改池状态**：不加 `--apply` 时池条目**原地不动**（仍为 `观察`），也**不发 `kb_id`** —— 报告用 `state_before` / `state_after` 两个字段区分「判定通过」与「已落实」。**没做的事不得记成做了**：曾实测一次 dry-run 就把 7 条标成 `已入库` 并发了假 `learn-*` id，于是池声称「已入库」而 KB 里根本没有那篇文档（本版已由 `--apply` 把关，并配 selftest 断言）。

**回滚**：库内文档 id 形如 `learn-<key>`，且 `category` 前缀统一为 `学习-` ⇒ `kb.py list --category 学习-偏好` 即可一眼看全某类学习产物，逐条 `kb.py delete --id learn-<key>` 即可撤销；`decisions.jsonl` 保留了"哪次运行写进去的"。

> ⚠️ **但"撤销"的正道不是 `delete`，而是废止提案**（P0-2）：`delete` **不可逆且不留痕**，
> 而 `retire --approve` 只在正文首行加标记 + 打 `已废止` 标签，**原文完整保留**。
> `delete` 只应作为用户明确要求"彻底抹掉"时的最后手段。

## 6. 与既有设施的接缝（不另立一套）

### 6.1 与 KB-First 的分工

| 环节 | 谁做 | 何时 |
| --- | --- | --- |
| **读** | KB-First 检索（阶段 0，`kb.py retrieve`） | 每次任务**开工前** |
| **写** | 学习模型 K5（阶段 6 收尾） | 每次 L2 任务**收尾后** |

> ⚠️ **两者共用同一个库，但方向相反、时机不重叠** —— 不存在"自己写的刚写进去就检索到自己"的循环污染，因为写入发生在收尾、检索发生在下次开工。
> ⚠️ **读侧约定（P0-2 的一部分，**靠人/模型遵守，无机器强制**）**：KB-First 命中一条文档时，若其正文**首行**为 `⚠️ 已废止`，应视为**已被替代**、**不得作为当前口径引用**，并以其中标注的 `替代条目 learn-<key>` 为准。这是"废止"在读取侧的唯一落点 —— `kb.py retrieve` **不**自动过滤（见 §7 第 10 条）。

### 6.2 与「复盘沉淀」六路分流的分工

阶段 6 的六路分流负责**记下来**（写进技能本体/模板/反模式清单/memory），学习模型负责**归纳**（把多次记录收敛成稳定结论）。**两者的落点不重叠**：

| 信号 | 去向 | 依据 |
| --- | --- | --- |
| 用户**纠正**（"别这样"） | **当场**走第 6 路回写技能本体 | 已被既有纪律覆盖（阶段 6 第 4 条） |
| 多次出现的同类结论 | 学习模型归纳 → KB | 本模块（≥2 次才升级为偏好） |
| 仅本次有效的事实 | 工作区 memory 一行 | 既有纪律 |

> ⚠️ **本模块不新增"第 7 路"** —— KB 是既有六路之外的第 7 个落点，但**它不是"分流目的地"**：写进 KB 的是**归纳后的长期知识**，而六路分流处理的是**本次的沉淀物**。把 KB 塞进分流表会与「KB 禁止推入 git 仓」的约束打架（六路里有三路是入库/推送）。

### 6.3 与信息安全 S1–S4 的接缝

- **S1 凭据永不落盘**：累积池与 KB 文档中**不得出现凭据**；K4 的敏感扫描命中即驳回（§5）。
- **S3 出站前扫描**：KB **不出站**（不入任何 git 仓），故不触发 S3；但**若某次任务要从 KB 导出内容对外**，则该导出物须走出站扫描。
- **S4 访问控制**：累积池与 KB 属基础设施例外，读写**不算越界**；但**不得**把 KB 内容复制进工作区交付物后当作"自己的产出"。

## 7. 诚实边界（如实登记，不假装有保护）

1. **语义归类无法机器判定** —— "这条算不算偏好"靠模型/人；脚本只校验结构、计数、去重、阈值。**故它不是门禁**（`checks.py plan` 检查项 20 只校验结构合法与派生自洽）。
2. **脚本不做识别** —— 与 `homework_model.py` 同一条纪律：**不从自由文本猜类型与置信**。若脚本被用来"猜"，等于把被刻意排除的启发式从后门放回来，并制造第二个语义源。
3. **阈值是未拟合先验** —— `MIN_EVIDENCE` / `AUTO_COMMIT` / `DUP_THRESHOLD`（以及判定层的 `ANCHORS` / `TAU`）都没有任何数据拟合支撑。**不得**据此声称"学习准确率 X%"，也不得作为"这条路比那条路好"的依据。⚠️ **调参后必跑 `kb_learn.py selftest`** —— §5.1（判定契约）记录了两轮"参数失配但无任何报错"的返修，那类失效只能由结构性断言拦住。
4. **"学到了对的东西"没有机器判据** —— 门槛只保证「同一条重复出现足够多次」，**不保证它是对的**。反复出现的偏见会被学成"偏好"，这是本模块的**结构性风险**，只能靠 §5 的两段式（高置信自动、其余人工）与定期复查缓解。**不得宣称"已自动保证学习质量"。**
5. **零样本 = 零学习** —— 没有真实交互留痕时，池为空、无候选。脚本**不产生样本**（同 `homework_model.py`）。
6. **不自动改写技能本体** —— 把学到的偏好直接写进 `SKILL.md`／`references/` 属**不可逆动作**，会改变此后每一次会话的行为。故本模块**只入 KB**；确需改技能本体时走既有的第 6 路，**须用户确认**（红线①）。
7. **库内去重默认关闭** —— 未开 `--kb-check` 时，池内去重仍然生效（确定性），但**与 KB 已有 1800+ 篇的重复不会被发现**；输出中如实标注。
8. **冲突判定仍归模型** —— `--contradicts` 只做「登记 + 冻结」，**它不判断两条是否真的矛盾**。故"标了冲突"**不等于**"冲突判定正确"：漏标（真矛盾却没声明）与误标（把互补当矛盾）**都无机器判据**。这不是缺陷而是刻意分工（语义归模型、算术归代码）。
9. **池内去重仍是字面级（P0 之后仍未修）** —— `key = sha1(normalize(text))`，同义改写（"别加 emoji" / "不要用表情符号"）**各自成条**，会**稀释证据计数**，使同一偏好换个措辞就各自够不到 `偏好 ≥2` 门槛（**"漏吸"**，与 P0-1 的"污染"方向相反）。语义近邻检查属 **P1**（复用 `kb.py retrieve`，零新增依赖），**本版没有** —— 不要以为它已经有了。
10. **废止只解决"写入侧"，读取侧靠约定** —— 放行后 KB 文档**仍是普通文档**：`kb.py retrieve` **不会**自动排除它，KB-First **仍可能命中**。缓解是"**文档自我标识**"（正文首行 `⚠️ 已废止` + 标签 `已废止`）与读侧约定（§6.1 末条），**无任何机器强制**。**不得**宣称"废止后就不会被检索到"。

## 8. 失败与降级

| 情形 | 行为 |
| --- | --- |
| 累积池不存在 | 自动创建（首次运行）；不报错 |
| 累积池损坏（jsonl 有坏行） | **跳过坏行并计数**，在结论里报「跳过 N 行」，**不静默丢弃** |
| KB 不可用（`kb.py` 缺失/报错） | `commit` **拒绝写入**（fail-closed，不假装入库成功），候选**原样留池**，结论里报「KB 不可用，本次未入库」 |
| KB 写一半失败 | 逐条写、逐条记 `decisions.jsonl`；已写的保留（幂等 id 保证重跑不重复），结论里报「成功 N / 失败 M」 |
| 敏感命中 | 按 §5 驳回路径，**不打印原文** |
