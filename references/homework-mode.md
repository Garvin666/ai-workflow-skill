# 作业模式（homework-mode，v4.7.0 新增）

> **定位**：ai-workflow 在**产出结构层**上的一个模式 —— 与 self-judge（认知轴：这次产出什么）、入口分型（来源轴：请求怎么来的）**正交叠加**，可叠加在任意主类与任意来源之上。
> **一句话**：**题目怎么问是一回事，答案该怎么写是另一回事** —— 后者由本模块统一。
> **本模块不新增任何东西**：不加主类取值、不加来源分型取值、不改任务分层判据、不加 plan 字段、不加脚本与门禁。它只规定**输出的组织方式**与**作答纪律**。⚠️ 该scope仅指**本模块**；同批的 `references/homework-judge.md` 是**判定层**，它确实新增了 `meta.作业判定` 与 `checks.py plan` 检查项 18/19（**缺省只 WARN**）—— 两句话**不要混读**（见 §6 与 §8）。
> **加载口径**：命中「作业识别」（§2）后加载；未命中不加载（勿预读）。

---

## 1. 定位与形态

| 项 | 值 |
| --- | --- |
| **模块名** | `homework-mode`（中文：**作业模式**） |
| **形态** | ai-workflow 的**内部子模块**（非独立顶层 skill）；本文件即其完整契约 |
| **所在轴** | **产出结构轴**（答案怎么组织）—— 与认知轴（产出什么）、来源轴（怎么来的）**三轴正交** |
| **触发落点** | 阶段 0 第 2 步（入口分型）**之后**的「作业识别」；见 `SKILL.md` 阶段 0 |
| **主语** | "这次是不是一道题、答案该按什么结构给" —— **判形态，不判能力、不判越界** |
| **适用对象** | 课程作业 / 习题 / 课后题 / 复习题 / 考试真题演练（**含用户只问其中一问**） |

**为什么不做成「来源分型的第四类」**（这是一处刻意的设计收敛，不是遗漏）：

来源轴枚举（消息 / 正式需求 / Bug）现有 **4 处载体** —— `SKILL.md` 阶段 0 第 2 步、`references/self-judge.md` §1.1、`assets/ledger-template.md` 命名规则表、`assets/熔断报告模板.md`。把作业塞进去要同步改 4 处，**且该枚举目前没有机器守卫**（`checks.py` 的 `PARITY_ITEMS` 不含它）→ 改 4 处、零守卫、且语义上还站不住：**一道作业题既可能是「消息」（一句话问题），也可能是「正式需求」（带交付物要求），来源轴本来就容纳得下它**。真正需要挂的不是「从哪来」，而是「按什么结构答」。故本模块做成**正交叠加**，与 `self-judge`／`method-judge`／`retrieval-judge` 的"同构叠加"风格一致。

## 2. 触发条件（作业识别，三判据）

阶段 0 在入口分型之后跑一次识别，**命中任一即叠加本模式**：

| # | 判据 | 特征 | 例 |
| --- | --- | --- | --- |
| **C1** | **显式题目特征** | 出现题干结构（已知 / 求 / 证明 / 计算 / 设计 / 论述 / 试述）或题号、小问编号 | 「已知 a=1, b=2，求 c」「第 3 题」「(1)(2) 两问」 |
| **C2** | **期望形态** | 要的是**答案与过程**，不是交付物（文件 / 系统 / 报告 / 上线） | 「这题怎么做」「帮我解一下」「步骤要详细」 |
| **C3** | **语境线索** | 教材、章节页码、老师要求、习题集、复习范围、期末考试 | 「第三章课后题」「我们老师要求用拉格朗日法」 |

**不触发的相邻情形**（别把同类都算进来）：

| 情形 | 归属 |
| --- | --- |
| 「给我生成一套练习题 / 题库 / 复习讲义」 | **学习资料生成类**（`references/playbook.md` 第四节），不是解题 |
| 「讲讲 XX 定理 / 什么是 XX」 | **讲解型**（L0 直接答）；可借用 §3 的 H2／H4 结构，但不必走全 H1–H5 |
| 「帮我查这道题的答案是不是这个」 | **校核型**：按 H1→H5 复算一遍并**给出独立结论**，不因"用户已给答案"而放弃验证（H5 硬要求） |
| 「这段代码为什么报错」 | **Bug 入口**（复现→根因→修复→回归），不是作业模式 |

> ⚠️ **识别是启发式，不是门禁**：无法机器判定，也没有对应判据（本模块刻意不加 —— 见 §8「诚实边界」）。误判**两条路都不致命**：漏判 = 按普通回答给出，少一层结构；误判 = 输出结构偏重，多几行小标题。

## 3. 五阶段解题结构（H1–H5，次序固定）

**次序固定、不可跳步；每一步的"判据"栏是"怎样才算做到"，不是"建议"。**

| 阶段 | 必须产出 | 判据（怎样算做到） | 常见不合格 |
| --- | --- | --- | --- |
| **H1 审题与已知条件提取** | 题目重述 + 已知量 / 未知量 / 约束 / 隐含条件（含单位与量纲） | 能把题面**逐项**映射到符号或清单；隐含条件（定义域、整数性、理想化假设、缺省恒定）**显式写出**；含多小问时**列出问数** | 直接开始算；把隐含条件当默认不给；漏掉某一小问 |
| **H2 思路分析与知识点关联** | 本题考什么 + 用什么方法 + 为什么这条路走得通 | 点明**知识点/定理/算法/理论**并能对上 H1 的条件；给出**选择理由**（一句可检验的判据，如"满足 X 定理前提①②"）；存在多条可行路径时**明示选了哪条、另一条为何不选** | 只报方法名不给理由；用未经声明适用条件的方法（如未验证收敛就用迭代法） |
| **H3 分步推导或求解** | 编号步骤，每步含「依据 → 代入/操作 → 中间结果」 | **不跳步**；确需跳步处标注「（略去代数整理）」并**给出可复算的中间量**；符号先于数字（先出解析式再代数）；中间结果可被读者独立复算 | 只给首尾；"显然可得"；把代数错误藏在跨行跳跃里 |
| **H4 关键步骤解释** | 对**易错 / 反直觉 / 易扣分**的步骤解释 | 至少 **1–2 处**解释"为什么这么做"；说明**替代做法为何不行**或**常见错误**（符号、边界、单位、公约数、循环不变量、论证跳跃） | 全篇平铺直叙，读者看不出哪一步是关键 |
| **H5 答案呈现与验证** | 最终答案**单独成块** + 验证过程 + 逐问核对 | 答案含**单位 / 有效数字 / 取值域约束**；验证方式见 §4 对应题型（**必须真做，且出示证据**）；**逐问核对**防漏问；结论与题问一一对应 | 答案埋在段落里；"经检验正确"这类无证据口令；答非所问 |

> ⚠️ **H5 是本模块与技能的接缝点，不是新增要求**：技能阶段 3 第 2 条的「验证闭环」在作业模式下**不放松** —— 数学要代回、编程要真跑、论述要引用可核。**H5 的"验证"若无证据，本模式视为未完成**。

## 4. 题型结构（三类主骨架 + 其他题型映射）

### 4.1 数学计算类（计算 / 推导 / 证明）

**骨架**：设与已知 → 依据公式/定理 → 代入 → 化简 → 数值结果 → 单位与量纲 → 验证。

**专属检查项**（H5 的验证方式，逐条真做）：

| 检查 | 做法 | 适用 |
| --- | --- | --- |
| 代回检验 | 把结果代回**原题条件或原式**，看是否成立 | 方程、不等式、求根、积分结果 |
| 量纲检验 | 逐项核量纲是否一致（物理量纲、矩阵维数、指数是否为无量纲） | 物理 / 工程 / 量纲公式 |
| 特例与退化检验 | 令参数取退化值（n=1、极限、零/对称情形）看是否符合直觉与已知特例 | 通用公式、递推、组合恒等式 |
| 量级估算 | 数量级是否合理（一眼可判的粗估） | 数值题 |
| 结论范围核对 | 是否违反定义域、整数性、正负性、单调性等约束 | 最值、取值范围、应用题 |

**证明题的额外要求**：证明骨架 = 命题重述 → 已知与待证 → 引用定理（**写全前提并逐条核对**）→ 推理链 → 结论。**禁止**"显然""易证"作为关键环节的替代（同 H3 不跳步）；反证法须写明**假设**与**矛盾点**落在哪一步。

### 4.2 编程实现类

**骨架**：需求拆解（输入 / 输出 / 约束 / 边界）→ 算法与数据结构 → 复杂度 → 代码 → 测试用例 → 实测输出。

**专属检查项**：

| 检查 | 做法 | 硬性 |
| --- | --- | --- |
| **真跑** | 实际执行代码并**贴原始输出**（含题给样例） | ✅ **必须**（伪造执行结果 = 红线，见 §8 I1） |
| 边界用例 | 空输入 / 单元素 / 最大规模 / 重复元素 / 全等或全反 | ✅ 必须 |
| 异常用例 | 非法输入、越界、超时、递归深度 | 建议 |
| 题给样例 | 题干给出的样例逐条跑过 | ✅ 必须 |
| 复杂度申报 | 声明的复杂度与实现一致（含空间）；与题目的规模上限匹配 | ✅ 必须 |
| 可读性 | 必要注释、变量语义化；不引入题目未要求的依赖 | 建议 |

> ⚠️ **作业模式不因"这是道题"而降低工程的验证门槛** —— 该跑就跑，与「代码类任务」同标准（`references/quality-gates.md` §二）。

### 4.3 论述写作类（论述 / 简答 / 小论文 / 案例评析）

**骨架**：审题拆解评分点 → 立场或论点 → 论证结构（分点 + 论据）→ 限定条件与反方 → 结论。

**专属检查项**：

| 检查 | 做法 | 硬性 |
| --- | --- | --- |
| **评分点对齐** | 把题干动词与限定词拆成评分点（"分析"要因果、"比较"要异同、"评价"要利弊与立场），逐点对应作答 | ✅ 必须 |
| **引用可核** | 文献 / 数据 / 案例**真实存在**且可溯源；外部链接用 `http_fetch.py --check-links` 探活 | ✅ 必须（编造文献 = 红线，见 §8 I2） |
| **不绝对化** | 结论含适用边界；存在反例或争议时**并陈**（对齐 `references/quality-gates.md` §一【反例】须并陈） | ✅ 必须 |
| 篇幅与格式 | 字数区间、引用格式、是否允许小标题 —— 按题目要求 | 按题 |
| 结构可见 | 论点句在段首；一段一个论点 | 建议 |

**简答题**则退化为"H1 审题 → 论点分点 → 每点一句论据 → 结论"，五阶段结构仍在，只是每阶段篇幅小。

### 4.4 其他题型的映射规则（不新增第四套骨架）

| 题型 | 借用骨架 | 附加要求 |
| --- | --- | --- |
| 实验 / 数据处理题 | 编程实现类（4.2） | 报告误差来源与有效数字；**不得伪造实验数据**（§8 I1） |
| 设计题（课程设计 / 方案设计） | 论述写作类（4.3）+ 数学计算类（4.1）的验证项 | 必须给出**约束满足核对**（尺寸、预算、容量、可行性） |
| 外语翻译 / 改写题 | 数学计算类（4.1） | 给出**关键词与语法点**依据；歧义处给出备选译法 |
| 选择 / 填空题（多题） | 逐题走 H1→H5（**压缩版**），每题独立答案 | 核对题号与选项字母；标注不确定题（见 §8 I3） |

> **规则**：借用时**显式声明**借了哪套骨架（一行），不要悄悄混用两套判据 —— 否则同一题内出现两套验收口径（违反「技能库卫生」第 4 条）。

## 5. 输出骨架（可直接照抄）

单题默认骨架（L0/L1 也照此组织，只是每节更短）：

```markdown
**题目**：<题干重述（含题号与问数）>

**已知**：… ／ **求**：… ／ **约束**：…（单位、定义域、隐含条件）

**思路**：考点 <知识点> → 方法 <方法> ← 依据 <为什么可行，一句可检验的判据>
（多条路径时：另 <路径> 因 <理由> 不选）

**求解**
1. <依据> → <代入/操作> → <中间结果>
2. …
3. …

**关键步骤说明**：第 <k> 步之所以…；若改用 <替代做法> 则 <为何不行 / 常见错误>

**答案**：<最终结果，含单位 / 有效数字 / 取值范围>

**验证**：<验证方式> → <证据>（数学：代回 / 量纲 / 特例；编程：原始输出；论述：引用探活）
**逐问核对**：(1) ✓ … (2) ✓ …
```

多题作业：**每题独立成块**，块间用分隔线；最后给一张「题号 → 答案摘要 → 验证方式」对照表（便于自检漏题）。

## 6. 与既有机制的接缝（不得另立一套）

| 机制 | 作业模式下的行为 | 唯一口径源 |
| --- | --- | --- |
| **self-judge（认知轴）** | **照跑，取值不变**（`chat`／`code`／`content` 三态不动，本模块**不新增第四类**）。作业题按其实际产出去判：口算问答偏会话态、编程题偏代码态、论述题偏内容态 | `references/self-judge.md` §1 |
| **homework-judge（结构轴 · 模式选用）** | **同轮照跑**：判"要不要叠加本模式"，落 `meta.作业判定`（缺省 WARN）。**它是本模块的判定层**，不是本模块的替代；**两套 mode 取值不得合并**（本模块的三判据 C1–C3 是**判据语义源**，快判的 `mode` 三态是**落盘形态**，冲突时以本模块 §2 为准） | `references/homework-judge.md` §1.1 |
| **入口分型（来源轴）** | 照判（消息 / 正式需求 / Bug），**本模块不占用该轴**；Bug 类作业（"我的代码为什么错"）**优先走 Bug 闭环**，闭环后再按本模式补 H1→H5 的表述 | `SKILL.md` 阶段 0 第 2 步 |
| **任务分层 L0/L1/L2** | **判据不变**（见 §7）；本模式只叠结构，不改分层 | `SKILL.md`「任务分层」 |
| **method-judge（步骤级）** | 照跑：解题过程本身会命中"缺知识/缺事实"（如需查公式表、需查证事实），按既有能力路由引入 | `references/method-judge.md` |
| **retrieval-judge（检索级）** | 照跑：涉及**时效性事实**（最新数据、现行标准、软件版本）**必须**检索；纯公式推导可判 `needs_retrieval=false` | `references/retrieval-judge.md` |
| **验证闭环（阶段 3 第 2 条）** | **不放松**，并由 §4 的题型专属检查项具体化 | `references/quality-gates.md` §二 |
| **独立审核 / 返修复查 / 熔断** | 照用。作业模式**不新增触发条件**，也不豁免任何一条 | `SKILL.md` 阶段 3 |
| **留痕（plan / trace / Ledger）** | 照用：L0 不落 plan；L2 正常留痕。⚠️ `meta.作业判定` 是**判定层（`homework-judge`）**落的字段，**不是本模块新增的**；本模块自身**不动** plan 结构（见 §8） | `references/data-model.md` |

## 7. 结构恒定、流程开销按分层裁剪

**这是本模块最容易被误读的一点**：H1–H5 是**产出结构**（写出来长什么样），不是**流程开销**（要不要建目录、落 plan、跑门禁）。二者解耦：

| 分层 | 是否建任务目录 / 落 plan | 是否仍按 H1–H5 组织答案 | 典型情形 |
| --- | --- | --- | --- |
| **L0 轻操作豁免** | 否（直接答） | ✅ **是** | 单题、单问、纯推导的"口算题" |
| **L1 快速通道** | 命中 `assets/templates/作业解题.yaml` 且无实质差异 | ✅ 是 | 同类多题作业、按上次口径复跑 |
| **L2 全流程** | 是 | ✅ 是 | 多题 + 需产出文件；编程题需真跑并留证据；需检索查证事实 |

> **不得**因"按 H1–H5 作答"就宣称"必须走六阶段"（那会把结构成本误算成流程成本，违反三项核心原则的效率项）；**也不得**因"只是道题"就跳过 H5 的验证（那是把质量成本省掉）。

## 8. 作答纪律与诚实边界

### 四条作答纪律（与既有红线同级，作业模式内不豁免）

| # | 纪律 | 具体口径 |
| --- | --- | --- |
| **I1** | **不得伪造执行输出** | 编程题 / 实验题的数字、报错、测试结果必须来自**真实运行**；未运行就说"未运行"，不得凭想象写输出 |
| **I2** | **不得编造文献、数据与引用** | 引用须真实且可核（探活为证）；记不清就标注"待核实"，不得生成看起来合理的假引用/假数据 |
| **I3** | **不得把未验证的推断写成已验证** | 未做验证的结论标注「未经验证」或「估算」；不确定的题**显式标注不确定**，不用自信语气掩盖 |
| **I4** | **受评场景须提示学业诚信** | 用户明示这是**考试 / 测验 / 要求独立完成的测评**时，**不代做**，改为提供方法讲解与自查思路；此判断由用户语义触发，**是纪律项、不是门禁** |

### 诚实边界（如实登记，不假装有保护）

1. **识别是启发式的，无机器判据**：本模块**刻意不新增** plan 字段或 `checks.py` 判据 —— 加一个"是否作业题"的门禁，第一次抓到的必然是误判（"这是不是一道题"无法稳定机器判定），收益低于噪音成本。⚠️ **同批的判定层 `homework-judge` 确有 `meta.作业判定` + 检查项 18/19**，但那是"把快判结构化留痕"（**缺省只 WARN**），**不是**给"是否作业题"加门禁 —— 本条的结论（无门禁）**不变**。
2. **本模块不保证答案正确**：它的判据是「**过程可复算 + 验证已做 + 未验证处已标注**」，**不是**「答案一定对」。交付说明里不得声称"答案已验证正确"，只能声称"已按 X 方式验证"。
3. **无法判定用途**：是否属于作弊 / 是否违反校规，**不由本流程裁定**；I4 覆盖的是"用户明示受评"这一可判情形，其余靠使用者自律。
4. **"结构齐全"≠"得分高"**：H1–H5 保证的是**过程可读、可复算、不漏问**；评分标准（教师口径）不在本流程射程内。

## 9. 交付前自检清单（作业模式专用）

| # | 检查项 | 判定方式 |
