# 产物工程手法（写判据 · 自校验 · 可测性）

做「机器判据」与「可交付产物」时的手法与坑。**按需 grep 本文件相应小节。**

> **这是什么**：从一次外部产物的**逆向拆解**里提炼的 16 条**工程手法**（自校验 / 写判据 / 可测性内建 / 循环调度 / 工具链工程）。**它是纪律，不是判据** —— 本仓**不为它新增** `scripts/checks.py` 判据、**不新增脚本**（逆向拆解模式的诚实边界条明规）。
> **它不是什么**：原始对象的**视觉工艺原则**（缓动 / 发光 / 减动效 / 静止构图 / 命中区）**不在本页** —— 那部分在 `references/aesthetic-rubric.yaml` 的 H 层（出处与安装形态见 `references/external-skills.md`）。本页只留**工程手法**。
> **来源与取证**：被拆对象 = 第三方技能 hairline-create 的**工程实现层**（lucasmarkes/hairline@a2217852fed6d1a4f20bc7d43d4fad1a3de117b8；它是一个「给一个想法就画一张等距线稿图」的**单文件产物生成器**）。逐条位置锚、证据档与「代价」全文在任务档案 `tasks/逆向拆解-hairline-create-2026-10-09/`，**本页不复述取证过程**。
> **§1–§5 来自它；§6 来自第二、三个被拆对象**（一个 AI agent 审计器 + 一个 agent 长期记忆服务，见 §6 与 §6.12 开头）—— 三处来源不同，**勿把各节的「代价」互相套用**。
> **读法**：每条给「**机制 → 本仓怎么用（改写点）→ 代价**」。⚠️ **代价是被拆对象实际承担的**；**改写点是我的判断，改写后是否更好未经实测**（见 §9）。

## 1. 自校验：让产物自带可复算的证据

### 1.1 内容摘要写进产物头部，由校验器复算（fail-closed）

- **机制**：把一段**声明为不可变**的核心代码的**内容摘要**写进它自己的头部（行内 sha256），校验器复算比对 —— 任何手改**必然**被下一次校验发现。
- **本仓怎么用（改写点）**：
  1. **摘要口径必须写成人读文字**（被拆对象只写在代码里：等价于「除首行外全部内容，末尾按恰好一个换行计」—— 这是**隐含契约**，CRLF 检出下会破，靠同函数的行尾归一才成立）；
  2. 明确它**只证「产物内 = 本目录」**，**不证「本目录 = 上游正版」** —— 后者归 `.vendor/hairline.lock.json` 这类台账 ＋ `scripts/external_skill_lint.py --verify-lock`。**两套机制分工，不得互相冒充**；
  3. 摘要之前**先做行尾归一**（见 §5.4）。
- **代价**：改核心代码必须用工具重算摘要（对本仓是硬摩擦 —— 但这正是设计意图）。

### 1.2 把「机器管什么、人看什么」写成可查对照

- **机制**：在人读文档里逐项标明**哪几项机器管、哪几项只能人看**，并与校验器头部的判据清单**一一对应**。
- **本仓怎么用（改写点）**：本仓已有「**SKIP 不并入 PASS**」这条**判据侧**纪律，但「**边界必须人读可查**」**没有既有对位条目** ⇒ 写下来：
  - 新增 / 修改机器判据时，**同步改人读文档的边界说明**；
  - 边界说明里**不得**把「没检查」写成「通过」（被拆对象这里是**人工同步、无守卫** ⇒ 本仓承认它是**声明**，不假装自动一致）。
- **代价**：靠人工同步，**没有守卫**——文档与判据脱节时机器不会报警。

## 2. 写判据的五个坑

### 2.1 黑名单不可能穷举 —— 且**不得把风险等级不同的东西并成一条**

- **机制**：约束「模型自由书写的代码」时，用**外联黑名单**（`fetch` / `XMLHttpRequest` / `<script>` / `eval` / `.cookie` …）机器化「单文件自包含」。
- **两个坑**：
  1. **穷举无上界**：被拆对象的清单未覆盖 `importScripts` / `Worker` / `<object>` / `<embed>` / `<use href>` / CSS `@import` / `image-set()` / `srcset` 等。⇒ 按**有界否定**写法：只写「**在该清单内未覆盖下列 token**」，**不写**「不存在这些风险」；
  2. **风险等级合并**：被拆对象把「用 DOM API 建节点」与「读 `.cookie`」并成**同一条 FAIL** ⇒ 报错只能给一个理由，且两类风险被等同。**本仓若采纳，拆成两条**（外联 / 取用宿主能力）。
- **代价**：清单本身是维护面 —— 每加一个 token 都是一次「想全」的赌注。

### 2.2 只有黑名单时，「什么都不做」的产物**全绿** ⇒ 必须配白名单

- **机制**：一个不画任何东西、不注册循环、不写读数的空产物能通过**所有**黑名单 ⇒ 必须配「必须出现的调用」白名单。被拆对象用**前瞻否定**排除同名不同物（`map.set` 不该被当成 `set`），并**穷举三种合法写法**。
- **本仓怎么用（改写点）**：⚠️ **「穷举合法写法」是把维护面押在「作者能想全」上**（漏一种就把合法写法判红）⇒ 采纳时**显式登记这个上界**，并优先用「**收窄取数范围**」降低穷举需求（见 §2.3）。
- **代价**：白名单是**文本级**存在性检查（注释已被剥离，但**字符串里出现 `pointer(` 仍算命中** ⇒ 存在假绿面）。

### 2.3 自写词法剥离是**最后一档**手段，先试「收窄取数范围」

- **问题**：判据是正则，但源码里混着注释、字符串、模板字面量、正则字面量。直接对全文跑正则会有**两个方向**的错 ——
  - **假红**：注释里写「不要用 `stroke-width`」被判违规（把**说明文字**当代码）；
  - **假绿**（更坏）：字符串里出现 `//` 被当注释 ⇒ **后面真正的违规被整段跳过**。
- **被拆对象的解法**：自写约 38 行 JS 词法剥离（注释删掉；字符串按开关保留原文或清空；正则字面量按「斜杠是否位于值起点」判断；模板 `${…}` 用**栈**记 brace depth）。
- **本仓怎么用（改写点）**：**先收窄取数范围，其次才是自写词法** —— 本仓既有做法是**结构化取块**（`scripts/checks.py` 的 `_frontmatter()`，原文措辞「结构化取块，非字符窗口」），比剥离全文更省、更稳。自写词法**无单测**、**只管一种语言**、`/` 歧义本身是**启发式** ⇒ 定为**最后一档**。
- **代价**：手写状态机是长期维护面；语言演进（新字面量形式）会让它失准。

### 2.4 数「调用的形状」要逐字符配平；但**豁免条件必须可核**

- **机制**：`tset(tw, to, now, delay)` 少给第 4 个参数 ⇒ `t0 = now + undefined = NaN` ⇒ **画不出来也不报错**（静默失效，最难查）。正则数不清「逗号是否在同一层」⇒ **逐字符配平**（只在 `depth === 1` 时计逗号）。
- **⚠️ 反面样本（本页最值得记的一条）**：它的豁免写作 `if (given < 4 && !call.includes("..."))` —— **只要该调用文本里任意位置出现 `...` 就整体放过**，而**不检查展开的实参有几个**。⇒ 这是 **fail-open 的豁免：豁免的触发条件本身不可核**。
- **本仓怎么用（改写点）**：本仓已有「豁免必须写理由」「豁免了却本次没 FAIL 会 WARN」「单条登记四键不全 ⇒ 该条作废、不放行」（`scripts/checks_judges.py`）；**增量**是更细的一层纪律 —— **豁免的触发条件本身必须可核**。提问式自检：
  > **「这条豁免，谁来把它的触发条件置真？」**
  答不出「谁」的豁免，等价于把该判据关掉。
- **代价**：配平是又一处**手写解析**（与 §2.3 同源成本）。

### 2.5 借宿主解释器做**真语法**校验时，必须区分「产物有缺陷」与「环境不可用」

- **机制**：把解释器当 **oracle**（写临时文件 → `node --check` → 抓 stderr 行号 → `finally` 删临时目录）。**「这段代码能不能作为模块加载」不是文本层能判的**（剥离 ≠ 解析）。
- **坑**：被拆对象 `status !== 0` **一律**报「图有语法错」⇒ 环境问题（不可写临时目录、无执行权限、解释器缺失）被**误报成产物缺陷** —— 「**判据造信号**」的典型形态（⚠️ **全红与全绿一样，要先怀疑判据**）。
- **本仓怎么用（改写点）**：借外部 oracle 的判据**必须带降级 / 分流分支**（本仓同族纪律：关键判定命令**不接管道取 rc**、先落文件再取 rc；`references/policy.md` §1.3 的 `3 = 无法判定 ⇒ 拒绝`）。另：被拆对象 `spawnSync` **未设 `timeout`** ⇒ 未设边界。
- **代价**：进程开销（对批量校验是硬成本）；临时目录靠 `finally` 清理，**进程被强杀则残留**（无陈旧清理）。

## 3. 可测性内建（把验证夹具做进产物）

### 3.1 地址参数即夹具：给「人」留可复现的地址，工具顺带复用

- **机制**：产物用 URL 参数暴露少量**离散状态**（`?at=x,y` / `?w=` / `?intensity=` / `?theme=` / `?play=`），页面加载后**派发一个真实 `PointerEvent`**；工具用**同一手法**做同一件事（**不是给测试开后门**）。
- **本仓怎么用（改写点）**：对外它是「可分享一个状态」的功能，对内它是夹具 —— ⚠️ **测试面与交付物耦合**（改地址协议 = 改产品），设计时要认下这个代价。定位为「**人可复现**」，**不声称等价于真手检**（合成事件 ≠ 真实指针：触摸、压力、指针捕获都验不了）。
- **代价**：参数一多，地址空间按**因子组合**增长（八图 = 4 参数 × 2 取值）。

### 3.2 契约面收窄成「代理对象」，让「越界」在文本层可判

- **机制**：插件 / 脚本**不拿真 DOM**，只拿一个**只有 getter/setter 的窄对象**（只能写一个字符串）⇒ 契约面被压到 1 个属性 ⇒ 「不许测 DOM」这类文本判据**才有可判性**。
- **本仓怎么用（改写点）**：想让「越界」可判时，**先收窄契约面，再写判据**。⚠️ 契约面越窄，**任何新读写需求都必须改宿主**（可预见的扩展成本）。
- **代价**：表达力受限于设计；读回的值来自宿主局部状态，与真实渲染**可能短期不一致**（属**未写出的隐含前提**）。

### 3.3 代理量：一律**警告级**；阈值必须带来源样本；**时序敏感的判据，阴性结论比阳性结论可信**

- **机制**：把「静没静」「看不看得出」这类只能靠眼睛的性质，换成**可从像素 / 时序算出**的量（静帧判定 / 墨迹异或率 / 覆盖面积比），且**每个阈值都写明它的实测样本**（如「两范例静息外接框占 36%」）。
- **本仓怎么用（改写点）**——两条**增量**（其余与既有面重叠，见 §8）：
  1. **代理量一律 warn / 信息级，不得升为 FAIL** —— 代理 ≠ 原物（墨迹异或率高**不**蕴含答案语义更好）；
  2. ⭐ **时序敏感的判据，阴性结论比阳性结论可信** —— 「机器太忙」会被判成 `moving`（被拆对象作者自认「run it again before you believe it」）⇒ **负结论须复核**。
- **代价**：阈值是**经验值且与图形语言绑定**，换一类产物就要重标；像素级扫描开销不小。

## 4. 循环与调度

### 4.1 共享单帧循环 ＋「tick 返回布尔」自动休眠 ＋ 异常**降级但保可见**

- **机制**：多个独立组件**共享一个**渲染循环，组件自己决定「还要不要帧」（`b.awake = !!b.tick(dt, now)`）；**全员静下来则循环彻底停**（不是空转）；`dt` 钳位（切回标签页不喂进巨大 `dt`）；子步细分后再积分（稳定性）；每帧调用**幂等**；异常时**本组件停下 ＋ 异步重抛**（不静默吞）。
- **本仓怎么用（改写点）**：
  1. ⭐ **采用「异常降级」必须同时具备「错误可见的出口」** —— 否则只是把一种静默失效换成另一种（页面表现只是「某些东西不动了」）；
  2. `tick` 返回值的语义是**隐式契约**（返回真 = 还要帧），写反会**静默**变成常驻循环 ⇒ 机器判据在这里**只能给信息、不是检查**（被拆对象自己的措辞即如此）。
- **代价**：异步重抛把异常**移出**原始调用栈（丢上下文）；多处全局状态（数组 / Map / WeakMap / 单例）在注销时必须**同步清干净，漏一处即泄漏**。

## 5. 工具链工程

### 5.1 同一物理量：**同源，或明确分工**（不得「自称同源、实际两套口径」）

- **问题**：从自由书写的代码里抽「唯一权威声明」时，若两处工具各用一套正则，会判出**不同**结果。被拆对象 build.mjs#nameOf 取「**最后一个** `hairline({`」，而 validate.mjs#declared 要求「**文件末尾**的 `hairline({…})`」—— 而 build.mjs 的注释**自称**「as validate.mjs reads it」（**自称同源，实际不同源**）。
- **本仓怎么用（改写点）**：同一物理量的多个消费者必须**同源**（引 `references/skill-hygiene.md` 第 4 条：跨模块同源 ＋ 守卫 ＋ 成对阴性对照）**或明确分工**，且**分工要写下来**。
- **代价**：抽取方式仍是**启发式**（正则）—— 声明里含嵌套 `}`、或模板字符串内含 `hairline({`，就会取错。

### 5.2 一份实现多处复用（防「两条路径不同源」）

- **机制**：链上多个工具 **import 同一份实现**（构建器 / 校验器），而不是各拼一遍 ⇒ 防「**校验的那份 ≠ 交付的那份**」这类双路径缺陷。
- **本仓怎么用（改写点）**：归入 `references/skill-hygiene.md` 第 4 条射程，**只作正面样本**（不新造纪律）。
- **代价**：导出面被撑大，**内部实现成了事实 API**（改名即破坏兼容，且**无版本声明**）；被 import 时不能有副作用 ⇒ 依赖 CLI 守卫（见 §5.3），**守卫一旦失效则整条工具链静默 no-op**。

### 5.3 CLI-vs-模块 判定：`realpath` 归一再比（并显式处理 Windows 大小写），且**抽成一处**

- **机制**：`import.meta.url` 与 `process.argv[1]` 做**字符串**比较，会在（a）符号链接 / 目录联接安装、（b）Windows 盘符与路径**大小写**差异下失效 ⇒ 要么被 import 时误执行，要么当 CLI 跑时**什么都不做**（静默 no-op，最难发现）。
- **本仓怎么用（改写点）**：
  1. **抽成一处**（被拆对象把同一个 `same()` **复制三份** —— 正犯 `references/skill-hygiene.md` 第 4 条）；
  2. **加 `try`**：`realpathSync` 对**不存在**的路径**抛异常**（被拆对象三处均未加 ⇒ 入口被删 / 被移会让工具直接崩，报错是 `ENOENT`，对使用者不友好）。
- **代价**：守卫被工具链（打包器重写 `import.meta.url`、`argv[1]` 形态变化）破坏时，**静默 no-op**。

### 5.4 做「内容相等 / 哈希」之前统一行尾 —— 但要**中央封装**，且**不得**用 `trimEnd()` 静默改尾

- **机制**：跨平台检出（`core.autocrlf`）会让**同一份内容**在不同机器上哈希不同、字符串不等 ⇒ **假红**。先归一（`\r\n` → `\n`）再比。
- **本仓怎么用（改写点）**：
  1. **归一到一处中央封装**（被拆对象散在三处调用点 ⇒ 新增一处拼接就得记得加）；
  2. **不得**用 `trimEnd()` 静默抹掉末尾空行（会无声改写「文件末尾几个换行」的约定）；
  3. 判行尾按本仓既有口径取**计数多数派**（**不凭「出现过 CRLF」**），且**结论有时点** ⇒ **每次重测、不跨时点复用**；
  4. 只归一 `\r\n`，**未覆盖孤立 `\r`** ⇒ 封装里一并处理。
- **代价**：归一动作**多一处调用点就多一个漏点**。

### 5.5 平台 / 环境差异抽成有名字的小函数并导出，但**回退目标必须可查**

- **机制**：把平台差异（缓存目录、输入解析）抽成**命名函数** ⇒ 可测、可复用，且人读文档能**直接引用**（被拆对象的人读文档把三个平台的路径逐字写出来了）。
- **本仓怎么用（改写点）**：**允许静默回退，但回退目标必须被打印 / 可查** —— 被拆对象的 `cacheDir()` 在环境变量缺失时**静默退到别处**（事后才发现「装到别处了」）。
- **代价**：平台分支是**硬编码枚举**，新平台需改代码（无配置面）。

## 6. 判据的可信度工程与知识的演化（第二、三个被拆对象：iFixAi / hindsight）

> **来源**：`ifixai-ai/iFixAi@bef9c5eeb96fd255d83ee00a2930c4d19a329f6c`（Apache-2.0）—— 一个「审计 AI agent 有没有按业务规则做事」的诊断器。它与本页在做同一件事：**把「判定」工程化**，只是它判 agent、本仓判产物。取证过程（逐条位置锚、证据档、代价）在工作区任务档案内，**本页不复述**。
> ⚠️ **与 §1–§5 同口径：本节是纪律，不是判据** —— **不为它新增** `scripts/checks.py` 判据、**不新增脚本**、**不改 rubric 阈值**。

### 6.1 不可自证要写成**可校验的结构**，不是一句纪律

- **机制**：它的运行账本在**构造期**就拒绝自评 —— 被测模型若出现在评审模型列表里直接抛异常（ifixai/evaluation/manifest.py 第 189-193 行，错误信息写明「self-judging is signaled by an empty judge_models list」）。
- **本仓怎么用（改写点）**：本仓「执行者不得自审」是**纪律项**，无任何数据层校验 ⇒ 送审记录、决策记录、`--contradicts` 配对里两个字段填同一来源时，机器不会拦。改写点：**凡有「评审者 / 执行者」两栏的留痕，把「二者不得相等」写成可机检的结构约束**。
- **代价**：只挡「同一个标识符」。同一厂商不同模型、不同来源但同源产物，仍构成事实自证 —— 它挡的是**最粗的一层**，写纪律时要如实说这句。

### 6.2 平局取更严的一侧

- **机制**：多评审投票，平局按 fail > partial > pass 裁决（docs/methodology.md「ties break conservatively」）。
- **本仓怎么用（改写点）**：本仓「对抗式互审 + 主代理汇总裁决」**没有规定判向** ⇒ 两个审核子代理结论冲突时怎么裁凭当场判断。改写点：把判向写死（**冲突取更严的一侧**），并写明理由 —— 判错的代价不对称：放过一个问题比多报一个问题的代价高。
- **代价**：系统性压低评价 ⇒ 必须同时保留「建议类 / 风格类不进问题清单」这条既有约束，否则保守判向会退化成「总能挑出毛病」。

### 6.3 为向后可验证，允许显式复刻历史 bug —— 但要写在注释里

- **机制**：运行 ID 由内容摘要派生；字段演进后为不让历史 ID 全部失配，校验函数**按 schema 版本分别复刻各历史版本（含一个已知 bug）的哈希载荷**，注释直言「v1 verification re-creates that buggy payload so historical run_ids verify」，并对旧档发弃用警告。
- **本仓怎么用（改写点）**：本仓台账（.vendor/*.lock.json）与摘要口径同样存在「字段演进 → 旧结论失配」。改写点：**凡为兼容而保留旧口径 / 旧 bug 形状的地方，必须把「这是刻意的」写进代码注释**，否则下一个人会顺手修好，从而让所有历史结论失效。
- **代价**：代码里保留 bug 的形状是认知负担，且**没有机器能判断「这个兼容是否还有人需要」** ⇒ 需配一处人读说明。

### 6.4 防「被测方迎合判据」：给判据喂不可预测的输入

- **机制**：每跑生成一个 16 位随机 nonce 注入被测对象的系统提示，注释写明目的是防止被测方按提示哈希缓存「标准答案」（ifixai/evaluation/manifest.py 第 53-60 行）。
- **本仓怎么用（改写点）**：本仓既有的「阴性对照夹具」「判据造信号」都是**防自己**（防判据写错）；这条是**防对方**（防被检对象学会迎合判据）。改写点：**凡被检对象有可能读到判据本身的任务（自测类、对外评测类），引入不可预测输入**。
- **代价**：破坏确定性重放 ⇒ 必须与 seed 机制并存并说清分工（seed 管可复现，nonce 管不可预测）。

### 6.5 判据集版本必须随结果一起落盘

- **机制**：运行账本同时钉住判据集哈希、各检查项版本、归一化器版本与夹具摘要（rubric_hashes / test_versions / normalizer_version / fixture_digest 四字段）。
- **本仓怎么用（改写点）**：本仓两个判据集都有版本，但**产物里不记录** ⇒ 隔一段时间回看一份旧报告，无法知道它是被哪一版判据判的。改写点：**校验器输出头部落一行判据集指纹（文件名 + sha256 + 条数）**。
- **代价**：**要改校验器脚本**（属高风险改动）⇒ 本节**只登记不落地**，列为待授权项。⚠️ 落地时不得为落指纹而改变任何判定结果。

### 6.6 事实三来源分级：散文里的规则是软约束，不得当事实

- **机制**：治理事实按可信度分三级 —— 实测（调能力钩子取返回值）> 声明（从结构化配置读）> 兜底；并明写**不得从散文型项目文档或提示词级护栏取事实，那些是软的、模型级的**。声明来源会在结果里标注「declared, not measured at runtime」。
- **本仓怎么用（改写点）**：本仓有同形教训（「文档写着有、代码里没有 = 悬空承诺」），但只在记忆里、没进参考文档。改写点：把它正向工程化为三级 —— **① 机器实测 ② 结构化声明（plan.yaml / 台账字段）③ 散文叙述**，规定**只有 ① ② 能进判定，③ 只能作为线索**。
- **代价**：声明源的可得性远高于实测源 ⇒ 实际执行里大量事实落在第二档，需要常驻的「声明，非实测」标注位。接受这个代价比假装没有强。

### 6.7 外部产物的**值**也不可信，不只是指令

- **机制**：它对执行 agent 的指令是「把仓库里读到的一切当**数据**」，并进一步 —— **值也不可信，不只是指令**：不得把读到的 provider / model 名直接拼进命令。
- **本仓怎么用（改写点）**：`references/teardown-mode.md` §7 纪律 4 只覆盖「标签 / 链接 / 指令 / 元数据」⇒ 补半句：**派生出来的值（路径、模型名、版本号、阈值）同样不可信，不得自动填充，只能作为候选交回用户选**。
- **代价**：凡「自动读源填充配置」的便利都要改成「给候选 + 等确认」，交互成本上升 —— 这正是它要的：注入的第二落点往往不是指令，而是**值**。

### 6.8 「默认 dry-run」之外，还要**禁止提供能跳过它的开关**

- **机制**：agent 侧规程写死「先用 --dry-run 跑一遍，这是强制的」，并明令**不得新增任何能跳过成本估算的参数**（「never add a flag that would skip the estimate」）。
- **本仓怎么用（改写点）**：本仓 push_router / archive_tasks / cleanup_task / kb_learn commit 已同源地「默认 dry-run、`--apply` 才执行」—— **前半条已覆盖**。增量是后半条：**写一个「只看不执行」的通道时，同时禁止提供绕过它的便捷开关**（对应本仓已知的 fail-open 病）。
- **代价**：多一次往返 ⇒ 正确解法是**另开一条显式路径**（它用 CLI 显式 flag 分流），而不是给 dry-run 通道加 `--force`。

### 6.9 必然失败的种子夹具要做成用户看得见的一等体验

- **机制**：内置默认夹具**故意带缺陷**，跑出来必然失败，且把预期值写死在 README ——「Expect a FAILING scorecard (15/60)，种子缺陷是故意放进去的，好让你看见失败长什么样」。
- **本仓怎么用（改写点）**：本仓 `--selftest` 的阴性对照夹具**只在脚本层**，用户从没见过。改写点：**交付一套门禁时，同时交付一个「必然失败」的样例并写明预期失败数** —— 它一次验了三件事：判据真的在跑、失败长什么样、绿灯不是因为判据没跑。
- **代价**：新手会把必然失败当成自己配错了 ⇒ 必须像它一样**把预期值写进可见处**，否则这条会从「对照」变成「惊吓」。

### 6.10 出站扫描管文件，运行时外发要另配「可自证将发送什么」

- **机制**：提供一条命令打印**将要发送的完整字段清单**，明列不发什么（代码 / 发现 / 分数 / 提示词 / 文件路径 / IP），CI 中自动关闭，三种退出方式。
- **本仓怎么用（改写点）**：本仓 `outbound_scan.py` 扫的是**文件里的本机路径**，**运行时外发（遥测 / API 调用 / 上报）不在射程** ⇒ 两个面互补，不得互相冒充。改写点：凡会往外发数据的动作，必须有一条「打印将发送什么」的等价路径，且**与真实发送路径同源**（否则预览本身会撒谎）。
- **代价**：预览实现必须与发送实现同源 ⇒ 正确做法是**让预览复用发送端的字段装配函数**，不是另写一份清单。

### 6.11 未检测态：从分子和**分母**同时掉落

- **机制**：证据不足 → 独立状态（insufficient_evidence / inconclusive / not applicable），与通过 / 失败分开；**空类目从分子和分母同时去掉**，子集运行自动重归一（docs/scoring.md「Null categories drop from both numerator and denominator」）。
- **本仓怎么用（改写点）**：本仓已规定「SKIP 不得并入通过率」，**但没规定分母怎么办**。改写点：补一句 —— **SKIP 既不进分子也不进分母；分母只由「实际被判的项」组成**，并在汇总行同时报出「被判项 / 总项」，使「通过率 100% 是因为只判了 2 条」这种形态**自己暴露**。
- **代价**：必须为每类判据定义「多小的样本算没测到」的门槛（它是每检查项至少 10 条证据），否则「未检测」会退化成收纳一切例外的垃圾桶。

> **§6.12–§6.18 来自第三个被拆对象**：`vectorize-io/hindsight@44d5340148fd47efb34e184d61f87ab5e2d8d1e2`（MIT）—— 一个 agent 长期记忆服务（retain / recall / reflect 三原语 + 记忆整合）。它与 §6.1–§6.11 的审计器做的是**相反方向**的事：一个判「这一刻对不对」，一个管「结论怎么随时间变」。取证在任务档案内，**本页不复述**。

### 6.12 冲突不是判胜负：更新后的文本**必须含演变**

- **机制**：它的整合管线对冲突有三条合并规则 —— 冗余 → 合并成更干净的一条；**直接矛盾 → 保留两态并加时间标记，要求「updated text must capture both states」，不做覆盖**（无解释时才取最新）；状态更新 → 显式写「used to / now / changed from X to Y」。原文一句概括：「我们不做覆盖，而是尝试生成一条解释事实如何随时间变化的时间叙事。」
- **本仓怎么用（改写点）**：本仓学习模型对冲突的处置是**双向冻结等人裁**（P0，按危险度分级），这个哲学**不换**。可抄的是**表述层**：本仓 `--supersedes` / 废止目前只加 `⚠️ 已废止` 标记，**不要求新条目写出演变**。改写点：**凡取代旧结论的新条目，正文必须同时含旧态与新态**（「此前判 X，现改为 Y，因为 Z」），而不只是写新结论 —— 否则读者看到的是一个没有来历的结论。
- **代价**：「演变叙事」由模型生成，**可能引入原文没有的因果**（把相关写成因果）⇒ 必须能指回触发变更的来源，不允许凭空叙述。

### 6.13 证据计数既是**门槛**，也是**裁决输入**

- **机制**：它的冲突分析把「现有观察的 proof count（支撑事实条数）+ 源记忆 + 时间序」一起喂给模型，由模型判这是冗余、矛盾还是状态变化 —— 计数**不只用来决定要不要收**，还用来决定**谁赢**。
- **本仓怎么用（改写点）**：本仓 `kb_learn.py` 的证据计数目前**只有一个用途**（达门槛才入库）。改写点：**两条候选冲突时，把各自证据计数作为裁决输入之一显式写出来**（连同时间序），而不是只由模型凭印象裁。
- **代价**：计数多 ≠ 对 —— 反复出现的偏见会被计成高 proof。本仓学习模型已经写明「学到的东西是对的没有机器判据」，这条不会因本条而改变，只是让裁决过程**可复核**。

### 6.14 区分**持久知识**与**瞬时状态** —— 不区分会把临时变化不断判成冲突

- **机制**：它明写只提炼持久事实 ——「User visited Acme Corp at Room 105 会变成 Acme Corp is located in Room 105；但 User is currently in Room 105 不追踪，因为瞬时位置数据一直在变」，并给出理由：**这个区分显著减少了假冲突**。
- **本仓怎么用（改写点）**：本仓记忆层已有「只写判据、不存快照」的口径，但**缺机制理由**。改写点：把这条理由补进去，并把判据写成一句可执行的问话 —— **「这条换个任务、下个月还成立吗？」答否 ⇒ 不进持久层**。
- **代价**：「什么是持久的」本身是判断，判错就会永久丢掉本该保留的变化 ⇒ 判错的条目要有回流通道（本仓：日常日志层保留原始，持久层只放提炼后的）。

### 6.15 **合并会扩大可见面** —— 合并前先问边界

- **机制**：它的观察合并时，标签取**并集**（让所有贡献者都能看到自己参与创建的知识），且合并**只在同一安全域内进行**（严格匹配防跨用户泄漏）。
- **本仓怎么用（改写点）**：本仓学习模型 K3 蒸馏要做「同物理量合并 + 去重」，**从未问过「合并会不会扩大可见面」**。改写点：**合并两条来源不同的条目时，必须声明合并后的适用范围，且不得超出任一来源的可见面**；跨项目 / 跨工作区的经验合并尤其要先过这一问（对应出站扫描只管「路径」，管不了「合并后的语义可见面」）。
- **代价**：并集只增不减 ⇒ 可见面随时间单调膨胀。本仓 KB 是个人库，实际风险低，但**「合并后的适用范围」这一栏必须有**，否则跨项目经验会被静默泛化。

### 6.16 出站扫描管**文件**，入站扫描管**内容** —— 且分脱敏 / 阻断两档

- **机制**：它的 Memory Defense 对每个写入请求扫 secrets 与 PII（45 个模式），命中要么**脱敏**（`[REDACTED:github_token]`）要么**整条阻断**不入存储。
- **本仓怎么用（改写点）**：本仓 `outbound_scan.py` 扫的是「将外发的**文件**里的本机路径」，**入站内容（外部产物的正文、网页抓取结果、用户粘贴的材料）完全没有扫描面**。改写点：**把「外部内容当不可信数据」从一条纪律扩成一个两档处置面** —— 命中敏感特征时，能脱敏就脱敏（保留可用性），脱敏会破坏语义的则整条阻断。
- **代价**：45 个模式是**黑名单**，必然有漏检与误报（本页 §2.1 已写明黑名单不可能穷举）⇒ 登记为纪律，**不得声称已覆盖**。

### 6.17 反面样本：**安全能力做成 opt-in = fail-open**

- **机制**：上面那套扫描是 **opt-in，默认关闭**（「An opt-in, per-bank policy」）。
- **本仓怎么用（改写点）**：与 §6.8「禁止提供能跳过估算的开关」**互为反例** —— 同一件事（一个安全 / 成本闸门），一个做成强制、一个做成可选。改写点：把这对反例**并排**看，因为单独看任一条都只是「一个设计选择」，并排才能看出**判据**：**闸门的默认值就是它的实际强度** —— 默认开的闸门会被绕过一次，默认关的闸门等于没有。
- **代价**：并排反例会让人误以为「必须默认开」⇒ 须同时写明例外：确有闸门需要显式开启（本仓 `--apply` 类），判据是**它保护的是不可逆动作还是便利性**。

### 6.18 两条反模式的**外部佐证**（同一结论的第二个独立来源）

- **机制**：它的反模式表里列了两条与本仓既有教训**独立同形**的条目 —— ①「在同一个请求里既写入又检索 —— 写入的内容尚未建索引」 ②「用 metadata 做过滤 —— metadata 不可过滤，要过滤就用 tags」。
- **本仓怎么用（改写点）**：① 对应本仓「**刚写完就自证 = 假信号**（换独立进程）」；② 对应本仓「**不可机检的字段不得当过滤维度**」。两条都已有，但**只有本仓一个来源**。改写点：**把外部佐证写进对应条目** —— 同一结论有两个独立来源时，它从「我们的习惯」升级为「工程共识」，说服力不同。
- **代价**：**别顺手把它整张反模式表抄进来** —— 其中「retain 前不要预摘要，存原文让它自己抽」与本仓「不转录、只抽取」**正好相反**，且两边都对：它有自动抽取管线，本仓没有。抄之前先问「它这么做的前提我有没有」。

### 6.20 判据与算子**同物**（第三个被拆对象：lieflat-less-ai-tone）

> 本条补的是 6.1／6.4／6.9 没覆盖的一角：**判据说东、算子测西**。6.1 管「不可自证要写成可校验结构」，6.4 管「防被测方迎合」，6.9 管「必然失败的种子夹具」—— 三者都默认「算子测的就是规则说的东西」，本条把这个默认变成判据。

**6.20.1 同物性核验**：新增判据前，用正例与反例各 3 条撞一遍，只问一句「测的东西是不是规则说的东西」。现成反例：上游第 6 条规则只处理 `#` 标题与独立加粗行里的序数编号，其算子正则却在测**正文句首**的「首先／其次」—— **它测的恰是规则明写「不要改」的那一类**，照搬会让改写方向反转。

**6.20.2 分母与解析侧同源**：结构类指标的分母必须是被测对象自身的计数单位（同类元素总数），不用字数代替。上游自报（C 档）：问句小标题按字数算差 32 倍，换成「占小标题比例」后差异消失。**换一个切分器就换一套分母，跨工具不可比** —— 故不得拿本仓比率去对上游倍率。

**6.20.3 软启动出口**：新判据首版只 WARN，配阴性对照；攒够真实样本再议升档，升档须有独立证据记录。理由：外部倍率多为 C 档（语料不入库、第三方不可核验），拿 C 档证据给自家交付设阻断，方向是错的。

> **落地痕迹**：本仓 `scripts/humanize_scan.py` 的 H14–H17 即按本条执行 —— 全部 WARN、配 `scripts/fixtures/humanize/struct-positive.md` 与 `scripts/fixtures/humanize/struct-negative.md` 双向夹具、行号与既有 RULES 同源（不复用上游算子，H17 按「只认标题」重写）。

1. **本页是纪律，不是判据**：没有任何一条被机器检查 ⇒ 「读过本页」**不等于**「做到了」，也不会有 FAIL 提示你漏了。**缺失不报警**是它的固有代价。

5. **不覆盖**：本页不含它的**视觉工艺原则**（在 H 层）、不含它的**来源 / 许可 / 账本**（在 `references/external-skills.md`）、不含**拆解取证过程**（在任务档案）。
