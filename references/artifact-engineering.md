# 产物工程手法（写判据 · 自校验 · 可测性）

做「机器判据」与「可交付产物」时的手法与坑。**按需 grep 本文件相应小节。**

> **这是什么**：从一次外部产物的**逆向拆解**里提炼的 16 条**工程手法**（自校验 / 写判据 / 可测性内建 / 循环调度 / 工具链工程）。**它是纪律，不是判据** —— 本仓**不为它新增** `scripts/checks.py` 判据、**不新增脚本**（逆向拆解模式的诚实边界条明规）。
> **它不是什么**：原始对象的**视觉工艺原则**（缓动 / 发光 / 减动效 / 静止构图 / 命中区）**不在本页** —— 那部分在 `references/aesthetic-rubric.yaml` 的 H 层（出处与安装形态见 `references/external-skills.md`）。本页只留**工程手法**。
> **来源与取证**：被拆对象 = 第三方技能 hairline-create 的**工程实现层**（lucasmarkes/hairline@a2217852fed6d1a4f20bc7d43d4fad1a3de117b8；它是一个「给一个想法就画一张等距线稿图」的**单文件产物生成器**）。逐条位置锚、证据档与「代价」全文在任务档案 `tasks/逆向拆解-hairline-create-2026-10-09/`，**本页不复述取证过程**。
> **读法**：每条给「**机制 → 本仓怎么用（改写点）→ 代价**」。⚠️ **代价是被拆对象实际承担的**；**改写点是我的判断，改写后是否更好未经实测**（见 §8）。

## 1. 自校验：让产物自带可复算的证据

### 1.1 内容摘要写进产物头部，由校验器复算（fail-closed）

- **机制**：把一段**声明为不可变**的核心代码的**内容摘要**写进它自己的头部（行内 sha256），校验器复算比对 —— 任何手改**必然**被下一次校验发现。
- **本仓怎么用（改写点）**：
  1. **摘要口径必须写成人读文字**（被拆对象只写在代码里：等价于「除首行外全部内容，末尾按恰好一个换行计」—— 这是**隐含契约**，CRLF 检出下会破，靠同函数的行尾归一才成立）；
  2. 明确它**只证「产物内 = 本目录」**，**不证「本目录 = 上游正版」** —— 后者归 `.vendor/hairline.lock.json` 这类台账 ＋ `scripts/external_skill_lint.py --verify-lock`。**两套机制分工，不得互相冒充**；
  3. 摘要之前**先做行尾归一**（见 §5.4）。
- **代价**：改核心代码必须用工具重算摘要（对本仓是硬摩擦 —— 但这正是设计意图）。

### 1.2 把「机器管什么、人看什么」写成可查对照

- **机制**：在人读文档里逐项标明**哪几项机器管、哪几项只能人看**，并与校验器头部的判据清单**一一对应**。
- **本仓怎么用（改写点）**：本仓已有「**SKIP 不并入 PASS**」这条**判据侧**纪律，但「**边界必须人读可查**」**没有既有对位条目** ⇒ 写下来：
  - 新增 / 修改机器判据时，**同步改人读文档的边界说明**；
  - 边界说明里**不得**把「没检查」写成「通过」（被拆对象这里是**人工同步、无守卫** ⇒ 本仓承认它是**声明**，不假装自动一致）。
- **代价**：靠人工同步，**没有守卫**——文档与判据脱节时机器不会报警。

## 2. 写判据的五个坑

### 2.1 黑名单不可能穷举 —— 且**不得把风险等级不同的东西并成一条**

- **机制**：约束「模型自由书写的代码」时，用**外联黑名单**（`fetch` / `XMLHttpRequest` / `<script>` / `eval` / `.cookie` …）机器化「单文件自包含」。
- **两个坑**：
  1. **穷举无上界**：被拆对象的清单未覆盖 `importScripts` / `Worker` / `<object>` / `<embed>` / `<use href>` / CSS `@import` / `image-set()` / `srcset` 等。⇒ 按**有界否定**写法：只写「**在该清单内未覆盖下列 token**」，**不写**「不存在这些风险」；
  2. **风险等级合并**：被拆对象把「用 DOM API 建节点」与「读 `.cookie`」并成**同一条 FAIL** ⇒ 报错只能给一个理由，且两类风险被等同。**本仓若采纳，拆成两条**（外联 / 取用宿主能力）。
- **代价**：清单本身是维护面 —— 每加一个 token 都是一次「想全」的赌注。

### 2.2 只有黑名单时，「什么都不做」的产物**全绿** ⇒ 必须配白名单

- **机制**：一个不画任何东西、不注册循环、不写读数的空产物能通过**所有**黑名单 ⇒ 必须配「必须出现的调用」白名单。被拆对象用**前瞻否定**排除同名不同物（`map.set` 不该被当成 `set`），并**穷举三种合法写法**。
- **本仓怎么用（改写点）**：⚠️ **「穷举合法写法」是把维护面押在「作者能想全」上**（漏一种就把合法写法判红）⇒ 采纳时**显式登记这个上界**，并优先用「**收窄取数范围**」降低穷举需求（见 §2.3）。
- **代价**：白名单是**文本级**存在性检查（注释已被剥离，但**字符串里出现 `pointer(` 仍算命中** ⇒ 存在假绿面）。

### 2.3 自写词法剥离是**最后一档**手段，先试「收窄取数范围」

- **问题**：判据是正则，但源码里混着注释、字符串、模板字面量、正则字面量。直接对全文跑正则会有**两个方向**的错 ——
  - **假红**：注释里写「不要用 `stroke-width`」被判违规（把**说明文字**当代码）；
  - **假绿**（更坏）：字符串里出现 `//` 被当注释 ⇒ **后面真正的违规被整段跳过**。
- **被拆对象的解法**：自写约 38 行 JS 词法剥离（注释删掉；字符串按开关保留原文或清空；正则字面量按「斜杠是否位于值起点」判断；模板 `${…}` 用**栈**记 brace depth）。
- **本仓怎么用（改写点）**：**先收窄取数范围，其次才是自写词法** —— 本仓既有做法是**结构化取块**（`scripts/checks.py` 的 `_frontmatter()`，原文措辞「结构化取块，非字符窗口」），比剥离全文更省、更稳。自写词法**无单测**、**只管一种语言**、`/` 歧义本身是**启发式** ⇒ 定为**最后一档**。
- **代价**：手写状态机是长期维护面；语言演进（新字面量形式）会让它失准。

### 2.4 数「调用的形状」要逐字符配平；但**豁免条件必须可核**

- **机制**：`tset(tw, to, now, delay)` 少给第 4 个参数 ⇒ `t0 = now + undefined = NaN` ⇒ **画不出来也不报错**（静默失效，最难查）。正则数不清「逗号是否在同一层」⇒ **逐字符配平**（只在 `depth === 1` 时计逗号）。
- **⚠️ 反面样本（本页最值得记的一条）**：它的豁免写作 `if (given < 4 && !call.includes("..."))` —— **只要该调用文本里任意位置出现 `...` 就整体放过**，而**不检查展开的实参有几个**。⇒ 这是 **fail-open 的豁免：豁免的触发条件本身不可核**。
- **本仓怎么用（改写点）**：本仓已有「豁免必须写理由」「豁免了却本次没 FAIL 会 WARN」「单条登记四键不全 ⇒ 该条作废、不放行」（`scripts/checks_judges.py`）；**增量**是更细的一层纪律 —— **豁免的触发条件本身必须可核**。提问式自检：
  > **「这条豁免，谁来把它的触发条件置真？」**
  答不出「谁」的豁免，等价于把该判据关掉。
- **代价**：配平是又一处**手写解析**（与 §2.3 同源成本）。

### 2.5 借宿主解释器做**真语法**校验时，必须区分「产物有缺陷」与「环境不可用」

- **机制**：把解释器当 **oracle**（写临时文件 → `node --check` → 抓 stderr 行号 → `finally` 删临时目录）。**「这段代码能不能作为模块加载」不是文本层能判的**（剥离 ≠ 解析）。
- **坑**：被拆对象 `status !== 0` **一律**报「图有语法错」⇒ 环境问题（不可写临时目录、无执行权限、解释器缺失）被**误报成产物缺陷** —— 「**判据造信号**」的典型形态（⚠️ **全红与全绿一样，要先怀疑判据**）。
- **本仓怎么用（改写点）**：借外部 oracle 的判据**必须带降级 / 分流分支**（本仓同族纪律：关键判定命令**不接管道取 rc**、先落文件再取 rc；`references/policy.md` §1.3 的 `3 = 无法判定 ⇒ 拒绝`）。另：被拆对象 `spawnSync` **未设 `timeout`** ⇒ 未设边界。
- **代价**：进程开销（对批量校验是硬成本）；临时目录靠 `finally` 清理，**进程被强杀则残留**（无陈旧清理）。

## 3. 可测性内建（把验证夹具做进产物）

### 3.1 地址参数即夹具：给「人」留可复现的地址，工具顺带复用

- **机制**：产物用 URL 参数暴露少量**离散状态**（`?at=x,y` / `?w=` / `?intensity=` / `?theme=` / `?play=`），页面加载后**派发一个真实 `PointerEvent`**；工具用**同一手法**做同一件事（**不是给测试开后门**）。
- **本仓怎么用（改写点）**：对外它是「可分享一个状态」的功能，对内它是夹具 —— ⚠️ **测试面与交付物耦合**（改地址协议 = 改产品），设计时要认下这个代价。定位为「**人可复现**」，**不声称等价于真手检**（合成事件 ≠ 真实指针：触摸、压力、指针捕获都验不了）。
- **代价**：参数一多，地址空间按**因子组合**增长（八图 = 4 参数 × 2 取值）。

### 3.2 契约面收窄成「代理对象」，让「越界」在文本层可判

- **机制**：插件 / 脚本**不拿真 DOM**，只拿一个**只有 getter/setter 的窄对象**（只能写一个字符串）⇒ 契约面被压到 1 个属性 ⇒ 「不许测 DOM」这类文本判据**才有可判性**。
- **本仓怎么用（改写点）**：想让「越界」可判时，**先收窄契约面，再写判据**。⚠️ 契约面越窄，**任何新读写需求都必须改宿主**（可预见的扩展成本）。
- **代价**：表达力受限于设计；读回的值来自宿主局部状态，与真实渲染**可能短期不一致**（属**未写出的隐含前提**）。

### 3.3 代理量：一律**警告级**；阈值必须带来源样本；**时序敏感的判据，阴性结论比阳性结论可信**

- **机制**：把「静没静」「看不看得出」这类只能靠眼睛的性质，换成**可从像素 / 时序算出**的量（静帧判定 / 墨迹异或率 / 覆盖面积比），且**每个阈值都写明它的实测样本**（如「两范例静息外接框占 36%」）。
- **本仓怎么用（改写点）**——两条**增量**（其余与既有面重叠，见 §7）：
  1. **代理量一律 warn / 信息级，不得升为 FAIL** —— 代理 ≠ 原物（墨迹异或率高**不**蕴含答案语义更好）；
  2. ⭐ **时序敏感的判据，阴性结论比阳性结论可信** —— 「机器太忙」会被判成 `moving`（被拆对象作者自认「run it again before you believe it」）⇒ **负结论须复核**。
- **代价**：阈值是**经验值且与图形语言绑定**，换一类产物就要重标；像素级扫描开销不小。

## 4. 循环与调度

### 4.1 共享单帧循环 ＋「tick 返回布尔」自动休眠 ＋ 异常**降级但保可见**

- **机制**：多个独立组件**共享一个**渲染循环，组件自己决定「还要不要帧」（`b.awake = !!b.tick(dt, now)`）；**全员静下来则循环彻底停**（不是空转）；`dt` 钳位（切回标签页不喂进巨大 `dt`）；子步细分后再积分（稳定性）；每帧调用**幂等**；异常时**本组件停下 ＋ 异步重抛**（不静默吞）。
- **本仓怎么用（改写点）**：
  1. ⭐ **采用「异常降级」必须同时具备「错误可见的出口」** —— 否则只是把一种静默失效换成另一种（页面表现只是「某些东西不动了」）；
  2. `tick` 返回值的语义是**隐式契约**（返回真 = 还要帧），写反会**静默**变成常驻循环 ⇒ 机器判据在这里**只能给信息、不是检查**（被拆对象自己的措辞即如此）。
- **代价**：异步重抛把异常**移出**原始调用栈（丢上下文）；多处全局状态（数组 / Map / WeakMap / 单例）在注销时必须**同步清干净，漏一处即泄漏**。

## 5. 工具链工程

### 5.1 同一物理量：**同源，或明确分工**（不得「自称同源、实际两套口径」）

- **问题**：从自由书写的代码里抽「唯一权威声明」时，若两处工具各用一套正则，会判出**不同**结果。被拆对象 build.mjs#nameOf 取「**最后一个** `hairline({`」，而 validate.mjs#declared 要求「**文件末尾**的 `hairline({…})`」—— 而 build.mjs 的注释**自称**「as validate.mjs reads it」（**自称同源，实际不同源**）。
- **本仓怎么用（改写点）**：同一物理量的多个消费者必须**同源**（引 `references/skill-hygiene.md` 第 4 条：跨模块同源 ＋ 守卫 ＋ 成对阴性对照）**或明确分工**，且**分工要写下来**。
- **代价**：抽取方式仍是**启发式**（正则）—— 声明里含嵌套 `}`、或模板字符串内含 `hairline({`，就会取错。

### 5.2 一份实现多处复用（防「两条路径不同源」）

- **机制**：链上多个工具 **import 同一份实现**（构建器 / 校验器），而不是各拼一遍 ⇒ 防「**校验的那份 ≠ 交付的那份**」这类双路径缺陷。
- **本仓怎么用（改写点）**：归入 `references/skill-hygiene.md` 第 4 条射程，**只作正面样本**（不新造纪律）。
- **代价**：导出面被撑大，**内部实现成了事实 API**（改名即破坏兼容，且**无版本声明**）；被 import 时不能有副作用 ⇒ 依赖 CLI 守卫（见 §5.3），**守卫一旦失效则整条工具链静默 no-op**。

### 5.3 CLI-vs-模块 判定：`realpath` 归一再比（并显式处理 Windows 大小写），且**抽成一处**

- **机制**：`import.meta.url` 与 `process.argv[1]` 做**字符串**比较，会在（a）符号链接 / 目录联接安装、（b）Windows 盘符与路径**大小写**差异下失效 ⇒ 要么被 import 时误执行，要么当 CLI 跑时**什么都不做**（静默 no-op，最难发现）。
- **本仓怎么用（改写点）**：
  1. **抽成一处**（被拆对象把同一个 `same()` **复制三份** —— 正犯 `references/skill-hygiene.md` 第 4 条）；
  2. **加 `try`**：`realpathSync` 对**不存在**的路径**抛异常**（被拆对象三处均未加 ⇒ 入口被删 / 被移会让工具直接崩，报错是 `ENOENT`，对使用者不友好）。
- **代价**：守卫被工具链（打包器重写 `import.meta.url`、`argv[1]` 形态变化）破坏时，**静默 no-op**。

### 5.4 做「内容相等 / 哈希」之前统一行尾 —— 但要**中央封装**，且**不得**用 `trimEnd()` 静默改尾

- **机制**：跨平台检出（`core.autocrlf`）会让**同一份内容**在不同机器上哈希不同、字符串不等 ⇒ **假红**。先归一（`\r\n` → `\n`）再比。
- **本仓怎么用（改写点）**：
  1. **归一到一处中央封装**（被拆对象散在三处调用点 ⇒ 新增一处拼接就得记得加）；
  2. **不得**用 `trimEnd()` 静默抹掉末尾空行（会无声改写「文件末尾几个换行」的约定）；
  3. 判行尾按本仓既有口径取**计数多数派**（**不凭「出现过 CRLF」**），且**结论有时点** ⇒ **每次重测、不跨时点复用**；
  4. 只归一 `\r\n`，**未覆盖孤立 `\r`** ⇒ 封装里一并处理。
- **代价**：归一动作**多一处调用点就多一个漏点**。

### 5.5 平台 / 环境差异抽成有名字的小函数并导出，但**回退目标必须可查**

- **机制**：把平台差异（缓存目录、输入解析）抽成**命名函数** ⇒ 可测、可复用，且人读文档能**直接引用**（被拆对象的人读文档把三个平台的路径逐字写出来了）。
- **本仓怎么用（改写点）**：**允许静默回退，但回退目标必须被打印 / 可查** —— 被拆对象的 `cacheDir()` 在环境变量缺失时**静默退到别处**（事后才发现「装到别处了」）。
- **代价**：平台分支是**硬编码枚举**，新平台需改代码（无配置面）。

## 7. 与既有面的分工（**同一物理量只写一处**）
