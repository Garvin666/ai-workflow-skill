# 反思重试机制（v4.1.0 新增）

> **定位**：它是「执行期六动作」第④步（跑验证信号）**失败后**的第一响应——一个**自动化内层闭环**，先于人工「返修复查」与「熔断」。
> **目标**：把"可自我纠正的失败"在自动化层消化，**避免每次失败都升级到人工/熔断**。
> **配套**：配置落 `assets/plan-template.yaml` 的 `meta.反思重试配置`（步骤级可覆盖）；机器校验见 `scripts/checks.py plan` 检查项 12；记录落 `tasks/<任务>/trace.jsonl`（`action=retry`）。

---

## 1. 为什么需要它（与既有机制的关系）

此前失败升级链是：**验证失败 → 人工「返修复查」→ 触顶 → 对抗式互审 → 熔断**。
问题：很多失败是"可自我纠正"的——临时网络抖动、参数微调、一次性实现偏差、验证脚本误判——直接升级到人工/熔断是浪费。

反思重试机制在**验证失败**与**返修复查**之间插入一层自动化闭环，把这类失败就地消化。它与既有机制**不另立一套**：

| 位置 | 行为 |
| --- | --- |
| 触发 | 步骤验证信号未通过 / 结果不满足预期 / 校验失败（见 §2 的 T1–T3） |
| **先于「返修复查」** | 自动重试**耗尽**（达到「最大重试次数」） → 才升级到「返修复查」（人工/审核驱动，上限 2 轮，触顶→对抗式互审→熔断 F1） |
| **不绕过「熔断」** | 环境类硬失败（**F3 证据不可得 / F4 越界 / F5 配额硬阻断**）**明确排除在触发条件外**，直接走熔断，不在重试里耗次数 |
| **不混入 R1–R6 重规划** | 目标/事实变更不是"重试能解决"的事，走重规划（自适应计划） |

> ⚠️ 关键区分：**重试≠重规划≠返修**。
> - **重试**：同一个实现，调一下再跑（参数/环境/一次性偏差）；
> - **重规划 R1–R6**：目标或事实变了，原路径整体不对；
> - **返修复查**：人工/审核驱动的带问题清单回归。
> 三者是不同维度的计数器（见 §6），记录时显式区分——呼应「同一物理量判据跨模块同源」。

## 2. 触发条件（可判定）

| 编号 | 触发条件 | 可判定信号（须有证据） |
| --- | --- | --- |
| **T1** | 验证信号未通过 | 本步「验证方式」返回非预期，以**原始输出**为证（测试失败栈 / 对账差额 / 探活非 2xx） |
| **T2** | 结果不满足预期 | 产出物存在，但对照验收标准有**可量化偏差**（如"要求 ≥95% 实测 91%"） |
| **T3** | 校验失败 | CI / 对账 / 链接探活 / 编译 **非 0** |

**不触发（防误重试）**：

- **R1–R6 重规划触发**：目标/事实变更不是重试能解决的，走重规划；
- **F3 证据不可得 / F4 越界 / F5 配额硬阻断**：环境类硬失败，直接熔断，不在重试里耗次数；
- **红线③**：越界属结构性问题，重试无意义；
- **单次工具报错未耗尽重试**（见 SKILL.md「门禁不可用时的行为」）：本机制内部的重试次数计数器正是为它而设，未耗尽不算升级。

## 3. 配置项（取值域）

配置落在 `plan.yaml` 的 `meta.反思重试配置`；任意步骤可在 `steps[].反思重试` 做**步骤级覆盖**（不写则用 meta 级）。整段缺省＝关闭自动重试（向后兼容，旧 plan 不受影响）。

| 配置项 | 取值域 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `最大重试次数` | 整数 ≥1 | 3 | 达到上限后按「终止策略」升级，不再自动重试 |
| `触发条件` | `T1` / `T2` / `T3` 的子集 | T1,T2,T3 全开 | 可精简为只监控某些失败类型 |
| `终止策略` | **枚举**（见 §4） | 升级返修复查 | 达到上限后的去向；**唯一取值源 = 本手册 + `checks.py` 常量，二者口径守卫同源** |
| `退避` | 字符串（如 `"2s"` / `"指数退避"`） | 空（立即重试） | 应对限流类失败（F5 接近但属于硬阻断，不在此列） |
| `反思最低要求` | 字符串（如 `"根因+调整方案"`） | 空（不强制格式） | 缺反思格式不计为"有效重试"——防无脑"再试一次" |

> 机器只校验**结构性合法**（次数是否整数 ≥1、触发条件/终止策略取值是否在枚举内、步骤级覆盖是否合法）。**语义层面**（"这次重试真的改了什么"）无法机器强制，靠抽查（见 §7）。

---

## 4. 终止策略（枚举 + 适用场景）

达到「最大重试次数」后，按配置的「终止策略」决定去向。**这是唯一取值源，且被 `checks.py` 的口径守卫锁定**（手册写的枚举 == 代码常量，解析不到即 FAIL）。

| 取值 | 含义 | 适用场景 |
| --- | --- | --- |
| **升级返修复查**（默认，推荐） | 把"已自动重试 N 轮 + 末轮反思"作为「返修复查」问题清单起点，转入人工/审核驱动 | 大多数场景；让"可纠正失败已试过、仍不行"才升级人工 |
| **触发熔断** | 直接触发熔断 F1 路径（停/冻/证/拦/报） | 该步不可逆或自动重试无意义（如"重试只会重复同样不可恢复的错误"） |
| **升级用户决策** | 升级用户，给出已试路径与代价，由用户定夺 | 再试将浪费大量资源 / 需换方案 / 涉及不可逆动作的取舍 |
| **重规划R** | 失败表明原路径整体错（但未到全量重规划），先做一次 R 类重规划留痕 | 失败根因指向"目标/事实理解偏差"而非实现偏差 |

## 5. 每轮反思强制四要素

为防止"再试一次"式无脑重试，每轮重试**必须**产出以下内容（与「缺陷修复双条件」「熔断报告根因区分」同构）。四要素是记录格式要求，不是门禁——填了什么、根因对不对靠抽查。

1. **失败现象**：原始输出 / 与预期的具体差异（贴证据，不写"应该没问题"）；
2. **根因假设**：区分"**证据支持**"与"**推测**"——与熔断报告「卡点根因」同一纪律；
3. **调整方案**：与上一轮**有何不同**（若说不出不同，说明这轮重试无效，应升级而非继续耗次数）；
4. **验证方式**：仍用本步验证方式，或临时补充一个更敏感的判据。

> 若连续两轮调整方案"无不同"，机制**应主动终止**——继续重试只是重复同样的失败，属于浪费，应升级到「终止策略」指定的去向。

## 6. 记录方式（落盘，不靠记忆）

复用 `tasks/<任务>/trace.jsonl`（与 `checks.py trace` 同构、可 `--replay` 回放）。**每次重试追加一行**：

```json
{"ts":"2026-09-18 10:30","step":"3","action":"retry","attempt":2,"result":"通过","note":"T1：对账差 0.3%；根因=浮点舍入（证据支持）；调整=改用 Decimal；验证=同脚本复跑","elapsed_s":42}
```

字段：

- `action=retry`（与 `trace` 的其他 action 区分）；
- `step` / `attempt`（第几轮重试）/ `result`（本轮结果）/ `note`（根因·调整摘要）；
- `elapsed_s`（可选，本轮耗时）。

> ⚠️ `trace.jsonl` **不得写进 `交付物` 字段**——它是留痕不是产物；写进去会被 `_is_file_like()` 命中并按存在性判定，把留痕误当成果（同 SKILL.md 阶段 6 约定）。

**报告口径**：

- 交付说明 / 自检表**显式报告**「本任务重试总次数 / 触顶步（若有）」；
- 终止策略为升级类时，把"已自动重试 N 轮 + 末轮反思"作为「返修复查」问题清单起点；
- 自检表须标注该项为 **`机器`**（重试记录存在性 + 次数 ≤ 上限可由 `checks.py` 校验）还是 **`人审`**（反思质量）。

**计数纪律**：重试次数（`attempt` 计数）≠ 返修复查轮次（≤2）≠ 重规划次数（≤3）。三者是不同维度计数器，记录与报告时**显式区分**，不混用同一个数字。

---

## 7. 诚实边界（契合技能风格）

- **"自动触发"是纪律 + 结构化格式要求**；**"反思质量"无法被机器强制判定**（同 `用户放行` 字段逻辑）。
- 工具**只校验两件事**：① 实际重试次数 ≤ 配置上限；② 重试记录存在性（有重试就必须有 `action=retry` 行，否则视为"无脑重试没留痕"）。
- 填了什么、根因对不对、调整方案是否真的不同——**靠抽查**（独立审核或复盘四问），不靠机器门禁。文档里原样写明"它不是门禁"，否则就是造"看起来有门禁其实没有"的假安全感，比不做更糟。
- **不得声称"已自动保证失败被正确处理"** —— 只能说"重试次数在配置内且已留痕"，反思质量另计。
