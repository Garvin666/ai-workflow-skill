# 策略模型（ai-workflow 显式策略集）

> **定位**：把 `gate.py`（运行时闸门）+ 信息安全 **S1–S4** + 越界授权白名单注册为**显式策略集**，目标是把"散落纪律"升级为「**默认 deny + fail-closed** 的可执行默认值」。策略模型与 P0 的数据模型 / 状态模型正交：它管"**什么动作被允许、默认怎么处置**"。
> **版本**：1（2026-09-21，P1-2 新增）
>
> ⚠️ **权威源声明（必读）**：
> 1. **访问控制策略的事实源 = `scripts/gate.py`**（fail-closed 由代码保证：无法判定 → `rc=3` 拒绝，绝不默认放行）。本文件引用不重述代码。
> 2. **信息安全策略的事实源 = `references/security-guide.md`**（单一事实源，正文只做索引）。本文件引用不重述细则。
> 3. 本文件是**策略的集中注册 + 方向声明**，**不是新增门禁**——它把既有规则摆到一起，让"默认 deny + fail-closed"成为显式默认，而非散落纪律。

## 一、访问控制策略（gate.py，fail-closed）

> 来源：`scripts/gate.py` 模块 docstring 与 `cmd_check` / `needs_authorization` / `--selftest`。**事实源即代码**，本表为可读摘要。

### 1.1 动作与判定域

| 项 | 取值 | 含义 |
| --- | --- | --- |
| **意图 INTENTS** | `read` / `write` / `delete` / `move` | 对目标的动作类型 |
| **范围判定 verdict** | `INSIDE` / `INFRA` / `OUTSIDE` | 落在工作区根内 / 命中基础设施例外 / 工作区外 |
| **高风险意图** | `write` / `delete` / `move` | 写删既有文件，须先取得当次授权 |
| **基础设施例外 INFRA_EXCEPTIONS** | `~/.workbuddy/skills/` 等三类路径 | 仅限**读取与工具用途**；写/删既有文件**不豁免**确认 |

### 1.2 决策表：范围 × 意图 → 结论

| 范围判定 | 意图 | 需授权？ | 结论 |
| --- | --- | --- | --- |
| `INSIDE` | 任意 | 否 | `ALLOW`（工作区内常态读写不需过闸） |
| `INFRA` | `read` | 否 | `ALLOW`（仅限工具用途，不算越界） |
| `INFRA` | `write` / `delete` / `move` | **是** | 无授权 → `DENY`；有 `--allow-outside` → `ALLOW_AUTHORIZED` |
| `OUTSIDE` | 任意 | **是** | 无授权 → `DENY`；有 `--allow-outside` → `ALLOW_AUTHORIZED` |

### 1.3 退出码语义（fail-closed 落地）

| rc | 含义 |
| --- | --- |
| `0` | 放行（含基础设施例外） |
| `1` | 拒绝（越界 / 基础设施例外下的写删而无授权） |
| `2` | 用法错误 |
| `3` | **fail-closed**：无法判定（规则加载失败 / 路径解析失败）→ 拒绝，不退回自带副本 |

> ⚠ **范围豁免 ≠ 风险确认**：`INFRA` 命中只豁免读取与工具用途；对写/删既有文件，USER.md 第 2 条明确"豁免的只是越界申请这一步、**不豁免**高风险前置确认"。第一版把 INFRA 一律判 ALLOW 是**假绿**（比不装闸门更危险），现决策表已分意图。

## 二、信息安全策略（S1–S4，default-deny）

> 来源：`references/security-guide.md` §一–§四。**单一事实源 = security-guide.md**；SKILL.md「信息安全与数据保护」节为其索引。

| # | 策略 | default-deny 方向 | 机检 |
| --- | --- | --- | --- |
| **S1 凭据永不落盘** | API Key/Token/密码/私钥只经环境变量或 `--token`；不写文件/记忆/台账/plan/日志 | **默认禁止写任何地方**；展示只给前缀掩码+长度 | 纪律项（无机器门禁） |
| **S2 敏感信息先分级** | 四级：L1 凭据 / L2 个人隐私 / L3 商业秘密 / L4 内部基建 | **未识别默认按最严一级**（"不知道算不算敏感"≠"不敏感"） | 分级靠人审 |
| **S3 对外动作先有清单** | 外发前列文件/字段清单、目标位置、可见性、留存期、回滚 | **未列清单不得执行**；实际外发与清单不符即中止 | 第 3/4 项机器化（出站扫描），余纪律 |
| **S4 访问控制具体到路径** | 授权写明「路径+读/写+一次性/持续+用途」；主动收窄；禁泛授权 | **目录级泛授权默认拒绝**；上一任务授权不延续 | 登记机检（依据不可机核） |

> **四条底线与三条红线同级（不可豁免）**。S3 出站扫描**只有第 3/4 项机器化**（本机绝对路径 / 内部路径）：`scripts/outbound_scan.py` 命中即 FAIL 并阻塞推送（fail-closed：扫描器导入失败同样阻塞）。**第 1/2/5/6/7/8 项仍是纪律项**——不得声称六项都自动拦截。

## 三、越界授权登记策略

> 来源：`security-guide.md` §四（访问控制与授权登记）＋ `gate.py` 登记逻辑。

**顺序铁律（登记 ≠ 放行）**：

```
先请求 → 拿到当次同意 → 再执行 → 后登记
```

| 位置 | 内容 | 机检 |
| --- | --- | --- |
| `plan.yaml` 的 `meta.越界授权` | `{路径, 操作, 依据, 时间}` 作白名单 | 有（`checks.py plan` 检查项 9：交付物落工作区外且未登记即 FAIL） |
| `Ledger.md` 的「越界授权记录」 | 路径 + 用户授权原话摘要 + 时间 | 人审 |
| 交付说明 | 本次是否越界、越界了哪些路径、依据 | 人审 |

> ⚠ **登记是事后可追溯，不是事前许可**；门禁只能抓"没登记"，抓不到"登记了但没真授权"（依据由模型自填、无法机核）。**技能生成例外**：正在生成的技能其功能实现本身须跨出工作区时，无需申请即可执行，但须说明越界了哪些路径。

## 四、策略方向总览（default deny + fail-closed）

| 策略 | 默认 | fail-closed 行为 | 机检？ |
| --- | --- | --- | --- |
| 范围拦截（gate.py） | 越界 / 基础设施例外下的写删 → 拒绝 | 无法判定范围 → 拒绝（rc=3） | ✅ 代码 |
| 凭据（S1） | 不落盘 | — | ❌ 纪律（抽查） |
| 敏感分级（S2） | 未识别 = 最严 | — | ❌ 人审 |
| 出站（S3） | 未列清单 = 不执行 | 扫描器导入失败 = 阻塞推送 | ✅ 第3/4项；余 ❌ |
| 授权（S4） | 泛授权 = 拒绝 | — | ✅ 登记；❌ 依据 |

> **一句话方向**：能默认拒绝的默认拒绝；不能默认判定的，fail-closed 到"拒绝 / 澄清 / 升级人工"，而非"放行 / 猜 / 自动"。这与状态模型（§四「已机判 / 仍靠纪律」对应表）的分工一致。

## 五、诚实边界

沿用本技能一贯风格（与 `security-guide.md` §九、`gate.py` 模块 docstring 同构）：

1. **「跑过闸门」≠「安全」** —— gate.py 拦得住"未登记/未授权的越界动作"，但**无法判断"该授权的动作有没有被漏掉"**（你不说要删什么，它一无所知）。它是**拦截 + 留痕**，不是许可。
2. **凭据永不落盘无法机证** —— 只有独立审核抽查提高检出率，属纪律项。
3. **越界授权"依据"不可机核** —— 登记是白名单、是追溯，不是许可；顺序永远是"先请求 → 授权 → 执行 → 登记"。
4. **出站扫描只有第 3/4 项机器化** —— 机器化部分只认字面路径；靠变量拼接 / Base64 / URL 编码等间接形态出现的路径不在射程内。第 1/2/5/6/7/8 项仍是纪律项，**不得声称六项都自动拦截**。
5. **策略模型描述规则，不描述"执行者是否诚实填写"** —— 任何"已由本文件保证安全"的说法都不成立。
