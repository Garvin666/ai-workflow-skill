# 数据模型（ai-workflow 中心数据模型）

> **定位**：`plan.yaml` 是 ai-workflow 的**中心数据模型** —— 阶段 3 落盘、阶段 5 对账、熔断门禁、履历归档都读写它。本文件把该数据模型的**结构**与**枚举**集中登记为单一文档，供人查阅、供机器守卫。
> **版本**：1（2026-09-21，P0-1 新增）
>
> ⚠️ **权威源声明（必读）**：所有枚举的**取值单一源 = `scripts/checks.py` 的常量**。本文件的枚举表是**受守卫镜像** —— 由 `checks.py skill` 的口径守卫（`PARITY_ITEMS` 的 7 项 + `_check_category_decl` 的主类声明块）与代码常量同源校验；本文件已并入各枚举的「源规格」，**任一处漂移即 FAIL**。
>
> **改一枚举的固定动作**：改 `scripts/checks.py` 常量 → 改该枚举在 §2.1「权威文档源」列出的**全部**文档（含本文件 §2.2） → 跑 `checks.py skill`。缺任一步都会 FAIL。

## 一、plan 结构 schema

> 用途：把 `meta` 与 `steps[]` 的字段名 / 类型 / 必填 / 约束 / 校验项一表查全。机器上**可执行**的定义在 `scripts/checks.py`，本表是**可读描述**（二者以 `PLAN_META_REQUIRED` / `PLAN_STEP_REQUIRED` 等常量为锚）。

### 1.1 meta 顶层

| 字段 | 类型 | 必填 | 约束 | 校验项 |
| --- | --- | --- | --- | --- |
| 任务 | 字符串 | 是 | 与任务确认表目标一致 | `PLAN_META_REQUIRED` |
| 工作区根 | 字符串（绝对路径） | 是 | 本任务读写边界（红线③） | `PLAN_META_REQUIRED` / 检查项 9 |
| 创建时间 | 字符串（YYYY-MM-DD HH:mm） | 否 | 任务创建日 | — |
| 任务层级 | 枚举（L1 / L2） | 否 | 见 §2.2 任务分层 | — |
| 确认表 | 字符串（路径） | 否 | 任务确认表或本次确认记录 | — |
| 验证信号 | 字符串 | 是 | 完成时的可判定信号 | `PLAN_META_REQUIRED` |
| 复盘沉淀 | 字符串 | 否 | ≥1 条，或显式「无沉淀：理由」 | 检查项 M-1′（WARN） |
| 入口判定 | 对象（7 字段） | 否 | 填则结构须合法 | 检查项 13 |
| 方法选用 | 列表（每步一条） | 否 | 填则结构须合法 | 检查项 14 / 15 |
| 熔断状态 | 枚举（FUSE） | 否 | 缺省即「正常」 | `_check_fuse`（门禁） |
| 决策记录 | 列表（5 字段） | 否 | 每项：决策点 / 能力类 / 依据 / 选择 / 时间 | `checks.py decide` |
| 计划修订 | 列表（5 字段） | 否 | 每项：版本 / 触发 / 时间 / 变化 / 未变；**上限 3 条** | `checks.py revise` |
| 自研工具 | 列表（4 字段） | 否 | 每项：名称 / 用途 / 适用场景 / 仓库链接 | `checks.py selftool` |
| 越界授权 | 列表（4 字段） | 否 | 每项：路径 / 操作 / 依据 / 时间；**禁目录级泛授权** | 检查项 9 |
| 不可逆副作用 | 列表（5 字段） | 否 | 可否回滚 ∈ 可回滚 / 不可回滚 / 未知 | `_check_irreversible` |
| 用户放行 | 列表（2 字段） | 否 | 每项：时间 / 摘要（用户**原话**） | `_check_user_release` |
| 反思重试配置 | 对象 | 否 | 最大重试次数（整数 ≥1）/ 触发条件 / 终止策略 / 退避 / 反思最低要求 | 检查项 12 |

### 1.2 steps[]（每个步骤）

| 字段 | 类型 | 必填 | 约束 | 校验项 |
| --- | --- | --- | --- | --- |
| id | 整数 | 是 | 同 plan 内唯一 | — |
| 做什么 | 字符串 | 是 | 动词开头 | `PLAN_STEP_REQUIRED` |
| 输入 | 字符串 | 否 | 输入文件 / 数据 / 来源 | — |
| 预期产出 | 字符串 | 否 | 预期结果描述 | — |
| 验证方式 | 字符串 | 是 | 怎样算完成（可判定） | `PLAN_STEP_REQUIRED` |
| 状态 | 枚举（STATUS） | 是 | 见 §2.2 | `PLAN_STEP_REQUIRED` / `_check_fuse` |
| 交付物 | 字符串（路径） | 是 | 相对工作区根解析 | `PLAN_STEP_REQUIRED` / Anti-drop 对账 |
| 模型档位 | 枚举（TIER） | 否 | 填则须合法 | `_check_model_tiers` |
| 反思重试 | 对象 | 否 | 字段同 meta | 检查项 12 |

### 2.2 取值（受守卫镜像；**格式即守卫锚点，勿改格式**）

**步骤状态** —— 下表为守卫锚点行（`_p_status` 读取；**勿改格式、勿在行尾加说明**）：

```text
# status 取值: 待办 / 进行中 / 完成 / 受阻 / 熔断
```

**模型档位**：

| 档位 | 含义 |
| --- | --- |
| **strong** | 规划 / 关键实现 / 安全相关（容错低） |
| **mid** | 常规实现 |
| **cheap** | 探索 / 调研 / 测试 / 文档 |
| **default** | 显式声明「按阶段默认档位」（等价于留空） |

**熔断状态**（只列**存储态**；「复位」是**迁移动作**、不是第三个存储态，故不列）：

| 状态 | 类型 | 含义 |
| --- | --- | --- |
| `正常` | 存储态 | 正常流转（`plan.yaml` 留空即视为正常） |
| `已熔断` | 存储态 | 自动化已停止，等待用户决策 |

**能力类**：

| 序 | 能力 | 缺口类型 |
| --- | --- | --- |
| ① | **知识** | 缺领域知识 |
| ② | **算力** | 缺计算 / 推理算力 |
| ③ | **事实** | 缺外部事实 / 数据 |
| ④ | **手脚** | 缺外部执行能力 |

**重规划触发**：

| 触发 | 含义 |
| --- | --- |
| **R1** | 新事实推翻原假设 |
| **R2** | 验证信号不可达（换判定方式，非放弃判定） |
| **R3** | 中间产出暴露原计划未预见的依赖 |
| **R4** | 成本超阈（检索配额耗尽 —— 即熔断 F5 的前置信号） |
| **R5** | 用户中途改需求 |
| **R6** | 连续性断裂（会话中断 / 上下文丢失后重启） |

**反思触发**：

| 触发 | 含义 |
| --- | --- |
| **T1** | 验证信号未通过（以原始输出为证） |
| **T2** | 结果不满足预期（产出存在但对照验收标准有可量化偏差） |
| **T3** | 校验失败（CI / 对账 / 链接探活 / 编译非 0） |

**终止策略**：

| 终止策略 | 含义 |
| --- | --- |
| **升级返修复查** | 默认：达到重试上限后转入返修复查 |
| **触发熔断** | 直接按熔断机制熔断 |
| **升级用户决策** | 暂停自动化、升级由用户裁决 |
| **重规划R** | 转入 R1–R6 重规划 |

**提交类型**（Git commit 注释；规范与用法见 `references/git-conventions.md` §3）：

| 类型 | 含义 |
| --- | --- |
| `feat` | 新增功能 |
| `fix` | 修复 bug |
| `refactor` | 代码重构，功能不变 |
| `docs` | 更新文档注释 |

> ⚠️ 本表**刻意用反引号**而非加粗：`_p_tiers` 只认 `| **小写词** |`，此处若用加粗会把
> feat/fix/refactor/docs 并进**模型档位**集合 → 假 FAIL（两表在同一个文件里，判据必须正交）。
> ⚠️ 扩展类型（chore/perf/test 等）须**先经用户确认**，再同步三处：本表 →
> `scripts/checks_core.py` 的 `VALID_COMMIT_TYPES` → `scripts/git_check.py` 的 `COMMIT_TYPES`。

**作业模式**（homework-judge 的模式选用；契约与判据见 `references/homework-judge.md`。
⚠️ 它是**「模式选用」枚举**，与**主类**三态是**两个物理量** —— 字形相近但语义无关，不得合并、不得互推）：

| 模式 | 含义 |
| --- | --- |
| **作业题** | 含题干结构（已知/求/证明/计算/设计/论述或题号小问）且要答案与过程 → **叠加作业模式**，按 H1–H5 组织 |
| **讲解题** | 要求讲解概念、原理或答疑，不针对具体题目求解 → 不叠加；可借用 H2／H4 结构 |
| **非作业** | 生成练习题/题库、普通工程文档任务、闲聊 → 不叠加，按宿主模式处理 |

**任务分层**（映射，非独立常量，源自 `category` + 复杂度）：

| 层级 | 判据 | 执行方式 |
| --- | --- | --- |
| L0 | 纯问答 / 查询 / 翻译 / 单文件读取 / 改一行 | 直接做，不建任务目录、不走阶段 0–6 |
| L1 | 命中 `assets/templates/` 同类模板且无实质差异 | 快速通道（引用模板缓存的查重结论） |
| L2 | 产出文件 / 代码 / 报告、多步、数据分析、跨文件改造、方案评审 | 完整走阶段 0–6 |

## 三、诚实边界

沿用本技能一贯的「诚实边界」风格：

1. **本文件是镜像，不是源** —— 取值单一源是 `scripts/checks.py` 常量。本文件的表由口径守卫保证不漂移（漂移即 FAIL），但**它本身不产生规则**；删掉本文件只会让守卫少一个镜像源，不会改变任何行为。
2. **散文重述仍不可机器全守卫** —— `SKILL.md` 与部分 `assets/` 文档中仍存在**散文式**枚举重述（如能力四类名、档位名）。把「从任意 markdown 句子/表格里稳定提取枚举」当前提已被本技能前四轮实践证明不成立（见 `references/self-judge.md` §1 记的 14 种假绿），故这类散文重述**只靠人审**，不纳入门禁。**不得宣称本文件覆盖了全部重述。**
3. **结构 schema 是描述，不是强制** —— §一 的字段表由 `checks.py` 的常量与检查项锚定，但「某字段业务上为何必填」属领域语义，不在本文件建模范围内。
4. **平台门控 / 常量守卫不覆盖本文件** —— `guard_constants.py` 只校验 `scripts/` 下**跨文件同名**常量（实测本模型各枚举**无跨脚本重复**，故其 GROUPS 未因此新增登记）；本文件的同源由**口径守卫**（`checks.py skill`）承担，二者分工不同，不可互代。

  - ⚠️ **实测订正（诚实登记）**：动手前的实测表明枚举的**代码侧单一源**（`checks.py`）与**部分文档↔代码守卫**（`PARITY_ITEMS` 7 项 + 主类声明块）**已存在**，并非从零缺失；本文件的增量是「**中心结构 schema** + **把镜像集中到一处并纳入守卫**」，不是「新造单一源」。

- **v2（2026-09-23，v4.7.0）**：登记第 9 个受守卫枚举「**作业模式**」—— 随 `homework-judge`（模式选用快判）新增，源规格为 **3 处**（`references/homework-judge.md` §1 的模式表 + `scripts/judges.json` 的 `homework_judge.mode.criteria` + 本文件 §2.2 镜像），由口径守卫「作业模式」项并集比对。
  - ⚠️ **必须写死的分界**：作业模式三态（作业题／讲解题／非作业）是**「模式选用」枚举**，与**主类**三态是两个**不同物理量** —— 前者答"要不要叠加作业模式"，后者答"这次产出什么"。二者**不得合并、不得互相推导**（合并会造成两套口径同形异义，正是本文件要防的那类漂移）。
  - ⚠️ **解析器为什么锚定表头**：`| **中文加粗** |` 在本文件里**不唯一**（档位表、能力表、熔断表、关系表皆用加粗首格），沿用"全文件扫格式"会把这些表并进作业模式集合 → 假 FAIL（v4.6.0「提交类型」首版即此坑）。故取结构性锚定（表头 `| 模式 | 含义 |` 唯一）。
  - ⚠️ **格式即锚点**：§2.2 各表的**列格式**被 `_p_tiers / _p_status / _p_caps / _p_triggers / _p_fuse / _p_reflect_trigger / _p_reflect_term` 解析，改表形须同步改这些解析器（或退出本文件的源规格）。
