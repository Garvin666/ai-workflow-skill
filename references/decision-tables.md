# 决策模型（ai-workflow 决策表集中映射）

> **定位**：把散落在 `capability-routing.md` / `adaptive-planning.md` / `method-judge.md` / `reflection-retry.md` 四份手册里的「**输入 → 输出映射 + 阈值**」抽成**决策表集中映射**——一份可查、可抽样人审对照的契约中心。它与 `self-judge`（入口级判定契约）同构，是「步骤级 / 计划级」的判定契约。
> **版本**：1（2026-09-21，P1-1 新增）
>
> ⚠️ **权威源声明（必读）**：
> 1. **枚举取值单一源 = `scripts/checks.py` 常量**；取值的受守卫镜像 = `references/data-model.md` §2.2（已并入 `checks.py skill` 口径守卫）。本文件**不重述取值**，只引用——改一枚举取值走 `data-model.md` 的「固定动作」（改常量 → 改全部文档源 → 跑 `checks.py skill`）。
> 2. 本文件描述「**决策契约**（条件 → 决策 → 触发者 → 守卫）」，**不是取值源、不是权重**。它回答「给定输入，决策是什么」，**不回答**「模型如何得出打分」（那是 realization，见 §十）。
> 3. 各表的取值（R1–R6 / T1–T3 / M1–M5 / 四类能力 / 终止策略）均与源手册逐一对应；本文件**不新增任何取值**，只做集中映射。

## 一、能力路由决策表（四类能力的「该用 / 不该用」判据）

> 来源：`capability-routing.md` §一（四类能力与判据）＋ §二（决策三步）。**取值源**：`VALID_CAPABILITY`，镜像见 `data-model.md` §2.2「能力类」。

| 缺口类型 | 手段 | ✅ 该用的判据 | ❌ 不该用的判据 | 机检 |
| --- | --- | --- | --- | --- |
| ① **知识** | 加载其它 skill | 任务需专门方法论 / 领域流程，且本地或市场确有匹配技能 | 技能只是"看起来沾边"；或它教的正是本技能已定义过的东西 | 取值（类别）机检；**判据靠人审** |
| ② **算力（隔离）** | 派子代理 | 子任务独立、可并行、高噪音只读、或需未参与者独立视角 | 子任务间有依赖；任务琐碎；开销大于收益 | 同上 |
| ③ **事实（外部）** | 联网检索 | 需本机推不出的当世事实（版本 / 价格 / star / 许可证 / 在职者） | 工作区内已有产物 / 台账 / 日志（用 `Grep`/`Read` 就够） | 同上 |
| ④ **手脚（执行）** | `scripts/` / 本地工具 / MCP | 需确定性计算 / 结构解析 / 批量产出 / 探活 | 需语义判断的场合（塞进脚本 = 假确定性） | 同上 |

**决策三步（引入任何能力前走一遍）**：

```
① 识别缺口：这一步缺的是 知识/算力/事实/手脚 哪一类？说不清 → 不引入或先想清
② 估收益：引入带来什么可验证改善（更准/更全/更快/更省）？说不出 → 不引入
③ 估开销：上下文/轮次/成本/失败面？收益 ≤ 开销 → 不引入
→ 通过：写声明 + 一条决策记录（格式见 adaptive-planning.md §三）
```

> ⚠️ **判据不是检查清单**：走到 ③ 判定"不引入"是完全正常的结论，且**不需留痕**（留痕只针对实际引入能力的动作）。硬规则：语义判断不外包脚本、确定性判断不外包肉眼。

## 二、方法选用决策表（步骤级工具 / 方法快判）

> 来源：`method-judge.md` §3.1（维度 Schema）＋ §5（阈值路由）。**词汇源**：能力类取自 `capability-routing.md` §一（见 §一，不另造）。

### 2.1 判定维度 → 能力类映射（Schema-First：先定维度，再判定）

| 维度 | 含义 | 原语 | 高分指向 |
| --- | --- | --- | --- |
| **M1 确定性需求** | 能否由脚本 / 工具确定性完成 | Score | 手脚 / 事实 |
| **M2 语义需求** | 是否需语义理解 / 领域判断 | Score | 知识 / 算力 / 人工 |
| **M3 时效 / 外部性** | 是否需当世事实 / 外部数据 | Score | 事实 |
| **M4 独立性 / 并行性** | 子任务是否独立、可并行、需独立视角 | Score | 算力 |
| **M5 本机可得性** | 所需事实 / 工具工作区内是否已有 | Score | **高分 = 不联网**（反向指针） |

> M1–M4 是语义维度（定能力类），M5 是效率指针（只校正，呼应「只读先于写入、本地先于联网」）。

### 2.2 阈值路由（confidence → 行为）

| 区间 | 行为 | route_hint | 机检 |
| --- | --- | --- | --- |
| `needs_tool=false` | **不引入、inline 做**；不写决策记录 | inline 执行 | 结构（缺省 WARN，非 FAIL） |
| `needs_tool=true` 且 `confidence ≥ 0.95` | **自动选用** top candidate | 选用 `<tool>` | 同上 |
| `0.70 ≤ confidence < 0.95` | **中置信**：选 top 但标记待复核 / 单句确认 | 选用 `<tool>`（待复核） | 同上 |
| `confidence < 0.70` **或** 候选 fit 差距极小（歧义） | **fail-closed**：澄清一句 / 选最安全默认 | 澄清 | 同上 |

> ⚠️ **校准优先于准确率**：自动采信阈值取保守值 0.95；低置信档取「澄清 / 最安全默认」，不猜。详见 §十一诚实边界。

## 三、自适应重规划决策表（R1–R6）

> 来源：`adaptive-planning.md` §2.1（触发条件）＋ §2.2（不触发）。**取值源**：`VALID_TRIGGER`，镜像见 `data-model.md` §2.2「重规划触发」。

| 触发 | 条件 | 典型场景 | 是否重规划 |
| --- | --- | --- | --- |
| **R1** | 新事实推翻原假设 | 许可证不兼容；字段与预期不符；star 证项目停更 | ✅ 必须（先留痕再改） |
| **R2** | 验证信号不可达 | 依赖缺失 / 环境不支持 → **换判定方式，非放弃判定** | ✅ 必须 |
| **R3** | 中间产出暴露未预见依赖 | 出现新前置（"先拿凭据才能继续"） | ✅ 必须 |
| **R4** | 成本超阈 | 某步开销远超预估（检索配额耗尽＝熔断 F5 前置） | ✅ 必须 |
| **R5** | 用户中途改需求 | 验收标准 / 交付物形态变化 | ✅ 必须 |
| **R6** | 连续性断裂 | 会话中断 / 上下文丢失后重启 | ✅ 必须 |

**不触发重规划（防过度重规划）**：单次工具报错（未耗尽重试）／进度慢但路径正确／"更优雅写法"但路径仍可达／用户的**澄清**而非**变更**。

> **判据一句话**：改的是「路径」还是「目标 / 事实基础」？只改路径且新路径不更可靠 → 不重规划。重规划四步固定次序：①停 ②记（追加 `meta.计划修订`）③改（已完成步骤原记录保留不覆写）④报。同一任务重规划 **≤3 次**（超 3 次 → 停下来与用户对齐，非熔断）。

## 四、反思重试触发决策表（T1–T3）

> 来源：`reflection-retry.md` §2（触发条件）。**取值源**：`VALID_REFLECT_TRIGGER`，镜像见 `data-model.md` §2.2「反思触发」。

| 触发 | 条件 | 可判定信号（须有证据） | 是否触发重试 |
| --- | --- | --- | --- |
| **T1** | 验证信号未通过 | 本步「验证方式」返回非预期，以**原始输出**为证（失败栈 / 对账差额 / 探活非 2xx） | ✅ |
| **T2** | 结果不满足预期 | 产出存在，但对照验收标准有**可量化偏差**（"要求 ≥95% 实测 91%"） | ✅ |
| **T3** | 校验失败 | CI / 对账 / 链接探活 / 编译 **非 0** | ✅ |

**不触发（防误重试）**：R1–R6 重规划（目标/事实变更非重试能解）／ F3 证据不可得 / F4 越界 / F5 配额硬阻断（环境类硬失败，直接熔断）／ 红线③（越界重试无意义）／ 单次工具报错未耗尽重试。

> ⚠️ **三计数器正交**：重试次数（`attempt`）≠ 返修复查轮次（≤2）≠ 重规划次数（≤3）。记录时显式区分（见 `reflection-retry.md` §6 计数纪律）。

> 来源：`reflection-retry.md` §4（终止策略）。**取值源**：`VALID_TERMINATION`，镜像见 `data-model.md` §2.2「终止策略」。唯一取值源，被 `checks.py` 口径守卫锁定。

| 取值 | 含义 | 适用场景 | 机检 |
| --- | --- | --- | --- |
| **升级返修复查**（默认，推荐） | 把"已重试 N 轮 + 末轮反思"作返修复查问题清单起点 | 大多数场景 | 取值机检 |

## 六、检索快判决策表（检索级源选用）

> 来源：`retrieval-judge.md` §3.1（维度 Schema）＋ §5（阈值路由）＋ §5.1（否定断言证据门槛）。**词汇源**：源类五类定义在 `retrieval-judge.md` §1，**本节不重述**（沿用 P1「决策表只做映射、不重述枚举」原则）。

### 6.1 判定维度 → 源类映射（Schema-First：先定维度，再判定）

| 维度 | 含义 | 高分指向 |
| --- | --- | --- |
| R1 信息缺口 | 既有知识 + 当前上下文是否已足够 | 缺口大 → 必须检索 |
| R2 本机可得性 | 所需信息工作区内是否已有 | 本地资产（**反向指针**：高分＝不必联网） |
| R3 留痕可复用性 | 是否已有同类任务的结论 / 踩坑 | 历史留痕 |
| R4 外部时效性 | 是否依赖当世事实 | 联网 |
| R5 候选池纯净度 | 目标源内噪声占比 | **校正指针**（反向：低分＝先清洗候选池） |

### 6.2 阈值路由（confidence → 行为）

| 区间 | 行为 |
| --- | --- |
| `needs_retrieval=false` 且 `confidence ≥ 0.95` | 不检索、直接做；允许下否定断言（限上下文已完整覆盖） |
| `needs_retrieval=true` 且 `confidence ≥ 0.95` | 自动检索 top candidate（fit_score 最高者） |
| `0.70 ≤ confidence < 0.95` | 检索后**实读结果**再采信；不得仅凭 fit_score 断言；标记待复核 |
| `confidence < 0.70` 或候选间 fit_score 极近 | fail-closed：问一句澄清，或**只报「未检索」** |

### 6.3 否定断言证据门槛（本模块特有）

| 情形 | 允许的表述 | 禁止的表述 |
| --- | --- | --- |
| 已检索且**出示 0 命中原始输出** | 「已检索 <源类清单>，0 命中」→ 可断言不存在 | — |
| 未检索 / 只做了部分检索 | 「**未检索**，无法判定」 | ~~「不存在」「没有」「未使用」~~ |
| 检索了但源类未覆盖全部五类 | 「在 A/B 内 0 命中；C/D/E **未检索**」 | ~~笼统的「查过了，没有」~~ |

> ⚠️ **与「二、方法选用」低置信档的差别**：方法选用低置信时"退回最保守手段"即可（手段是自选的）；检索低置信时**不能**用"换个源再猜一次"掩盖 —— **信息缺口不会因为换个源就消失**，只能如实报"未检索"（`retrieval-judge.md` §5.1）。

## 七、模式选用决策表（结构级：要不要叠加作业模式）

> 来源：`references/homework-judge.md` §1（mode 三态）＋ §3.1（W1–W5 维度）＋ §5（阈值路由）。**取值源**：`HOMEWORK_MODES`，镜像见 `data-model.md` §2.2「作业模式」。**判据语义源**是 `references/homework-mode.md` §2（C1–C3）—— 本表沿用 P1 原则，只做「判据 → 决策 → 触发者 → 守卫」的集中映射，**不重述判据定义、不新增取值**。

### 7.1 判定维度 → 模式映射（Schema-First：先定维度，再判定）

| 维度 | 含义 | 原语 | 高分指向 |
| --- | --- | --- | --- |
| **W1 题干结构度** | 是否含明确题意结构（已知条件 / 所求 / 条件限制 / 小问编号） | Score | 作业题 |
| **W2 期望形态** | 期望「答案与过程」，还是「交付物 / 系统」 | Score | 作业题 |
| **W3 语境线索** | 教材 / 章节 / 作业 / 复习 / 考试这类学习语境的强度 | Score | 作业题 / 讲解题 |
| **W4 受评压力** | 是否处于考试、测验或限时评价场景 | Score | 作业题（**并触发手册 I4 的诚信提示**） |
| **W5 结构收益** | 按 H1–H5 完整结构作答相比直接回答的增益 | Score | **反向指针**：低分 = 直接答即可（**效率闸门**） |

> **W5 是效率闸门**（阻止"所有题都套五阶段"）；**W4 只驱动附加提示**，**不裁定是否该帮**（诚信边界见 `homework-judge.md` §10）。

### 7.2 阈值路由（confidence → 行为）

| 区间 | 行为 | route_hint |
| --- | --- | --- |
| 主模式 `confidence ≥ 0.95` | **自动采信**，按对应 `route_hint` 执行 | 见下表 |
| `0.70 ≤ confidence < 0.95` | **中置信**：按主模式**轻量起步**（结构从简）并标记待复核 | 同主模式（压缩档） |
| `confidence < 0.70` **或** `ambiguity = true` | **fail-closed**：返回一句澄清，**不猜测、不默认** | 澄清 |

| 模式 | route_hint |
| --- | --- |
| **作业题** | 叠加作业模式：按 H1→H5 组织；题型骨架见 `references/homework-mode.md` §4 |
| **讲解题** | 不叠加；按讲解组织，可借 H2／H4，不必走全五阶段 |
| **非作业** | 不叠加；按宿主模式（`self-judge` 的 category 与来源分型）正常处理 |

### 7.3 与相邻情形的分界

| 项 | 说明 |
| --- | --- |
| **相邻情形表** | `references/homework-mode.md` §2（生成题库属学习资料类；「代码为什么报错」属 Bug 入口；「答案是不是这个」属校核型）—— **本表不复制** |
| **边界判例锚** | `references/homework-judge.md` §9（8 条判例，供抽样人审对照） |
| **组合态** | `mode` 允许 `A+B`（top2 差 < `combine_mode_delta` = 0.15）；**刻意不设 `secondary`**（模式本就允许并用，与 `self-judge` 互斥主类不同） |
| **与主类不可互推** | `mode` 与 `self-judge` 的 `category` 是**两个物理量**；**不得用 `category` 反推 `mode`**（见 §十一第 7 条） |

### 7.4 机检

| 检查 | 载体 | 强度 |
| --- | --- | --- |
| 结构校验（7 项必填、落 `meta.作业判定`） | `checks.py plan` 检查项 18 | 缺省 **WARN**（不追认历史计划）；填写则结构非法即 FAIL（含 `needs_homework` 与 `mode` 矛盾 → FAIL） |
| 抽样人审指路（组合态 / `confidence < 0.95` / `ambiguity`） | `checks.py plan` 检查项 19 | 只 **WARN**，不改退出码 |
| 模式枚举同源（手册 ↔ 模板 json ↔ 代码常量） | `checks.py skill` 口径守卫：作业模式 | 漂移即 **FAIL** |

## 八、学习信号判定决策表（经验级：这次有什么值得学）

> 来源：`learning-judge.md` §3.1（维度 Schema）＋ §5（阈值路由）。**取值源**：`LEARNING_KINDS`，镜像见 `data-model.md` §2.2「学习类型」。管线（K1–K5）见 `learning-model.md`。

### 8.1 判定维度 → 学习类型映射（Schema-First：先定维度，再判定）

| 维度 | 含义 | 原语 | 高分指向 |
| --- | --- | --- | --- |
| **V1 复现性** | 这条经验下次还会遇到吗 | Score | 值得学 |
| **V2 特征性** | 是使用者 / 本项目的特征，还是通用常识 | Score | 值得学（通用常识不占库位） |
| **V3 纠正强度** | 用户是否明示纠正或强调 | Score | 偏好（只提高证据权重，**不松动门槛**） |
| **V4 缺口度** | 当前知识库未覆盖的程度 | Score | 值得学 |
| **V5 稳定性** | 一个月后还成立吗 | Score | 长期知识（低分 → 记工作区 memory 而非 KB） |

### 8.2 阈值路由（confidence → 行为）

| 区间 | 行为 |
| --- | --- |
| `confidence ≥ 0.95` | 自动采信 → 进 K2 抽取 |
| `0.70 ≤ confidence < 0.95` | 进 K2 但标 `观察`（即便过门槛也**不自动入库**） |
| `confidence < 0.70` **或** `ambiguity = true` | **fail-closed：不进池 / 留池观察，不向用户追问** |
| 真正入库 | 另需过 `kb_learn.py` 的**六条门槛**，且**状态未冻结**（两段式：高置信自动入、其余留候选）—— 状态级路由见 §8.3 |

> ⚠️ **fail-closed 的动作与另四块刻意不同**（`hold` vs `clarify`）：这里"不动"而不是"追问" ——
> 写错长期知识的代价不对称（**漏记可补、错记难清**），且收尾阶段追问会把收尾变成一次交互（效率项）。
> ⚠️ **`confidence` 是「分布集中度」，不是「值得学的程度」** —— 判『无』判得**准**同样给出高置信，
> 两者不可混读（`learning-judge.md` §5.1 已把这条列为显式陷阱，并记了它引发的一次断言写错）。

### 8.3 知识生命周期状态路由（**池条目状态，不是 `kind`** —— P0，2026-09-25 补）

> ⚠️ **这一节与上面两节的物理量不同**：`kind` 回答「这属于哪类知识」，`state` 回答「**这条知识现在能不能动**」。
> 二者**不得混写进同一张表**（把两根轴压成一根是本技能明令禁止的写法）。

| 池状态 `state` | 由谁置入 | `commit` 时的去向 | 解除方式（**只在用户**） |
| --- | --- | --- | --- |
| `观察` | 默认态 | 过六条门槛 → `入库`；否则留池 | — |
| `冲突` | `note --contradicts <text\|key>`（**双向冻结**双方） | **冻结：门槛结果不生效，永不入库** | 用户裁决后人工解除 |
| `待废止` | `commit` 生成废止提案时 | **不写 KB、不改旧文档**，等放行 | `retire --approve <id> --apply` 放行 / `--reject <id>` 驳回 |
| `已废止` | 上一步放行后 | **终态，永不再写回 KB**（否则废止会被下次 `commit` 自动撤销） | 人工（KB 侧只加标记，未删除） |
| `已入库` | `commit --apply` **写库成功后** | 已在 KB（`category=学习-*`）；再 commit 走 `update`（幂等） | 人工（`retire` 放行后“只加标记不删除”） |

> ⚠️ **共同原则**：**新增/更新可自动（按置信度），冻结与废止只提案（按危险度）** —— 即"**按危险度分级，而非只按置信度**"。
> ⚠️ **dry-run 不改池状态**：`commit` 不加 `--apply` 时池状态**原地不动**（仍为 `观察`）、也**不发 `kb_id`** —— 报告用 `state_before` / `state_after` 区分「判定通过」与「已落实」。**没做的事不得记成做了**（曾实测：一次 dry-run 就把 7 条标成 `已入库` 并发了假 `learn-*` id）。
> ⚠️ **守卫的边界**：本节的状态取值**没有**口径守卫（它不进 plan、不是受保护枚举），是**代码内常量**（`KB_CONFLICT_STATE` 等）；`selftest` 只保证行为不自相矛盾，**不保证模型把该冻的冻了**。

### 9.1 派生规则决策表（`verdict` ＝ Δ（`veto` / `ambiguity` / `confidence` / `amendments`）；**按序短路**）

| 输入条件（按序短路） | 裁决 | 处置 | 判据（机检） |
| --- | --- | --- | --- |
| ① `veto.triggered == true` | **拒绝** | 停止 + 说明命中轴 + 替代方向 + 申诉指引；**不计熔断、不入学习池** | D1（triggered→拒绝）/ D2（拒绝→triggered）|
| ② `veto.suspect == true` | **澄清** | 不得放行；返回**一句**澄清问题 | D17（`suspect` 缺失 / 非布尔 → FAIL；否则中间带静默放行）|

## 十一、诚实边界

沿用本技能一贯的「诚实边界」风格（与 `self-judge.md` §10 / `method-judge.md` §10 同构）：

1. **本文件是映射，不是源** —— 取值单一源是 `scripts/checks.py` 常量；本文件由口径守卫保证与源一致（漂移即 FAIL），但**本身不产生规则**。删掉本文件只会让守卫少一个镜像源，不改任何行为。
2. **决策模型描述契约，不描述 realization** —— M1–M5 打分、confidence 由主代理 LLM（Realization A 脑内协议）在动手前单次前向产出，**无独立训练、无单独权重**；本文件不承诺"判定已校准"（见下条）。
3. **校准不可机器强制** —— `confidence` 由模型自填，**无法被工具证明"真的校准"**。`checks.py plan` 检查项 14 对 `meta.方法选用` 整段缺省只 WARN、填了才校验结构（缺省 = 向后兼容，**不追认历史计划**）。**不得宣称该字段是强制门禁。**
4. **类型合法 ≠ 判断正确** —— 本文件保证输出落在已知类别/取值内（零类型错误），**不保证选对**。把"格式合规"误读成"结论可信"正是 `checks.py plan` 第 11 项曾三次被误读成绿的同一种根因。
5. **判错比不判更危险** —— 故低置信一律降级到"澄清 / 最安全默认"（fail-closed），自动采信阈值取保守值 0.95。
6. **不替代安全关键门禁** —— 红线③越界判定（`_check_scope`）、出站扫描、口径守卫、自研工具漏登记检测保留 AST/代码实现；本文件仅作辅助信号与可查契约。
7. **两套三态枚举不得合并（§七 专属，模式选用）** —— `mode`（作业题／讲解题／非作业）是**结构级「模式选用」**枚举，`self-judge` 的 `category` 是**入口级「产出什么」**枚举：**字形相近、语义无关**。不得用 `category` 反推 `mode`，也不得为省一张表把两者并成一枚枚举。⚠️ **守卫的边界**：口径守卫：作业模式只保证「三源取值一致」，**不保证二者不被合并** —— 防合并靠本文件与 `homework-judge.md` §1 的显式声明 + 人审，**不得宣称已有机器判据拦截合并**。
8. **六套判定枚举两两不得合并（§八 专属，学习类型）** —— `kind`（偏好／领域知识／流程坑／事实／无）是**经验级「学习类型」**枚举，与主类三态（产出什么）、模式三态（要不要按作业结构答）、能力四态（缺哪类能力）、源类五态（检索该查哪类源）、裁决四态（该不该按原样做）**都是不同的物理量**。六者各盯一根轴，**不得互相推导**（如用 `category` 推 `kind`、用 `mode` 推 `kind`、用 `verdict` 推 `kind` 均属禁止）。⚠️ **守卫的边界同上**：口径守卫：学习类型只保证「三源取值一致」，**不保证不被合并**；防合并靠本文件与 `learning-judge.md` §1 的显式声明 + 人审，**不得宣称已有机器判据拦截合并**。
9. **学习模块的"学到的东西是对的"没有机器判据** —— 门槛只保证「同一条重复出现足够多次」，**不保证它正确**；反复出现的偏见会被学成"偏好"。这是该模块的**结构性风险**，只由 §八 的两段式（高置信自动、其余人工）与定期复查缓解。**不得宣称"已自动保证学习质量"。**
10. **学习模块的两处「有保护但不满」照实登记（P0 后仍未闭环）** —— ① **池内去重仍是字面级**（`sha1(normalize(text))`）：同义改写（「别加 emoji」／「不要用表情符号」）各自成条，会**稀释证据计数**，使同一偏好换个措辞就各自够不到 `偏好 ≥2` 门槛（属 P1，**本版未做**）；② **废止不阻止检索命中**：放行后文档仍是普通文档，`kb.py retrieve` **不会**自动排除，读取侧只靠「正文首行 `⚠️ 已废止` 自我标识 + 约定」，**无机器强制**。**不得**宣称"废止后就不会被检索到"，也不得宣称"去重已语义化"。
