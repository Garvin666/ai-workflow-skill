# 决策模型（ai-workflow 决策表集中映射）

> **定位**：把散落在 `capability-routing.md` / `adaptive-planning.md` / `method-judge.md` / `reflection-retry.md` 四份手册里的「**输入 → 输出映射 + 阈值**」抽成**决策表集中映射**——一份可查、可抽样人审对照的契约中心。它与 `self-judge`（入口级判定契约）同构，是「步骤级 / 计划级」的判定契约。
> **版本**：1（2026-09-21，P1-1 新增）
>
> ⚠️ **权威源声明（必读）**：
> 1. **枚举取值单一源 = `scripts/checks.py` 常量**；取值的受守卫镜像 = `references/data-model.md` §2.2（已并入 `checks.py skill` 口径守卫）。本文件**不重述取值**，只引用——改一枚举取值走 `data-model.md` 的「固定动作」（改常量 → 改全部文档源 → 跑 `checks.py skill`）。
> 2. 本文件描述「**决策契约**（条件 → 决策 → 触发者 → 守卫）」，**不是取值源、不是权重**。它回答「给定输入，决策是什么」，**不回答**「模型如何得出打分」（那是 realization，见 §七）。
> 3. 各表的取值（R1–R6 / T1–T3 / M1–M5 / 四类能力 / 终止策略）均与源手册逐一对应；本文件**不新增任何取值**，只做集中映射。

## 一、能力路由决策表（四类能力的「该用 / 不该用」判据）

> 来源：`capability-routing.md` §一（四类能力与判据）＋ §二（决策三步）。**取值源**：`VALID_CAPABILITY`，镜像见 `data-model.md` §2.2「能力类」。

| 缺口类型 | 手段 | ✅ 该用的判据 | ❌ 不该用的判据 | 机检 |
| --- | --- | --- | --- | --- |
| ① **知识** | 加载其它 skill | 任务需专门方法论 / 领域流程，且本地或市场确有匹配技能 | 技能只是"看起来沾边"；或它教的正是本技能已定义过的东西 | 取值（类别）机检；**判据靠人审** |
| ② **算力（隔离）** | 派子代理 | 子任务独立、可并行、高噪音只读、或需未参与者独立视角 | 子任务间有依赖；任务琐碎；开销大于收益 | 同上 |
| ③ **事实（外部）** | 联网检索 | 需本机推不出的当世事实（版本 / 价格 / star / 许可证 / 在职者） | 工作区内已有产物 / 台账 / 日志（用 `Grep`/`Read` 就够） | 同上 |
| ④ **手脚（执行）** | `scripts/` / 本地工具 / MCP | 需确定性计算 / 结构解析 / 批量产出 / 探活 | 需语义判断的场合（塞进脚本 = 假确定性） | 同上 |

**决策三步（引入任何能力前走一遍）**：

```
① 识别缺口：这一步缺的是 知识/算力/事实/手脚 哪一类？说不清 → 不引入或先想清
② 估收益：引入带来什么可验证改善（更准/更全/更快/更省）？说不出 → 不引入
③ 估开销：上下文/轮次/成本/失败面？收益 ≤ 开销 → 不引入
→ 通过：写声明 + 一条决策记录（格式见 adaptive-planning.md §三）
```

> ⚠️ **判据不是检查清单**：走到 ③ 判定"不引入"是完全正常的结论，且**不需留痕**（留痕只针对实际引入能力的动作）。硬规则：语义判断不外包脚本、确定性判断不外包肉眼。

## 二、方法选用决策表（步骤级工具 / 方法快判）

> 来源：`method-judge.md` §3.1（维度 Schema）＋ §5（阈值路由）。**词汇源**：能力类取自 `capability-routing.md` §一（见 §一，不另造）。

### 2.1 判定维度 → 能力类映射（Schema-First：先定维度，再判定）

| 维度 | 含义 | 原语 | 高分指向 |
| --- | --- | --- | --- |
| **M1 确定性需求** | 能否由脚本 / 工具确定性完成 | Score | 手脚 / 事实 |
| **M2 语义需求** | 是否需语义理解 / 领域判断 | Score | 知识 / 算力 / 人工 |
| **M3 时效 / 外部性** | 是否需当世事实 / 外部数据 | Score | 事实 |
| **M4 独立性 / 并行性** | 子任务是否独立、可并行、需独立视角 | Score | 算力 |
| **M5 本机可得性** | 所需事实 / 工具工作区内是否已有 | Score | **高分 = 不联网**（反向指针） |

> M1–M4 是语义维度（定能力类），M5 是效率指针（只校正，呼应「只读先于写入、本地先于联网」）。

### 2.2 阈值路由（confidence → 行为）

| 区间 | 行为 | route_hint | 机检 |
| --- | --- | --- | --- |
| `needs_tool=false` | **不引入、inline 做**；不写决策记录 | inline 执行 | 结构（缺省 WARN，非 FAIL） |
| `needs_tool=true` 且 `confidence ≥ 0.95` | **自动选用** top candidate | 选用 `<tool>` | 同上 |
| `0.70 ≤ confidence < 0.95` | **中置信**：选 top 但标记待复核 / 单句确认 | 选用 `<tool>`（待复核） | 同上 |
| `confidence < 0.70` **或** 候选 fit 差距极小（歧义） | **fail-closed**：澄清一句 / 选最安全默认 | 澄清 | 同上 |

> ⚠️ **校准优先于准确率**：自动采信阈值取保守值 0.95；低置信档取「澄清 / 最安全默认」，不猜。详见 §七诚实边界。

## 三、自适应重规划决策表（R1–R6）

> 来源：`adaptive-planning.md` §2.1（触发条件）＋ §2.2（不触发）。**取值源**：`VALID_TRIGGER`，镜像见 `data-model.md` §2.2「重规划触发」。

| 触发 | 条件 | 典型场景 | 是否重规划 |
| --- | --- | --- | --- |
| **R1** | 新事实推翻原假设 | 许可证不兼容；字段与预期不符；star 证项目停更 | ✅ 必须（先留痕再改） |
| **R2** | 验证信号不可达 | 依赖缺失 / 环境不支持 → **换判定方式，非放弃判定** | ✅ 必须 |
| **R3** | 中间产出暴露未预见依赖 | 出现新前置（"先拿凭据才能继续"） | ✅ 必须 |
| **R4** | 成本超阈 | 某步开销远超预估（检索配额耗尽＝熔断 F5 前置） | ✅ 必须 |
| **R5** | 用户中途改需求 | 验收标准 / 交付物形态变化 | ✅ 必须 |
| **R6** | 连续性断裂 | 会话中断 / 上下文丢失后重启 | ✅ 必须 |

**不触发重规划（防过度重规划）**：单次工具报错（未耗尽重试）／进度慢但路径正确／"更优雅写法"但路径仍可达／用户的**澄清**而非**变更**。

> **判据一句话**：改的是「路径」还是「目标 / 事实基础」？只改路径且新路径不更可靠 → 不重规划。重规划四步固定次序：①停 ②记（追加 `meta.计划修订`）③改（已完成步骤原记录保留不覆写）④报。同一任务重规划 **≤3 次**（超 3 次 → 停下来与用户对齐，非熔断）。

## 四、反思重试触发决策表（T1–T3）

> 来源：`reflection-retry.md` §2（触发条件）。**取值源**：`VALID_REFLECT_TRIGGER`，镜像见 `data-model.md` §2.2「反思触发」。

| 触发 | 条件 | 可判定信号（须有证据） | 是否触发重试 |
| --- | --- | --- | --- |
| **T1** | 验证信号未通过 | 本步「验证方式」返回非预期，以**原始输出**为证（失败栈 / 对账差额 / 探活非 2xx） | ✅ |
| **T2** | 结果不满足预期 | 产出存在，但对照验收标准有**可量化偏差**（"要求 ≥95% 实测 91%"） | ✅ |
| **T3** | 校验失败 | CI / 对账 / 链接探活 / 编译 **非 0** | ✅ |

**不触发（防误重试）**：R1–R6 重规划（目标/事实变更非重试能解）／ F3 证据不可得 / F4 越界 / F5 配额硬阻断（环境类硬失败，直接熔断）／ 红线③（越界重试无意义）／ 单次工具报错未耗尽重试。

> ⚠️ **三计数器正交**：重试次数（`attempt`）≠ 返修复查轮次（≤2）≠ 重规划次数（≤3）。记录时显式区分（见 `reflection-retry.md` §6 计数纪律）。

> 来源：`reflection-retry.md` §4（终止策略）。**取值源**：`VALID_TERMINATION`，镜像见 `data-model.md` §2.2「终止策略」。唯一取值源，被 `checks.py` 口径守卫锁定。

| 取值 | 含义 | 适用场景 | 机检 |
| --- | --- | --- | --- |
| **升级返修复查**（默认，推荐） | 把"已重试 N 轮 + 末轮反思"作返修复查问题清单起点 | 大多数场景 | 取值机检 |
| **触发熔断** | 直接走熔断 F1（停/冻/证/拦/报） | 该步不可逆或重试无意义 | 取值机检 |

## 七、诚实边界

沿用本技能一贯的「诚实边界」风格（与 `self-judge.md` §10 / `method-judge.md` §10 同构）：

1. **本文件是映射，不是源** —— 取值单一源是 `scripts/checks.py` 常量；本文件由口径守卫保证与源一致（漂移即 FAIL），但**本身不产生规则**。删掉本文件只会让守卫少一个镜像源，不改任何行为。
2. **决策模型描述契约，不描述 realization** —— M1–M5 打分、confidence 由主代理 LLM（Realization A 脑内协议）在动手前单次前向产出，**无独立训练、无单独权重**；本文件不承诺"判定已校准"（见下条）。
3. **校准不可机器强制** —— `confidence` 由模型自填，**无法被工具证明"真的校准"**。`checks.py plan` 检查项 14 对 `meta.方法选用` 整段缺省只 WARN、填了才校验结构（缺省 = 向后兼容，**不追认历史计划**）。**不得宣称该字段是强制门禁。**
4. **类型合法 ≠ 判断正确** —— 本文件保证输出落在已知类别/取值内（零类型错误），**不保证选对**。把"格式合规"误读成"结论可信"正是 `checks.py plan` 第 11 项曾三次被误读成绿的同一种根因。
5. **判错比不判更危险** —— 故低置信一律降级到"澄清 / 最安全默认"（fail-closed），自动采信阈值取保守值 0.95。
6. **不替代安全关键门禁** —— 红线③越界判定（`_check_scope`）、出站扫描、口径守卫、自研工具漏登记检测保留 AST/代码实现；本文件仅作辅助信号与可查契约。
