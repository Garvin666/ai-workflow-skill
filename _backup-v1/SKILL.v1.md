# AI 工作流

按以下 6 个阶段顺序执行任务。各阶段含硬性指令（"必须/禁止"），不得跳过或简化。

## 前置检查

首次使用或环境异常时，运行 `scripts/setup_env.ps1` 初始化 venv。调用任何 Python 脚本前，先确认：

| 检查项 | 就绪标准 | 未就绪处理 |
| --- | --- | --- |
| venv | `C:\Users\26717\.workbuddy\binaries\python\envs\ai-workflow\Scripts\python.exe` 存在 | 运行 setup_env.ps1 |
| 依赖 | requests / openpyxl / python-docx / pypdf 可 import | 运行 setup_env.ps1 |
| AI Key | 环境变量 AI_API_KEY 已设置（调 AI 时才需要） | 提示用户设置，或降级为主模型直接处理 |

脚本调用一律用 PowerShell `&` 运算符：`& "C:\Users\26717\.workbuddy\binaries\python\envs\ai-workflow\Scripts\python.exe" <脚本> <参数>`。

## 阶段 0：开工前查可用 Skill

**必须**在进入阶段 1 前完成 Skill 检索，并在回复中说明结果（有则列出，无则明确说明未找到）：

1. 检查本地已安装 skill：用户级 `~/.workbuddy/skills/` 与项目级 `.workbuddy/skills/` 清单。
2. 本地无匹配时，用 find-skills / 推荐市场搜索现成可装的 skill。
3. 判定：匹配 → 优先加载复用，不重复造轮子；部分匹配 → 复用可复用部分，差异点按本工作流执行；无匹配 → 按本工作流全新执行。
4. **快速通道**：查 `assets/templates/` 是否已有同类任务的确认表模板；有 → 向用户提议"按上次配置开跑"，用户确认后跳过阶段 1 的追问循环（配置有出入的点仍需逐条确认），并直接引用该模板已缓存的查重结论（无重大变化时免重复查重）。

## 阶段 1：任务理解（交互式追问循环）

**未获得用户确认前，禁止执行任何脚本或产出文件。**

1. 用澄清问题多轮追问，每轮 1-4 个问题，选择题优先并附推荐项；下一轮基于上一轮回答深挖。走阶段 0 快速通道的任务除外。
2. 追问直至五要素齐备：① 目标 ② 输入（文件/数据/来源）③ 交付物（格式/路径/命名）④ 验收标准 ⑤ 边界约束（禁做事项/依赖/时限）。
3. 五要素齐备后输出「任务确认表」（目标/输入/交付物/验收/约束五行），并在**同一轮消息**里请求放行——用户回复"确认/开干"即视为放行，**禁止再单独发起一轮确认提问**；用户提出纠正则修改后再次请求放行。
4. **模板沉淀**：确认通过后，将任务确认表存为 `assets/templates/<任务类型>.yaml`（命名用任务类型，如 `数据分析`、`选品分析`），供下次快速通道复用；同类型已存在则更新而非新建。

## 阶段 2：调研（开源查重优先）

**未完成开源查重并给出复用决策前，禁止进入实现环节。**

1. **查重按任务类型分流**：
   - 开发/建项目类 → 查重对象是开源项目与数据集：用 WebSearch + GitHub API（`https://api.github.com/repos/<owner>/<repo>` 批量循环查询，失败自动重试 1 次）检索是否已有可复用实现；英文关键词与中文关键词各搜一轮；产出「开源查重对比表」（项目/数据集名称、功能覆盖度、Star/活跃度、许可证、可复用部分、与本任务差距），并给出决策：直接复用 / 克隆改造 / 参考思路自研（三选一附理由），倾向克隆到本地精读。
   - 调研/报告类 → 查重对象是既有报告与横评文章：先检索是否已有同类调研（避免重复劳动、站在现成横评上做增量），GitHub API 仅作为 star/活跃度**数据源实测**，不作为查重对象；产出「既有资料盘点表」+ 数据实测记录。
2. **并行检索硬规则**：检索方向 ≥3 个时，必须并行派发子代理或并行发起多个独立检索调用，禁止主代理串行逐个等待（见阶段 3 编排规则）。
3. 查重结论并入任务确认表交用户确认后，再用 `scripts/http_fetch.py` 抓取所需数据/资料并落盘到任务目录。
4. **引入前安全与许可检查**：决定克隆/复用外部项目或安装其依赖前，核对许可证兼容性，并做基础安全检查（可疑混淆脚本、硬编码密钥、异常网络外联、维护者可信度）；有疑点先向用户说明再引入。

## 阶段 3：AI 处理（先计划、明步骤、精检索、编排与质检）

**未产出执行计划表前，禁止调用任何处理脚本；每步未明确目标前，禁止发起检索。**

1. **任务目录制**：开工时在工作区根目录建 `tasks/<任务类型>-<YYYY-MM-DD>/` 任务目录，`plan.yaml`、交付物、中间数据**统一落盘在该目录内**（plan.yaml 用 `assets/plan-template.yaml` 格式：步骤编号、做什么、输入、预期产出、验证方式、状态）。禁止把 plan.yaml 或交付物直接散落在工作区根目录，避免多任务相互覆盖。执行中实时更新状态；任务中断可凭该文件断点续做。
2. 逐步执行：每步开始前重述目标与判定标准，完成后核对预期产出是否达成并更新 plan.yaml 状态（待办/进行中/完成）；未达成先修正再推进。
3. 精确检索：按每步实际需要定向检索——精确关键词、按需读片段、先索引/摘要后原文，禁止整库加载或无目的浏览；引用标明来源文件/URL。
4. **Token 纪律（省 token 与精简对话，依据《调研-token优化与对话精简-2026-09-10》）**：
   - **缓存优先**：prompt/调用结构做到稳定前缀在前、动态内容在后；DeepSeek 调用保持前缀一致吃磁盘 KV 缓存（命中 98% 折扣），Anthropic 调用对稳定块加 `cache_control`；多轮任务复用同一系统提示词，禁止每次改写前缀。
   - **上下文分层**：长对话/长任务上下文按热（近 10 轮原文）/温（滚动摘要）/冷（目标级摘要）三层管理；每层压缩控制在 40-60%，**禁止压到 90%+**（会导致重新取数，总成本反升）。
   - **按需加载**：记忆/资料只取索引与摘要，命中后再读片段原文（同第 3 条）；历史任务先读 plan.yaml 断点，不重跑已完成步骤。
   - **选型黑名单**：RouteLLM、GPTCache、Memobase 已停更，只参考思路不引入为依赖；LiteLLM 必须 ≥1.83.7（历史版本有在野 CVE 与供应链投毒事件）。
5. 需要调用外部模型做批量总结/生成时用 `scripts/ai_call.py`，调用侧同步遵守第 4 条 Token 纪律；项目差异化流程（量化/选品/小说/学习资料）查 `references/playbook.md`。

### 子智能体编排

- 独立可并行的子任务并行派发多个子代理；探索用 Explore、方案设计用 Plan、写码执行用通用代理。
- 主代理负责拆分任务、汇总结果；可委派的重复性工作不亲自做。
- **Handoff 结构化交接**：派发给子代理的提示必须包含以下字段，不得用自由文本——`task`（做什么）、`background`（项目背景与约束）、`input_paths`（输入文件绝对路径）、`acceptance`（验收标准）、`deliverable_path`（交付物落盘路径）。

### 质量把关（信任但验证）

- **子代理产出未经主代理核实（查真实文件/输出），不得进入下一环节。**
- 关键产出对照任务确认表的验收标准逐项核对；不合格带具体问题退回重做（最多 2 轮）。
- **对抗式互审**：2 轮退回仍不合格时，停止单线返工，改派两个子代理分别独立审查该产出并互相质证，主代理汇总裁决；仍不合格才升级向用户说明。
- 交付前终审：数据完整性、格式正确性、编码正确、与需求一致。

## 阶段 4：Office 产出

1. 用 `scripts/office_io.py` 生成 Excel/Word/PDF，报告结构参照 `assets/report-template.md`。
2. 写文件统一 `utf-8-sig` 编码；Word 中文内容指定中文字体。
3. 产出前先列出将写入的文件路径清单；生成库的用法与坑见 `references/office-guide.md`。

## 阶段 5：自检交付

1. **Anti-drop guard（计划-交付对账）**：核对 plan.yaml 中每个步骤都有对应的实际交付物或明确结论，步骤数与交付数一致；发现遗漏步骤先补齐再交付，禁止静默跳过。
2. 逐项核对自检清单并输出状态表：文件存在、可正常打开、编码正确、数据完整、符合验收标准。
3. 全部通过后用 present_files 交付；任何一项不通过，回到对应阶段修复后重新自检。
4. 交付说明保持简洁：结论 + 关键文件 + 下一步建议。

## 脚本速查

| 脚本 | 用途 | 示例 |
| --- | --- | --- |
| setup_env.ps1 | 初始化 venv 与依赖 | `powershell -File scripts\setup_env.ps1` |
| ai_call.py | 调 AI 模型 | `ai_call.py --prompt-file p.txt` 或 `echo 提问 \| ai_call.py` |
| http_fetch.py | 联网抓取 | `http_fetch.py <URL> --out data.html` |
| office_io.py | Office 读写 | `office_io.py excel-write out.xlsx --rows json文件` |
| run_stage.ps1 | 状态检查 + 一键调脚本 | `run_stage.ps1 http_fetch.py <URL>` |

详细参数说明：运行各脚本加 `--help`。

## 故障排查

- 控制台乱码 → 脚本已强制 UTF-8 输出；若仍乱码，用 `chcp 65001` 后重试。
- AI 调用 401/超时 → 检查 AI_API_KEY / AI_API_BASE / AI_MODEL 三个环境变量；脚本自带 3 次退避重试。
- Excel 打开乱码 → 确认写文件用的是脚本默认 `utf-8-sig`。
- PowerShell 报"无法识别"→ 检查是否用了 `&` 运算符加引号完整路径调用。
