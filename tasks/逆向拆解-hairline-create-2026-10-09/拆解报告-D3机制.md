## §1 契约与自校验

### M01 · 引擎自带「行内内容哈希头」，由校验器复算（fail-closed 自校验）

- **位置（A）**：`@a2217852:kernel.js#第 1 行` = `/* hairline kernel sha256:3a19aa2640ba8c6c… */`；复算口径在 `@a2217852:validate.mjs#validate` 第 215–220 行：`kernel.indexOf("\n")` 切出第一行 → 取头里的 64 位 hex → 与 `sha256(kernel.slice(cut+1) + "\n")` 比对。
- **解决什么问题**：① 「页面里的工程内核是不是这个目录的那一份」原本只能靠人眼；② 「内核被谁改过」在文本层完全不可见。做成「内容摘要写在自己头上」，任何改动**必然**被下一次校验发现 ⇒ 与 ppt-master 的 `attribution_guard.py` 同族，但**机制不同**（那是「文件名+尺寸+摘要」清单，这是「自身内容摘要」）。
- **复用条件**：产物内嵌一份**声明为不可变**的第三方/核心代码；改动它属于**变更支持请求**而非常规修改。
- **代价**：
  1. 摘要口径是**隐含契约**（`slice(cut+1)` 再补一个 `"\n"` —— 即「除首行外全部内容，末尾按恰好一个换行计」）。这个口径**没有写进任何文档**，只在代码里；它在 CRLF 检出下会破，靠同函数里的 `unix()` 先归一才成立。⇒ **本仓若照搬，必须把口径写成人读文字，并配行尾归一的断言**（本仓项目记忆里已有「固定长度窗口是定时炸弹」的同类教训，这里是「隐含口径是定时炸弹」）。
  2. 改核心代码**必须**用工具重算摘要 ⇒ 对「想小改一行」的人是硬摩擦（这是设计意图，但也是真实的可用性代价）。
  3. **它只证明「页面里的内核 = 本目录内核且未被手改」，不证明「本目录内核 = 上游正版」** —— 后者归 `.vendor/hairline.lock.json` ＋ `external_skill_lint.py --verify-lock`。**两套机制分工，不得互相冒充**。
- **档**：A（代码与注释原文均在）。

### M02 · 产物「单文件自包含」由**外联黑名单**机器化

- **位置（A）**：`@a2217852:validate.mjs#BAD` 的 `outside` 项（第 90–91 行）与它的 `import` 第二正则（第 94 行）。

## §2 判据实现（**本节是本轮最有可迁移价值的一节**）

### M03 · `bare(src, words)`：为「正则判据」自写一层 JS 词法剥离

- **位置（A）**：`@a2217852:validate.mjs#bare`，第 41–78 行（含 41–53 行注释解释两档 `words`）。
- **解决什么问题**：判据是**正则黑名单**，但源码里混着注释、字符串、模板字面量、正则字面量。直接对全文跑正则会有**两个方向**的错：
  - **假红**：注释里写「不要用 `stroke-width`」⇒ 被判违规（把**说明文字**当代码）；
  - **假绿**：字符串里出现 `//` ⇒ 被当注释，**后面真正的违规被整段跳过**（这是更坏的方向：`bare` 特意「按 JS 的方式读」，就是为了让「字符串里的 `//` 不是注释，且它之后的代码仍被检查」）。
- **机制要点（A）**：三态处理 —— 注释删掉；字符串按 `words` 开关**保留原文或清空**；正则字面量按「斜杠是否位于**值起点**」判断（`prev` 落在 `(?:|[(,=:[!&|?{};+\-*%<>~^])` 集合内即视为正则）；模板 `${…}` 用**栈**记 brace depth（`open.push(depth++)`）以回到模板续读。`words` 两档让「读注释后代码」与「读字符串内字」两类判据**共用同一个剥离器**。
- **复用条件**：判据要以正则匹配**人类可读文件里的代码片段**（脚本、配置、模板、Markdown 代码块、YAML 里的内嵌脚本）。
- **代价**：
  1. 38 行**有状态的手写词法**，是长期维护面；`/` 的歧义判断本身是**启发式**（靠 `prev` 字符集合），不是语法分析。
  2. 该剥离器**没有单测**（在被拆对象的 12 个文件里未见测试文件；**T4**：只在 `@a2217852:skills/hairline-create/` 这一路径集内检索，未检索到测试）。
  3. **只管 JS**：换 TS / JSX 就要重做。
  4. **C 档（推断）**：JS 语法演进（新字面量形式）会让它失准 —— 我没有构造反例，故只作推断登记。
- **对本仓的直接含义**：本仓有同类问题的**更省解**已存在 —— `checks.py` 用 `_frontmatter()` **结构化取块**（原文措辞「结构化取块，非字符窗口」）而不是剥离全文。⇒ 采纳时**优先「收窄取数范围」，其次才是「自写词法」**（后者是最后一档）。

### M04 · 双向判据：黑名单 BAD ＋ 白名单 NEED，且单条带第二个「清空字符串」正则

- **位置（A）**：`@a2217852:validate.mjs#BAD`（5 组）与 `#NEED`（5 条，`handle` 占 2 条）；`outside` 的第二正则；`NEED#handle` 的**前瞻否定** `(?<![.\w$])set\s*[:(,}]`。
- **解决什么问题**：**只有黑名单时，「什么都不做」的产物全绿**。一个不画任何东西、不注册循环、不写读数的空 figure 能通过所有黑名单 ⇒ 必须配 NEED 把「必须出现的调用」也机器化。
- **机制要点（A）**：`handle` 用 `(?<![.\w$])` 排除 `map.set(k, v)` 这类**同名不同物**；并**穷举三种合法写法**（`set(v)` / `set: f` / 简写 `{ set, destroy }`）。
- **复用条件**：判据面对**模型自由书写**的结构化声明（「必须有某调用」「不得有某调用」）。
- **代价**：
  1. **黑名单永远不全**（作者在 `look.md` 明写边界，见 M14）。
  2. NEED 是**文本级**存在性检查：`bare()` 已删注释，但**字符串里出现 `pointer(` 仍算命中** ⇒ 存在假绿面。**C 档（推断）**：我没有构造反例，只按代码语义推断。
  3. 「穷举合法写法」**无上界**：漏一种就把合法写法判红。本文件把 `set` 的三种写法压进一个正则 ⇒ 可读性与可维护性都受损。
  4. ⚠️ **口径分裂**：`NEED` 与 `BAD` 各判一半，而**同一条规则的两半可能落在不同条目**（rule 04 在 BAD，rule 07 同时在 BAD 与 NEED）⇒ 「某条规则的机器覆盖度」无法从条目名读出，只能读注释（注释里确实标了 rule 号，但那是**人写的标注**，无守卫）。
- **档**：A；第 2 条 C；第 4 条 B（我按条目分布归纳）。

### M05 · 括号配平数实参（`tweens()`）—— 以及其中一处**不可核的豁免（fail-open）**

- **位置（A）**：`@a2217852:validate.mjs#tweens`，第 118–134 行。
- **解决什么问题**：`tset(tw, to, now, delay)` 少给第 4 个参数 ⇒ `t0 = now + undefined = NaN` ⇒ 值 NaN ⇒ **路径画不出来但也不报错**（静默失效，最难查）。正则数不清「逗号是否在同一层」，故逐字符配平：只在 `depth === 1` 时计逗号。
- **复用条件**：要对「调用的**形状**」而非「文本出现」做判据。
- **代价**：
  1. 又一处**手写解析**（与 M03 同源成本）。
  2. ⚠️ **最好的一条反面样本**：豁免条件写作 `if (given < 4 && !call.includes("..."))` —— **只要该调用文本里任意位置出现 `...` 就整体放过**，而它**不检查展开的实参有几个**。⇒ 这是 **fail-open 的豁免**：豁免条件本身**不可核**。
     - 本仓**已有**同族纪律（`scripts/checks_judges.py`：「豁免必须写理由」「豁免了却本次没 FAIL 会 WARN」「单条登记四键不全 ⇒ 该条作废，不放行」）⇒ 本条的**增量**不是「豁免要留痕」，而是「**豁免的触发条件本身必须可核**」这一更细的一层。
  3. **C 档（推断）**：豁免本意是放行 `tset(tw, to, now, ...args)` 这类转发；但 `includes` 的粒度使「注释外的无关字符串里出现 `...`」也能触发。未构造反例。
- **档**：A（代码）；「这是 fail-open」为 B（按代码语义归纳）；第 3 条 C。

### M06 · 借宿主解释器做**真语法**校验，而不是自写 parser

- **位置（A）**：`@a2217852:validate.mjs#parse`，第 197–209 行：`mkdtempSync(join(tmpdir(), "hl-parse-"))` → 写 `figure.mjs` → `spawnSync(process.execPath, ["--check", file])` → 从 stderr 抓 `figure.mjs:(\d+)` 行号 → **`finally` 删临时目录**（`rmSync(recursive, force)`）。
- **解决什么问题**：「这段代码能不能作为模块加载」不是文本层能判的（`bare()` 只是**剥离**，不是**解析**）。做法是把解释器当 **oracle**。
- **复用条件**：宿主已有该语言的解释器；你在意「真语法」而非「文本形状」。
- **代价**：
  1. **进程开销**：每次校验 spawn 一个 Node（对一个交互式流程可接受，对批量校验是硬成本）。
  2. **没有降级分支**：`run.status !== 0` 一律报「图有语法错」⇒ **环境问题（不可写临时目录、无执行权限、解释器缺失）会被误报成产物缺陷**。这是「判据造信号」的典型形态。
  3. **无 `timeout`**：`spawnSync` 未设上限。`--check` 正常很快，但这是**未设边界**。
  4. 临时目录名前缀固定（`hl-parse-`），靠 `finally` 清理；**进程被强杀则残留**（无陈旧清理）。
- **档**：A；第 2 条 B；第 3/4 条 C。
- **本仓同构**：本仓「关键判定命令一律不接管道取 rc（管道会吞退出码）」「先落文件再取 rc」是同一族纪律 —— 把**外部程序的判定**当真 oracle，**但必须自己控制怎么读它的结论**（退出码/标准错分流）。

### M07 · 从自由书写的代码里抽「**最后一个**权威声明」，但**两处口径不同**

- **位置（A）**：`@a2217852:build.mjs#nameOf`（第 23–26 行，`[...figure.matchAll(/\bhairline\s*\(\s*\{/g)].at(-1)`，注释明写「the last hairline({ … }) call, as validate.mjs reads it, so a `name:` earlier in the figure is not taken for it」）；对照 `@a2217852:validate.mjs#declared`（第 139 行 `/…\}\s*\)\s*;?\s*$/`，**要求它出现在文件末**）。
- **解决什么问题**：figure 里可能**先**出现 `name:`（对象字面量、示例文本）⇒ 取「第一个匹配」会取错名，从而**写错输出文件名**（静默）。
- **复用条件**：要从模型自由书写的产物里抽「唯一权威声明」。
- **代价**：
  1. **两处口径不同**：`build.mjs` 取「最后一个 `hairline({`」，`validate.mjs` 要求「文件末尾的 `hairline({…})`」。二者可判出**不同**结果（例如 `hairline({…});` 之后又有一句语句）⇒ 组合是「build 认得出名字、validate 判 declare 失败」。**该组合 fail-closed（会报错）**，可接受；但它证明**同一物理量有两套判据**，而 `build.mjs` 的注释自称「as validate.mjs reads it」（**自称同源，实际不同源**）。
  2. 抽取方式仍是启发式（正则），**C 档（推断）**：若声明里含嵌套 `}`、或模板字符串内含 `hairline({`，会取错。
- **档**：A（两处代码）；第 1 条 B（我按两处正则的差异归纳）；第 2 条 C。

## §3 运行与调度

### M08 · 单帧循环 ＋ `tick` 返回布尔（自动休眠）＋ 异常「降级但保可见」

- **位置（A）**：`@a2217852:kernel.js#frame` 第 398–414 行、`#wake` 415–421、`#start` 426–441、`#register` 450–484；配套 `#stepS` 294–312、`#tset` 348–353。全文 `requestAnimationFrame` **只出现 2 次**（413、419，均在 `frame`/`wake` 内）。
- **解决什么问题**：多图形共处一页时，只有「还在动」的才需要帧；figure 若各自起 `requestAnimationFrame`，就会出现多个各自为政、忘停、且无法统一尊重减动效的循环。
- **机制要点（A）**：
  - `b.awake = !!b.tick(dt, now)` ⇒ **tick 的返回值决定它自己还要不要下一帧**；
  - `raf = any ? requestAnimationFrame(frame) : 0` ⇒ **全员静下来则循环彻底停**（不是空转）；
  - `dt = Math.min(0.05, Math.max(0, (now - last) / 1e3))` ⇒ 切回标签页不会喂进一个巨大 dt；
  - `stepS` 用 `n = Math.max(1, Math.ceil(dt * 240))` 子步细分后再积分 ⇒ 稳定性；
  - `tset` 首行 `if (tw.to === to) return;` ⇒ **每帧调用安全（幂等）**；
  - `catch { b.awake = false; setTimeout(() => { throw err; }, 0); }` ⇒ **本 figure 停下，异常异步重抛**（不静默吞掉）；
  - `IntersectionObserver` 带 `rootMargin: "80px"`（离屏 80px 内就唤醒），且同一 stage 的多个 board **继承彼此的可见性**（`for (const p of peers) b.vis = p.vis`），避免重复观察。
- **复用条件**：多个独立组件共享一个渲染循环；组件自己决定「还需不需要帧」。
- **代价**：
  1. 「异步重抛」把异常**移出**原始调用栈（丢上下文），且**已经**把该组件停掉 ⇒ 页面表现只是「**某些东西不动了**」；若没人看控制台，只能靠**宿主侧的错误显示面**兜（此处是 bench 的 `error` 监听 + `look.mjs` 的 item 12）。⇒ **采纳此机制必须同时具备「错误可见的出口」**，否则等于把静默失效换成另一种静默失效。
  2. `tick` 返回值的语义是**隐式契约**（返回真 = 还要帧）。写反（恒返回真）会**静默**变成常驻循环。上游只能靠 `rules.md#07` 的 Rejected 项 + `look.mjs` 的「still/moving」观察来抓 —— **机器判据在这里只能给「信息，不是检查」**（`look.mjs` 第 403–405 行的原文即如此措辞）。
  3. 三处全局状态（`boards` 数组、`byStage` Map、`handlers`/`touring` 两个 `WeakMap`）＋ `io`/`rm` 两个单例 ⇒ `unregister` 必须同步清三处，**漏一处即泄漏**；代码用「最后一个 board 消失时 `unobserve` + `stop()`」兜底，但这依赖「计数正确」这一前提。
- **档**：A；第 1、2、3 条为 B/C（按代码语义归纳，未构造反例者标 C）。

## §4 可测性内建（把「验证夹具」做进产物本身）

### M09 · 产物地址参数即夹具：`?at=` / `?w=` / `?intensity=` / `?theme=` / `?play=`

- **位置（A）**：`@a2217852:bench.html#window.hairline` 第 89、92–99、149、151–159 行；人读文档 `@a2217852:look.md#The pictures`（四个参数 ＋ 八图矩阵）。
- **解决什么问题**：无头浏览器/工具**无法 hover、无法拖滑杆、无法按主题按钮** ⇒ 视觉验证要么靠人肉操作、要么根本做不了。做法是**给「人」留可复现的地址**，工具**顺带复用同一地址**（不是给测试开后门）。
- **机制要点（A）**：`?at=x,y` 在页面加载后**派发一个真实 `PointerEvent("pointermove")`**，坐标由 viewBox 反推 client 坐标；`look.mjs#POINT`（第 166–172 行）用**同一手法**做同一件事。
- **复用条件**：产物的状态可由少量离散输入决定，且这些输入能用 URL 表达。
- **代价**：
  1. 参数解析写在**产品页**里（`URLSearchParams`）：对外是「可分享一个状态」的好功能，对内是**测试面与交付物的耦合**（改地址协议 = 改产品）。
  2. `?at=` 走的是**合成事件路径** ⇒ 它验证不了真实设备的指针行为（触摸、压力、指针捕获）。`look.md` 说八张图「work in any browser, for a look by hand」，**没有**声称等价于真手检。
  3. 参数一多，地址空间成因子组合（八图 = 4 个参数 × 2 个取值）。
- **档**：A。

### M10 · 「代理对象」当契约面，而不是把宿主 DOM 交出去

- **位置（A）**：`@a2217852:bench.html#window.hairline` 第 122–126 行：`read` 是**只有 getter/setter 的对象**，`set` 里 `value == null ? "" : String(value)`，真正写 DOM 的动作留在宿主侧。
- **解决什么问题**：figure 若拿到真 DOM 节点，就会去读写更广的 DOM，也就**没法用「不许测 DOM」的文本判据约束它**。给一个**极窄的代理**，契约面被压到 1 个属性 ⇒ 判据（`readout` NEED）才有可判性。
- **复用条件**：插件/脚本要写宿主的一小块状态，而你想让「越界」在文本层可判。
- **代价**：① 表达力被压到写一个字符串（这是设计意图，但也是选择成本）；② `read` 用 getter/setter 而**非** `Proxy` ⇒ **读**回来的值来自宿主局部变量，与 DOM 可能短期不一致（此处无碍，属**未写出的隐含前提**）；③ 契约面「只剩 1 个属性」使**任何新的读写需求都必须改宿主**（可预见的扩展成本）。
- **档**：A；第 2/3 条为 C（推断）。

### M11 · 机器可测的「代理量」——且**每个阈值都带它的实测样本**

- **位置（A）**：`@a2217852:look.mjs` 第 44–53 行（常量与它们的注释）、`#moved` 56–60、`#beats` 63–65、`#INK` 68–80、`#settle` 180–189、`#STATE` 151–163。
- **解决什么问题**：把「静没静」「答案看不看得出来」「构图够不够满」这类**原本只能靠眼睛**的性质，换成**可从像素/时序算出**的量：
  - `settle()`：等 `WAIT 1500ms` → 每 `STILL 250ms` 取一次 `#stage > svg` 的 **innerHTML 字符串** → 两次相同即「静」→ 记下**从加载到静共几秒**；超过 `CAP 5000ms` 返回 `null`（＝没静过）。
  - `moved(rest, answer)`：两张 240px 图的**墨迹掩码**按位异或的像素数 ÷ 静息墨迹数。
  - `INK`：以**画面左上 14px 处的底色**为基准，通道差 ≥ `INKED 24` 记 1；**排除外侧 12px**（避开画框自己的描边）。
  - `beats()`：运动条 16 帧、每 40ms 一帧（末帧 600ms ≈ 700ms 补间的大半程）。
  - 三个阈值的**样本来源都写在注释里**：`SMALL 0.25`（两范例静息外接框占 36%）、`FAINT 0.37`（Terrain 74% / Riffle 139% 的一半）、`INKED 24`（纸面上灰线距底色 31）。
- **复用条件**：被验对象能在无头浏览器里渲染，且「好/坏」有可像素化的代理。
- **代价**：
  1. **代理量 ≠ 原本要判的东西**：墨迹异或率高**不**蕴含答案语义更好；`SMALL` 只看外接框面积比，不看内容是否成图。⇒ 采纳时必须把它写成**警告级代理**，不能写成「已通过」（上游确实把它做成 warn/信息，不是 fail —— 这点是可取的一半）。
  2. **阈值是经验值且与图形语言绑定**：换一类产物就要重标；上游已注明样本来源，**这是它做对的部分**，但门槛本身不可迁移。
  3. **时序敏感 ⇒ 假红**：`settle` 会把「机器太忙」判成 `moving`；作者自己写「run it again before you believe it」⇒ **该判据的阴性结论比阳性结论可信**（负结论要复核）。
  4. 静帧判据取 **innerHTML 字符串相等** ⇒ figure 若每帧重写「等价但字面不同」的路径，会被判「一直在动」。
  5. `INK` 在页面内用 canvas 逐像素扫（每图数十万像素级循环）⇒ 开销不小（此处用 `data:` URL，不受 CORS 污染限制）。
- **档**：A（常量、注释、代码）；第 1、3、4 条为 B/C（第 3 条作者自认，A）。

## §5 工具链工程

### M12 · 同一份实现被三个工具复用（防「双路径不同源」）

- **位置（A）**：`@a2217852:build.mjs#assemble` / `#nameOf`（导出）；`@a2217852:validate.mjs#validate`（导出）；`@a2217852:look.mjs` 第 39–40 行 `import { assemble, nameOf } from "./build.mjs"` 与 `import { validate } from "./validate.mjs"`。
- **解决什么问题**：若 `look.mjs` 自己再拼一遍页面，就会出现「**校验的那份页 ≠ 交付的那份页**」这类双路径缺陷（本仓项目记忆记着同族病：两条路径算出两份名单，差异不知来自接线还是数据源）。
- **复用条件**：一条链上多个工具需要**同一份变换**。
- **代价**：
  1. 导出面被撑大（`look.mjs` 另导出 `moved` / `beats` / `SHOTS` / `cacheDir` / `point` / `same`；`build.mjs` 另导出 `same`）⇒ **内部实现成了事实 API**，改名即破坏兼容（无版本声明）。
  2. 被 import 时不能有副作用 ⇒ 依赖 M13 的 CLI 守卫；守卫一旦失效（打包器重写 `import.meta.url`、`argv[1]` 形态变化），**整个工具链静默 no-op**。
- **档**：A；第 1 条为 B，第 2 条为 C。

### M13 · CLI-vs-模块 判据：`realpath` 归一再比，并显式处理 Windows 大小写

- **位置（A）**：`@a2217852:build.mjs` 第 29–32 行（`#same` ＋ 守卫）、`@a2217852:validate.mjs` 第 242–246 行、`@a2217852:look.mjs` 第 425–429 行 —— **三份 `same()` 逐字相同**；注释原文：「The skill is often installed as a symlink, so the path Node was given is resolved before it is compared.」
- **解决什么问题**：`import.meta.url` 与 `process.argv[1]` 做**字符串**比较，会在（a）**符号链接/目录联接安装**、（b）**Windows 盘符与路径大小写**差异下失效 ⇒ 要么被 import 时误执行，要么作为 CLI 运行时**什么都不做**（静默 no-op，最难发现）。
- **复用条件**：同一文件既要可 import（供复用、可测）又要可当 CLI；且**安装方式不受控**。
- **代价**：
  1. 同一个 `same()` **复制三份**（本仓的硬约定是「同一物理量不得两处定义」）⇒ 改一处必须记得改三处，否则**判据分裂**（本仓已有同类事故：同一物理量两处定义）。
  2. `realpathSync` 在**路径不存在**时**抛异常**，此处未加 `try`（三处均未加）⇒ 「被删/被移的入口」会让工具直接崩（fail-closed，但错误信息是 `ENOENT`，对使用者不友好）。**C 档**：我未构造反例。
- **档**：A（代码）；第 2 条 C。

### M14 · 在做「内容相等 / 哈希」之前统一行尾并 `trimEnd`

- **位置（A）**：`@a2217852:build.mjs#assemble` 第 16–19 行（kernel、bench、figure **三处**都 `replace(/\r\n/g, "\n")`）。`@a2217852:validate.mjs#unix`（第 33 行）＋ `#validate` 第 213、215 行。
- **解决什么问题**：跨平台检出（`core.autocrlf`）会让**同一份内容**在不同机器上哈希不同、字符串不等 ⇒ 假红。
- **复用条件**：判据涉及「内容摘要 / 字符串相等 / 拼接后哈希」。
- **代价**：① `trimEnd()` **静默抹掉末尾空行** ⇒ 依赖「文件末尾几个换行」的约定会被无声改写（本仓同类教训：判行尾**不能凭「出现过 CRLF」**，要取计数多数派）；② 只归一 `\r\n`，**未覆盖孤立 `\r`**；③ 归一动作散在三处调用点，**新增一处拼接就得记得加**（无中央封装）。
- **档**：A；第 1、2 条为 B。

### M15 · 平台/环境差异抽成有名字的小函数并导出

- **位置（A）**：`@a2217852:look.mjs#cacheDir`（第 95–100 行：`HAIRLINE_LOOK_CACHE` → macOS `~/Library/Caches/…` → Windows `%LOCALAPPDATA%\hairline-look` → 其他 `$XDG_CACHE_HOME` 或 `~/.cache`）、`#point`（103–106）、CLI 侧参数校验（440–443）。
- **解决什么问题**：平台差异与输入解析若散在主流程里，就**不可测、不可复用**；抽出来还能被人读文档直接引用（`look.md` 把三个平台的路径逐字写出来了）。
- **复用条件**：同一逻辑在不同平台/环境下有分支，且人读文档要复述这些分支。
- **代价**：① `cacheDir` 有**静默回退**（`LOCALAPPDATA` 缺失即退到 `join(home, "AppData", "Local")`）⇒ 环境异常不报错，只在事后发现「装到别处了」；② 平台分支是**硬编码枚举**，新平台需改代码（无配置面）。**C 档**：第 ① 条我按代码路径推断，未构造环境反例。
- **档**：A；第 1 条 C。

## §6 人机边界

### M16 · 把「机器判据的能力边界」**写进人读文档**，并与判据清单一一对应

- **位置（A）**：`@a2217852:look.md` 开篇（"The validator reads text. This is what only eyes can check."）；`@a2217852:look.md#What to see` 前导（"`look.mjs` answers 8, 9 and 12, and measures part of 4; the rest are answered from the sheet."）；`@a2217852:validate.mjs` 头部 22 行注释（14 项清单，逐项一行说明「它查什么」）。

- **复用条件**：验收面是「机器判据 ＋ 人类判断」混合。
