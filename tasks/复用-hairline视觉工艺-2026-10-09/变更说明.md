## 3. 关键判断（为什么这么做）

1. ⭐ **hairline 交付的是「产物生成器」，不是「方法论」**：其 `skills/hairline-create` 的用途是「给一个想法画一张等距线稿图」。故折进本体的正确形态是**产物外挂、原则入判据集** —— ② 它的产物是一种**风格**（isometric 线稿），内置化会把「一种风格」写成「本仓默认」。
2. ⭐ **它的规则绝大多数在判断层**：其 `look.md` 自述「**The validator reads text. This is what only eyes can check.**」⇒ 按其自述与本仓已立口径，**给判断层硬配机器判据＝制造假绿**。故本轮**按 judgeability 分档**，而非「十条规则逐条转成判据」。
3. **重叠先排除，不重复造**（本仓硬约定「同一物理量不写两处」；重叠会让既有阴性对照恒判假绿）：

   | hairline 规则 | 处置 | 依据 |
   | --- | --- | --- |
   | 02 按距离错峰 | **不新增** | 既有 **G16** `rhythm_ladder` 已覆盖 |
   | 06 构造不穿透 | **不新增** | 既有 **R4** `geometry_occlusion` 已覆盖 |
   | 04 唯一强调色（半面） | **不新增** | 既有 **G2** / **G8** 已覆盖 |
   | 04 发光/阴影/滤镜（另一面） | 新 **H2** `machine` | 未被覆盖；且**只判发光、不判抬升**（elevation 是功能性的，不越权） |
   | 08 两只钟（缓动纪律） | 新 **H1** `machine` | 未被覆盖 |
   | 07 循环屏外休眠（兜底面） | 新 **H3** `machine` | 未被覆盖；**代理信号**，屏外那一半机器无从观测 |
   | 05 静止态是构图 | 新 **H4** `manual` | 只有眼睛能看 ⇒ `check: null` |
   | 01 命中区不动 | 新 **H5** `manual` | 需「随时间的位形序列」，单帧几何判会造 100% 假绿 |

4. **未迁移 4 条**（强绑定 isometric 画面、对通用视觉产物**无判别力**，硬搬＝凭空发明契约）：03「不出框」（依赖 400×320 固定画框与指针极值位形）／07 的**屏外休眠半面**／09「圆角化 + 亮外暗内」（依赖 `prism` 双环实体这一表示法）／10「图内无文字」（依赖图元即几何）。**边界写进判据集 `note`**。
5. **安装形态按「体积 ＋ 源目录性质」判**：源是普通 GitHub 仓库、不受插件管理 ⇒ 不会被上游删建 ⇒ **不必用联接**；12 文件 / 127 KB ⇒ 复制安装（与 `humanizer` 先例一致：真实目录、`patched: false`）。**代价如实登记**：上游更新**不会自动生效**，须按 §7.3 整体重取。
6. ⭐ **H1 的射程是本轮最实的一条经验**：首版无射程的 H1 把**合规产物**的 `.spinner{animation:spin 1.2s linear infinite;}` 判 FAIL —— 旋转／进度／跑马灯用线性**是对的**（匀速旋转的物理语义本就是线性），原样套用属**作用域错配**（同 G1/G6/G7/G11 一族）。处置：H1 加 `scope` 参数、**默认 `transition`**，要连 `animation` 一起禁须**显式** `scope: all`。

> **过程留痕（不掩盖，六处自身缺陷）**：
> ① **`s2` 改写脚本首版 `sub()` 写成 `src.replace(...)`**（每次都从**原始串**替换）⇒ 前序编辑被**静默丢弃**、8 项回读断言全红。改为作用于**累积串**后通过。⇒ 本仓硬约定第 5 条（同文件多处编辑须串行 ＋ 逐处回查）的**实证**；抓到它的正是「回读断言」。
> ② **给上游文件 `rules.md` / `look.md` 加了反引号**，被「文档引用完整性」判为技能内引用 ⇒ **FAIL=1 假断链**（`REF_PATTERN` 只匹配反引号包裹的裸名）。本仓既有约定「**外部路径用纯文本提及、不加反引号**」写在 `diagram-mode.md` 首部，本次**违反**；改纯文本带路径后 FAIL 归零、引用数回到 **142**。⇒ **s2 的验证方式本就写着「引用完整性无死链」，但当时没跑** —— 这一条是被 `checks.py skill` 而不是被自设断言抓到的。
> ③ **`s5` 首版幂等判据写错**：`s.count(old)==0 and new in s`。对**插入型**编辑（new 以 old 为前缀）该条件**永不成立** ⇒ 第二次运行把同一段**又插了一遍**，`diagram-mode.md` / `ppt-mode.md` 各重复一次（证据留 `s5-dup-evidence/`）。修法＝判据改看**目标态**（`new in s`），另用「HEAD ＋ 编辑表」重推做**逐字节对照**证明修复精确。⇒ 与「**插入型编辑的回读断言必须与替换型分开**」同源。
> ④ **行尾污染（第 4 处，同属自查发现）**：`Path.write_text` 默认 `newline=None` ⇒ 按 `os.linesep` 把 `\n` 写成 `\r\n`，**把 11 个文件的行尾改成了 CRLF**（本仓 `.gitattributes` 是 `* text=auto eol=lf`）。已按 s1 基线副本**逐文件还原原状**，并断言「内容零变化 ＋ git diff 逐字节不变」。⇒ 教训：**写盘一律显式 `newline=""`**，否则「只改内容」会变成「内容 ＋ 行尾」两处改动。

## 6. 复盘沉淀（学习点）

> 类别：**流程坑** —— 「第三方『审美/风格类』技能折进本体的正确形态」＋「写盘侧的行尾与幂等」。

1. ⭐ **审美类第三方技能的复用形态：产物可外挂、原则须分档**。它交付的是**产物生成器**（一种风格），不是方法论 ⇒ 内置化会把「一种风格」写成「默认」。而其规则**绝大多数在判断层** ⇒ 提炼进判据集时**必须按 `judgeability` 分档**：能机器量的走 `machine` 实跑、只有眼睛能看的走 `manual`（`check: null` ⇒ SKIP「人审点」）。**给判断层硬配机器判据＝制造假绿**。
2. ⭐ **「原样迁移」是默认的危险假设，实测常常推翻它**。H1 首版把合规产物的旋转加载器判 FAIL —— 规则的**适用射程**（作用域）没说清时，套到通用产物上就是**作用域错配**（与 G1/G6/G7/G11 同族）。⇒ 迁移一条规则前先问：**它当初约束的对象，与我要约束的对象是同一类吗？** 修法＝给判据加**射程参数**并让默认值取**最保守（最窄）**的那档。
   > **同型第 2 次（本轮内）**：收尾复验的**自设判据**也犯了同一件事 —— 把 git-ignored 的 `plan.yaml` 按 `eol=lf` 期望 ⇒ 假 FAIL（见 §4 过程留痕 ⑤、证据 `s6c.log` / `s6d.log`）。⇒ 这条不止约束「迁移别人的规则」，**同样约束自己临时写的判据**：写判据时先把**输入集合**划清楚（哪些文件受这条约束、哪些不受），否则「全红」里混着假红。
3. ⭐ **幂等判据要看「目标态」而不是「旧串是否消失」**。插入型编辑的 `new` 以 `old` 为前缀 ⇒「旧串仍在」对**已应用**的编辑同样成立，按旧串判会把同一段**再插一遍**。正解：`if new in s: skip`。姊妹条：**插入型编辑的回读断言必须与替换型分开**。
4. ⭐ **同一物理量的计数，跨文件必须机器对账**。本次判据条数散在 5 处（判据集本体 / `SKILL.md` ×3 / `README.md` ×2 / `checks_core.py` / `ops.md` / `plan-template.yaml`），且**改动前就已有「30 条 vs 31 条」两处陈旧**。⇒ 收尾必须**机器数数**（解析判据集 `id:` 条目）再比对，**不手写**；同时区分「**现在时计数**（须改）」与「**历史版本注记**（不得改写 —— 改它＝篡改历史）」，历史链条采取「**追加上一段**」而非「改写上一段」。
5. ⭐ **写盘必须显式管行尾**：`Path.write_text` 的 `newline=None` 会按 `os.linesep` 转换 ⇒ 在 Windows 上把 `\n` 写成 `\r\n`，于是「只改内容」变成「内容 ＋ 行尾」两处改动（本次 11 个文件被静默改成 CRLF）。修法＝写盘显式 `newline=""`；**已发生时的正解是「按改动前的原状逐文件还原」**，并用三条判据自证（内容 sha 不变 / `git diff --numstat` 不变 / 目标行尾一致）。判行尾取**计数多数派**，别凭单个文件推广。
6. ⭐ **「上一轮结论＝待复测假设」**：`s4` 首版输出的 H1 FAIL 分布是**收窄前**的 —— 改完判据**没复跑**。正解＝改完**复跑**并**保留前后两份输出**做对照；否则会把「已修好的旧结论」当成现状交付。
7. **自设断言 ≠ 门禁**：本轮两处 FAIL（假断链、行尾）都是**技能自带门禁**抓到的，而不是我自设的回读断言。⇒ 自设断言只覆盖「我想到的」，**交付前必须跑一遍技能自带门禁**；`s2` 的验证方式写着「引用完整性无死链」却没跑，是可复用的反面教材。
