# PPT 模式（ppt-mode，v4.25.0 新增）

> **定位**：ai-workflow 在**产出结构层**上的第六个模式 —— 与 self-judge（认知轴：这次产出什么）、入口分型（来源轴：请求怎么来的）**正交叠加**，可叠加在任意主类与任意来源之上。它与**作业模式**、**文献阅读模式**、**逆向拆解模式**、**图示设计模式**、**科研模式**同轴不同域：作业模式管「题目该怎么答」，文献阅读模式管「一篇文献该怎么读」，逆向拆解模式管「一个外部产物该怎么拆」，图示设计模式管「一份内容该不该画」，科研模式管「一次研究活动从选题到投稿怎么组织」，本模式管「**一份演示文稿该讲什么、给谁看、按哪条路由做、交付前拿什么证明它成了**」。  
> **一句话**：**PPT 的难点不在“怎么把页面做漂亮”，而在“事先定死给谁看什么”与“交付前谁来证明它站得住”** —— 本模块把这两端落成可检查的产出结构与验收契约；**中段的工程实现不由本模块承担**，它整体交给第三方技能 `ppt-master`。  
> **为什么只做契约层、不复刻执行过程**：`ppt-master`（v6.6.0）自身已是**完整的路由工作流** —— 三条顶层路由 + 每路由的 Plan → Do·Check·Act 阶段框架 + `⛔ BLOCKING` 用户门 + 自带机器校验器。本仓若再复刻一套页面产出步骤，同一物理量就有两处口径（违反本仓硬约定第 4 条），且两套门禁会在「谁说了算」上打架。故本模块**只定义 ai-workflow 侧的前置契约、交接契约与验收契约**，执行全程以 `ppt-master` 的现行路由权威为准。  
> **本模块不新增门禁**：不加主类取值、不加来源分型取值、不改任务分层判据、**不加 plan 字段、不加 judge 判定层、不加 `checks.py` 判据**。§6 六条产出义务、**§9 二十七条设计原则**与 §10 九项自检**都是纪律项**。  
> **加载口径**：命中「PPT 识别」（§2）后加载；未命中不加载（勿预读）。  
> **依赖坐标**（引用外部资产必须钉坐标，本仓 `references/teardown-mode.md` §6 的 T1 对此有硬要求）：`ppt-master`，上游 `hugohe3/ppt-master`，本机版本 **6.6.0**，许可 **MIT**，安装形态**目录联接**（`~/.workbuddy/skills/ppt-master` → `~/.codex/skills/ppt-master`），宿主侧适配层见 `references/external-skills.md`。⚠️ **不得写「最新版」**。  
> **写法约定**：本页提及 `ppt-master` 自身的文件名一律**用纯文本、不加反引号** —— `scripts/checks.py` 的「文档引用完整性」把反引号内的 .md / .py 视为**技能内引用**，给外部路径加反引号会产出假断链（与 `references/external-skills.md` §5 的边界说明同一处置）。

## 1. 定位与形态

| 项         | 值                                                                         |
| --------- | ------------------------------------------------------------------------- |
| **模块名**   | `ppt-mode`（中文：**PPT 模式**）                                                 |
| **形态**    | ai-workflow 的**内部子模块**（非独立顶层 skill）；本文件即其完整契约                             |
| **所在轴**   | **产出结构轴**（演示文稿产出怎么组织）—— 与认知轴、来源轴**三轴正交**                                  |
| **触发落点**  | 阶段 0「入口分型」**之后**的「PPT 识别」；与「作业识别 / 科研识别 / 文献识别 / 图示识别 / 外部产物识别」并列         |
| **主语**    | “这次是不是要出一份演示文稿、该按什么契约做” —— **判形态，不判能力、不判越界**                              |
| **适用对象**  | 从主题/材料/数据生成 pptx · 复刻或美化既有 pptx · 填充原生 pptx 模板 · 造可复用模板工作区 · 由演示稿导出的自播放视频 |
| **角色**    | **演示作者**（deck author）—— 先定读者，再定路由，最后才动手做页                                 |
| **执行承接方** | 第三方技能 `ppt-master`（**唯一执行方**；本模块不内置任何页面产出步骤）                              |

**为什么不做成「来源分型的第四类」**（与五个既有模式同一条设计收敛，不是遗漏）：来源轴枚举（消息 / 正式需求 / Bug）现有 **4 处载体**（`SKILL.md` 阶段 0 第 2 步、`references/self-judge.md` §1.1、`assets/ledger-template.md`、`assets/熔断报告模板.md`），**且该枚举没有机器守卫**。把「要出一份 PPT」塞进去要同步改 4 处、零守卫、语义还站不住 —— 「做个 PPT」既可能是一句消息，也可能是带格式与验收要求的正式需求。真正需要挂的不是「从哪来」，而是「**按什么契约做、做到什么算完**」。

## 2. 触发（PPT 识别三判据，命中任一即叠加）

| # | 判据                                                                                          |
| - | ------------------------------------------------------------------------------------------- |
| ① | **显式演示特征**：说「做 PPT / 幻灯片 / 演示文稿 / 汇报材料 / 路演稿 / 课件 / slide deck」，或给出一份 .pptx / 模板要求填充、美化、改原生 |
| ② | **期望形态是演示文稿产物**（.pptx，或由其导出的演示视频 MP4），而不是 Word / Markdown 报告、不是单张图、不是一份数据表                  |
| ③ | **场合语境**：汇报 / 路演 / 授课 / 答辩 / 评审 —— 读者是**看**，不是逐字读                                           |

**相邻情形别混**：

| 情形                    | 归属                                                        |
| --------------------- | --------------------------------------------------------- |
| 只要大纲与文案、不要 pptx 成品    | **不叠加**（属内容产出）                                            |
| 改既有 pptx 的**文字**、不动版式 | `tencent-local-office-edit`（轻改），**不叠加**                   |
| 单张示意图 / 架构图 / 时序图     | `references/diagram-mode.md`                              |
| PPT **内嵌的图**          | 先过 `references/diagram-mode.md`，再交给 `ppt-master` 落版（见 §7） |
| 纯网页版演示（deck 主题体系）     | **不叠加**（不是 pptx 交付物）                                      |
| 手上只有截图 / 图片           | **不叠加** —— 读不出字号、色值、版心，只能做视觉仿写（另一类任务）                     |
| 由演示稿导出视频              | **叠加**（属本模式射程，见 §8）                                       |

## 3. 五段结构 Y0–Y4（次序固定，不可跳步）

本模块**不新造页面产出步骤**，只定 ai-workflow 侧的五段契约，并逐段**映射**到 `ppt-master` 的现行机制：

| 段             | 一句话判据                                                                                   | 落到 `ppt-master` 的哪一步                      |
| ------------- | --------------------------------------------------------------------------------------- | ----------------------------------------- |
| **Y0 定需求**    | **五问定死**：受众 / 场合 / 篇幅（页数上限）/ 素材来源（事实从哪来）/ 交付形态（可编辑 pptx ／ 演示视频 ／ 可复用模板工作区）。答不出的问，先问用户   | 路由**前置条件**；Generate 的源内容处理与工程初始化两步        |
| **Y1 选路由**    | 三路由择一（生成 / 造模板 / 改原生）＋ 必要时子档择一（默认 / Quick / 图→pptx / 美化）；**写出被否掉的路由与理由**                | 其路由权威文件 §2 的路由矩阵（本模块**不另立一套**）            |
| **Y2 定盘**     | 沟通契约（这份稿怎么论证）＋ **自由设计 vs 既有模板的明确选择**；有事实缺口先补（走 `references/retrieval-judge.md` 的否定断言门槛） | Generate 的策略阶段与其确认门；造模板路由的事实简报与确认门        |
| **Y3 出页**     | 逐页产出；标出该页触发的模块；守其形状 / 字号 / 色值守则（**设计标准见 §9**）                                           | Generate 的执行阶段；改原生路由的页计划与编辑段              |
| **Y4 机器门与交付** | **跑 `ppt-master` 自带校验器并出示原始输出**；过出站守卫；产物落工作区根                                           | Generate 的后处理与导出段；改原生路由的导出与校验段（校验器清单见 §8） |

> ⚠️ **Y1–Y3 的「怎么做」不在本页**：路由选择、门禁、逐页步骤一律以 `ppt-master` 的现行路由权威为准。本页只负责「进它之前要定死什么、出来之后要验什么」。  
> ⚠️ **Y2 的确认门与 `ppt-master` 的 `⛔ BLOCKING` 门是同一件事**：见 Y-c，**不得代答**。

## 4. 分界：可验层 / 判断层（本模式的核心）

| 层       | 含什么                                                         | 机器有对应吗 | 由谁承担                                                                                                                                   |
| ------- | ----------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| **可验层** | 渲染后的几何 / 字号 / 色值、形状与文本的叠压、OOXML 包合法性、未改动页的**往返字节一致**、产物可被解析 | **有**  | **`ppt-master` 自带校验器**（见 §8 清单）；本仓既有 `scripts/check_aesthetics.py --product ppt` ＋ `references/aesthetic-rubric.yaml` 亦可复用（**只引用不重述**） |
| **判断层** | 讲什么、给谁看、一页承载几件事、该不该拆页、路由与档位怎么选、模板与自由设计怎么取舍                  | **没有** | Y0–Y2 的**显式作答** ＋ **§9 二十七条设计原则** ＋ §10 九项自检（纪律项）                                                                                      |

**两者防法不同，不得混用**：给判断层硬配机器判据会制造**假绿**（机器算不出「这页该不该留」）；给可验层只靠人眼会让验收失效（人眼数不准坐标与叠压）。这与 `references/diagram-mode.md` §4、`references/teardown-mode.md` §4 同构。

## 5. 角色契约 Y-a–Y-d（演示作者的四条可执行立场）

| #       | 立场         | 判据                                                                                            |
| ------- | ---------- | --------------------------------------------------------------------------------------------- |
| **Y-a** | **读者视角优先** | 每一页先答「读者看完这一页要记住哪一句」。答不出 ⇒ 该页**删或并**，不是「先把内容放上去」                                              |
| **Y-b** | **事实有出处**  | 页面上一切数字 / 引述 / 结论都要能追到来源；**不得为了版面好看编数或凑指标**。否定性断言走 `references/retrieval-judge.md` §5.1 的证据门槛 |
| **Y-c** | **不代答用户门** | `ppt-master` 的 `⛔ BLOCKING` 门与确认门**必须交回用户**；不得推断用户意图后自行放行（其全局执行纪律第 2 条明文要求停下等确认）              |
| **Y-d** | **不静默降级**  | 模板缺失 / 图像后端不可用 / 字体缺字 / 依赖未装 ⇒ **声明并选择**（换路径或降级），**不得**悄悄改成自由设计、悄悄换素材、悄悄少做页                   |

## 6. 产出义务 E1–E6

| #      | 义务          | 判据                                                                                                                                                      |
| ------ | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **E1** | **路由与档位钉死** | 写清选了哪个路由与哪个档位、**以及被否掉的路由及理由**；引用 `ppt-master` 必须带版本号（本条承 `references/teardown-mode.md` T1 的坐标纪律）                                                        |
| **E2** | **页表与主张对齐** | 交付前给出「页号 → 该页唯一主张 → 证据出处」三列表；**一页一主张**，一页里两个主张即该拆页                                                                                                      |
| **E3** | **素材来源台账**  | 逐项登记用到的图片 / 图标 / 模板：自产 / 用户提供 / 第三方及其许可。**禁**把他人模板或素材当成自有成果交付                                                                                           |
| **E4** | **机器门原始输出** | **出示校验器实跑输出**，不是「我认为没问题」。未跑即如实登记**未检测**，**不得**写成通过（空输入不得冒充「没问题」）                                                                                        |
| **E5** | **出站守卫**    | 对外发布 / 分享 / 导出交付包前先过 `outbound-publish-guard`；含地图的页面先过 `geo-map-compliance-guard`                                                                       |
| **E6** | **不碰第三方本体** | **不得修改** `ppt-master` 目录内任何文件 —— 其完整性门禁脚本是 fail-closed（校验自身 frontmatter 元数据与 LICENSE / SPONSORS 摘要，改动即中止）。要改行为只能经其**公开配置**（如模板库、`.env` 图像后端），且配置不得落凭据明文 |

## 8. 与 `ppt-master` 的交接契约

**进它之前（本模块必须交付给它的）**：① Y0 五问的答案 ② 内容来源与**工作区根内的**交付路径 ③ 用户在 Y0–Y2 上的门决策记录。

**出它之后（它必须交回的）**：① 产物（.pptx 及其中间物）② 所选路由与档位（供 E1 登记）③ 合规的 `⛔ BLOCKING` 门记录 ④ **自带校验器的原始输出**（供 E4 出示）。

**其自带校验器（机器验收的实跑来源，本模块只要求「跑并出示」）**：SVG 质量校验、pptx 交付校验、OOXML 包（OPC）校验、往返一致校验（**未改动页须逐字节还原**）、批量校验、批注校验。

**不在其射程内的三条（如实登记，勿假装覆盖）**：

1. **图 → pptx 的档位标注为「Codex 宿主支持」** ⇒ 在非 Codex 宿主下该档位**不可用**，须如实声明并退回默认路由。
2. **依赖需另装**（演示文稿生成、模板注册、字形、旁白音频等各自的第三方包，见其依赖清单）⇒ 装进**隔离环境**，不污染全局；未装时其脚本会直接失败，属正常失败而非静默降级。
3. **其 PDF → Markdown 路径依赖 PyMuPDF，许可为 AGPL-3.0**（仅该脚本导入）⇒ 走到这条路径前**先评估许可**；本仓**不再分发**该依赖。

## 9. 设计原则（27 条 —— 判断层的工作标准）

> **定位**：这 27 条是 §4「判断层」的**可执行标准** —— 机器算不出「这页该怎么排」，故它们**不是门禁**，而是 Y0–Y4 逐段作答、Y3 出页与 §10 九项自检的**共同依据**。其中**可验的那一半**（几何 / 字号 / 色值 / 形状叠压 / OOXML 包 / 往返一致）仍由 `ppt-master` 自带校验器承担（见 §8 交接契约），本模块**不另造判据**（理由见 §11 第 1 条）。  
> **来源**：用户 2026-10-09 指定「做 PPT 遵循这些原则」，逐条落到本模式；**同日两次追加** —— ① 「图形技法可以更丰富一点，主旨是让 ppt 看上去更美观更饱满」⇒ **C 组由 2 条扩为 8 条**（⑪–⑱），总数 15 → 21；② 「图形技法**再更多一点**」⇒ **C 组再扩为 14 条**（⑲–㉔，补视觉层级与视线动线 / 图形化表达 / 构图平衡与视觉重量 / 留白经营 / 版式节奏与多样性 / 装饰记号系统化），D 组顺延为 **㉕–㉗**，**总数 21 → 27**；`§10` 自检同步加一条**观感复检**（8 → 9 项）。

**A. 版式基底 —— 先立规矩，再放内容**

| 原则              | 主要落点          | 层             | 判据要点                                                                                   |
| --------------- | ------------- | ------------- | -------------------------------------------------------------------------------------- |
| ① **母版定制**      | Y2 定盘 / Y3 出页 | 判断＋可验         | 用**母版 / 版式**统一字体、色板、占位符、页码与安全区；**不在单页手改样式**。选模板即走 `ppt-master` 的模板工作区路由；「版式是否统一」由其实跑校验 |
| ② **网格排版**      | Y3 出页         | 判断（对齐几何可部分机检） | 元素一律落到**栅格**（分栏 / 基线 / 卡片网格）上，靠**对齐**而非目测摆放；栏宽、边距、间距成比例                                |
| ③ **CRAP 设计原则** | Y3 出页         | 判断            | 逐页四问：**对比**够不够 / **重复**（视觉语言）一致否 / **对齐**有无游离元素 / **亲密性**相关项成组否 —— 任一不过即返工该页           |
| ④ **字体嵌入**      | Y4 交付         | 判断＋可验         | 交**可编辑 pptx** 时按需嵌入字体（或设计期就只用目标机器可靠字体），防缺字**静默回退**；许可与体积权衡入台账                          |
| ⑤ **矢量图标**      | Y3 出页         | 判断＋可验         | 图标一律**矢量**（SVG / EMF），不用位图贴图 —— 保证缩放清晰、可换色；同稿内图标风格成套                                   |

**B. 信息结构 —— 一页只讲一件事**

| 原则                    | 主要落点           | 层            | 判据要点                                                                            |
| --------------------- | -------------- | ------------ | ------------------------------------------------------------------------------- |
| ⑥ **一页一观点**           | Y0–Y3          | 判断           | 每页**有且仅有一个主张**（＝ E2 页表那一句）；一页两个主张即**拆页**，不是压字号                                  |
| ⑦ **信息降噪**            | Y3 出页          | 判断           | 逐元素问「删了会损失信息吗」—— 装饰线、重复标签、无信息量的图标与底纹一律删；提高**数据墨水比**                             |
| ⑧ **叙事逻辑搭建**          | Y0 定需求 / Y2 定盘 | 判断           | 先搭**全稿叙事线**（问题→证据→结论 / SCQA / 金字塔），页序服务论证；不按「我手上有什么素材」排序                        |
| ⑨ **信息图 Infographic** | Y3 出页          | 判断（图本体归图示模式） | 关系 / 流程 / 对比优先用**信息图**而非文字堆叠；**「该不该画这张图」先过 `references/diagram-mode.md`**，成品再落版 |
| ⑩ **数据可视化**           | Y3 出页          | 判断＋可验        | 图表**选型**对（趋势 / 对比 / 分布 / 关系）、坐标与标注完整、去冗余网格与图例；数据出处守 Y-b                         |

**C. 图形技法 —— 让画面更美观、更饱满**

| 原则            | 主要落点  | 层  | 判据要点                                                                                                            |
| ------------- | ----- | -- | --------------------------------------------------------------------------------------------------------------- |
| ⑪ **布尔运算**    | Y3 出页 | 判断 | 复杂形状用**合并 / 相交 / 减除**从基本形（矩形 · 圆 · 多边形 · 线）造出，**不以描图位图代替矢量形状**；造出的形状须**可换色、可无损缩放**                              |
| ⑫ **蒙版处理**    | Y3 出页 | 判断 | 图片用**蒙版 / 渐变遮罩 / 形状裁剪**控制焦点与文字可读性；**压字处必须保证对比度**（深底配浅字或反之，必要时垫半透明衬底）                                            |
| ⑬ **形状语言成套**  | Y3 出页 | 判断 | 同稿内**圆角半径 / 描边粗细 / 投影参数三层次成套**（如「无描边＋轻投影」的卡片、「细描边」的标签），**不逐页现编**；成块内容一律**容器化**（卡片 / 色块 / 分区），不用裸文字堆叠            |
| ⑭ **光影与质感**   | Y3 出页 | 判断 | 用**渐变 / 投影 / 高光 / 低饱和微纹理**做出层次与温度，避免**纯色死平**；渐变取**同色系深浅**（不跨色相）；全稿**光源方向统一**（如一律左上）、投影参数一致                      |
| ⑮ **图片处理**    | Y3 出页 | 判断 | 图片**统一色温与饱和度**（同稿不混冷调暖调）、按**视觉重心裁剪**、必要时**去背景**或**加统一衬底**；**禁用拉伸变形**去填满留白；主图与缩略图**风格一致**                        |
| ⑯ **空间与纵深**   | Y3 出页 | 判断 | 建**前 / 中 / 后景**三层（靠大小 ＋ 明暗 ＋ 虚实区分）；可用**等轴测 / 悬浮卡片 / 半透明叠层**造纵深；**避免全稿压成一张平面**                                   |
| ⑰ **色彩体系与强调** | Y3 出页 | 判断 | **色板的定义**归 ① 母版定制；本条规定**已定色板的用法** —— 主色 ＋ 辅助色 ＋ 强调色**三档**，面积比近似 **60‑30‑10**；强调色**只给真焦点**（一页至多一处）；**禁**彩虹色与多色等权 |
| ⑱ **画面饱满度**   | Y3 出页 | 判断 | 目标**饱满但不拥挤**：有意义的内容**落满版心安全区**（不留大片无意义空白），元素间**留呼吸间距**（不贴边、不过度重叠）；**疏密有节奏** —— 大图页配少量字、密表页配留白                   |
| ⑲ **视觉层级与视线动线** | Y3 出页 | 判断 | 每页先立**一主一辅**：用大小 / 明暗 / 色相 / 位置四手段**唯一地**把视线引到主观点；视线动线（Z 型 / F 型 / 汇聚型）服务阅读顺序 —— **不平均用力、不四角抢焦** |
| ⑳ **图形化表达** | Y3 出页 | 判断（图本体归图示模式） | 能用**图形 / 图标 / 图表**讲清的，不要写成整句或纯文字列表；抽象概念转成**具象比喻或结构图**。「这张图该不该画、画成哪类」仍先过 `references/diagram-mode.md`（本条规定的是「**优先图形化**」这一取向） |
| ㉑ **构图平衡与视觉重量** | Y3 出页 | 判断 | 画面**视觉重量**均衡 —— 大块浅色与小块深色可等价，避免一侧压死一侧发飘；出现「头重脚轻 / 一边倒」时用**体量 / 留白 / 元素位置**配平（**不是**强行居中） |
| ㉒ **留白经营** | Y3 出页 | 判断 | 留白是**设计元素**不是剩余空间 —— 用四周呼吸边距与元素间距**分组、分区、定节奏**；留白要**有意为之且成比例**，既不留大片无意义空白、也不用元素填满每一寸 |
| ㉓ **版式节奏与多样性** | Y3 出页 | 判断 | 全稿版式**有变化不单调** —— 在**统一母版**下轮换版式族（图文分栏 / 大图 / 金句页 / 数据页），不每页同款；但**变的是布局、不变成风格**（字体与色板仍统一） |
| ㉔ **装饰记号系统化** | Y3 出页 | 判断 | 若用装饰（编号 / 引线 / 分隔符 / 角标 / 进度点），须**成套且跨页一致**、且**承载信息或层级**（不是纯点缀）；**只作无信息量的纯装饰即违反 ⑦ 降噪** |

> ⚠️ **五条易混的边界（防「原则打架」）**：① **㉒ 留白 vs ⑱ 饱满度（同一枚硬币）** —— **留白是「分组与呼吸」的手段，饱满是「不留无意义空白」的目标**；判法同一句：*「这块空白是在分组 / 引导视线，还是只是没内容可放？」* —— 前者即留白（留且成比例），后者即补内容或收边。**两者都不许把版心塞满、也都不许满版发空**。② **㉔ 装饰 vs ⑦ 降噪** —— 装饰**承载信息或层级**（编号 / 进度 / 归属 / 引线）即留、且要成套；**纯点缀**（无信息量的飘带 / 光斑 / 图标）才归 ⑦ 删。③ **⑱ 饱满度 ≠ 违反 ⑦ 降噪** —— 降噪删的是**无信息量**的装饰，饱满度要求的是**有信息量**的内容落满版心；判法同一句：*「这个元素删了会损失信息吗」* —— 会损失就留且要摆好，不会损失就删（**要「不空」，不是要「堆」**）。④ **⑰ 色彩体系不越权改母版** —— **色板定义**归 ① 母版定制（Y2 定盘时定死），本组只规定其**用法**。⑤ **本组只判效果、不判手法** —— 用布尔 / 蒙版 / 渐变 / 等轴测哪种工具**不作要求**；**⑳ 图形化**只说「优先图形化」这一取向，「**这张图该不该画、画成哪类图**」仍唯一归 `references/diagram-mode.md`（本组不越权）。

## 10. 自检 9 项（纪律项，**机器不校验**）

1. Y0 的五问是否**逐问有答案**，还是默认了「受众= reviewers」这类没问过的假设？
2. Y1 是否**只选一个路由 + 一个档位**，并写了**被否掉的路由与理由**？
3. Y2 是否**明确选择了**自由设计或既有模板，而不是让执行方替用户决定？
4. 是否**未代答**任何 `⛔ BLOCKING` 门与确认门（Y-c）？
5. 是否发生过**静默降级**（换素材 / 少做页 / 改路由）而未声明（Y-d）？
6. E2 的**页表与主张对齐**是否逐页作答，且**一页一主张**？
7. E4 是否**出示了校验器的实跑原始输出**？未跑的那几项是否如实写成**未检测**而非通过？
8. §6 的 E6 是否守住 —— 有没有为了「让它更好用」而动过 `ppt-master` 目录内的文件？
9. **观感复检（承 §9 C 组）**：逐页过一遍 —— 画面是否**既饱满又不拥挤**？形状语言是否**成套**（圆角 / 描边 / 投影三层次一致）？图片是否**统一色温**而非张张不同调？色彩是否**主辅强调三档、且强调只给一个真焦点**？（纪律项，机器不校验）

## 11. 诚实边界（原样遵守，勿夸大）

1. **本模块不新增门禁**：**无 plan 字段、无 judge 判定层、无 `checks.py` 判据、无脚本**。理由三条：① 「这是不是要做一份演示文稿」比「这是不是一道题」**更易混淆**（一句"帮我弄个汇报"即可命中，也可能只是要大纲）；② 若落新判据字段，按本仓 v4.14.0 口径它在 L2 缺省判 FAIL ⇒ 此后每个 L2 任务都多一处必填结构，而收益（识别准确率）**无机器 oracle 可验**；③ 真正能机器验的部分（几何 / OPC / 往返一致）**已由 `ppt-master` 自带校验器覆盖** ⇒ 本模块只要求「跑并出示」，**不新起一套**。故 §6 六条义务与 §10 九项自检**都是纪律项**，**不得**宣称「已自动拦截」。
2. **机器验收的覆盖是借来的**：§4 可验层的判据实现**全部在 `ppt-master` 内**（及本仓既有的审美判据集），本模块不新增判据、也不保证其校验器覆盖了全部呈现风险（例如「这页信息量是否过载」无机器判据）。
3. **安装形态是零拷贝的目录联接，代价是单点依赖**：`ppt-master` 本体在 `~/.codex/skills/ppt-master`，WorkBuddy 侧只是联接。**该目录被移动或清理，本模式立即失效**；反之它被上游更新，本模式会跟着变（**不锁版本**，故 E1 的版本号必须**每次实读**、不得沿用本页写的 6.6.0）。
4. **「已被宿主技能索引识别」尚未端到端验证**：本任务实测到的是「联结路径下入口文件可读、frontmatter 可解析、其完整性门禁实跑通过」；**宿主加载器是否把它当一等技能列出，未验证**。调用时若索引未命中，**按路径直读其入口文件**仍然可行。
5. **本模块不代跑业务链路**：`ppt-master` 的端到端生成需其依赖与（出 AI 图时的）外部模型 API Key。**凭据不落盘、不入记忆、不打印**；未配置则走无图路径或由用户自备素材。
6. **触发识别是纪律项**：「这是不是要出一份演示文稿」**无法机器判定**。
7. **与 `pptx-authoring` 的让渡是口径决定、不是能力评估**：本次**未**对两者做同场景产出质量对照；「全面接管」是用户 2026-10-09 的选择，不代表已实测 `ppt-master` 在本机优于 `pptx-authoring`。降级通道（§7）因此保留。
8. **本页是纪律项契约**：`SKILL.md` 侧的判定口径、触发词与索引行已同批写入，`references/external-skills.md` 侧已登记来源与账本，否则会出现「手册在、入口不在」的悬空承诺。
9. **文案去味借的是本仓既有判定，不是外部技能**：`humanizer`（外部）只提供**改写手法**；「这篇 PPT 文案有没有 AI 味、够不够」的**判定唯一在本仓**（`humanize_scan.py` ＋ `meta.文风判定`）。**不得**把外部技能的通过当作本仓判定的通过。
