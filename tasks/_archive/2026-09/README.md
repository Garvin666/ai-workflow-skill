## 二、为什么没有归档最旧的 `技能增强-ai-workflow-v2.4.3-2026-09-10`

它比上面 6 个都旧，但**被 `references/ops.md` 以反引号路径引用**：

```
tasks/技能增强-ai-workflow-v2.4.3-2026-09-10/_test_server.py
```

`checks.py skill` 的「文档引用完整性」会扫 `SKILL.md` 与 `references/*.md` 中**反引号包裹、
后缀为 md/yaml/py/ps1** 的路径，再用 `skill_dir/ref` 做**存在性校验**。归档 v2.4.3 会
**直接导致自检 FAIL**（引用指向 `references/ops.md` 的 403 分类实测证据）。

> ⇒ **切分线：2026-09-10 的任务归档，保留 v2.4.3 原位；2026-09-11 起全部保留。**
> 归档后实测：`checks.py skill` **19/19 FAIL=0**、`checks.py status` **无 WARN**。

**这条教训的普适性**：归档**不是纯粹的文件移动**，它是有外部约束的破坏性动作。
动手前必须先扫「谁引用了这个目录」。
