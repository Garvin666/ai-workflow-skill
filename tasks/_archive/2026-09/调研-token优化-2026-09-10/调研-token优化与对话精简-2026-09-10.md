## 三、面向 Agent / 工作流项目的落地建议（按性价比排序）

**组合拳参考**（awesome-llm-token-optimization 结论）：缓存前缀（90%）+ 路由（60-95%）+ 批量（50%）+ 压缩（5-20x）+ 响应缓存 = 对朴素方案省 95-99%。

1. **第一步（零成本，今天就能做）**：重排 prompt 结构——系统提示词/工具定义等稳定内容放最前，动态内容放最后；把 DeepSeek 调用保持前缀一致吃磁盘缓存，Anthropic 调用加 `cache_control`。仅此一步 agent 场景实测省 78%。
2. **第二步（改造 agent 记忆）**：跨会话记忆接 **Mem0 / OpenMemory（本地版）**——免费、Apache-2.0、65k star 最活跃，且在低 token 预算下基准领先；这与你的 Agent 第二大脑三层记忆架构思路完全同构，可直接借鉴 Mem0 的"抽取→去重→按需检索"管线。
3. **第三步（会话内精简）**：长工具输出/长 RAG 上下文接 **Headroom（MCP server 形态）**或 **LLMLingua-2 多语版**；对话历史用**热/温/冷三层滚动摘要**，每层压缩控制在 40-60%，**切忌压到 90%+**（会触发重取，总成本反升）。
4. **第四步（网关统一管理）**：多模型工作流上 **LiteLLM（≥1.83.7）**或 **Bifrost** 做路由+预算+缓存统一层；高频简单任务分流到便宜模型。
5. **避坑清单**：
   - RouteLLM、GPTCache、Memobase 均已停更或半停更，只参考思路，不作为新项目依赖；
   - 语义缓存阈值过低会"答非所问"（0.85 以下危险），生产建议 0.90-0.95；
   - 路由省的是调用费，但质量回退会带来重试/返工成本，**度量口径应是"每成功任务成本"而非"每次调用成本"**。
