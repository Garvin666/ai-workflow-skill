## 4. 两条假 PASS 通道（我亲手复现的原始输出）

夹具建在 `~/.workbuddy/cache/ai-workflow/verdict/`（缓存例外白名单内）。

**夹具 A —— 测 `~/.workbuddy/<p>` 通道**
```
目录内文件：plan.yaml（交付物 skills/ai-workflow/scripts/setup_env.ps1 在目录内不存在）
[ OK ] Anti-drop 对账 — 已完成步骤 1 个，交付物确认 1 个
=== 结果：7/7 通过，FAIL=0 ===
```

**夹具 B —— 测 `base.parent/<p>` 通道**
```
child 目录内文件：plan.yaml（交付物 target.md 在 child 内不存在，实际位于其上级 parent/）
[ OK ] Anti-drop 对账 — 已完成步骤 1 个，交付物确认 1 个
=== 结果：7/7 通过，FAIL=0 ===
```

**根因**（`scripts/checks.py:166`）：
```python
return [base / p, Path.home() / ".workbuddy" / p, base.parent / p]
```

- `Path.home()/".workbuddy"/p`：**这不是"用户主目录"**（注释如此写），而是 `~/.workbuddy/`。当交付物写作 `skills/<技能>/…` 时，该候选会命中 `~/.workbuddy/skills/<技能>/…`——**与 R6 原缺陷同型**，只是把「遍历所有技能目录」换成了「固定前缀」。故 R6 的"**彻底移除**"表述不成立。
- `base.parent/p`：按文档用法 `--base <工作区根>` 时，`base.parent` = **工作区根的上级**，使交付物落在边界之外也能判 PASS，与红线③直接冲突。

> 设计取舍提示：`base.parent` 在「`--base` 传任务目录」的老用法下是有意义的（便于交付物写相对工作区根的路径）。修的时候须兼顾——不能简单删除而不改文档口径。
