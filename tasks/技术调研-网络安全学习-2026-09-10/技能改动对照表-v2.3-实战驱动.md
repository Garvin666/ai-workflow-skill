## 二、关键改动明细

### 1. checks.py：修「假绿」（最严重）

**症状**（实测复现，用非 venv 解释器）：
```
[ERROR] 缺少 pyyaml，请先运行 scripts/setup_env.ps1 安装依赖
=== ai-workflow 计划对账 ===
=== 结果：0/0 通过，FAIL=0 ===     ← 误导性结论
EXIT=0                            ← 调用方判定"通过"
```

**根因**：`check_plan()` 正确 `return 2`，但 `main()` 第 392 行 `return 1 if n_fail else 0` 把 `code` 吞掉；且 `results` 为空仍打印汇总行。

**修复**：
```python
# 新增依赖守卫（load_plan / check_plan 共用）
def _require_yaml():
    try:
        import yaml
    except ModuleNotFoundError:
        print("[ERROR] 缺少 pyyaml，请先运行 scripts/setup_env.ps1 安装依赖", file=sys.stderr)
        print("[HINT ] 若 venv 已建好，请直接用 venv 解释器运行：", file=sys.stderr)
        print("        ...\\envs\\ai-workflow\\Scripts\\python.exe checks.py ...", file=sys.stderr)
        raise SystemExit(2)
    return yaml

# main()：不再吞错误码 + 未执行不报"全绿"
if code != 0 and not results:
    print("=== 结果：未执行（环境或输入不满足，见上方 [ERROR]）===")
    return code
print(f"=== 结果：{len(results) - n_fail}/{len(results)} 通过，FAIL={n_fail} ===")
return 1 if n_fail else code
```

**修复后实测**：错误解释器 → `EXIT=2`、无"全绿"行；正确解释器 → `6/6 通过`、`EXIT=0`。

### 2. Anti-drop 首次在真实任务上证明价值

plan.yaml 中 step 4 曾被标为「完成」，但 `网络安全学习进度表.xlsx` **并不存在**。对账输出：
```
[FAIL] 步骤 4 交付物缺失 — tasks/.../网络安全学习进度表.xlsx
=== 结果：6/7 通过，FAIL=1 ===
```
补生成后 → `6/6 通过，交付物确认 5/5`。**结论：标"完成" ≠ 已交付，必须落到文件系统校验。**

### 3. 交付前置动作：外链必探活

实战中拦下 1 条会交付出去的死链：`https://owasp.org/www-project-zap/` → 404（来自子代理转述），修正为 `https://www.zaproxy.org/` 并复测 200。
→ 已写入 SKILL.md 第 5 条硬规则 + quality-gates 反模式第 20 条。
