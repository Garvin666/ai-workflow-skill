## 四、与 superpowers 的对照（取什么、不取什么）

参照对象：`obra/superpowers`（286,871 star，MIT，pushed 2026-09-14）。

| superpowers 机制 | 本技能处理 | 理由 |
| --- | --- | --- |
| **强制前置检查**（1% 可能适用就必须调用） | ❌ **不取** | 与用户 2026-09-11 定稿的「最高准则」（流程是手段不是目的，由模型自判）**直接冲突**；照搬会推翻既有准则 |
| 反合理化红线表（12 条） | ✅ **取其形、改其义** | 改造为「拦『没想清楚』」而非「拦『没调用』」；8 条 |
| 声明制（announce "Using [skill] to [purpose]"） | ✅ 取 | 一行声明，同时作为决策留痕原始素材 |
| 优先级（process 先于 implementation） | ✅ 取 | 落为「方法先于执行」「只读先于写入、本地先于联网」 |
| 按需加载 / progressive disclosure | ✅ 取（本技能原已具备） | 新手册明确标注「按需加载，勿预读」 |
| `SUBAGENT-STOP`（子代理不吃这套） | ✅ 取 | 落为「子代理只回传浓缩结论」（`orchestration.md` 已有） |
| writing-plans 的「右尺寸 / 咬合粒度」 | ✅ 取并适配 | 落为拆解四规则第 1、4 条 |
| executing-plans 的「遇阻即停、不硬闯」 | ✅ 取 | 与本技能既有「受阻即登记、熔断」一致 |

## 六、独立审核发现与返修（v3.0.0 收尾）

审核者：**未参与本次改造**的子代理，全程只读（技能目录零改动，测试数据写在临时目录）。审核要求其逐条核验"文档声称 ↔ 代码实现"，并亲手造 fixture 验证门禁真伪。

**审核通过的部分**：门禁真实生效（自造 5 组违规全部 FAIL）、零回归（新旧脚本逐 plan 比对，FAIL 集合 0 处不同）、红线与熔断机制逐字节未改、回滚清单无遗漏（返修前）。

**审核发现并返修的 5 个问题**（全部是"描述与实现脱节"，属本技能已记录的结构性弱点）：

| # | 问题 | 返修 |
| --- | --- | --- |
| **P1** | 文档两处写 `checks.py mark --revise` —— 该参数**不存在**（实为独立子命令 `checks.py revise`），照文调用直接 argparse 报错 | `SKILL.md` 与 `adaptive-planning.md` 两处改为 `checks.py revise` |
| **P2** | `decide` 文档用法未列 `--choice`，而门禁强制其非空 → **照文档执行会被自家门禁判 FAIL** | `--capability` 与 `--choice` 均改为 `required=True`；SKILL.md 命令行补全四参数并注明"均必填"；新增 T6 阴性对照验证 |
| **P3** | 模板新增 `steps[].决策依据` 在 `checks.py` 中零引用；本任务原验收标准「缺决策依据必 FAIL」对 steps 级**不成立** | **删除该字段**（避免假机制）；原验收标准经 `checks.py revise` 记为计划修订（R2）并更正 |
| **P4** | 门禁 FAIL 文案称"每项含 5 个字段"，实际只强制 3 个 | FAIL 文案**改由 `DECISION_KEYS`/`REVISION_KEYS` 常量生成**（单一事实源），并把"能力类"补入必填 |
