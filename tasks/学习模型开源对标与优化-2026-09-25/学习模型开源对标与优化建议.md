# 学习模型 · 开源对标与设计优化建议

> **范围**：对 `ai-workflow` v4.8.0 新增的**学习模型**（`learning-model` / `learning-judge` / `kb_learn.py`）做开源对标 —— 拆解业界设计理念，找出可迁移原理，并给出分级优化方案。
> **检索时间**：2026-09-25（star 数为当日快照）。
> **方法**：`gh search repos` 多路检索（8 组关键词 + 3 组 topic）→ 按「与你的模型同构度」筛出 **16 个仓库** + **2 篇论文** + **1 个综述** → 拉取 README 精读 → 逐条对照**代码实现**（不是只对照文档）。
> **一句话结论**：**没有可直接替换的项目** —— 业界主流是「记忆存取基础设施」，你要的是「知识收敛管线」，两者不同物种；但**每一个环节都有可迁移的成熟原理**。最值钱的发现不在"缺什么新功能"，而是**三个「声称有、实际不可达」的失效**（本轮已用探针取证），其中一条会让**互相矛盾的结论双双入库**。

## 0. 摘要：三句话

1. **你的两条核心设计是对的，而且被业界验证过**：①「语义归类归模型/人、算术归代码」= 业界共识（tigerless 的 "No LLM client inside the library — judgement is borrowed from the host agent"，cognee 的 "LLM-dependent improvement stages skip automatically"）；②「两段式入库」= 业界四种同构方案（cognee 的 *accepted lessons*、reflect-skill 的 *human gate*、tigerless 的 *authority tiers*、caura 的 *trust tiers*）。**这两条不要动。**
2. **真正的缺口是三样：时间维度、废止路径、暴露率验证。** 三者都有一个共同特征 —— **缺失时不报错**，只是慢慢地把库污染掉。本轮取证证实：你的「冲突检测」在真实运行中**不可达**（两条相反结论会同时进"入库"桶）。
3. **可迁移原理共六条**（§2），其中最值钱的两条是：**「按动作危险度分级」而不是只按置信度分级**（删除/废止必须比新增更难），以及 **「沉默必须与通过可区分」**（防"功能性失效伪装成正常运行"——这正是你本轮已经踩过两次的坑的通用解法）。

## 2. 拆解：八条设计原理

### 原理 1 · 分层蒸馏，而不是一次抽干
**出处**：`TencentDB-Agent-Memory` 的 `L0 Conversation → L1 Atom → L2 Scenario → L3 Persona`（"raw conversations are distilled layer by layer"）；`OpenViking` 的 `L0 摘要 / L1 概览 / L2 全文`（"judge relevance **before** opening full content"）；`claude-mem` 的 Progressive Disclosure；`tigerless` 的五级读取（索引行→摘要→提纲→全文→原始消息，"每一级的成本比上一级高一个数量级，且每一级都是一个可以停下的地方"）。

**对照你的模型**：K3 的"精炼骨架"是把一条经验压成**单层**的四段（【结论】【依据】【证据】【适用边界】）。方向对（结构化 + 强制边界），但**没有"先摘要再下钻"的分层**，压完就只剩一句话。

**有实证的警告**：`LongMemEval` 的 **Finding 1** 明确指出 —— **round（回合）才是最佳存储粒度；进一步压缩成单个"用户事实"会因信息损失损害整体性能**（只在多会话推理上略有改善）。你的"【结论】一句话可独立读懂"正是那种"单个事实"压缩。

> **可迁移**：结论层与证据层**分列**（你已有【依据】字段，但依据是"指针"而不是"内容"）；池条目保留**原文快照**，而不是只留 `sha1` 指纹（见 §4-B、§5-P0-3）。

### 原理 2 · 时间不是可选项（有效期 / 废止 / as-of）
**出处**：`tigerless` 用 `valid_from` + `invalid_at` 定义有效期，**"Supersede leaves the chain intact and `recall --as-of` answers as of a date, so updating never destroys"**；`projectmem` 的 `--supersedes` 配一句经验教训 —— **"A retired decision no longer resurfaces. `supersedes` has existed since <早期版本> … documents how to retire one, which is why models never called it."**（有废止能力但没写文档 ⇒ 模型从不调用）；`mem0` 把 *Temporal Reasoning* 列为新算法五大改进之一；`LongMemEval` 把 **Knowledge Updates** 与 **Temporal Reasoning** 列为核心能力之二。

**对照你的模型**：`pool.jsonl` 只有 `first_seen` / `last_seen`（观测时间），**没有知识本身的有效期**，也没有任何"这条被推翻了"的表达。KB 文档 id = `learn-<key>`，**改措辞 = 新 key = 新文档**，旧文档不会失效。

> **实证危害**（见 §4-A/§4-C）：语义等价或相反的两条会各自独立存在；**被推翻的旧结论继续被 KB-First 检索命中**并注入此后每一次任务 —— 这正是 `reflect-skill` 警告的 **"one wrong or hallucinated line becomes permanent and poisons every future session"**。

### 原理 3 · 去重必须是语义级，不能是字面级
**出处**：`telemem` 的 pipeline 第二段就是 **semantic clustering deduplication**（"Uses LLMs to semantically merge similar memories, reducing conflicts and improving consistency"）；`A-mem` 用向量近邻建链；`ACE` 提供 `[deduplication]` extra（embedding-based）；最强的是 `LongMemEval` **Finding 2** —— **用抽取出的"用户事实"扩展索引键**，比"用记忆原文当键"的平面索引：recall@k **+4%**、下游准确率 **+5%**。

**对照你的模型**：`key = sha1(normalize(text))[:12]`，`normalize` 只做空白/标点/全半角/大小写折叠 —— 是**纯字面哈希**。

> **实证**（§4-B）：`报告里不要加 emoji` 与 `不要在报告中使用表情符号` **各自独立成条**。⇒ 池内去重只防"换标点"，不防"换说法"；同一偏好以不同措辞出现时，`evid_count` 被**稀释**在多个 key 上，**各自都够不到门槛** ⇒ 该学的学不到（这是"漏吸"型失效，方向与 §4-A 的"错吸"相反）。

### 原理 4 · 按动作危险度分级，而不是只按置信度分级
**出处**：`tigerless` 的 **authority tiers** —— **"an unattended pass may add and update, deletion only ever arrives as a proposal you confirm"**；`caura` 的 *trust tiers / keystone policies / audit trails*；`reflect-skill` 的 **human gate** —— "the safety property is that the agent can *suggest* freely but can *commit* nothing on its own. **Proposals are cheap and reversible; promotion is deliberate and owned by you.**"；`cognee` 的 *accepted lessons*。

**对照你的模型**：你的两段式是**按置信度**切的（`≥0.85` 自动 / 其余观察）。方向对，**但缺一个维度**：你的"自动"路径里**只有"新增/更新"**，没有"删除/废止"这个**明显更危险**的动作 —— 而业界所有成熟方案都把它单独拎出来，**一律走提案**。

> **可迁移**：置信度决定"**加**不加"，危险度决定"**删**不删"。这两个判据正交，不应混成一根轴。

### 原理 5 · 「漏了」不等于「丢了」
**出处**：`tigerless` 的一条明确不变式 —— **"Write coverage is the system's job, not the agent's judgement. Distillation is triggered at boundaries and runs without holding up the task; the full trace is copied first, so *'missed by the distiller' never means 'lost by the system'*."**；`projectmem` 同向 —— **"AI never reads `events.jsonl` directly. That file is for tools… Tools distill the raw log into compact AI-readable summaries."**（AI 只读蒸馏物，原始日志由工具保管且**永不重写**）。

**对照你的模型**：K1 的克制品格是**"只读索引与指针，不整读历史任务正文"** —— 效率上完全正确（你甚至把它写成了"主动克制"纪律）。但缺一步：**先把命中的原始证据固化下来**。你的 `sources` 只是**指针**（任务目录 / 实测输出路径），一旦那些留痕被归档、被清理（你已有 `tasks/_archive/` 归档动作与 `tmp/` 清理习惯），**指针断裂 = 证据永久丢失**，而池里那条只有一句话结论、无法复核。

> **可迁移**：**先复制证据，再蒸馏结论**。让"蒸馏器漏了"退化成"系统还留着"，而**不是**"系统丢了"。

### 原理 6 · 「沉默」必须与「通过」可区分
**出处**（三条实证）：
- `projectmem`：`precheck --snooze 2h` 暂停警告时 —— **"the pause itself is logged, and every commit shows one dim line so silence is never mistaken for a clean check."**
- `memU`：`detect` / `doctor` —— **显式探测"记忆化能不能工作"（有没有可识别的会话日志）与"检索能不能工作"（有没有可 patch 的指令文件）**，而不是假定已装上就等于已生效。
- `tigerless`：**"An enabled setting, a prompt instruction, or a tool call with zero hits does not show that the intervention was used."** + **"report the exposure rate alongside scores"**（把「暴露率」作为与分数并列的必报项）。

**对照你的模型**：你**本轮已经踩过两次同型失效** —— ① `τ = 0.35` ⇒ softmax 的 `max` 结构上不可达 0.70 ⇒ `band` 恒 `hold` ⇒ **整条管线永不吸收任何条目**；② `Path.home()` ≠ 真实 KB ⇒ **KB 恒判不可用**。两次都**不报错、不 FAIL**，是"伪装成运行正常"的失效。

> **你已经找到了解法的一半**（结构性断言 + 候选路径探测），但**只在 `selftest` 里有**。运行时**没有任何机制**回答"这次的管线到底生效了吗"。`projectmem` 与 `tigerless` 的答案是：**把"没发生"也记下来**，并**报告暴露率**。

### 原理 7 · 反射与预计算（把"每次都要查"变成"读一页"）
**出处**：`hindsight` 的 **mental models / knowledge pages** —— **"A *mental model* is a standing answer to a question about a bank ('What are this user's preferences?'). You define the question once; Hindsight writes the answer, stores it, and rewrites it in the background as the bank learns more. **Reading one is a database read — no retrieval, no LLM call** — so an agent can boot with a page of settled knowledge instead of rediscovering it every session."**；`hindsight` 的 **reflect** 操作（"form new connections between memories"）；`A-mem` 的 **Memory Evolution**（新增记忆时**反向更新**旧记忆的 metadata/context）；`letta` 的 sleep-time compute（空闲时预计算）。

**对照你的模型**：写入侧（K5）做得比读取侧充分。**读**仍是每次开工现检索（`kb.py retrieve`），没有"预计算的稳定答案页"。你的 `meta.学习判定.入库/候选` 是对账字段，不是检索加速器。

> **可迁移**（P2，非紧急）：对高频问题（如"使用者的报告偏好是什么"）维护一页**预计算答案**，收尾时重写；读取零成本。这同时解掉 `LongMemEval` **Finding 4** 的一半问题（"即使 recall 完美，**读**准仍然非平凡"）。

### 原理 8 · 评测要可复现，而不是宣布不可测
**出处**：`mem0` 公开 LoCoMo 92.5 / LongMemEval 94.4 / BEAM，并**开源评测框架** `mem0ai/memory-benchmarks`（"so anyone can reproduce the numbers"）；`hindsight` 声称 SOTA 且**声明被 Virginia Tech 与 The Washington Post 独立复现**（"Other scores are self-reported by software vendors"）；`tigerless` 的评测纪律最值得抄：**配对比较**（+37/−17, **p=0.009**）、**明确声明"绝对数值与已发表的 LongMemEval 分数不可比"**（因为 haystack 有界）、**明确声明系统间比较"licenses no attribution to either half"**、以及上面那条 **"report the exposure rate"**；`cognee` 的 BEAM 报告**主动登记"剩余复现缺口"**。

**对照你的模型**：§7.3/§7.4 的立场是"阈值未拟合、**不得**声称准确率、'学到了对的东西'没有机器判据"。

> **评价**：态度比业界更诚实，但**走到了另一个极端** —— "不可测"被当成了终点。`tigerless` 给出了中间路线：**不做拟合，也能有可复现的回归证据**（对照臂 + 配对检验 + 明确声明可比边界 + 报暴露率）。你的模型缺的不是"准确率"，而是**"改一次参数后，我能不能知道它没退化"**。

## 4. 本轮代码取证：三个「声称有、实际不可达」的失效

> 方法：沙箱池 + 独立子进程复核 + 阳性对照。原始输出：`tmp/probe_findings.txt`；脚本：`tmp/probe_hidden_failures.py`。

### A. `state="冲突"` 在真实运行中**不可达** ⇒ 两条互相矛盾的结论**双双入库**

**取证输出**（对 `方案 A 可行` 与 `方案 A 不可行` 两条）：

```
① 两条矛盾结论 → 两个不同 key（3b9097158606 / cbf299f9acf8）
② commit（dry-run）：
     入库 : 2 条  ['方案 A 可行', '方案 A 不可行']
     观察 : 0 条
     冲突 : 0 条        ← 应为 2 条
③ 函数级：evaluate(state=观察) → "入库"；evaluate(state=冲突) → "冲突"
④ 静态搜索：CLI 中 '--state' 出现 0 次；把 state 赋值为"冲突"的代码 0 处
```

**根因是循环依赖**：`evaluate()` 的冲突分支（`kb_learn.py:459`）条件是 `if cand.get("state") == "冲突"` —— **要进这个分支，条目必须已经是"冲突"状态**；而让它变成"冲突"的唯一途径就是**走进这个分支**。全程序**没有任何赋值入口**（`cmd_note` 新增时硬编码 `state="观察"`，也没有 `--state` 参数）。

**后果**：手册 §4.2 门槛 5「不与非本任务证据冲突」与 §4.3 第 4 条「冲突检测」**是死代码**。更糟的是方向 —— 不是"漏判冲突"，而是**两条自相矛盾的知识被同时判为「入库」**（如上：可行 / 不可行 双双入库）。这与 `reflect-skill` 警告的失败模式完全一致：**一条错的线会永久污染每个未来会话**，而你这里会同时污染两次。

> ⚠️ **与 τ 过大同型**：不报错、不 FAIL、看着正常。**这是 v4.8.0 的第三个同型失效**，而且是最严重的一个。

### B. 池内去重是**字面级**的 ⇒ 语义等价的不同表述**各自独立**

```
① 阳性对照（仅标点差异）：'报告里不要加 emoji。' vs '报告里，不要加emoji' → 合并，evid_count=2   ✅ 生效
② 阴性探针（语义等价）：'报告里不要加 emoji' vs '不要在报告中使用表情符号'
     → 两个独立 key（bbf106196492 / 774674099a42），第二条 action="新增"                    ❌ 漏网
```

**后果**：同一偏好换措辞出现时，证据计数被**稀释**在多个 key 上，**每一条都够不到 `偏好 ≥2` 的门槛** ⇒ **该学的学不到**。注意这与 §4-A 方向相反：A 是"错吸"（不该进的进了），B 是"漏吸"（该进的进不来）。手册 §4.1 说「`key` 的稳定性是去重的地基」—— 这句话**只对措辞差异成立**，对同义改写不成立，而后者才是真实语料的常态。

### C. 零「废止 / 失效」路径 ⇒ 被推翻的结论继续被检索命中

```
kb_learn.py 中：'supersede' 0 处；'废止' 0 处；'retire' 0 处；'invalid_at' 0 处；'valid_from' 0 处；'衰减/decay' 0 处
KB 文档 id 生成式：kb_id = 'learn-' + key  ⇒ 改措辞 = 新 key = 新文档，旧文档不失效
```

**后果**：`kb.py delete --id learn-<key>` 这条**手工**撤销路径存在（你的 §5 回滚段写了），但**没有任何自动或半自动路径**。现实中"偏好变了""结论被证伪了"是常态，而**旧文档会一直在库里被 KB-First 命中**。

> 这完全复现了 `projectmem` 记录的那条教训：**有能力、没路径、没文档 ⇒ 模型从不调用**。

## 5. 优化方案（分级 + 具体改法）

> **共同纪律**：以下每一项都遵守你的既有红线 —— 语义归模型/算术归代码；不自动改技能本体；阈值只写一处；**任何软化/新增判据都要配阴性对照**。

### P0-1 · 让「冲突」真正可达（修 §4-A）

**设计**：语义判定不可机器化，所以**判定仍在模型**，但脚本提供**确定性的成对登记与冻结**：
- `kb_learn.py note` 新增 `--contradicts <text|key>`；
- 脚本用 `cand_key` 定位被指向的条目，**双向**标 `state = "冲突"`（新条目 + 旧条目各一份，`conflict_with` 互指），并**冻结双方**（两者都不得入库，即使门槛全过）；
- `decisions.jsonl` 记 `action="冲突登记"` + 双方 key（供回滚）。

**为什么这样切**：把"判断两条是否矛盾"留给模型（语义），把"登记/冻结/留痕"留给脚本（确定性）。这与你已有的分工完全同构。

**验证**：`selftest` 加两组 —— 正向（`--contradicts` 指向条 ⇒ 双方 verdict 均"冲突"、均不入库）+ 阴性对照（不给 `--contradicts` ⇒ 仍按原门槛入库）。

**影响面**：`kb_learn.py` + `references/learning-model.md` §4.3 第 4 条（把"声称"改成"可达的实现口径"）+ `learning-judge.md` 的 `route_hint`（冲突分支）。**不改枚举**，故口径守卫三源不受影响。

### P0-2 · 新增「废止」动作，且**永远走提案**（修 §4-C）

**设计**（照 `tigerless` 的 authority tiers 切）：
- `note --supersedes <text|key>` ⇒ 新条目带 `supersedes` 字段；
- `commit` 时：新条目照走两段式（可能是自动入库），**但旧条目的废止永远不自动执行** —— 写入池侧 `retire_proposals.jsonl`，等用户放行；
- 放行后：KB 侧优先 `kb.py update`（若有）改写为"⚠️ 已废止，替代条目 `learn-<newkey>`"；保守做法是**保留旧文档但加废止标记**（不删 —— 与 `tigerless` 的 "updating never destroys" 一致，也保住审计链）。

**关键点**：**新增/更新可以自动（按置信度），废止/删除一律提案（按危险度）** —— 这是原理 4 的落地。

**影响面**：`kb_learn.py` + 手册 §5 新增一行 + 池目录新增一个文件。

### P0-3 · K1 增加「证据固化」（修原理 5）

**设计**：`note` 时把 `--source` 命中的留痕**片段**（或用户原话，已脱敏）一并写入池条目 `evidence_snapshot`（**截断保长度上限**，如 800 字符/条），并追加写池目录 `archive/<YYYY-MM>.jsonl`。
- 这样即使原任务目录被归档/清理，**证据仍在池内可复核**；
- 与你的敏感纪律一致：`evidence_snapshot` **同样过 `scan_sensitive`**，命中即整条驳回。

**影响面**：`kb_learn.py` + 手册 §4.1（池结构表加一列）。

### P1-1 · 语义近邻检查（修 §4-B，**不改 key**）

**为什么不能改 key**：`key` 必须**稳定且可复现**（它是幂等的锚），改成语义哈希会把不确定性引入地基。正确做法是**保留字面 key，另加一道语义近邻关卡**：
- `commit` 复用 **`kb.py retrieve` 同一引擎**（这正是你 `kb_search_duplicate` 已有的做法）做**池内**近邻：新条目落池时检索池内已有条目，最高分 ≥ `DUP_THRESHOLD` ⇒ 提示"疑似同义，可合并"并**输出对照的双方 key**，由模型/人决定是否 `--merge-into <key>`；
- **不引入任何新依赖**（复用既有引擎），也**不自动合并**（语义合并是 LLM 的活，脚本只报候选）。

**影响面**：`kb_learn.py`（复用现成函数，改动小）。

### P1-2 · 时间字段（修原理 2 的读侧）

池条目与 KB 文档增加 `valid_from`（首见即为 valid_from）与 `superseded_by`（废止后回填）。**先只加字段与留痕，不参与门槛** —— 门槛改动须等有回归证据（§5-P2-2）再做。

### P1-3 · 运行时暴露率（修原理 6）

`commit` 输出固定增加一段**暴露率报告**：
```
{ "管线生效": {"进池": N, "达门槛": M, "实际入库": K, "留观察": X, "冲突冻结": Y, "驳回": Z},
  "空跑告警": "本次 K4 判定全为『观察』且有 M>0 条因同一原因被挡 ⇒ 疑似门槛配置失效" }
```
理由：把"没发生"显式写出来（`projectmem` 的 "silence is never mistaken for a clean check"）。**特别是**：若某次运行**有候选但零入库且全部卡在同一条门槛**，要主动告警 —— 这正是 τ 过大那类失效的运行时特征。

### P2-1 · 小规模回归验收集（修原理 8）

建一个**不用于拟合、只用于防退化**的验收集（如 20–30 条已标注的历史信号：`text` → 期望 `kind` / 期望去向），跑 `kb_learn.py` 得**对照表**并**配对比较**；报告里**必须**同时给出 ① 样本量、② 每类的错误明细、③ **暴露率**、④ 一句"本集与真实分布不可比"的声明。**唯一用途**：改 `ANCHORS`/`TAU`/门槛后，**证明没退化**。这不违反你"不声称准确率"的纪律 —— 它声称的只是"**相对自己没退化**"。

### P2-2 · mental model 页 + reflect
- **mental model**：对 2–3 个高频问题（"报告偏好是什么""本机环境硬约束有哪些"）维护**预计算答案页**，收尾时用池内条目重写；读取零成本（`hindsight` 同款）。
- **reflect**：收尾时对池内**不同 key 但语义相邻**的条目做一次"关联建议"（只输出建议，不改库 —— `A-mem` 的 Evolution 是自动的，你应取**提案版**）。

## 6. 一处需要你拍板的设计分歧：要不要新增第 5 类「技能」

**业界普遍比你多一类**：`ELL` 四原则里第三是 **Skill Learning**（"abstracting recurring patterns from experience into **reusable skills**, which are actively refined and validated"）；`ACE` 的核心结构是 **Skillbook**；`TencentDB-Agent-Memory` 的四类资产里 **Skill** 是独立一类；`memU` 主打 "**automatically distills your own reusable skills** from your agent history"；`OpenViking` 号称统一 Memory + RAG + **Skills**。

**你的四类是**：偏好 / 领域知识 / 流程坑 / 事实 —— 都是**陈述性知识（know-what）**，**没有一类装"怎么做"（know-how）**。

**但这不能草率照抄**，理由是三条：
1. **会动口径守卫三源**（`learning-judge.md` §1 表 + `data-model.md` §2.2 + `judges.json`）+ 检查项 20 的 `LEARNING_KINDS` ⇒ 属**契约级改动**，须专门立项；
2. **你的 `流程坑` 已经在承担一半**（"踩过的坑与规避法"本身就是 know-how），加"技能"会产生**语义重叠**（一条"绕开 shim 删目录"既像流程坑又像技能）；
3. 你的既定纪律是**不自动改技能本体** —— 而"技能"这一类最自然的归宿**恰恰是技能本体**（`references/` 或某个 scripts），于是"学到技能却只能放 KB"会显得别扭。

**建议**：**先不新增枚举**。可选的低成本替代：在 `领域知识`/`流程坑` 的 `route_hint` 里注明「**若该条已是一条可执行套路，建议走既有第 6 路人工沉淀为技能**（须用户确认）」。等 §5-P2-1 的验收集跑过几轮、确有"技能类被反复错分类"的证据后，再决定是否立项。**不要为了对齐业界而新增物理量** —— 那正是你自己在 `learning-judge.md` 里反复强调的"两根轴不能压成一根"的反面。

## 7. 明确不建议采纳的

| 业界做法 | 为什么不适合你 |
| --- | --- |
| 引入向量库 / embedding 依赖（`A-mem` 的 ChromaDB、`telemem` 的 FAISS） | 违反你的**零新增依赖**；1866 篇规模用 `kb.py` 既有引擎足够；**语义近邻可复用现成引擎**（§5-P1-1） |
| 「每轮对话后自动写」（`Memori` / `claude-mem` 的 after-each-turn） | 你的**收尾回路**（阶段 6）更省，且避免执行期开销 —— 这是你刻意的效率设计，别退回去 |
| 让 agent 自动改写技能本体（`A-mem` 的自动 evolution、Kayba 的 "fixes shipped as PRs"） | 违反你的 §7.6 与红线①；`reflect-skill` 的 human gate **正是支持你的一方** |
| 把累积池当最终存储 | 你已正确区分（池=暂存、KB=真相）；`tigerless` 的 "files are the truth, index is a rebuildable cache" 与你同向 |
| 用 LLM 自动消解冲突（`telemem` 的语义合并） | 与"语义归模型、**算术归代码**"冲突；且自动消解会把不确定性写进长期库。**人工裁决 + 提案**才对 |
| 追求 benchmark 分数（LoCoMo/LongMemEval 的绝对分） | 你的语料是**单用户私有工作流**，与这些合成基准分布不同；照抄分数没有意义（`tigerless` 自己也明确声明不可比）。**只借它们的"评测纪律"，不借它们的数字** |

## 8. 建议的落地顺序

```
第 1 步（P0，修缺陷，不改契约）
  P0-1 冲突可达  →  P0-2 废止提案  →  P0-3 证据固化
  共同点：只动 kb_learn.py 与手册，不动枚举 ⇒ 口径守卫三源不受影响，风险最低
  每项都配 selftest 正/负向断言

第 2 步（P1，增强，仍不改契约）
  P1-1 语义近邻提示（复用 kb.py retrieve）→ P1-3 暴露率告警 → P1-2 时间字段（只留痕）

第 3 步（P2，能力扩展，需先有证据）
  P2-1 小规模回归验收集（先做，它是后面所有门槛改动的安全网）
  → P2-2 mental model / reflect

第 4 步（慎，契约级）
  「技能」类是否新增 —— 等 P2-1 跑出证据再议（§6）
```

**若只做一件事**：做 **P0-1**。它把"手册声称有、代码里不可达"的冲突检测修好，直接堵住"两条矛盾知识同时入库"这个最严重的污染源；成本低（一个参数 + 一处分支 + 两组断言），且**不改任何枚举**。
