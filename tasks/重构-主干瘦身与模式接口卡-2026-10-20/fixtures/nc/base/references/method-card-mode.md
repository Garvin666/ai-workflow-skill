# 方法原理卡片（method-card-mode）—— 科研制图第三通道 · 完整契约

> **本文件的定位**：`references/research-mode.md` §7.11.1 通道表的**第三行**（方法原理卡片）的**细则手册** —— 规定「**卡片长什么样、包含什么、怎么生成、怎么验收**」。通道归属总表、RF1–RF8 配图纪律、输出拨盘仍以 §7.11 为准，**不在此重述**。
> **加载口径**：**R5 出「方法解释图」/ 用户点名「方法卡片 / 算法卡片 / 教学卡片」时加载**；只做一张卡时可按 §3–§5 分节读。
> **与既有节的关系**：本通道是**本仓自建**（契约 ＋ 引擎 ＋ 验收器三件套），**不是**外部上游 —— 与 §7.11 的 `diagram-design`（数据图与示意图的引擎）**无关、不混用**；**不新增** plan 字段 / judge / `checks.py` 判据（承 research-mode §9 同一纪律）。
> **机制来源**：本通道由 v4.35.0 任务建立 —— 版式抽象自用户提供的 21 张「机器学习算法系列」参考卡片。**参考物不复刻**：只抽象出「五区骨架 ／ 暖白纸底配色系 ／ 公式矢量链」三条结构性经验，文案与图形全部自行撰写、程序化生成。

## 1. 定位与形态

| 维度 | 内容 |
| --- | --- |
| **回答什么问题** | 「**这个方法是什么、为什么这么做、怎么一步步算**」—— 一张卡片 = 一个方法的一页讲解 |
| **形态** | **图文复合版面**：页眉 / 核心思想（含公式）/ 4 格步骤分解（含子图）/ 示意区（双视角大图）/ 总结条 —— 卡面 1200×1600（3:4） |
| **产物** | **PNG @2x**（2400×3200，预览与学习）＋ **PDF**（矢量，投稿与打印）；HTML 仅为导出中间载体（**会话内预览可，不作交付承诺**） |
| **与前两通道的关系** | 卡片**不是第四种图** —— 卡内子图仍属「数据图 / 示意图」（读者从子图读数或读关系）；卡片整体是「**被阅读的版面**」（读者读公式、步骤、结论） |

## 2. 触发

命中任一即用本通道：

1. 科研 R5 需要**方法解释图**（论文方法节的教学式解析，或答辩/汇报的方法讲解图）；
2. 用户点名「**方法原理卡片 / 算法卡片 / 教学卡片**」类产物；
3. 学习资料类任务需要「**一图讲清一个方法**」的卡片（本通道用途之一）。

不适用（转对应通道）：单张数据图 / 单张示意图（→ §7.11 前两通道）；演示稿（→ PPT 模式）；方法极复杂时**拆多张卡**（一卡一方法），**不挤进一张**。

## 3. 产出结构（五区，固定，不得增删区）

| 区 | 内容义务 | 常见失败 |
| --- | --- | --- |
| **页眉** | 系列名（左）＋ 卡序编号（#01、#02…）＋ 英文标题（中）＋ 中文标签 ＋ 分类标签（右） | 标题过长挤压侧栏 |
| **核心思想** | **一句话**（含因果链：为什么需要 → 做什么 → 代价是什么）＋ **公式**（LaTeX → 纯 path SVG） | 口号式空话；公式过小 |
| **步骤区** | **4 格版式**（引擎现行固定 4 列）：编号 ＋ 动词短语标题 ＋ 说明 ≤50 字 ＋ 子图 ＋ caption；方法步骤 ≠ 4 时**并小步 / 拆卡**适配 | 步骤写成流程描述而非方法分解；子图无 caption |
| **示意区** | **两张互补视角大图**（如「过程 ↔ 结果」「几何 ↔ 数值」）＋ 方向箭头 ＋ 1 个强调徽章 ＋ 底部对照说明 | 两图是同一视角的重复；徽章与图意无关 |
| **总结条** | **一句话结论**（含适用条件与代价，不吹成万能） | 「非常强大 / 效果很好」式评价 |

> ⚠️ **内容义务的核心是「可核」**：卡片内所有示例数字须**固定种子可复现**，并在交付说明中注明为说明性示例（承 §7 第 4 条）。

## 4. 版式规范（唯一口径源 = 引擎内常量）

| 项 | 值 | 备注 |
| --- | --- | --- |
| 卡面 | 1200×1600 px（3:4） | 导出 @2x = 2400×3200 |
| 设计令牌 | 16 槽（纸底 / 分区底两级 / 描线两级 / 墨色三级 / 主蓝两级 / 暖色两级 / 砖红 / 米色 / 灰填充） | `scripts/methodcard_lib.py` 的 `TOKENS` 为**唯一源**（取值 = 参考图脚本采样 ＋ 目视校正，采样证据存建立任务的 fixtures） |
| 字体（标题） | **Playfair Display 600/700（静态 woff2 内嵌）** | ⚠️ 见下方字体纪律 |
| 字体（正文） | Microsoft YaHei 栈 | 正文与常见标签 |
| 字体（中文衬线） | Source Han Serif SC Heavy 栈 | 中文标题块 / 示意区大标题 |
| 字体（公式） | ziamath → **纯 path SVG**（零 font / 零 text / 零远程引用） | 天然免 Type3；显示高度由 `eq_scaled()` 反推 |

> ⚠️ **字体纪律（实测教训，勿违）**：标题字体**必须**「**静态字体文件内嵌**」（@font-face ＋ base64）——**禁止**使用系统「**可变字体**」：Windows 的 Sitka 家族即 SitkaVF.ttf，Chrome 打印 PDF 时**无法子集嵌入**，整段标题会落成 **Type3**（阅读器显示完全正常，期刊/印厂拒收）。实测对照：Sitka 标题 → 每份 PDF 各 5 处 Type3；换静态内嵌 Playfair → **Type3=0**。字体文件在 `assets/fonts/`；缺文件时构建**告警**并降级到 Cambria/Georgia（安全但质感次优，**不静默**）。

> **字体资产来源与许可（如实登记）**：**Playfair Display**，作者 Claus Eggers Sørensen，许可 **SIL Open Font License 1.1**（允许商用、嵌入与再分发；OFL 允许随产品分发字体文件本身，但不允许单独出售字体）。静态 woff2 取自 `@fontsource/playfair-display` npm 发行包（jsDelivr CDN），落 `assets/fonts/playfair-display-600.woff2`（23228 B）与 `-700.woff2`（23224 B），**随技能发行**。⚠️ 体积代价**实测**：base64 内联后 **61940 字符（≈60 KB）/ 卡**（两个 weight 各一段），占单卡 HTML 的 **54%～60%**（ridge 113043 B ／ gmm 102182 B）——**这是「矢量 PDF 零 Type3」的门票价，不是可选项**。

## 5. 工具链与验收

| 工具 | 职责 | 用法 |
| --- | --- | --- |
| `scripts/methodcard_lib.py` | 引擎核心库：SVG 工具 ＋ **10 个子图组件**（散点拟合 / 系数柱 / 等高线 / 密度 / 热力格 / 曲线 / 箭头 / 徽章 / 高斯椭圆 / 聚类椭圆）＋ 公式封装 | `--selftest`（10 组件冒烟 ＋ 公式纯路径断言） |
| `scripts/methodcard_build.py` | 五区骨架 HTML/CSS ＋ 组装 ＋ **Chrome 原生导出**（PNG @2x / PDF 矢量；无 Playwright 依赖，规避其 SIGTERM 卡死） | `--selftest`（结构 ＋ 零远程引用 ＋ 字体内嵌断言） |
| `scripts/methodcard_check.py` | **几何自检器**：SVG 图元越界（rect / circle / 旋转椭圆 / line / polyline）＋ 版面溢出（卡面之下不得有内容）＋ PNG 尺寸断言 | `<card>.html --png <card>.png`；`--selftest`（1 正 4 反 ＋ 像素白/脏对照） |
| `scripts/check_vector_export.py` | **矢量件验收**（复用，见 §7.11.5）：零 Type3 / 字体全嵌入 / 单页 / 图幅 / 文本可提取 | `--expect 1200x1600` |

> **标准验收链**（一张卡交付前全过）：`methodcard_build --selftest` → 生成 HTML → 导出 PNG/PDF → `methodcard_check <html> --png <png>` → `check_vector_export <pdf> --expect 1200x1600`。四项全绿只等于「**机器可见维度**无问题」（**≠ 卡片内容合格**，见 §7）。
> **导出通道**：`methodcard_build.export_png() / export_pdf()` —— Chrome 无头原生（`--screenshot` / `--print-to-pdf`），探测链 Chrome → Edge，不能静默降级。

## 6. 与既有面的分界

| 既有面 | 分界 |
| --- | --- |
| `references/research-mode.md` §7.11 | 本文件是通道表**第三行的细则**；归属总表、RF1–RF8、输出拨盘以 §7.11 为准（**不重述**） |
| `references/diagram-mode.md`（P0–P4） | P0–P4 管「一张图该不该画、画成什么」；本通道管「**一页讲解**的版面结构」。卡片**内**子图：类数据图的仍按前两通道规则绘制；**示意性子图**（教学示意、非真实数据）须在图注写明「示意」 |
| 外部技能 `diagram-design` | **无关、不混用** —— 其 45 类型为工程/数据/架构图，无教学卡片类；且其「低密度、删除优先」哲学与卡片的高密度相反 |
| `references/ppt-mode.md` | 卡片是**独立版面产物**；进 PPT 时先出卡片 PNG/PDF，再交 `ppt-master` 落版（同 §7.11.6 对 PPT 内嵌图的处置） |
| 学习资料类任务 | 本通道服务「学习资料」用途；但学习信号回路（learning 相关）**不在本文件**，各归各 |

## 7. 诚实边界（如实登记，勿夸大）

1. **机器判据只覆盖「几何 ＋ 文件完整性」**：`methodcard_check.py`（图元越界/版面溢出/尺寸）＋ `check_vector_export.py`（矢量件四维）。**卡片内容对不对**（文案、数据、逻辑、公式含义）**全部靠人审** —— 不得宣称「已自动拦截」。
2. **几何检查不覆盖 path 内部**：公式 path 由 ziamath 保证 ＋ `methodcard_lib.py --selftest` 的纯路径断言；`methodcard_check.py` 对 path 只计数、按「未检测」报出。
3. **text 元素只按锚点粗查**（字宽不可靠），仅 WARN 不计 FAIL。
4. **示意性子图的数字是「说明性示例」**：固定种子可复现，**不是**真实测量，**不得**当数据图引用；用于论文/正式材料时图注须标明示意属性。
5. **审美质感不机器可检**：版式凭证 = 样板**用户目检** ＋ 几何自检；迭代轮次取决于目检反馈（本通道建立时两张样板各经 3 轮）。
6. **导出依赖本地 Chrome/Edge**：探测链命中即用；皆无时**显式报错**（fail-closed），不静默降级 —— 这是本机事实，换机未测。
7. **字体降级链**：缺 `assets/fonts/` 的 woff2 时构建告警并降级到系统安全字体（Cambria/Georgia）；降级态**不阻断构建**，但质感贴合度下降。
8. 本文件**不新增** plan 字段 / judge / `checks.py` 判据 / rubric 条目（承 research-mode §9 同一纪律）。
