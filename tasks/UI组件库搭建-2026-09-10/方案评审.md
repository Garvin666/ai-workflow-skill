## 二、工程形态候选方案对比

| 维度 | 候选 1：dist 产物 + `file:` 依赖 | 候选 2：源码直引（path alias 指向 `ui库/src`） | 候选 3：源码直引为主 + build 兜底 |
| --- | --- | --- | --- |
| 可行性 | 高（标准库发布形态） | 高（Vite/TS 项目天然支持） | 高 |
| 改组件后的生效速度 | 需重新 build | 保存即生效 | 保存即生效 |
| 调试体验 | 差（跳转到 dist） | 好（直接跳源码） | 好 |
| 额外工具依赖 | 需 d.ts 生成链 | 无 | 无 |
| 对其他项目的侵入 | package.json 一行 | 一行 alias 配置 | 一行 alias 配置 |
| 可移植性（分享给他人） | 好 | 差（需同构环境） | 好 |
| 维护成本 | 中 | 低 | 中 |

**推荐：候选 3**。主推源码直引（自用场景够快够省），同时保留 `npm run build` 产出 `dist` 供不想配 alias 的场景使用。理由：自用组件库的最高频痛点是「改完不能立刻看到效果」，候选 1 恰好踩中；而候选 2 单独存在时又无法脱离本机环境复用。候选 3 成本仅多一个 build 脚本。

## 三、组件层复用决策

| 模块 | 决策 | 理由 |
| --- | --- | --- |
| Button / Input / Card | **自研** | 零依赖诉求；shadcn 源码强绑 Tailwind，与 CSS 变量方案冲突，只借鉴其 API 命名与令牌分层 |
| FlipCard / Cube / Carousel3D | **自研** | 纯 `transform` + `perspective`，无需依赖；自研可统一到本库的动画时长与缓动令牌 |
| TiltCard | **自研**（参考 react-parallax-tilt 思路） | 该库 MIT 且活跃可直用，但引入后会破坏「主入口零依赖」红线，故自研 |
| Canvas3D / ModelViewer / Chart3D / Graph3D | **复用 R3F + drei，仅自研外壳** | 3D 渲染底座自研无意义；进度/错误兜底/UI 开关等业务外壳自研 |

## 四、一个需要说明的版本变更

确认表里写的是 React 18，实施时改为 **React 19.3**。原因：`@react-three/fiber@9` 的 peer 要求 React 19；若坚持 React 18 需锁到 R3F 8（2024 年版本线，已不再跟进）。纯函数组件在 18/19 间基本互通，但 3D 入口的底座决定了必须选边。

**建议**：按 React 19.3 + R3F 9.7 + drei 10.7 实施；若你的存量项目锁死 React 18，请告知，我把 3D 入口降级到 R3F 8 线（改动仅限 package.json 与 three 入口，成本可控）。
